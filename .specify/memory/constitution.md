# Secret Santa Bot Constitution

## Core Principles

### I. Тайна по умолчанию (NON-NEGOTIABLE)

- Кто кому дарит, знает только Санта — и только про своего подопечного. Подопечный не знает своего Санту
  до «раскрытия». Администратор не видит пар ни в интерфейсе, ни в ответах API.
- Ни один ответ API не содержит пар «Санта → подопечный», кроме ответа самому Санте о его подопечном и служебного
  просмотра владельца.
- **Владелец** (с 3.0.0) — владелец компании в своей компании и владелец бота в любой компании. Компанию без
  назначенного владельца ведёт владелец бота.
- **Служебный просмотр владельца** (с 2.0.0) — единственное исключение: только владелец компании события или владелец
  бота, отдельный экран, вход явным действием (ввод слова), каждое открытие записывается в журнал события (без самих
  пар); просмотр не меняет статусы участников. Участникам об этой возможности (пары может открыть владелец своей
  компании, а владелец бота — в любой компании; чужое письмо может открыть администратор) честно сказано в README; в
  приложении — по решению владельца проекта.
- Администратор видит только статусы (зарегистрирован, письмо заполнено/пусто, открыл ли подопечного, подарок готов,
  получен ли подарок, указан ли адрес).
  Содержимое чужого письма открывается лишь отдельным действием с явным подтверждением и записью в журнал.
- Ограничения, которые нужны лишь затем, чтобы администратор не вычислил пары косвенно, обязательны для
  администраторов; на владельца (компании — в своей компании, бота — в любой) они не распространяются. Вписывать в
  жеребьёвку после неё, менять подопечных и принудительно отменять жеребьёвку может только владелец.
- **Закреплённые пары** (с 2.3.0) — решение владельца до жеребьёвки «кто кому дарит»: их видит и меняет только
  владелец в панели события. Администраторам они не отдаются ни в интерфейсе, ни в ответах API; запись журнала и
  причина невозможности жеребьёвки не содержат имён.
- **Тайна между компаниями** (с 3.0.0): права владельца и администратора действуют только в своей компании; ни
  организатор, ни владелец компании не видят событий, людей, семей, пар и журнала другой компании.
- **Названия компаний личные** (с 3.0.0): название, которое дал компании владелец бота, видит только владелец бота;
  своё название компании видит только тот, кто его дал. Ни одно название не входит в ответы API и сообщения другим
  людям и не пишется в журнал компании. Исключение (с 3.1.0) — **общее название** компании, которую создал человек в
  открытом боте: его видят люди этой компании и владелец бота, людям вне компании оно не уходит.
- Push-уведомления не содержат имени подопечного и текста письма: превью видно на экране блокировки.
- Адрес доставки участника видит только он сам, его Санта в этом эвенте и владелец в служебном просмотре;
  администратор видит лишь, указан ли адрес.
- История эвентов не ослабляет тайну: в завершённых эвентах администраторы видят состав и статусы, но не пары;
  каждый участник видит только свои пары и свою переписку.

### II. Проще некуда для участника

- Вход без паролей: личность = аккаунт Telegram. Регистрация только по пригласительной ссылке; в **открытом боте**
  (с 3.1.0 — бот, которому при выкате разрешено создание компаний людьми) — и без неё: человек называет себя и заводит
  свою компанию. Закрытый бот (по умолчанию) человека без ссылки не регистрирует.
- Работает на iOS, Android и компьютерах через Telegram без установки чего-либо ещё.
- Весь интерфейс (с 4.0.0) — на языке человека и понятен человеку без технического опыта. Языки бота: русский,
  английский, испанский, португальский (бразильский), французский, немецкий, китайский (упрощённый), итальянский,
  турецкий, индонезийский, польский. Язык человека: выбранный им самим (в «Профиле» мини-приложения и командой
  `/language`; можно вернуть «как в Telegram») → язык его Telegram, если он есть в боте → русский для белорусского,
  украинского, казахского, киргизского, таджикского, узбекского, армянского, азербайджанского и туркменского → английский.
  Русский интерфейс для русскоязычных — прежний. Слова подтверждения — на языке человека.
- Длинные тексты (письмо — до 4000 символов: столько помещается в одно сообщение Telegram) редактируются
  в мини-приложении, а не сообщениями в чате.

### III. Спецификация до кода

- Любое изменение поведения начинается с обновления спецификации в `specs/` по процессу Spec Kit:
  `/speckit-specify` → (`/speckit-clarify`) → `/speckit-plan` → `/speckit-tasks` → `/speckit-implement`.
- Спецификация — источник истины. Если код и спецификация расходятся, правится то, что неверно,
  и расхождение фиксируется в той же ветке.
- Каждая фича живёт в своей ветке `NNN-короткое-имя` и своей папке `specs/NNN-короткое-имя/`.

### IV. Только дизайн-система

- Любой интерфейс строится из токенов и компонентов `design-system/` (цвета, типографика, отступы,
  радиусы, тени, компоненты).
- В разметке и коде страниц запрещены «сырые» цвета, размеры в px и отступы вне шкалы токенов;
  это проверяет автотест `tests/design-system.test.mjs`.
- Нужен новый элемент — сначала он добавляется в дизайн-систему (токены → компонент → превью
  в `design-system/preview.html` → описание в `design-system/README.md`), потом используется.
- Цвета опираются на тему Telegram (`--tg-theme-*`), чтобы светлая и тёмная темы работали автоматически.

### V. Бесплатно и без своего сервера

- Проект работает на бесплатном тарифе Cloudflare Workers + D1 без банковской карты.
- Код укладывается в лимиты бесплатного тарифа: ≤ 10 мс CPU на вызов, ≤ 50 внешних запросов
  (включая запросы к D1) на вызов, ≤ 100 000 запросов в сутки.
- Массовые рассылки идут через очередь `outbox` пачками, а не в одном вызове.
- Никаких платных сервисов и внешних зависимостей во время работы, кроме Telegram Bot API.

### VI. Проверено до выката

- Алгоритм жеребьёвки покрыт юнит-тестами (исключения, невозможные случаи, замены после жеребьёвки).
- Перед выкатом проходит сквозной тест: локальный Worker + имитация Telegram API, полный сценарий игры
  и проверки тайны (админ не видит пар, уведомления без имён, чужие запросы отклоняются).

### VII. Владелец — максимальные права

- **Владелец бота ⊇ владелец компании ⊇ администратор** (с 3.0.0) — в каждой компании. Владелец бота один; у каждой
  компании — свой назначенный владелец или, пока его нет, владелец бота.
- Владелец компании может в ней всё, что может администратор, и больше: назначать и снимать админов, передавать свои
  права человеку компании, сбрасывать и удалять эвенты, закреплять пары, вписывать и менять подопечных после
  жеребьёвки, принудительно отменять её, открывать служебный просмотр.
- Только владельцу бота: создавать, называть и удалять компании, ссылки владельца компании и «вести самому» (вернуть
  компанию себе), переносить участие на новый аккаунт (аккаунт один на все компании), передавать права владельца бота,
  журнал бота, страница настройки `/setup`. Владелец бота может всё в любой компании; в компании, где он не человек
  компании, он «гость»: его нет в её списках и рассылках организаторам, его изменения — в её журнале под его именем.
- **Открытый бот** (с 3.1.0): создать компанию может любой зарегистрированный человек — он становится её владельцем; во
  владении у человека не больше двух компаний (у владельца бота ограничения нет); владелец компании может удалить свою
  компанию без событий. Остальное «только владельцу бота» — прежнее.
- Любая новая возможность администратора сразу доступна владельцу компании и владельцу бота; это проверяет автотест.
- Права владельца — это доступ ко всем парам, поэтому путь к ним защищён: ключ настройки вводится только в форму,
  ссылка владельца бота срабатывает один раз и снова выдаётся только после смены `ADMIN_SECRET` (или токена бота
  `BOT_TOKEN`: от обоих считается код ссылки); ссылка владельца компании — одноразовая, со случайным кодом, её создаёт
  и отзывает только владелец бота.

## Безопасность и данные

- Каждый запрос мини-приложения проверяется по подписи Telegram `initData` (HMAC-SHA-256 с токеном бота).
- Webhook принимает запросы только с секретным заголовком `X-Telegram-Bot-Api-Secret-Token`.
- Секреты (`BOT_TOKEN`, `ADMIN_SECRET`) хранятся только в секретах Cloudflare и никогда не попадают
  в репозиторий; `.dev.vars` и `.env*` в `.gitignore`.
- Пользовательский текст никогда не вставляется в HTML как разметка (только `textContent`
  в мини-приложении, экранирование в сообщениях бота).
- Храним минимум данных: Telegram ID, имя, ник, письма, адрес доставки (только если эвент его спрашивает), переписку
  Санты и подопечного, настройки уведомлений, семьи (группы исключений), заявки на вступление и отметки «удалён
  организатором» (чтобы при запрете возврата удалённый не вошёл по ссылке снова), обращения участников к
  организаторам (переписку обращения видят участник, админ, который его ведёт, и владелец; пока обращение никто не взял —
  все админы), закреплённые пары владельца (видит только владелец), журнал действий организаторов и бота (без пар,
  писем и текстов), компании и принадлежность к ним людей (в какие компании человек входил по ссылкам событий,
  администратор ли он в каждой, своё название компании), назначенные владельцы компаний, признак «название общее»
  (компанию создал человек в открытом боте), язык интерфейса человека (с 3.2.0; пусто — язык по умолчанию), язык его
  Telegram и язык кнопки меню его чата (с 4.0.0; язык Telegram запоминается при обращении). В открытом
  боте хранится и человек без компании — до своей компании или вступления по ссылке.
- Тексты для людей (с 3.2.0) — только из словаря (`src/i18n/<язык>/`): ответ — на языке того, кто спросил, сообщение
  бота — на языке получателя при отправке; подробности журнала (с 4.0.0) — на языке смотрящего (новая запись хранит и
  отложенный текст, прежние записи — по-русски, как записаны).
- События, семьи и журнал принадлежат компании; права администратора и владельца компании действуют только в своей
  компании. Организатор не видит событий, людей, семей и журнала другой компании: чужое событие для него — как
  несуществующее. Владелец бота ведёт компании без своего владельца.
- Ссылка владельца компании (с 3.0.0) — случайный одноразовый код (80 бит) в базе: действует до использования, отзыва
  или замены новой; её видит только владелец бота (в ответ на создание), в журнал и ответы другим людям она не попадает;
  из одновременных переходов права получает один, владелец бота получает сообщение, кто стал владельцем.
- Журнал бота (с 3.0.0) — создание и удаление компаний, смена их владельцев, создание и отзыв ссылок владельца компании
  (без кодов), смена владельца бота; его видит только владелец бота. Удалить можно только компанию без событий.
  Эвенты хранятся как история, пока владелец не удалит эвент; удалённый из эвента участник теряет в нём письмо,
  пары, переписку и обращения.
- Ограничение «тайна» — организационное, не криптографическое: владелец аккаунта Cloudflare технически
  может открыть базу. Это явно сказано в README.

## Процесс разработки

- Платформа разработчика — Windows; скрипты Spec Kit — PowerShell (`.specify/scripts/powershell/`).
- Проект живёт в `C:\ClaudeProjects\secret-santa-bot\`; в самой `C:\ClaudeProjects\` файлы не создаются.
- Сообщения коммитов — по-русски или по-английски, кратко и по сути; одна логическая единица на коммит.
- **README.md обновляется в той же ветке, что и фича**, если фича меняет установку, настройку, секреты, команды,
  роли или то, как пользоваться ботом. В `tasks.md` каждой фичи есть отдельная задача на README; фича без неё
  не считается готовой.
- Перед коммитом: `npm test` — быстрые тесты всего Worker (тайна, права, одновременные вызовы, число запросов,
  дизайн-система, слова, описание API `docs/api.md`); перед слиянием и выкатом: `npm run test:e2e`
  (или `npm run test:all` — оба подряд).
