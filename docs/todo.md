## Сделать позже

Не начато; делать только по слову владельца, через Spec Kit.

- **Добавить в событие знакомых боту людей** (отложено владельцем 2026-11-17). Сейчас после удаления события его
  участников не позвать кнопкой «Пригласить участников»: она берёт людей из существующего события, а у удалённого их
  уже нет. Люди при этом остаются в `users` с именем, и ссылка нового события впускает их без повторного ввода имени.
  Идея: организатор выбирает зарегистрированных людей, которых нет в событии (поиск по имени и `@username`), и
  добавляет их сразу. Новое действие (например, `admin.member.add { event, ids }`) через `atomic`: при двойном нажатии —
  одно сообщение и одна запись журнала `member.add`; добавленному — сообщение с кнопкой «✏️ Написать письмо», админам —
  без звука. Схема и `REGISTRY` не меняются. Решить заранее: только при открытой регистрации (правило «закрыто — значит
  никто»); после жеребьёвки — как одобрение заявки (без пары, вписывает владелец) или запретить; отметку «удалён
  организатором» снимать; согласия нет, а сам выйти участник не может — в сообщении сказать «если не участвуешь —
  напиши организатору»; у заблокировавших бота — отметка в списке. Мягкий вариант — личное приглашение выбранным людям
  кнопкой «Участвовать» (через `joinByInvite`).
  **По `@username`** бот человека не найдёт (`getChat` по `@username` — только публичные группы и каналы) и первым не
  напишет тому, кто не нажимал Start. Значит, «по тегу» — это только поиск в том же списке. `users.username` сейчас
  пишется лишь при первом сообщении и при вводе имени — для поиска обновлять его при каждом сообщении боту (запись —
  только при изменении).
