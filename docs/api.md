# API мини-приложения, бот и журнал — сводный контракт

Актуальное описание всех 59 действий API, порядка проверок, кодов журнала, режима ожидания ответа в чате бота, кнопок
бота и ссылки на мини-приложение. Составлено по коду (фича 022, `main` после шага 6 рефакторинга) и сверяется тестом
`tests/api-doc.test.mjs` с таблицей действий `ACTIONS` (`src/api.js`) и с кодами журнала, которые пишет сервер.

Контракты фич 001–014 (`specs/*/contracts/`) — история решений; если они расходятся с этим документом, верен этот
документ, а источник истины для обоих — код. Внутреннее устройство API (таблица действий, контекст вызова, модули,
пакеты чтений) — `specs/019-api-actions/contracts/api-actions.md`; атомарные действия — `specs/020-claims-snapshots/`.

## Как читать

- **Кто** — роль из таблицы действий: `любой` — любой человек с верной подписью Telegram; `зарегистрированный` — написал
  боту имя; `участник` — участник события из поля `event`; `участник или админ` — участник события или любой админ;
  `админ` — администратор бота (владелец тоже админ); `владелец` — только владелец бота.
- **Событие** — `да`: нужно поле `event` (id события); `если передано`: с полем — действие события, без него — общее;
  `—`: событие не нужно.
- **В завершённом** (событие со `status = 'finished'`) — `нет`: отказ 400 до обработчика с текстом из раздела действия;
  `да`: работает; `7 суток`: читать можно всегда, писать — 7 суток после завершения (`CHAT_GRACE_MS`, `src/status.js`),
  потом отказ обработчика; `проверяет обработчик`: конвейер пропускает, свой порядок отказов — в разделе; `—`: действие
  без события.
- Тексты в «ёлочках» — побайтно как в коде; `<…>` — подстановка. Время — миллисекунды Unix (`Date.now()`), даты —
  `YYYY-MM-DD`, id людей — Telegram ID.
- «Сообщения» — что ставится в очередь `outbox` другим людям (отправляется после ответа и cron); тексты сообщений здесь не
  повторяются — они в коде модуля.

## Запрос и ответ

- `POST /api/<действие>`, например `POST /api/admin.state`. Другой метод — 405 `method`.
- Заголовок `x-init-data` — строка `initData` мини-приложения Telegram; подпись проверяется по `BOT_TOKEN`
  (`validateInitData`, `src/telegram.js`), не старше 24 часов.
- Тело — JSON-объект с полями действия; нечитаемое тело считается `{}`. Числовые id принимаются и числом, и строкой.
- Ответ — JSON, `content-type: application/json; charset=utf-8`, `cache-control: no-store`:
  успех — `{ "ok": true, …поля ответа }`; отказ — `{ "ok": false, "error": "<текст для человека>" }` с кодом из раздела.
  Поля ответа ниже перечислены без `ok`.

## Порядок проверок и общие отказы

Конвейер `handleApi` (`src/api.js`) — один для всех действий, по порядку:

1. Не `POST` — 405 `method`.
2. Подпись `initData` не прошла — 401 «Не удалось проверить вход. Открой приложение заново из чата с ботом.»
3. Пользователь и настройки читаются одним пакетом (`openContext`); у пользователя снимается отметка «бот заблокирован»
   (`users.blocked_at = 0`) — до любых отказов по правам.
4. Роль не `любой`, а человек не зарегистрирован — 403 «Сначала зарегистрируйся по пригласительной ссылке.»
5. `admin.*`, а человек не админ — 403 «Только для администратора.» Затем сразу определяется владелец: если
   `settings.owner_id` недействителен, владельцем записывается самый ранний админ (`resolveOwner`, `src/roles.js`).
6. Действие без события (или `admin.audit` без `event`): не владелец там, где нужен владелец, — 403 (текст раздела);
   иначе обработчик.
7. Событие не найдено — 404 «Событие не найдено.»
8. Не `admin.*`: человек не участник события — 403 «Ты не участвуешь в этом событии.» (у `event.get` админ проходит и без
   участия).
9. Событие завершено, а у действия «в завершённом — нет» — 400 с текстом действия.
10. Нужен владелец, а вызвал не он, — 403 с текстом действия. **После** шага 9: админ на завершённом событии получает
    400, а не 403.
11. Нужно слово подтверждения (поле `confirm`, без учёта регистра и пробелов по краям), а его нет — 400 с текстом действия.
12. Обработчик: его отказы — в разделе действия (400, если не сказано иначе).

Неизвестное действие проходит тот же путь как строка-заглушка и получает 404 «Неизвестное действие» в конце: имя на
`admin.` — как админское действие события (шаги 5, 7, 9 с текстом «Событие завершено — менять его уже нельзя (доступны
просмотр, раскрытие и удаление).»), остальные — как действие участника (шаги 4, 7, 8).

| Код | Текст | Когда |
|---|---|---|
| 405 | `method` | не `POST` |
| 401 | «Не удалось проверить вход. Открой приложение заново из чата с ботом.» | подпись `initData` |
| 403 | «Сначала зарегистрируйся по пригласительной ссылке.» | не зарегистрирован |
| 403 | «Только для администратора.» | `admin.*` не админу |
| 404 | «Событие не найдено.» | нет события с таким `event` |
| 403 | «Ты не участвуешь в этом событии.» | действие участника не участнику |
| 400 | текст действия | событие завершено, «в завершённом — нет» |
| 403 | текст действия («… может только владелец бота.» или текст служебного просмотра) | действие владельца не владельцу |
| 400 | текст действия («Для … введи слово …») | нет слова подтверждения |
| 404 | «Неизвестное действие» | нет такого действия |
| 500 | «Ошибка сервера. Попробуй ещё раз.» | исключение в обработчике (`src/index.js`; в лог — `api failed`) |
| 500 | «База не подготовлена: примени миграции (см. README).» | схема базы ниже `REQUIRED_SCHEMA` (`src/db.js`) — до конвейера |

Эталон кодов и текстов отказов «без прав / нет события / завершено» для всех действий — `tests/fixtures/api-refusals.json`
(1125 ответов).

**Повторные нажатия (024).** Меняющее действие, вызванное дважды (в том числе одновременно, в одну миллисекунду),
меняет данные и рассылает сообщения один раз; второй вызов получает отказ из раздела действия. Рассылки по желанию
организатора — объявление (тот же текст), ручные напоминания, приглашение из другого события — в одном событии не чаще
раза в минуту: окно считается от времени первой рассылки (объявления или записи журнала), другой текст объявления — не
повтор. Плановые напоминания cron это окно не проверяют.

## Действия участника

### `me`

Кто: любой. Событие: —. Главный экран: кто я и мои события.

- **Запрос**: полей нет.
- **Ответ**: не зарегистрирован — `registered: false` (и больше ничего). Зарегистрирован — `registered: true`;
  `me` — `{ id, name, is_admin, is_owner, notify_mode }` (`is_owner` — только у админа-владельца; `notify_mode` —
  `sound` | `silent` | `off`); `events` — события новыми первыми: участнику — только свои, админу — все, каждое
  `{ id, title, status, finished_at, event_date, draw_done, member, unread }` (`unread` — непрочитанные сообщения
  переписки и обращений в событии); `limits` — `{ chars: 4000 }` (`MAX_CHARS`).
- **Отказы**: только общие.
- **Журнал**: не пишет.

### `notify.set`

Кто: зарегистрированный. Событие: —. Режим уведомлений «подопечный изменил письмо» (во всех событиях).

- **Запрос**: `mode` — `sound` | `silent` | `off`.
- **Ответ**: пустой.
- **Отказы**: 400 `bad mode` — другое значение.
- **Журнал**: не пишет. То же меняют кнопки бота `notify` / `nm:<режим>`.

### `event.get`

Кто: участник или админ. Событие: да. В завершённом: да. Экран события.

- **Запрос**: `event`.
- **Ответ**:
  - `event` — поля события для участника и панели (`publicEvent`, `src/status.js`): `id, title, status, finished_at,
    chat_until` (до какого времени открыта переписка завершённого; у идущего — 0)`, budget, event_date, place, deadline,
    notes, draw_done, revealed, ring, delivery_on, approval, rejoin` и `participants` — число зарегистрированных
    участников;
  - `announcements` — до 20 последних объявлений `{ id, text, created_at, author_name }` (`author_name` — «Организатор»,
    если имени нет);
  - `member` — у неучастника `null`; у участника `{ wishlist, wishlist_updated_at, has_ward, has_santa, gift_received,
    delivery, unread: { from_ward, from_santa } }` (`delivery` — свой адрес; кто подопечный и кто Санта — не отдаётся);
  - `can` — `{ edit_letter, chat_write }` (у неучастника оба `false`);
  - участнику — `support: { available, open, assignee_name, unread }` (есть ли кому писать, открыто ли обращение, кто его
    ведёт, непрочитанные ответы);
  - админу — `support_admin: { waiting, unread }` (ничьи обращения, кроме своего; непрочитанное во взятых им).
- **Отказы**: только общие (админ проходит без участия).
- **Журнал**: не пишет.

### `wishlist.save`

Кто: участник. Событие: да. В завершённом: нет — 400 «Событие завершено: письмо теперь только для чтения.»

- **Запрос**: `event`, `text` — письмо Санте; `\r\n` → `\n`, пробелы по краям не обрезаются.
- **Ответ**: `updated_at` — время сохранения; если текст не изменился — прежнее время, запись не меняется.
- **Отказы**: 400 «Слишком длинно: <n> символов, максимум 4000 (лимит сообщения Telegram).» (длина — в единицах UTF-16,
  как `String.length`).
- **Журнал**: не пишет. Санта получает уведомление cron через `NOTIFY_DELAY_MINUTES` после последней правки (без
  текста письма).

### `delivery.save`

Кто: участник. Событие: да. В завершённом: проверяет обработчик.

- **Запрос**: `event`, `text` — адрес доставки; переводы строк нормализуются, пробелы по краям обрезаются.
- **Ответ**: `updated_at` (как у письма).
- **Отказы** (по порядку): 400 «В этом событии адрес доставки не нужен.» (`delivery_on = 0`); 400 «Событие завершено:
  адрес теперь только для чтения.»; 400 «Слишком длинно: <n> символов, максимум 500.»
- **Журнал**: не пишет. Адрес видят только сам участник (`event.get`), его Санта (`ward.get`) и владелец в служебном
  просмотре; админ — только `has_delivery`.

### `ward.get`

Кто: участник. Событие: да. В завершённом: да. Подопечный — единственный ответ API с парой (кроме служебного просмотра).

- **Запрос**: `event`.
- **Ответ**: `state` — `no_draw` (жеребьёвки нет), `waiting` (у человека нет подопечного: вступил после жеребьёвки) или
  `ok`. При `ok`: `ward` — `{ name, wishlist, updated_at }` и `delivery`, если в событии нужен адрес; `previous` —
  прежний увиденный текст письма, если письмо изменилось с прошлого открытия (иначе `null`); `first_view` — открыт ли
  подопечный впервые; `gift_ready`.
- **Отказы**: только общие.
- **Журнал**: не пишет. Запоминает увиденное письмо (`pairs.seen_text`) — по этому признаку админ видит «открыл
  подопечного», а отмена жеребьёвки админом становится невозможной.

### `ward.gift`

Кто: участник. Событие: да. В завершённом: нет — 400 «Событие завершено: отметка только для чтения.»

- **Запрос**: `event`, `ready` — подарок готов (истина) или нет.
- **Ответ**: пустой.
- **Отказы**: 400 «У тебя пока нет подопечного.»
- **Журнал**: не пишет.

### `ward.received`

Кто: участник. Событие: да. В завершённом: нет — 400 «Событие завершено: отметка только для чтения.»

- **Запрос**: `event`, `received` — подарок получен (истина) или нет.
- **Ответ**: пустой.
- **Отказы**: 400 «У тебя пока нет Санты.»
- **Журнал**: не пишет. Сообщения: Санте — при первой отметке «получил» (повторная и одновременная — без сообщения).

### `message.send`

Кто: участник. Событие: да. В завершённом: 7 суток. Анонимная переписка Санты и подопечного.

- **Запрос**: `event`, `to` — `santa` (написать своему Санте) или любое другое значение — подопечному; `text`.
- **Ответ**: `message` — `{ id, mine: true, text, created_at }`.
- **Отказы**: 400 «Пустое сообщение.»; 400 «Слишком длинно: <n> символов, максимум 4000 (лимит сообщения Telegram).»;
  400 «Событие завершено больше недели назад: переписка доступна только для чтения.»; 400 «У тебя пока нет
  подопечного.» / «Жеребьёвка для тебя ещё не проведена.»; 400 «Пара изменилась — обнови экран.» (пару сменили между
  проверкой и записью).
- **Журнал**: не пишет. Сообщения: собеседнику — текст с заголовком без имён и кнопками «↩️ Ответить»
  (`msg:<сторона>:<событие>`) и «💬 Вся переписка». Сообщения собеседника помечаются прочитанными.

### `chat.get`

Кто: участник. Событие: да. В завершённом: да.

- **Запрос**: `event`, `with` — `santa` или любое другое значение — подопечный; `after` — id последнего полученного
  сообщения (0 или нет — последние 300).
- **Ответ**: `state` — `no_pair` или `ok`; при `ok`: `counterpart` (`santa` | `ward`), `writable` — можно ли писать
  (открыта ли переписка), `messages` — до 300 `{ id, mine, text, created_at }` по порядку (без имён и id собеседника).
- **Отказы**: только общие.

## Бот

Webhook `POST /tg`: принимаются `message` (только личные чаты) и `callback_query` (`src/bot.js`). Сообщения людям вне
ответа на нажатие — только через очередь `outbox`.

### Команды и текст

| Что прислали | Что делает бот |
|---|---|
| `/start` | зарегистрированному — меню (до 5 идущих событий, кнопка приложения, до 3 строк кнопок переписки, «🔔 Уведомления»); ждущему имя — просьба имени; иначе — «🎄 Это закрытый бот для игры в Тайного Санту. …» |
| `/start adm_<код>` | ссылка владельца со страницы `/setup`: код — `adm_` и 24 знака HMAC с ключом `BOT_TOKEN` от `ADMIN_SECRET` (`ownerLinkCode`); срабатывает один раз (`claimOwnerLink`, отметка `settings.owner_link_used` — тоже от `ADMIN_SECRET` и `BOT_TOKEN`): человек становится владельцем (и админом), прежнему — предупреждение, журнал `owner.link`; повторно — «Ссылка владельца уже использована. …». Неверный код — как простой `/start` |
| `/start inv_<код события>` | приглашение: нет события с таким кодом — «Эта пригласительная ссылка устарела. …»; уже участник — «уже участвуешь» и меню; зарегистрированный — вступление (`joinByInvite`: вступил / регистрация закрыта / удалён без возврата / заявка отправлена / заявка уже ждёт / заявку недавно отклонили); новый — закрыто или удалён без возврата — отказ, иначе `pending = name:<событие>:<код>` и просьба имени (без одобрения заявок — сразу участник, ещё без имени) |
| `/cancel` | сбросить ожидание (`pending`); незарегистрированному — просьба имени |
| любая команда `/…` | выключает режим ответа в переписку и в обращение (текст после неё никому не уйдёт) |
| текст при `pending = name…` | имя (1–40 символов, не с `/`): регистрация, затем вступление по запомненной ссылке (код сменился — «устарела»); админам — «… присоединяется к событию» |
| текст в режиме ответа | см. `users.pending` |
| остальное | меню |

### Режим ожидания (`users.pending`)

| Значение | Что ждёт бот | Правила |
|---|---|---|
| пусто | ничего | — |
| `name` | имя (владелец по ссылке, ещё без имени) | — |
| `name:<событие>:<код>` | имя после пригласительной ссылки | код — код ссылки в момент перехода; сменился — «устарела» |
| `msg_<ward\|santa>:<событие>:<собеседник>:<мс>` | сообщение в переписку (кнопка `msg:…`) | собеседник — Telegram ID, на кого нажали; через час — «⌛ Время ответа истекло — сообщение не отправлено. …»; пара сменилась — «🔄 Пара изменилась после нажатия «Ответить» — …»; длиннее 4000 — отказ, режим остаётся |
| `msg_<ward\|santa>:<событие>` | старый формат (до фичи 009) | всегда «⌛ Время ответа истекло …» |
| `sup_u:<событие>:<мс>` | сообщение участника организатору (кнопка `sup:u:…`) | час; как `support.send` |
| `sup_a:<обращение>:<мс>` | ответ админа в обращение (кнопка `sup:a:…`) | час; как `admin.support.send` |

Режимы `msg_…` и `sup_…` сбрасывает любая команда, пустое сообщение (стикер, фото — затем меню), отклонённое нажатие
кнопки и любой ответ. Сборка и разбор — `replyPending`, `supportPending`, `parsePending` (`src/bot.js`).

### Кнопки `callback_data`

Незарегистрированному на любую кнопку — «Сначала зарегистрируйся по пригласительной ссылке.» Отказы — всплывающим
ответом (`answerCallbackQuery`).

| `callback_data` | Где | Что делает | Отказы |
|---|---|---|---|
| `msg:<ward\|santa>:<событие>` | меню бота; «↩️ Ответить» под сообщением переписки | режим ответа в переписку | «Событие не найдено.»; «У тебя пока нет подопечного.» / «Жеребьёвка для тебя ещё не проведена.»; «Событие завершено больше недели назад — переписка только для чтения.» |
| `sup:u:<событие>` | «↩️ Ответить» участнику под ответом организатора | режим `sup_u` | «Ты не участвуешь в этом событии.»; «Событие завершено больше недели назад — обращения только для чтения.»; «Сейчас некому написать: в боте нет других организаторов.» |
| `sup:take:<обращение>` | «🙋 Взять» админам под новым обращением | взять (как `admin.support.take`), затем кнопки «↩️ Ответить» и «💬 Открыть» | «Только для администратора.»; «Обращение не найдено.»; отказы `admin.support.take` |
| `sup:a:<обращение>` | «↩️ Ответить» админу | режим `sup_a` (ничьё возьмётся ответом) | «Только для администратора.»; «Обращение не найдено.»; «Обращение уже закрыто.»; «Это твоё обращение — отвечать на него будут другие организаторы.»; «Обращение ведёт <имя>.»; «Событие завершено больше недели назад — обращения только для чтения.» |
| `req:<заявка>:<a\|r>` | «✅ Принять» / «❌ Отклонить» админам под заявкой | решение по заявке (как `admin.request.decide`, но без проверки «событие завершено» конвейера: принять в завершённое нельзя, отклонить — можно) | «Только для администратора.»; отказы решения по заявке |
| `notify` | «🔔 Уведомления» в меню | выбор режима уведомлений | — |
| `nm:<sound\|silent\|off>` | выбор режима | `users.notify_mode` (как `notify.set`) | неизвестный режим — молча |

Кнопки-ссылки: приложение (`web_app`, адрес — раздел ниже), «🎄 Участвовать» в приглашении из события (`url` —
пригласительная ссылка `https://t.me/<бот>?start=inv_<код>`).

## Ссылка на мини-приложение

`<base_url>/app?event=<id>&chat=<santa|ward>&support=<my|id>` — строит `appUrl` (`src/format.js`), `base_url` и имя бота
записывает страница `/setup`. Пустые параметры не пишутся. Кнопка меню чата (`setChatMenuButton`) открывает `/app` без
параметров.

| Параметр | Кто ставит | Что делает приложение (`start`, `openEvent`) |
|---|---|---|
| `event` | почти все кнопки «Открыть» в сообщениях бота | открыть это событие, если оно есть в `me.events`; без параметра у не-админа с единственным событием — открыть его сразу |
| `chat` | «💬 Вся переписка» под сообщением переписки | `santa` — открыть переписку с Сантой, `ward` — с подопечным (если пара есть) |
| `support` | «💬 Открыть» в сообщениях обращений | `my` — участнику: вкладка «Инфо» и его обращение; число — админу: вкладка «Админ» и это обращение |

Подпись `initData` приложение берёт у Telegram (`Telegram.WebApp.initData` или `#tgWebAppData`); без неё — экран «Открой
через Telegram». Вернувшись на главный экран, приложение убирает параметры из адреса.

## Остальные маршруты и расписание

| Маршрут | Что делает |
|---|---|
| `POST /tg` | webhook бота; заголовок `x-telegram-bot-api-secret-token` должен совпасть с производным секретом (`derivedSecret(env, 'webhook')`), иначе 403 `forbidden`; ответ всегда `ok` (ошибка — в лог `update failed`) |
| `/app` | страница мини-приложения (склейка `src/app/` со стилями дизайн-системы), `cache-control: no-store` |
| `/api/<действие>` | этот документ |
| `/setup` | GET — форма ключа; POST — ключ `ADMIN_SECRET`: неверный — 403, ссылка владельца уже использована — 423 до смены `ADMIN_SECRET` или `BOT_TOKEN`, нет `ADMIN_SECRET` (или короче 8) — 500; верный — настройка бота (webhook, команды `/start` и `/cancel`, кнопка меню, описания), `base_url` и имя бота в `settings`, ссылка владельца. Заголовки `no-store`, `no-referrer`, `frame-ancestors 'none'`, `noindex` (`src/setup.js`) |
| остальные пути | 200 «🎄 Бот Тайного Санты работает.» |
| любой, без `BOT_TOKEN` | 500 «Не задан секрет BOT_TOKEN (см. инструкцию).» |
| любой, схема не готова | 500 «База не подготовлена: примени миграции (см. README).» (у `/api/*` — в JSON) |

Cron — раз в минуту (`src/cron.js`), шаги независимы: уведомления Сантам об изменении письма или адреса подопечного
(через `NOTIFY_DELAY_MINUTES` после последней правки, без текста); с `REMINDER_HOUR` по местному времени
(`TIMEZONE_OFFSET_HOURS`) — не больше одного тяжёлого действия за вызов: автожеребьёвка (`draw_auto_date` наступила),
автораскрытие (`reveal_auto`, на следующий день после `event_date`), автозавершение (`finish_auto`, через 3 дня после
`event_date`), ежедневные напоминания (письмо — за 2 дня, за день и в день `deadline`, только до жеребьёвки; Сантам — за 2
дня и в день `event_date`, после жеребьёвки); отправка очереди `outbox`.
