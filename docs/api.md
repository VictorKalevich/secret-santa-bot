# API мини-приложения, бот и журнал — сводный контракт

Актуальное описание всех 77 действий API, порядка проверок, кодов журнала, режима ожидания ответа в чате бота, кнопок
бота и ссылки на мини-приложение. Составлено по коду (фича 022, `main` после шага 6 рефакторинга) и сверяется тестом
`tests/api-doc.test.mjs` с таблицей действий `ACTIONS` (`src/api.js`) и с кодами журнала, которые пишет сервер.

Контракты фич 001–014 (`specs/*/contracts/`) — история решений; если они расходятся с этим документом, верен этот
документ, а источник истины для обоих — код. Внутреннее устройство API (таблица действий, контекст вызова, модули,
пакеты чтений) — `specs/019-api-actions/contracts/api-actions.md`; атомарные действия — `specs/020-claims-snapshots/`.

**Слово (059).** В текстах для людей компания называется «комната»: экран «Комнаты», «🚪 Создать комнату», отказы и
сообщения — `specs/059-room-wording/contracts/texts.md`. Здесь, в коде и в спецификациях — внутренний термин «компания»;
цитаты текстов ниже — в новых словах.

**Компании (050).** Каждое событие, семья и запись журнала принадлежат компании; человек может быть в нескольких
компаниях и в каждой — со своими правами (`company_members`). Права администратора, списки людей, семьи, прошлые пары и
общий журнал считаются в пределах компании; чужое событие для организатора другой компании — как несуществующее.
Компанию без своего владельца (`companies.owner_id = 0`) ведёт владелец бота. Пока компания одна, всё работает как до
компаний; внутреннее устройство — `specs/050-company-scope/contracts/company-scope.md`.

**Компании (051).** Владелец бота создаёт компании (`bot.company.create`), отдаёт компанию владельцу одноразовой ссылкой
(`bot.company.link`, бот: `/start own_<код>`) или назначает владельцем человека компании (`admin.owner.transfer`), удаляет
пустую компанию (`bot.company.delete`) и читает журнал бота (`bot.audit`). Владелец компании может в ней всё, что владелец
(действия «владелец»), кроме `admin.transfer` (только владелец бота). В чужой компании владелец бота — гость: в её
списках его нет, её организаторам сообщения ему не приходят, его изменения пишутся в её журнал. Название компании,
которое дал владелец бота, видит только он; остальные видят своё название (`company.label.set`) или «Комната N».
Тексты «может только владелец бота» в компании с назначенным владельцем — «может только владелец» (`ownerWord`,
`src/format.js`). Контракт — `specs/051-companies/contracts/companies.md`.

**Язык человека (061).** Ответы API, сообщения бота и очереди, кнопки, команды и описание бота — на языке человека:
выбранный им (`lang.set`, бот `/language`), иначе язык его Telegram (из подписанных данных приложения и из `from`
сообщения или нажатия: есть в боте — он, `pt-br` → `pt`, `zh-hant` → `zh`; `be`, `uk`, `kk`, `ky`, `tg`, `uz`, `hy`, `az`,
`tk` → русский; прочие → английский), иначе последний известный язык Telegram (`users.tg_lang`), иначе русский. Языки:
ru, en, es, pt, fr, de, zh, it, tr, id, pl. Тексты в «ёлочках» ниже — русские; на других языках — переводы из
`src/i18n/<язык>/`. Журнал хранит русский текст и (для новых записей) ключ с подстановками — подробности показываются на
языке смотрящего. Контракт — `specs/061-i18n-languages/contracts/language.md`.

**Открытый бот (052).** Бот открытый, если в `vars` его окружения `OPEN_BOT = "1"` (второй бот), иначе закрытый (первый;
всё как в 051). В открытом боте человек без ссылки регистрируется, назвав имя, и любой зарегистрированный создаёт свою
компанию (`company.create`): он её владелец, название общее — его видят люди компании (`companies.shared = 1`); своих
компаний во владении — не больше двух (у владельца бота лимита нет). Свою пустую компанию владелец удаляет
(`company.delete`). В закрытом боте оба действия доступны только владельцу бота (как `bot.company.*`). Контракт —
`specs/052-open-bot/contracts/open-bot.md`.

## Как читать

- **Кто** — роль из таблицы действий: `любой` — любой человек с верной подписью Telegram; `зарегистрированный` — написал
  боту имя; `участник` — участник события из поля `event`; `участник или админ` — участник события или организатор его
  компании; `админ` — организатор компании действия (компания события из `event`, у общих действий — поле `company`):
  администратор компании, её владелец или владелец бота; `владелец` — владелец компании действия (у компании без своего
  владельца — владелец бота) или владелец бота; `владелец бота` — только владелец бота (`settings.owner_id`, 051).
- **Событие** — `да`: нужно поле `event` (id события); `если передано`: с полем — действие события, без него — общее;
  `—`: событие не нужно.
- **В завершённом** (событие со `status = 'finished'`) — `нет`: отказ 400 до обработчика с текстом из раздела действия;
  `да`: работает; `7 суток`: читать можно всегда, писать — 7 суток после завершения (`CHAT_GRACE_MS`, `src/status.js`),
  потом отказ обработчика; `проверяет обработчик`: конвейер пропускает, свой порядок отказов — в разделе; `—`: действие
  без события.
- Тексты в «ёлочках» — побайтно как в коде; `<…>` — подстановка. Время — миллисекунды Unix (`Date.now()`), даты —
  `YYYY-MM-DD`, id людей — Telegram ID.
- «Сообщения» — что ставится в очередь `outbox` другим людям (отправляется после ответа и cron); тексты сообщений здесь не
  повторяются — они в коде модуля.

## Запрос и ответ

- `POST /api/<действие>`, например `POST /api/admin.state`. Другой метод — 405 `method`.
- Заголовок `x-init-data` — строка `initData` мини-приложения Telegram; подпись проверяется по `BOT_TOKEN`
  (`validateInitData`, `src/telegram.js`), не старше 24 часов.
- Тело — JSON-объект с полями действия; нечитаемое тело считается `{}`. Числовые id принимаются и числом, и строкой.
- Ответ — JSON, `content-type: application/json; charset=utf-8`, `cache-control: no-store`:
  успех — `{ "ok": true, …поля ответа }`; отказ — `{ "ok": false, "error": "<текст для человека>" }` с кодом из раздела.
  Поля ответа ниже перечислены без `ok`.
- Тексты для людей (060) — из словаря (`src/i18n/<язык>/`): отказы и тексты ответа — на языке вызывающего
  (`users.lang`, пусто — русский), сообщения бота другим людям — на языке получателя при отправке, подробности журнала —
  на русском. Тексты ниже — русские; в шаге 1 язык у всех русский, ответы побайтно прежние.

## Порядок проверок и общие отказы

Конвейер `handleApi` (`src/api.js`) — один для всех действий, по порядку:

1. Не `POST` — 405 `method`.
2. Подпись `initData` не прошла — 401 «Не удалось проверить вход. Открой приложение заново из чата с ботом.»
3. Пользователь и настройки читаются одним пакетом (`openContext`); у пользователя снимается отметка «бот заблокирован»
   (`users.blocked_at = 0`) — до любых отказов по правам.
4. Роль не `любой`, а человек не зарегистрирован — 403 «Сначала зарегистрируйся по пригласительной ссылке.» Роль
   `владелец бота`, а вызвал не он, — 403 «Только для владельца бота.» (051).
5. `admin.*`, а человек не администратор ни в одной компании и не владелец бота — 403 «Только для администратора.»
   Затем сразу определяется владелец бота: если `settings.owner_id` недействителен, владельцем записывается самый ранний
   администратор компаний без своего владельца (`resolveOwner`, `src/roles.js`).
6. Действие без события (или `admin.audit` без `event`):
   - общее действие организатора (раздел «Действия админа без события»): компания — поле `company` или, если его нет,
     единственная компания вызвавшего (у владельца бота — единственная компания бота); не определилась — 400 «Выбери
     компанию.»; такой компании нет или вызвавший в ней не организатор — 403 «Только для администратора.»; не владелец
     там, где нужен владелец, — 403 (текст раздела); иначе обработчик в пределах этой компании;
   - `me`, `notify.set`, `name.set`, `company.label.set`, `company.create`, `company.delete`, `bot.*` — проверка слова
     подтверждения (шаг 11), затем обработчик.
7. Событие не найдено — 404 «Событие не найдено.» Дальше всё считается в пределах компании события.
8. `admin.*`: вызвавший не организатор компании события — 404 «Событие не найдено.» (чужое событие — как
   несуществующее). Не `admin.*`: человек не участник события — 403 «Ты не участвуешь в этом событии.» (у `event.get`
   организатор компании события проходит и без участия).
9. Событие завершено, а у действия «в завершённом — нет» — 400 с текстом действия.
10. Нужен владелец, а вызвал не он, — 403 с текстом действия. **После** шага 9: админ на завершённом событии получает
    400, а не 403. Текст — по компании (051): в компании, которую ведёт владелец бота, — «… может только владелец бота.»
    (как в разделе действия), в компании с назначенным владельцем — «… может только владелец.» (`ownerWord`).
    `admin.transfer` — только владелец бота (владельцу компании — 403 с текстом раздела).
11. Нужно слово подтверждения (поле `confirm`, без учёта регистра, пробелов по краям и диакритики — 061; слово — на языке человека), а его нет — 400 с текстом действия.
12. Обработчик: его отказы — в разделе действия (400, если не сказано иначе).

Неизвестное действие проходит тот же путь как строка-заглушка и получает 404 «Неизвестное действие» в конце: имя на
`admin.` — как админское действие события (шаги 5, 7, 8, 9 с текстом «Событие завершено — менять его уже нельзя (доступны
просмотр, раскрытие и удаление).»), остальные — как действие участника (шаги 4, 7, 8).

| Код | Текст | Когда |
|---|---|---|
| 405 | `method` | не `POST` |
| 401 | «Не удалось проверить вход. Открой приложение заново из чата с ботом.» | подпись `initData` |
| 403 | «Сначала зарегистрируйся по пригласительной ссылке.» | не зарегистрирован |
| 403 | «Только для владельца бота.» | действие `bot.*` не владельцу бота (051) |
| 403 | «Только для администратора.» | `admin.*` не администратору ни одной компании; общее действие — не организатору компании `company` или такой компании нет |
| 400 | «Выбери комнату.» | общее действие без `company`, а компаний у вызвавшего несколько (050) |
| 404 | «Событие не найдено.» | нет события с таким `event`; у `admin.*` — событие компании, где вызвавший не организатор (050) |
| 403 | «Ты не участвуешь в этом событии.» | действие участника не участнику |
| 400 | текст действия | событие завершено, «в завершённом — нет» |
| 403 | текст действия («… может только владелец бота.» или текст служебного просмотра; в компании с назначенным владельцем — «… владелец.») | действие владельца не владельцу |
| 400 | текст действия («Для … введи слово …») | нет слова подтверждения |
| 404 | «Неизвестное действие» | нет такого действия |
| 500 | «Ошибка сервера. Попробуй ещё раз.» | исключение в обработчике (`src/index.js`; в лог — `api failed`) |
| 500 | «База не подготовлена: примени миграции (см. README).» | схема базы ниже `REQUIRED_SCHEMA` (`src/db.js`) — до конвейера |

Эталон кодов и текстов отказов «без прав / нет события / завершено» для всех действий — `tests/fixtures/api-refusals.json`
(1125 ответов; с 035 — ещё 41 ответ действий `name.set` и `event.leave`; с 051 — ещё 125 ответов шести действий компаний,
ключи «051 …»).

**Повторные нажатия (024).** Меняющее действие, вызванное дважды (в том числе одновременно, в одну миллисекунду),
меняет данные и рассылает сообщения один раз; второй вызов получает отказ из раздела действия. Ручные рассылки
владельца и администраторов (повтор того же объявления, напоминания, приглашения из другого события) проходят не чаще
раза в минуту: окно считается от времени первой рассылки (объявления или записи журнала), другой текст объявления — не
повтор. Плановые напоминания cron это окно не проверяют.

### `me`

Кто: любой. Событие: —. Главный экран: кто я и мои события.

- **Запрос**: `texts` (060, необязательно) — версия словаря приложения, которая уже есть у приложения.
- **Ответ**: всем (060) — `lang` (язык человека), `texts_version` (версия словаря приложения этого языка,
  `<язык>:<8 знаков>`) и `texts` — словарь приложения `{ 'app.…': текст | формы | список }`, только если в запросе нет
  `texts` или версия другая; 061 — `lang_choice` (выбранный язык, `''` — как в Telegram), `lang_auto` (язык по Telegram:
  язык Telegram этого вызова, иначе запомненный, иначе `ru`) и `languages` — `[{ code, name }]` (языки бота, название на
  самом языке). Не зарегистрирован — ещё `registered: false` (и больше ничего; в открытом боте — ещё
  `open: true`, 052). Зарегистрирован — `registered: true`;
  `me` — `{ id, name, is_admin, is_owner, notify_mode }` (`is_admin` — администратор хотя бы в одной компании или
  владелец бота; `is_owner` — только у владельца бота;
  `notify_mode` — `sound` | `silent` | `off`); `events` — события новыми первыми:
  участнику — только свои, администратору — ещё все события компаний, где он администратор, владельцу бота — все, каждое `{ id, title, status, finished_at, event_date, draw_done, member,
  unread, company }` (`unread` — непрочитанные сообщения переписки и обращений в событии; `company` — id компании
  события, 051); `companies` (051) — видимые компании: владельцу бота — все по id; остальным — где он администратор или
  владелец и где участвует в событии, по времени вступления; каждая `{ id, title, named, role, organizer, owner, bot_run,
  owner_name, events, active, unread }`: `title` — владельцу бота название компании, остальным своё название или
  «Комната N» (N — номер среди всех его компаний по времени вступления), `named` — название не по умолчанию; `role` —
  `owner` | `admin` | `member` | `guest` (владелец бота без строки в компании); `organizer`, `owner` — права в ней
  (у владельца бота — всегда `true`); `bot_run` — компанию ведёт владелец бота; `owner_name` — имя владельца компании;
  `events`, `active`, `unread` — по его событиям этой компании; только владельцу бота — ещё `people` (людей в компании),
  `owner_id` (0 — ведёт сам), `link` (действует ли ссылка владельца; саму ссылку `me` не отдаёт); `limits` — `{ chars: 4000 }`
  (`MAX_CHARS`); `looks` — набор `{ postcards, masks }` (038, `src/looks.js`: 15 открыток `{ id, title }`;
  040 — 20 масок Санты `{ id, emoji, title }`) — приложение показывает только его, сервер принимает только из него.
  052 (поля — только там, где верны; у людей закрытого бота, кроме владельца бота, ответ прежний): `open: true` —
  открытый бот; `create` — владельцу бота `{ bot: true }`, человеку открытого бота `{ left }` (сколько своих компаний
  ещё можно создать, 0–2); у компании — `shared: true` (название общее: `title` — его, если своего названия нет),
  `rename: true` (он владелец компании с общим названием, не владелец бота — меняет общее название), `deletable: true`
  (открытый бот, он владелец компании, не владелец бота — удаляет её через `company.delete`).
- **Отказы**: только общие.
- **Журнал**: не пишет.

### `wishlist.save`

Доступно при выключенных черновиках. Изменение публикации сохраняет старый черновик для восстановления.

### `wishlist.draft`

Кто: участник. Событие: да. В завершённом: нет — 400 «Событие завершено: письмо теперь только для чтения.»

При включённом `letter_drafts` в `event.get.member.draft` автор получает `text` (null при отсутствии черновика),

Ответ содержит новую `revision` и прежнее время публикации `updated_at`. Конфликт версии или режима — 400.
Черновик доступен только автору. Запись не создаёт сообщений и записей журнала.

## Бот

Webhook `POST /tg`: принимаются `message` (только личные чаты) и `callback_query` (`src/bot.js`). Сообщения людям вне
ответа на нажатие — только через очередь `outbox`.

### Команды и текст

| Что прислали | Что делает бот |
|---|---|
| `/start` | зарегистрированному — меню (до 5 идущих событий — у человека с двумя и более видимыми компаниями с названием компании в скобках, 051; кнопка приложения, до 3 строк кнопок переписки, «🔔 Уведомления»; строка роли — владелец бота, «👑 Ты владелец — …» у назначенного владельца компании, администратор); ждущему имя — просьба имени (см. ниже); иначе — закрытый бот: «🎄 Это закрытый бот для игры в Тайного Санту. …»; открытый (052): `pending = name` и просьба имени с приветствием «🎄 Привет! Это бот для игры в Тайного Санту.» и кнопкой «✅ Продолжить как …» |
| `/start adm_<код>` | ссылка владельца со страницы `/setup`: код — `adm_` и 24 знака HMAC с ключом `BOT_TOKEN` от `ADMIN_SECRET` (`ownerLinkCode`); срабатывает один раз (`claimOwnerLink`, отметка `settings.owner_link_used` — тоже от `ADMIN_SECRET` и `BOT_TOKEN`): человек становится владельцем (и админом), прежнему — предупреждение, журнал `owner.link`; без имени — `pending = name` и просьба имени с кнопкой «✅ Продолжить как …»; повторно — «Ссылка владельца уже использована. …». Неверный код — как простой `/start` |
| `/start own_<код>` | ссылка владельца компании (051): кода нет (использован, отозван, заменён) — «Эта ссылка владельца уже использована или отозвана. Попроси новую.»; перешёл владелец бота — «Ты владелец бота — эту комнату и так ведёшь ты.»; уже владелец — «Ты уже владелец.»; зарегистрированный — становится владельцем компании (как `admin.owner.transfer`, журнал `company.owner` «по ссылке», код стирается; владельцу бота — кто стал владельцем) и «👑 Ты — владелец своей комнаты в «Тайном Санте»: …»; новый — `pending = name_own:<компания>:<код>` и просьба имени; дальше меню. Из одновременных переходов владельцем становится один |
| `/start inv_<код события>` | приглашение: нет события с таким кодом — «Эта пригласительная ссылка устарела. …»; уже участник — «уже участвуешь» и меню; зарегистрированный — вступление (`joinByInvite`: вступил / регистрация закрыта / удалён без возврата / заявка отправлена / заявка уже ждёт / заявку недавно отклонили); новый — закрыто или удалён без возврата — отказ, иначе `pending = name:<событие>:<код>` и просьба имени с кнопкой «✅ Участвовать как …» (без одобрения заявок — сразу участник, ещё без имени) |
| `/language` | любой, кого бот знает (061, и до регистрации): «🌐 Выбери язык бота и приложения:» и кнопки — «Как в Telegram (<язык>)» (`lang:auto`), языки по два в ряд (`lang:<код>`), у выбранного — «✓ »; незнакомому — как текст от незнакомого |
| `/cancel` | сбросить ожидание (`pending`); незарегистрированному — просьба имени |
| просьба имени (047) | есть имя из Telegram — «Имя в игре — **<имя>**, как в Telegram. Его увидят твой Санта, владелец и администраторы. Хочешь другое — нажми «✏️ Изменить имя» или просто напиши его.» и две строки кнопок: «✅ Участвовать как <имя>» (`reg:ok`; после пригласительной ссылки, `pending = name:…`) или «✅ Продолжить как <имя>» (без события), «✏️ Изменить имя» (`reg:edit`). Имя из Telegram — `first_name` и `last_name` через пробел (пробелы схлопнуты); не подходит под правило имени — только `first_name`; не подходит и оно — без кнопок: «Как тебя зовут? Напиши имя (и, если нужно, фамилию) — …» |
| любая команда `/…` | выключает режим ответа в переписку и в обращение (текст после неё никому не уйдёт) |
| текст при `pending = name…` | имя (1–40 символов, не с `/`; иначе «Напиши, пожалуйста, имя обычным текстом (до 40 символов).»): регистрация, затем вступление по запомненной ссылке (код сменился — «устарела»); админам — «… присоединяется к событию». Имя записывается один раз (047, `register`, `src/membership.js`): «присоединяется» — в пакете записи по прежнему состоянию; имя уже сохранено другим вызовом — «Имя уже сохранено. Сменить его можно в приложении: «Профиль» → «✏️ Изменить имя».» |
| текст в режиме ответа | см. `users.pending` |
| текст от незнакомого (записи нет) | как `/start` без ссылки: закрытый бот — «🎄 Это закрытый бот …», открытый — просьба имени (052) |
| остальное | меню; нет идущих событий и не организатор — «Сейчас ты не участвуешь ни в одном идущем событии. Попроси пригласительную ссылку на событие.» (открытый бот: «… Создай свою комнату в приложении или попроси пригласительную ссылку на событие.») |

### Режим ожидания (`users.pending`)

| Значение | Что ждёт бот | Правила |
|---|---|---|
| пусто | ничего | — |
| `name` | имя или кнопку `reg:ok` (владелец по ссылке, ещё без имени; в открытом боте — пришедший без ссылки, 052) | после имени — «Приятно познакомиться, <имя>! 🎉» и меню |
| `name:<событие>:<код>` | имя или кнопку `reg:ok` после пригласительной ссылки | код — код ссылки в момент перехода; сменился — «устарела» |
| `name_own:<компания>:<код>` | имя или кнопку `reg:ok` после ссылки владельца компании (051) | после имени — права, если код тот же («Создай первое событие в приложении…»); иначе — «Ссылка владельца уже использована или отозвана. Попроси новую.» (человек зарегистрирован без прав) |
| `msg_<ward\|santa>:<событие>:<собеседник>:<мс>` | сообщение в переписку (кнопка `msg:…`) | собеседник — Telegram ID, на кого нажали; через час — «⌛ Время ответа истекло — сообщение не отправлено. …»; пара сменилась — «🔄 Пара изменилась после нажатия «Ответить» — …»; длиннее 4000 — отказ, режим остаётся |

кнопки и любой ответ. Сборка и разбор — `replyPending`, `supportPending`, `parsePending` (`src/bot.js`).

## Ссылка на мини-приложение

`<base_url>/app?event=<id>&chat=<santa|ward>&support=<my|id>` — строит `appUrl` (`src/format.js`), `base_url` и имя бота
записывает страница `/setup`. Пустые параметры не пишутся. Кнопка меню чата (`setChatMenuButton`) открывает `/app` без
параметров.

| Параметр | Кто ставит | Что делает приложение (`start`, `openEvent`) |
|---|---|---|
| `event` | почти все кнопки «Открыть» в сообщениях бота | открыть это событие, если оно есть в `me.events` («‹» — на главный экран его компании, 051); без параметра: компаний в `me.companies` две и больше — экран «Компании»; иначе у не-админа с единственным событием — открыть его сразу |
| `chat` | «💬 Вся переписка» под сообщением переписки | `santa` — открыть переписку с Сантой, `ward` — с подопечным (если пара есть) |
| `support` | «💬 Открыть» в сообщениях обращений | `my` — участнику: вкладка «Инфо» и его обращение; число — админу: вкладка «Управление» и это обращение |

Подпись `initData` приложение берёт у Telegram (`Telegram.WebApp.initData` или `#tgWebAppData`); без неё — экран «Открой
через Telegram». Вернувшись на главный экран, приложение убирает параметры из адреса.

## Остальные маршруты и расписание

Cron — раз в минуту (`src/cron.js`), шаги независимы: уведомления Сантам об изменении письма или адреса подопечного
(через `NOTIFY_DELAY_MINUTES` после последней правки, без текста); с `REMINDER_HOUR` по местному времени
(`TIMEZONE_OFFSET_HOURS`) — не больше одного тяжёлого действия за вызов, каждое — в пределах компании события
(о неудаче автожеребьёвки узнают организаторы этой компании): автожеребьёвка (`draw_auto_date` наступила),
автораскрытие (`reveal_auto`, на следующий день после `event_date`), автозавершение (`finish_auto`, через 3 дня после
`event_date`), ежедневные напоминания (письмо — за 2 дня, за день и в день `deadline`, только до жеребьёвки; Сантам — за 2
дня и в день `event_date`, после жеребьёвки); отправка очереди `outbox`.

057: cron читает только отметки. Уведомления — участники с отметкой `members.notify_at` старше `NOTIFY_DELAY_MINUTES`
(индекс `members_notify`; отметку ставят `wishlist.save`, `wishlist.publish`, `delivery.save` при наличии Санты); решение
«уведомлять» — событие идёт, Санта есть, правка новее учтённой парой; отметка снимается, если после чтения не было новой
правки. Ежедневный шаг — идущие события без отметки `events.checked_on` = сегодня (индекс `events_unchecked`): отметка
ставится вместе с `last_daily`, когда автодействие событию не нужно; снимают `admin.game`, жеребьёвка (`admin.draw` и
cron) и `admin.reset.full`. Обычная минута — 3 запроса к базе.
