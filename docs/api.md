# API мини-приложения, бот и журнал — сводный контракт

Актуальное описание всех 69 действий API, порядка проверок, кодов журнала, режима ожидания ответа в чате бота, кнопок
бота и ссылки на мини-приложение. Составлено по коду (фича 022, `main` после шага 6 рефакторинга) и сверяется тестом
`tests/api-doc.test.mjs` с таблицей действий `ACTIONS` (`src/api.js`) и с кодами журнала, которые пишет сервер.

Контракты фич 001–014 (`specs/*/contracts/`) — история решений; если они расходятся с этим документом, верен этот
документ, а источник истины для обоих — код. Внутреннее устройство API (таблица действий, контекст вызова, модули,
пакеты чтений) — `specs/019-api-actions/contracts/api-actions.md`; атомарные действия — `specs/020-claims-snapshots/`.

**События без комнат (063).** Комнат (в коде и спецификациях 050–062 — «компаний») больше нет: у каждого события свой
владелец (`events.owner_id`) и организаторы — строки `event_admins` (владелец события — тоже в ней). Роли: владелец бота ⊇
владелец события ⊇ администратор события. Событие создаёт зарегистрированный человек (`event.create`) и становится его
владельцем: не больше 10 событий за 365 суток (удаление и передача события место не освобождают; у владельца бота
предела нет), в закрытом боте — только владелец бота и те, кому он разрешил (`bot.creator.set`). Организатор управляет
только своими событиями: чужое событие для него — как несуществующее. Владелец бота может всё в любом событии (все
события — `bot.events`); в событии, где он не участник и не организатор, он гость: в списках события его нет, сообщения
организаторам ему не приходят, его изменения пишутся в журнал события. Событие без своего владельца (`owner_id = 0`,
только данные до 063) ведёт владелец бота. Прежних действий `company.label.set`, `company.create`, `company.delete`,
`bot.company.create`, `bot.company.link`, `bot.company.delete`, `admin.users`, `admin.events.create` нет — они проходят
путь неизвестного действия; поля `company` в запросах нет. Прежние записи общих журналов комнат — в журнале бота как
история. Контракт — `specs/063-events-without-rooms/contracts/events-without-rooms.md`.

**Без масок и семей (062).** Действий `mask.set`, `admin.families`, `admin.family.save`, `admin.family.delete` нет: они
проходят путь неизвестного действия (раздел «Порядок проверок»). Семьи событий с «Учитывать семьи» миграция `0023`
перенесла во взаимные исключения участников, маски Санты стёрла; таблицы семей и колонки `events.families_on`,
`pairs.mask` остались ради отката и кодом не читаются — `specs/062-remove-masks-families/`.

**Владелец события.** Владелец события может в нём всё, что владелец (действия «владелец»). Тексты «может только
владелец бота» в событии со своим владельцем — «может только владелец» (`ownerWord`, `src/format.js`: событие без своего
владельца — «владелец бота»). Переименовать человека (`admin.rename`) и перенести участие (`admin.transfer`) может только
владелец бота: имя и аккаунт одни на все события.

**Язык человека (061).** Ответы API, сообщения бота и очереди, кнопки, команды и описание бота — на языке человека:
выбранный им (`lang.set`, бот `/language`), иначе язык его Telegram (из подписанных данных приложения и из `from`
сообщения или нажатия: есть в боте — он, `pt-br` → `pt`, `zh-hant` → `zh`; `be`, `uk`, `kk`, `ky`, `tg`, `uz`, `hy`, `az`,
`tk` → русский; прочие → английский), иначе последний известный язык Telegram (`users.tg_lang`), иначе русский. Языки:
ru, en, es, pt, fr, de, zh, it, tr, id, pl. Тексты в «ёлочках» ниже — русские; на других языках — переводы из
`src/i18n/<язык>/`. Журнал хранит русский текст и (для новых записей) ключ с подстановками — подробности показываются на
языке смотрящего. Контракт — `specs/061-i18n-languages/contracts/language.md`.

**Открытый бот (052).** Бот открытый, если в `vars` его окружения `OPEN_BOT = "1"` (второй бот), иначе закрытый (первый).
В открытом боте человек без ссылки регистрируется, назвав имя, и любой зарегистрированный создаёт события (`event.create`,
с пределом 063); в закрытом регистрация — только по ссылкам, а события создают владелец бота и те, кому он разрешил.
Признак читает только `openBot(env)` (`src/creation.js`). Контракт — `specs/052-open-bot/contracts/open-bot.md`.

## Как читать

- **Кто** — роль из таблицы действий: `любой` — любой человек с верной подписью Telegram; `зарегистрированный` — написал
  боту имя; `участник` — участник события из поля `event`; `участник или админ` — участник события или его организатор
  (владелец бота — организатор любого события); `админ` — организатор события из `event`: его администратор, его
  владелец или владелец бота; `владелец` — владелец события из `event` (`events.owner_id`; у события без своего
  владельца — владелец бота) или владелец бота, у действий без события (`admin.rename`, `admin.transfer`, признак `bot` в
  `ACTIONS`) — только владелец бота; `владелец бота` — только владелец бота (`settings.owner_id`, 051).
- **Событие** — `да`: нужно поле `event` (id события); `—`: событие не нужно.
- **В завершённом** (событие со `status = 'finished'`) — `нет`: отказ 400 до обработчика с текстом из раздела действия;
  `да`: работает; `7 суток`: читать можно всегда, писать — 7 суток после завершения (`CHAT_GRACE_MS`, `src/status.js`),
  потом отказ обработчика; `проверяет обработчик`: конвейер пропускает, свой порядок отказов — в разделе; `—`: действие
  без события.
- Тексты в «ёлочках» — побайтно как в коде; `<…>` — подстановка. Время — миллисекунды Unix (`Date.now()`), даты —
  `YYYY-MM-DD`, id людей — Telegram ID.
- «Сообщения» — что ставится в очередь `outbox` другим людям (отправляется после ответа и cron); тексты сообщений здесь не
  повторяются — они в коде модуля.

## Запрос и ответ

- `POST /api/<действие>`, например `POST /api/admin.state`. Другой метод — 405 `method`.
- Заголовок `x-init-data` — строка `initData` мини-приложения Telegram; подпись проверяется по `BOT_TOKEN`
  (`validateInitData`, `src/telegram.js`), не старше 24 часов.
- Тело — JSON-объект с полями действия; нечитаемое тело считается `{}`. Числовые id принимаются и числом, и строкой.
- Ответ — JSON, `content-type: application/json; charset=utf-8`, `cache-control: no-store`:
  успех — `{ "ok": true, …поля ответа }`; отказ — `{ "ok": false, "error": "<текст для человека>" }` с кодом из раздела.
  Поля ответа ниже перечислены без `ok`.
- Тексты для людей (060) — из словаря (`src/i18n/<язык>/`): отказы и тексты ответа — на языке вызывающего
  (`users.lang`, пусто — русский), сообщения бота другим людям — на языке получателя при отправке, подробности журнала —
  на русском. Тексты ниже — русские; в шаге 1 язык у всех русский, ответы побайтно прежние.

## Порядок проверок и общие отказы

Конвейер `handleApi` (`src/api.js`) — один для всех действий, по порядку:

1. Не `POST` — 405 `method`.
2. Подпись `initData` не прошла — 401 «Не удалось проверить вход. Открой приложение заново из чата с ботом.»
3. Пользователь, настройки, события, где он организатор, запись владельца бота и событие действия (поле `event`, если
   действию нужно событие) читаются одним пакетом (`openContext`); у пользователя снимается отметка «бот заблокирован»
   (`users.blocked_at = 0`) — до любых отказов по правам.
4. Роль не `любой`, а человек не зарегистрирован — 403 «Сначала зарегистрируйся по пригласительной ссылке.» Роль
   `владелец бота`, а вызвал не он, — 403 «Только для владельца бота.» (051).
5. `admin.*`, а человек не организатор ни одного события (общий признак `users.is_admin`) и не владелец бота — 403
   «Только для администратора.» Затем сразу определяется владелец бота: если `settings.owner_id` недействителен,
   владельцем записывается самый ранний по регистрации организатор событий без своего владельца (`resolveOwner`,
   `src/roles.js`).
6. Действие без события: роль `владелец` (`admin.rename`, `admin.transfer`, признак `bot`), а вызвал не владелец бота, —
   403 с текстом действия; затем проверка слова подтверждения (шаг 11) и обработчик.
7. Событие не найдено (в том числе нет поля `event`) — 404 «Событие не найдено.» Дальше всё считается в пределах этого
   события (контекст события `ctx.at(ev)`).
8. `admin.*`: вызвавший не организатор этого события и не владелец бота — участнику события 403 «Только для
   администратора.», остальным 404 «Событие не найдено.» (чужое событие — как несуществующее, 063). Не `admin.*`: человек
   не участник события — 403 «Ты не участвуешь в этом событии.» (у `event.get` организатор события и владелец бота
   проходят и без участия).
9. Событие завершено, а у действия «в завершённом — нет» — 400 с текстом действия.
10. Нужен владелец, а вызвал не он, — 403 с текстом действия. **После** шага 9: админ на завершённом событии получает
    400, а не 403. Текст — по событию: у события без своего владельца — «… может только владелец бота.» (как в разделе
    действия), у события со своим владельцем — «… может только владелец.» (`ownerWord`).
11. Нужно слово подтверждения (поле `confirm`, без учёта регистра, пробелов по краям и диакритики — 061; слово — на языке человека), а его нет — 400 с текстом действия.
12. Обработчик: его отказы — в разделе действия (400, если не сказано иначе).

Неизвестное действие проходит тот же путь как строка-заглушка и получает 404 «Неизвестное действие» в конце: имя на
`admin.` — как админское действие события (шаги 5, 7, 8, 9 с текстом «Событие завершено — менять его уже нельзя (доступны
просмотр, раскрытие и удаление).»), остальные — как действие участника (шаги 4, 7, 8).

| Код | Текст | Когда |
|---|---|---|
| 405 | `method` | не `POST` |
| 401 | «Не удалось проверить вход. Открой приложение заново из чата с ботом.» | подпись `initData` |
| 403 | «Сначала зарегистрируйся по пригласительной ссылке.» | не зарегистрирован |
| 403 | «Только для владельца бота.» | действие `bot.*` не владельцу бота (051) |
| 403 | «Только для администратора.» | `admin.*` не организатору ни одного события (и не владельцу бота); `admin.*` с событием — его участнику, который в нём не организатор (063) |
| 404 | «Событие не найдено.» | нет события с таким `event` или поля `event` нет; у `admin.*` — событие, где вызвавший не организатор и не участник (063) |
| 403 | «Ты не участвуешь в этом событии.» | действие участника не участнику |
| 400 | текст действия | событие завершено, «в завершённом — нет» |
| 403 | текст действия («… может только владелец бота.» или текст служебного просмотра; в событии со своим владельцем — «… владелец.») | действие владельца не владельцу; `admin.rename`, `admin.transfer` — не владельцу бота |
| 400 | текст действия («Для … введи слово …») | нет слова подтверждения |
| 404 | «Неизвестное действие» | нет такого действия |
| 500 | «Ошибка сервера. Попробуй ещё раз.» | исключение в обработчике (`src/index.js`; в лог — `api failed`) |
| 500 | «База не подготовлена: примени миграции (см. README).» | схема базы ниже `REQUIRED_SCHEMA` (`src/db.js`) — до конвейера |

Эталон кодов и текстов отказов «без прав / нет события / завершено» для всех действий — `tests/fixtures/api-refusals.json`;
намеренные изменения эталона по фичам перечислены в заголовке `tests/api-refusals.test.mjs`.

**Повторные нажатия (024).** Меняющее действие, вызванное дважды (в том числе одновременно, в одну миллисекунду),
меняет данные и рассылает сообщения один раз; второй вызов получает отказ из раздела действия. Ручные рассылки
владельца и администраторов (повтор того же объявления, напоминания, приглашения из другого события) проходят не чаще
раза в минуту: окно считается от времени первой рассылки (объявления или записи журнала), другой текст объявления — не
повтор. Плановые напоминания cron это окно не проверяют.

  (`msg:<сторона>:<событие>`) и «💬 Вся переписка»: подопечному — «💬 <b>Твой Тайный Санта (<название>) пишет:</b>»; Санте — «💬 <b>Тебе пишет твой
  подопечный (<название>):</b>». Название сокращается до 40 символов: заголовок и 4000 символов текста —
  одно сообщение Telegram. Сообщения собеседника помечаются прочитанными.

### `chat.get`

Кто: участник. Событие: да. В завершённом: да.

- **Запрос**: `event`, `with` — `santa` или любое другое значение — подопечный; `after` — id последнего полученного
  сообщения (0 или нет — последние 300).
- **Ответ**: `state` — `no_pair` или `ok`; при `ok`: `counterpart` (`santa` | `ward`), `writable` — можно ли писать (открыта ли переписка), `messages` — до
  300 `{ id, mine, text, created_at }` по порядку (без имён и id собеседника).
- **Отказы**: только общие.
- **Журнал**: не пишет. Сообщения собеседника помечаются прочитанными.

### `support.get`

Кто: участник. Событие: да. В завершённом: да. Свои обращения по событию.

- **Запрос**: `event`.
- **Ответ**: `available` — есть ли другой зарегистрированный админ; `writable` — открыта ли переписка события; `threads` —
  до 10 последних обращений (старые первыми) `{ id, status, assignee_name, created_at, closed_at,
  messages }`, сообщение — `{ id, mine, author, text, created_at }` (`author` — имя ответившего, у своих —
  пусто).
- **Отказы**: только общие.
- **Журнал**: не пишет. Ответы на обращения помечаются прочитанными.

### `support.send`

Кто: участник. Событие: да. В завершённом: 7 суток. Сообщение в открытое обращение или новое (одно открытое на участника в
событии).

- **Запрос**: `event`, `text`.
- **Ответ**: `thread` — id обращения; `message` — `{ id, mine: true, author: '', text, created_at }`.
- **Отказы**: 400 «Пустое сообщение.»; 400 «Слишком длинно: <n> символов, максимум 4000 (лимит сообщения Telegram).»;
  400 «Событие завершено больше недели назад — обращения только для чтения.»; 400 «Сейчас некому ответить на обращение.»; 400 «Не получилось отправить — попробуй ещё раз.»
- **Журнал**: `support.open` — при новом обращении. Сообщения: ничьё — всем админам (кроме автора) с кнопкой «🙋 Взять»;
  взятое — только ответственному с кнопкой «↩️ Ответить».

### `support.close`

Кто: участник. Событие: да. В завершённом: 7 суток.

- **Запрос**: `event`.
- **Ответ**: пустой.
- **Отказы**: 400 «Событие завершено больше недели назад — обращения только для чтения.»; 400 «Открытого обращения нет.»
- **Журнал**: `support.close`. Сообщения: ответственному (ничьё — всем админам), без звука.

### `event.leave`

Кто: участник. Событие: да. В завершённом: нет — 400 «Событие завершено — выйти из него уже нельзя.» Без слова `ВЫЙТИ`
в поле `confirm` — 400 «Чтобы выйти, введи слово ВЫЙТИ.» Выход участника из события (035) — любой участник, в том числе
админ и владелец.

- **Запрос**: `event`, `confirm`.
- **Ответ**: пустой.
- **Отказы**: 400 «Жеребьёвка уже прошла. Чтобы выйти, обратись к владельцу или администраторам.» (в том числе жеребьёвка
  записана одновременно с выходом раньше него); 400 «Событие завершено — выйти из него уже нельзя.» (завершено
  одновременно); 403 «Ты не участвуешь в этом событии.» — второй из одновременных выходов.
- **Журнал**: `member.leave`. Сообщения: каждому админу и владельцу, кроме вышедшего, — со звуком, с кнопкой «🛠 Открыть
  событие». Данные участия удаляются по `REGISTRY` (`src/db.js`), отметка «удалён из события» не ставится — вернуться
  можно по ссылке. Только пока человек участник, жеребьёвки нет и событие идёт — проверено в момент записи.

## Действия владельца бота

Права владельца бота (051, 063). Роль `владелец бота` (действия `bot.*`): остальным — 403 «Только для владельца бота.»
`admin.rename` и `admin.transfer` — роль `владелец` без события с признаком `bot`: не организатору ни одного события —
403 «Только для администратора.», организатору, который не владелец бота (в том числе владельцу события), — 403 с
текстом раздела.

### `admin.rename`

Кто: владелец. Событие: —. Переименовать человека — только владелец бота (063: имя одно во всех событиях); остальным
организаторам — 403 «Переименовать человека может только владелец бота.» Своё имя каждый меняет сам (`name.set`).

- **Запрос**: `id`, `name` (схлопываются пробелы).
- **Ответ**: пустой.
- **Отказы**: 400 «Имя должно быть от 1 до 40 символов»; 400 «Участник не найден» — нет зарегистрированного человека с
  таким `id`.
- **Журнал**: `rename` в журнале бота («<старое имя> → <новое>») — только если имя действительно изменилось (025): то же
  имя, повтор и второй из одновременных вызовов с тем же именем — успех без записи. Сообщений нет.

### `admin.transfer`

Кто: владелец. Событие: —. Перенос участия во всех событиях на новый аккаунт человека. Только владелец бота (051:
признак `bot` в `ACTIONS`); остальным, в том числе владельцу события, — 403 «Переносить участие на новый аккаунт может
только владелец бота.»

- **Запрос**: `from` — id старой записи, `to` — id нового аккаунта.
- **Ответ**: `events` — во скольких событиях было участие старой записи.
- **Отказы** (по порядку): 400 «Запись владельца не переносится: владелец восстанавливает доступ по новой ссылке
  владельца (смена ADMIN_SECRET → страница /setup).» (запись владельца бота; запись владельца события переносится); 400
  «Выбери две разные записи.» (нет `to`); 400 «Переносить участие на аккаунт владельца или администратора нельзя.»
  (новый аккаунт — организатор хотя бы одного события или владелец бота); 400 «Выбери две разные записи.» (нет `from`
  или записи совпадают); 400 «Старая запись не найдена.» (в том числе второй из двух одновременных переносов); 400
  «Новый аккаунт должен завершить регистрацию (написать боту имя).»; 400 «Новый аккаунт уже участвует в жеребьёвке
  события «<название>» — выбери другую запись.»
- **Журнал**: `transfer` — одна запись в журнале бота. Сообщения: новому аккаунту (с кнопкой приложения) и старому;
  организаторам событий старой записи (где она участник или организатор), кроме вызвавшего, — без звука. Участия,
  владение и организаторство событий, факты создания событий (предел `event.create`) и остальные данные человека
  переходят к новому аккаунту по `REGISTRY` (`src/db.js`). Если новый аккаунт уже участник события без пар — остаётся
  одно участие (письмо и адрес нового, если не пусты). Отметки «кто сделал» (автор записей журнала и объявлений,
  создатель события, решивший заявку, удаливший участника, закрывший обращение, ответственный и отправитель в
  обращениях) переходят к новому аккаунту (025); у старого остаются только сообщения очереди, адресованные ему.

### `bot.owner.transfer`

Кто: владелец бота. Событие: —. Передать права владельца бота (до 051 — `admin.owner.transfer`).

- **Запрос**: `id` — новый владелец бота: любой зарегистрированный человек (063).
- **Ответ**: пустой.
- **Отказы**: 400 «Передать права владельца можно только зарегистрированному человеку.»; 400 «Ты и так владелец.»; 400
  «Права владельца уже переданы.» — второй из одновременных вызовов.
- **Журнал**: `owner.transfer` в журнале бота («→ <имя>», автор — прежний владелец). События, их владельцы и
  организаторы не меняются (событие без своего владельца, `owner_id = 0`, дальше ведёт новый владелец бота). Прежний
  владелец бота получает разрешение создавать события (`users.can_create = 1`): на него теперь действует предел
  `event.create`. Сообщения: новому владельцу бота — с кнопкой приложения; организаторам событий прежнего владельца бота
  и событий без своего владельца — без звука. Пакет `atomic` по прежнему владельцу: всё — пока владелец прежний, смена
  настройки `owner_id` — захват; общий признак администратора обоих пересчитан.

### `bot.audit`

Кто: владелец бота. Событие: —. Журнал бота.

- **Запрос**: полей нет.
- **Ответ**: `entries` — до 100 последних записей журнала бота (записи с `event_id = 0`: создание и удаление событий,
  перенос участия, переименования, права владельца бота, разрешения создавать события; прежние общие записи комнат —
  как история), формат как у `admin.audit`.
- **Отказы**: только общие.
- **Журнал**: не пишет.

### `bot.events`

Кто: владелец бота. Событие: —. Все события бота (063); событие открывается обычными `event.get` и `admin.state`
(владелец бота — организатор любого события).

- **Запрос**: `offset` — сколько событий пропустить (нет или не число — 0).
- **Ответ**: `events` — до 50 событий новыми первыми (по времени создания) `{ id, title, status, event_date, owner_name,
  people }` (`owner_name` — имя владельца события, у события без своего владельца — владельца бота; `people` — число
  участников); `more` — есть ли следующая страница.
- **Отказы**: только общие.
- **Журнал**: не пишет.

### `bot.people`

Кто: владелец бота. Событие: —. Люди для «Кто может создавать события» и передачи прав владельца бота (063).

- **Запрос**: полей нет.
- **Ответ**: `people` — `{ id, name, username, can_create }` по имени (при равенстве — `id`), без самого владельца бота:
  в закрытом боте — все зарегистрированные; в открытом — зарегистрированные участники и организаторы событий, где
  владелец бота организатор.
- **Отказы**: только общие.
- **Журнал**: не пишет.

### `bot.creator.set`

Кто: владелец бота. Событие: —. Разрешить или запретить человеку создавать события в закрытом боте (063,
`users.can_create`).

- **Запрос**: `id`, `on` — разрешить (истина) или запретить.
- **Ответ**: пустой.
- **Отказы** (по порядку): 400 «В открытом боте создавать события может любой.»; 400 «Назначить можно только
  зарегистрированного человека.»; 400 «Уже разрешено.» / «Уже не разрешено.» (в том числе второй из одновременных
  вызовов).
- **Журнал**: `creator.grant` или `creator.revoke` в журнале бота (имя). Сообщения: человеку — о разрешении (с кнопкой
  «🎄 Открыть приложение») или о запрете («… Твои события остаются у тебя.»). Пакет `atomic` по прежнему значению:
  сообщение и журнал — пока значение прежнее, запись `can_create` — захват. Созданные события остаются у человека.

## Действия события (админ и владелец)

У всех действий раздела нужно поле `event`; общие отказы — раздел «Порядок проверок». «Админ» — организатор этого
события (строка `event_admins`: его администратор или владелец) или владелец бота; «владелец» — владелец этого события
или владелец бота. Организатор другого события получает отказ, как будто события нет (участнику события — 403 «Только
для администратора.»).

### `admin.state`

Кто: админ. Событие: да. В завершённом: да. Панель события одним ответом — только статусы, без пар, писем и адресов.

- **Запрос**: `event`.
- **Ответ**:
  - `users` — участники по времени вступления `{ id, name, username, registered, is_admin, is_owner, has_wishlist,
    in_draw, gift_ready, blocked, gift_received, ward_seen }` и `gift_sent`, `has_delivery`, если в событии нужен адрес
    (`is_admin` — организатор этого события, 063; `is_owner` — владелец события; `ward_seen` — открыл ли подопечного, у
    не попавших в жеребьёвку — `null`; `blocked` — Telegram сообщил, что бот заблокирован);
  - `requests` — ждущие заявки `{ id, user_id, name, username, created_at }`;
  - `removed` — исключённые из события `{ id, name, username, removed_at }`;
  - `support` — `{ threads, admins }`: открытые обращения и до 20 последних закрытых без текстов `{ id, user_id, name,
    status, assignee, assignee_name, created_at, closed_at, last_at, unread, readable }` и админы `{ id, name }`;
  - `exclusions` — `{ giver, receiver }` между участниками;
  - `fixed` — закреплённые пары `{ giver, receiver }` — **только владельцу**, у админа поля нет вовсе;
  - `me_member` — участвует ли сам вызвавший;
  - `organizers` (063) — владелец и зарегистрированные организаторы события `{ id, name, username, owner }`, владелец
    первым, остальные по имени (владелец бота-гость не показан);
  - `other_events` — события, где вызвавший организатор (владельцу бота — ещё события владельца этого события), кроме
    этого, новыми первыми `{ id, title, status }` (для «пригласить из события» и образца);
  - `settings` — поля `publicEvent` (в том числе `contacts_on`, `draw_auto_date`) и `registration_open, avoid_previous,
    invite_link, draw_at, owner_id, reveal_auto, finish_auto, draw_cancelable` (`owner_id` — владелец события, у события
    без своего владельца — владелец бота; признака истории пар нет: учтены ли прошлые пары, наружу не сообщается).
- **Отказы**: только общие.
- **Журнал**: не пишет.

### `admin.audit`

Кто: админ. Событие: да. В завершённом: да. Журнал события (063: только события; без `event` — 404 «Событие не
найдено.»; журнал бота — `bot.audit`).

- **Запрос**: `event`.
- **Ответ**: `entries` — до 100 последних записей журнала события `{ id, event_id, action, details, created_at,
  actor_name }` (`actor_name` — «бот» у записей бота, «кто-то», если имени нет); коды — раздел «Коды журнала».
- **Отказы**: только общие.
- **Журнал**: не пишет.

### `admin.role.grant`

Кто: владелец. Событие: да. В завершённом: да. Не владельцу — 403 «Назначать и снимать администраторов может только
владелец бота.» Назначить участника администратором события (063: права — только в этом событии).

- **Запрос**: `event`, `id`.
- **Ответ**: пустой.
- **Отказы**: 400 «Он(а) уже администратор.» (организатор этого события; в том числе второй из одновременных вызовов);
  400 «Назначить можно только участника события.» (не участник, гость или не зарегистрирован; в том числе вышел из
  события одновременно с назначением).
- **Журнал**: `role.grant` в журнале события (имя). Сообщения: назначенному — с кнопкой события; остальным организаторам
  события, кроме вызвавшего, — без звука. Пакет `atomic` по прежнему состоянию: всё — пока он участник и не организатор,
  строка `event_admins` — захват; общий признак администратора назначенного пересчитан.

### `admin.role.revoke`

Кто: владелец. Событие: да. В завершённом: да. Не владельцу — 403 «Назначать и снимать администраторов может только
владелец бота.»

- **Запрос**: `event`, `id`.
- **Ответ**: пустой.
- **Отказы**: 400 «Нельзя снять права владельца. Сначала передай владение событием.» (владелец события; в том числе
  владение ему передали одновременно); 400 «Он(а) не администратор.» (не организатор этого события; в том числе второй
  из одновременных вызовов).
- **Журнал**: `role.revoke` в журнале события (имя); его открытые обращения в этом событии снова ничьи — по
  `support.return` на каждое. Права в других событиях не меняются. Сообщения: снятому; остальным организаторам события,
  кроме вызвавшего, — без звука; по обращениям — организаторам с кнопкой «🙋 Взять» и автору. Пакет `atomic` по прежнему
  состоянию, удаление строки `event_admins` — захват; общий признак администратора снятого пересчитан.

### `admin.owner.transfer`

Кто: владелец. Событие: да. В завершённом: да. Не владельцу — 403 «Передать владение событием может только владелец
бота.» Передать владение событием (063; до 051 — передача прав владельца бота, теперь `bot.owner.transfer`).

- **Запрос**: `event`, `id` — зарегистрированный участник или организатор события.
- **Ответ**: пустой.
- **Отказы**: 400 «Ты и так владелец.» / «Он(а) уже владелец.» (`id` — нынешний владелец: сам вызвавший или другой); 400
  «Передать владение можно только участнику или администратору события.» (не участник и не организатор, гость, не
  зарегистрирован); 400 «Владение уже передано.» — второй из одновременных вызовов (владелец уже другой).
- **Журнал**: `event.owner` в журнале события («→ <имя>»). Новый владелец — организатор события (строка `event_admins`,

## Коды журнала

Таблица `audit`: `event_id` — событие записи, 0 — журнал бота (063: все записи без события — создание и удаление
событий, перенос участия, переименования, права владельца бота, разрешения создавать события; там же прежние общие
записи комнат 050–062 как история; читает только `bot.audit`), `company_id` — у новых записей 0 (колонка осталась ради

Записи остаются в журнале бота (туда с 063 относятся и бывшие общие журналы комнат) и показываются как история
(подробности семей — на языке смотрящего, `AUDIT_HISTORY`, `src/db.js`); новые не пишутся.

Журнал **не** пишут: действия участника (письмо, адрес, отметки, переписка, `notify.set`, `name.set`, кроме открытия и
закрытия обращения и выхода из события); чтения, кроме `admin.wishlist` и `admin.vault.*`; `admin.rename` без изменения
имени; повторное `admin.support.take` своего обращения; плановое напоминание cron без получателей; вступление по
ссылке, регистрация и заявка в боте; уведомления cron об изменении письма.

## Бот

Webhook `POST /tg`: принимаются `message` (только личные чаты) и `callback_query` (`src/bot.js`). Сообщения людям вне
ответа на нажатие — только через очередь `outbox`.

### Команды и текст

| Что прислали | Что делает бот |

### Режим ожидания (`users.pending`)

| Значение | Что ждёт бот | Правила |
|---|---|---|
| пусто | ничего | — |
| `name` | имя или кнопку `reg:ok` (владелец бота по ссылке, ещё без имени; в открытом боте — пришедший без ссылки, 052) | после имени — «Приятно познакомиться, <имя>! 🎉» (может создавать события — ещё «Создай первое событие в приложении — там появится пригласительная ссылка.») и меню |
| `name:<событие>:<код>` | имя или кнопку `reg:ok` после пригласительной ссылки | код — код ссылки в момент перехода; сменился — «устарела» |
| `name_own:<компания>:<код>` | прежнее ожидание (051) после ссылки владельца комнаты; с 063 бот его не ставит | имя или `reg:ok` — регистрация без события и без прав: «Приятно познакомиться, <имя>! 🎉» и «Эта ссылка больше не действует. …», затем меню |
| `msg_<ward\|santa>:<событие>:<собеседник>:<мс>` | сообщение в переписку (кнопка `msg:…`) | собеседник — Telegram ID, на кого нажали; через час — «⌛ Время ответа истекло — сообщение не отправлено. …»; пара сменилась — «🔄 Пара изменилась после нажатия «Ответить» — …»; длиннее 4000 — отказ, режим остаётся |

| `sup_u:<событие>:<мс>` | сообщение участника по обращению (кнопка `sup:u:…`) | час; как `support.send` |

Режимы `msg_…` и `sup_…` сбрасывает любая команда, пустое сообщение (стикер, фото — затем меню), отклонённое нажатие
кнопки и любой ответ. Сборка и разбор — `replyPending`, `supportPending`, `parsePending` (`src/bot.js`).

## Ссылка на мини-приложение

`<base_url>/app?event=<id>&chat=<santa|ward>&support=<my|id>` — строит `appUrl` (`src/format.js`), `base_url` и имя бота
записывает страница `/setup`. Пустые параметры не пишутся. Кнопка меню чата (`setChatMenuButton`) открывает `/app` без
параметров.

| Параметр | Кто ставит | Что делает приложение (`start`, `openEvent`) |
|---|---|---|
| `event` | почти все кнопки «Открыть» в сообщениях бота | открыть это событие, если оно есть в `me.events` (владельцу бота — любое); «‹» — к списку «Мои события» (063); нет параметра или события — «Мои события» |
| `chat` | «💬 Вся переписка» под сообщением переписки | `santa` — открыть переписку с Сантой, `ward` — с подопечным (если пара есть) |
| `support` | «💬 Открыть» в сообщениях обращений | `my` — участнику: вкладка «Инфо» и его обращение; число — админу: вкладка «Управление» и это обращение |

Подпись `initData` приложение берёт у Telegram (`Telegram.WebApp.initData` или `#tgWebAppData`); без неё — экран «Открой

Cron — раз в минуту (`src/cron.js`), шаги независимы: уведомления Сантам об изменении письма или адреса подопечного
(через `NOTIFY_DELAY_MINUTES` после последней правки, без текста); с `REMINDER_HOUR` по местному времени
(`TIMEZONE_OFFSET_HOURS`) — не больше одного тяжёлого действия за вызов, каждое — в пределах своего события
(о неудаче автожеребьёвки узнают организаторы события): автожеребьёвка (`draw_auto_date` наступила),
автораскрытие (`reveal_auto`, на следующий день после `event_date`), автозавершение (`finish_auto`, через 3 дня после
`event_date`), ежедневные напоминания (письмо — за 2 дня, за день и в день `deadline`, только до жеребьёвки; Сантам — за 2
дня и в день `event_date`, после жеребьёвки); отправка очереди `outbox`.

057: cron читает только отметки. Уведомления — участники с отметкой `members.notify_at` старше `NOTIFY_DELAY_MINUTES`
(индекс `members_notify`; отметку ставят `wishlist.save`, `wishlist.publish`, `delivery.save` при наличии Санты); решение
«уведомлять» — событие идёт, Санта есть, правка новее учтённой парой; отметка снимается, если после чтения не было новой
правки. Ежедневный шаг — идущие события без отметки `events.checked_on` = сегодня (индекс `events_unchecked`): отметка
ставится вместе с `last_daily`, когда автодействие событию не нужно; снимают `admin.game`, жеребьёвка (`admin.draw` и
cron) и `admin.reset.full`. Обычная минута — 3 запроса к базе.
