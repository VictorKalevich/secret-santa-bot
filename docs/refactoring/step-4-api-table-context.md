# Шаг 4. Таблица действий API и контекст запроса

> **Выполнен в 019** (2026-11-14), одной фичей: `specs/019-api-actions/`. Итог — `CLAUDE.md` (строка 019, «Структура»),
> числа — `docs/refactoring/baseline.md` (разделы 1–3, 6).

Фича Spec Kit: следующий свободный номер (ожидается `019`), короткое имя `api-actions`.
Нужны шаги 1 и 3. Сначала прочитай `docs/refactoring-roadmap.md`.

Шаг большой. Его можно разделить на две фичи по границе «часть А — таблица действий», «часть Б — контекст и
чтения»: часть А не меняет ни одного запроса к базе, часть Б не меняет ни одной проверки прав.

## Цель

- Права и условия каждого действия API записаны в одной таблице; проверки выполняются в одном месте до обработчика.
- Предметная логика с SQL уходит из `src/api.js` в модули.
- Настройки и список пользователей читаются один раз на вызов; тяжёлые действия делают меньше запросов и не
  читают письма там, где нужен только признак.

## Зачем

**Права.** `handleAdmin` (`src/api.js:283–752`) — один `switch` на 470 строк, 46 действий. Проверка владельца
стоит внутри каждой ветки, список разрешённого в завершённом событии (`FINISHED_OK`, `src/api.js:276–281`) — в
стороне. Новое действие легко добавить без проверки прав или без строки в `FINISHED_OK`. «Что разрешено в
завершённом событии» решается тремя способами: `FINISHED_OK`; точечные `isFinished` (`src/api.js:142`, `157`,
`193`, `201`, `720`); `chatWritable` внутри `src/chat.js:43` и `src/support.js:88`, `138`, `269`, `285`, `313`,
`350`.

**Логика в `src/api.js`** (номера строк — в этом файле): исключения — 568–593, закреплённые пары — 595–634,
параметры события — 465–495, участие админа — 524–538, письмо, адрес, отметки подарка — 141–221, сборка
`admin.state` — 386–456.

**Чтения.** Числа — в `baseline.md`, раздел 3. Каждый вызов `admin.*` читает настройки и всех пользователей,
затем функции читают их снова: `admin.state` — 15 запросов, `admin.remove` — 16, `admin.insert` — 15,
`admin.draw` — 14. `event.get` читает письма всех участников ради их числа (`src/api.js:112`); `checkDraw` — ради
списка пустых писем (`src/pairs.js:53`, `:83`), и разбор этих писем входит в те же 10 мс CPU, что и расчёт пар
(`baseline.md`, раздел 6).

**Слои.** В `src/db.js` рядом лежат проверка схемы, запросы и предметные правила (`familyExclusions`, снимки).
Простые предикаты `isFinished`, `chatUntil`, `chatWritable` экспортирует `src/events.js` (`:12–14`), и его
импортируют `pairs`, `membership`, `support`, `chat`, `api`, `bot`, `cron`. Циклов сейчас нет, но
`supportDeleteStmts` уже лежит в `db.js` «чтобы не было циклов импорта».

## Часть А. Таблица действий

### Порядок проверок, который нужно сохранить

Каждая строка — существующий отказ с тем же кодом и текстом. Номера строк в этом разделе — в `src/api.js`.

1. Не `POST` — 405 `method` (`src/api.js:58`).
2. Подпись `initData` — 401 (`:60`).
3. Снятие отметки «бот заблокирован» (`:66`) — до любых отказов по правам.
4. `me` (`:68`) — отвечает и незарегистрированному.
5. Не зарегистрирован — 403 (`:89`).
6. `notify.set` (`:91`).
7. `admin.*`: не админ — 403 «Только для администратора.» (`:99`).
8. Общие действия `admin.*` без события (`:291–378`): проверка владельца внутри.
9. Событие не найдено — 404 (`:382`). Сюда же попадает неизвестное `admin.*` без события.
10. Событие завершено, действие не в `FINISHED_OK` — 400 (`:383`).
11. Проверка владельца действия события — **после** пунктов 9 и 10. Админ на завершённом событии получает 400
    «Событие завершено…», а не 403.
12. Обработчик.
13. Неизвестное действие — 404 «Неизвестное действие» (`:269`, `:751`).

Для действий участника: событие не найдено — 404 (`:107`); `event.get` доступен участнику или админу (`:111`);
остальным не-участникам — 403 (`:138`).

### Что есть в таблице

Для каждого из 59 действий (13 участника, 46 `admin.*`; полный список с ролями — `docs/refactoring/step-7-docs-contract.md`):

- роль: любой с подписью / зарегистрированный / участник события / админ / владелец;
- текст отказа владельца — он у действий разный: шаблон «… может только владелец бота.» с подлежащим
  (`src/api.js:287`, `350`, `364`, `369`, `374`, `563`, `599`, `661`, `726`, `745`) и отдельный текст служебного
  просмотра (`:735`);
- нужно ли событие;
- разрешено ли в завершённом событии;
- обработчик.

Условные права остаются в обработчиках: переименование админа (`:342`), удаление админа (`:545`), заморозка
исключений для не-владельца (`:573`), видимость переписки обращений (`src/support.js:158`).

### Куда уходит логика

| Что | Откуда | Куда |
|---|---|---|
| Исключения, закреплённые пары | `src/api.js:568–634` | рядом с `src/pairs.js` (новый модуль правил пар) |
| Участие админа | `src/api.js:524–538` | `src/membership.js` |
| Параметры события, кольцевая, регистрация, ссылка, «не повторять пары» | `src/api.js:465–522` | `src/events.js` |

| Сборка `admin.state` | `src/api.js:386–456` | отдельная функция рядом с таблицей |
| Проверка слова подтверждения (`СБРОС`, `УДАЛИТЬ`, `ОТМЕНА`) | `src/api.js:662`, `727`, `746` | одна функция |

В `src/api.js` остаются разбор запроса, таблица и ответ. Новые модули — файлы `src/*.js` (тест слов читает
только верхний уровень `src/`, `tests/wording.test.mjs:17`).

### Что заденет в тестах

- `tests/rights.test.mjs` (шаг 1) и автотест e2e (`tests/e2e.test.mjs:1320`) берут список действий регуляркой
  по тексту `src/api.js`. После перехода — из таблицы (импорт модуля; `src/api.js` импортирует только `.js`).
- Автотест e2e перебирает действия по порядку на одном событии и реально их выполняет: `admin.registration`
  закрывает набор, `admin.event.finish` завершает событие, после чего действия вне `FINISHED_OK` получают 400
  раньше проверки владельца. Порядок действий в таблице должен повторять порядок `case` в `src/api.js`, либо
  автотест нужно перевести на свежее событие для каждого действия (как `tests/rights.test.mjs`).

## Часть Б. Контекст запроса и чтения

### Контекст

Один объект на вызов: `env`, `db`, `settings`, `me`, лениво — `users` и `ownerId`. Создаётся в `handleApi`,
`handleUpdate` и в cron, передаётся первым аргументом. Сигнатуры сейчас разные: `adminThread(env, ev, me,
isOwner, id)`, `adminList(db, ev, me, isOwner, users)`, `removeMember(env, ev, userId, {…})`,
`insertMember(env, ev, userId, actor)`, `saveFamily(env, actor, {…}, { owner })`.

Что становится общим: настройки и список пользователей. Что остаётся повторным чтением намеренно:

- событие внутри атомарных действий (`revealAll` читает `cur`, `src/events.js:163`);
- проверки после неудачного захвата (`src/pairs.js:134`, `248`, `370`; `src/events.js:181`;
  `src/membership.js:192`; `src/support.js:255`);
- повторное чтение события после записи исключений и закреплённых пар (`src/api.js:591`, `632`).

### Узкие чтения

- Число участников для `event.get` — запросом `COUNT`, без строк участников.
- Для жеребьёвки — колонки `user_id`, `name`, `wishlist_updated_at`, `delivery_updated_at` и признак «письмо
  пустое», посчитанный в базе.
- Для `admin.state` — признаки «письмо есть», «адрес есть» вместо текстов.
- Для рассылок (`finishEvent`, `announce`, `inviteFromEvent`, `deleteEvent`, `resetEvent`) — только `user_id`.

Пустота в базе обязана совпадать с `!text.trim()` в JS: `trim(X, char(9,10,11,12,13,32,160,5760,8192,…,8202,
8232,8233,8239,8287,12288,65279)) = ''`. Проверено: 0 расхождений на всех символах U+0001–U+FFFF. Тест паритета
обязателен.

### Чтения одним `batch`

`db.batch` считается одним запросом в лимите 50 и принимает `SELECT`. Объединить:

- пять чтений `checkDraw` (`src/pairs.js:53–64`);
- чтения `admin.state` (`src/api.js:387–402`) вместе со списком обращений;
- чтения перед перестройкой пар в `removeMember` и `insertMember` (`src/pairs.js:217–228`, `270–279`).

### Слои

- Предикаты `isFinished`, `chatUntil`, `chatWritable`, `CHAT_GRACE_MS` — в модуль без импортов.
- `familyExclusions` и снимки — из `src/db.js` в модуль рядом с парами (снимки — шаг 5; здесь только не мешать).

## Чего не делать

- Не менять тексты, коды ответов, поля ответов и их порядок там, где его сверяют тесты.
- Не менять условия захватов и состав `batch` атомарных действий — только то, откуда берутся прочитанные данные.
- Не трогать `src/draw.js`, `src/outbox.js`, `src/budget.js`.
- Не объединять тексты, которые отличаются хотя бы знаком (см. `docs/refactoring-roadmap.md`, «Мелочи»).

## Подводные камни

- `resolveOwner` не только читает: если владелец в настройках недействителен, он назначает самого раннего админа
  и записывает это (`src/roles.js:42–51`). Ленивое вычисление владельца отложит эту запись до первого действия,
  которому владелец нужен. Чтобы поведение не изменилось, для `admin.*` оставить вычисление сразу, а экономить
  на повторных чтениях списка пользователей.
- `me` сейчас вычисляет владельца только для админа (`src/api.js:70`).
- `admin.audit` бывает и общим, и по событию: ветка без `event` отвечает сама, с `event` — уходит в действия
  события (`src/api.js:324–327`, `689`).
- `admin.event.invite_from` числится в `FINISHED_OK`, чтобы дать свой текст отказа (`src/api.js:720`), а не общий.
- Ветка «перенести администратора может только владелец» (`src/api.js:357`) недостижима: не-владелец отсечён
  строкой `src/api.js:350`. Удалить при переносе.
- Отказы «событие завершено» в `cancelDraw`, `forceCancelDraw`, `announce` (`src/pairs.js:319`, `349`;
  `src/events.js:231`) через API недостижимы — их перекрывает общий отказ `src/api.js:383`. Оставить как защиту.
- Результаты `SELECT` внутри `batch` приходят массивом по порядку операторов; при объединении чтений не
  перепутать порядок.
- Письма в `checkDraw` нужны ещё для `lastUpdate` (`src/pairs.js:143`) — это время, а не текст.

## Приёмка

- `tests/rights.test.mjs` и `tests/secrecy.test.mjs` зелёные без правок ожиданий; список действий берётся из
  таблицы, их 59.
- Новый тест: для каждого действия ответ на запрос без прав, на несуществующее событие и на завершённое событие —
  тот же код и тот же текст, что до шага (эталон снять до начала работы скриптом и положить в `tests/fixtures/`).
- Число запросов (`tests/queries.test.mjs`), новые пороги «не больше»: `admin.state` — 6, `admin.draw.check` — 6,
  `admin.draw` — 10, `admin.remove` — 12, `admin.insert` — 11, действия обращений — на 2 меньше базовых,
  остальные — не больше базовых.
- Тест паритета «пустое письмо» JS ↔ SQL зелёный.
- `npm run bench:draw` — без ухудшения; эталон жеребьёвки зелёный без пересоздания.
- `npm test`, `npm run test:e2e` зелёные; в e2e меняется только способ получить список действий.
- В `src/api.js` нет `db.prepare`.
- `CLAUDE.md` (структура, жёсткое правило о владельце и автотесте), спецификации и план отмечены.
