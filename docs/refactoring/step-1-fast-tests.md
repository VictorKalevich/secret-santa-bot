# Шаг 1. Быстрые тесты всего Worker

Фича Spec Kit: следующий свободный номер (ожидается `016`), короткое имя `fast-tests`.
Сначала прочитай `docs/refactoring-roadmap.md` (ограничения и порядок работы) и `docs/refactoring/baseline.md`.

## Цель

`npm test` за секунды проверяет тайну пар, права ролей, атомарность и число запросов на действие — на настоящем
коде Worker и настоящем SQLite, без `wrangler dev`. Ни одна строка в `src/` в этом шаге не меняется.

## Зачем

- Тайну, права и атомарность сейчас проверяет только e2e: 194 секунды, 8 запусков `wrangler dev`, по правилам
  проекта — перед выкатом, а не перед коммитом. Остальные шаги плана меняют именно этот код.
- Проверки e2e на гонки чередование запросов не навязывают (`tests/e2e.test.mjs:439`, `1099`, `1108`, `1111`,
  `1445`, `1722`): они проходят, даже если запросы выполнились по очереди. С навязанным чередованием нашлись
  11 случаев дубля или порчи данных — см. `baseline.md`, раздел 4.
- Автотест «владелец ⊇ админ» (`tests/e2e.test.mjs:1319–1342`) пропускает два действия: регулярное выражение
  `[a-z.]+` не допускает «_», поэтому `admin.avoid_previous` и `admin.event.invite_from` не перебираются (44 из
  46). Порог «не меньше 35» позволяет молча потерять ещё девять. Действия идут в порядке исходника на одном
  событии, и `admin.event.finish` завершает его раньше `admin.reset.full`: админ получает 400 «Событие завершено»,
  и право владельца на сброс не проверяется.
- «Нет пар в ответе» проверяется по именам ключей JSON (`tests/e2e.test.mjs:177`, `528`, `688`), а не по
  значениям; для журнала проверка всегда истинна.
- `tests/unit.test.mjs` узнаёт запросы по подстроке SQL (`:46`, `:94`, `:95`) и ломается от переформатирования.

## Что уже проверено

Прототип лежит в `docs/refactoring/prototypes/` и работает на текущем коде:

- Весь Worker (`src/index.js`) запускается в Node на `node:sqlite`. Сценарий из 46 действий — 96 мс.
- `import APP_HTML from './app.html'` в Node решается перехватчиком загрузки `module.registerHooks`
  (`text-hooks.mjs`), без зависимостей.
- Интерфейс «мира» совпадает с `tests/harness.mjs` (`api`, `setup`, `say`, `press`, `cron`, `query`, `texts`,
  `lastText`): сценарии e2e переносятся почти дословно.
- Чередование одновременных вызовов задаётся детерминированно (`together`, `beforeWrite`); результат `atomic.mjs`
  одинаков от прогона к прогону.
- С исправленной регуляркой автотест прав находит 46 действий; владелец не получает ни одного 403, админ получает
  403 ровно на 11 действиях, которые тест уже ожидает (проверено на прототипе).

Особенности D1 и «мира», которые нужно сохранить, перечислены в `prototypes/README.md`.

## Чего не делать

- Не менять `src/`. Найденные дефекты только фиксируются тестами с `todo`.
- Не сокращать и не переписывать сценарии e2e, кроме пункта 10. e2e остаётся проверкой настоящего workerd.
- Не добавлять зависимостей. Не вводить поддельные таймеры: «перемотка времени» — правкой полей в базе, как в e2e.

## Подводные камни

- `node --test` запускает каждый файл в своём процессе: подмена `globalThis.fetch` и кэш «схема готова»
  (`src/db.js:16`) между файлами не пересекаются. Внутри файла `fetch` возвращать на место в `after`.
- Сценарий «база не подготовлена» (`tests/e2e.test.mjs:476`) в общем процессе не воспроизвести из-за кэша схемы —
  оставить в e2e.
- Проверки времени в `tests/draw.test.mjs` (`< 10 мс` на строках 310, 321, 332, 350, 390, 408, 517) меряют
  настенное время. Если новые файлы сделают их нестабильными — запускать `node --test` с
  `--test-concurrency=1`, а не ослаблять пороги.
- Вызовы из `Promise.all` в «мире» идут фактически по очереди. Гонки — только через `together` и `beforeWrite`.
- Захваты по метке времени (`ward.received`, обращения) дают дубль, только если время вызовов совпало до
  миллисекунды: проверять с `together(…, { sameMoment: true })`.
- Перестановка пар в тесте тайны: первичный ключ `pairs` — `(event_id, santa)`, уникальность — `(event_id, ward)`.
  Менять подопечных в одной транзакции через временное значение или удалением и вставкой строк.
