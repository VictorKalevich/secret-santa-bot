# Шаг 7. Сводный контракт API и правки документов

Фича Spec Kit: следующий свободный номер (ожидается `022`), короткое имя `docs-contract`.
Удобнее после шага 4: список действий берётся из таблицы. Код приложения не меняется.

## Цель

Актуальное описание API лежит в одном документе и сверяется тестом со списком действий. `CLAUDE.md`, README и
Конституция не расходятся с кодом.

## Зачем

`CLAUDE.md:36` называет актуальным контрактом `specs/005-events-history/contracts/events.md` плюс изменения
006–014. На деле описание одного действия собирается из многих файлов:

| Действие | Сколько файлов контрактов его описывают |
|---|---|
| `admin.state` | 9 (001, 002, 005, 006, 007, 008, 010, 012, 014) |
| `admin.remove` | 7 |
| `me`, `admin.game`, `admin.transfer`, `admin.draw`, `admin.insert` | по 5 |
| `admin.exclusion.add` | 4 |

Сам контракт 005 отсылает к 001–004 («как в 001/003», «остальные `admin.*` из 001–004»). Примерно для 17
действий единственное описание — в контрактах 001, 002 и 004. `admin.ring` не описан ни в одном контракте
(проверено поиском). Числа в таблице — по сверке контрактов 2026-11-14; при составлении сводного документа
источник — код, а не эти числа.

## Что сделать

1. **Сводный контракт** — один документ (место определить в плане фичи: `docs/api.md` или
   `specs/<фича>/contracts/api.md` с указателем из `CLAUDE.md`). Для каждого действия: поля запроса, поля ответа,
   отказы с кодом и текстом, кто может вызвать, работает ли в завершённом событии. Составляется по коду, не по
   старым контрактам. Отдельные разделы: порядок проверок доступа (он записан в
   `docs/refactoring/step-4-api-table-context.md`), коды журнала, формат `users.pending`, кнопки бота
   (`callback_data`), параметры ссылки `/app`.
2. **Тест**: каждое действие из таблицы действий есть в сводном контракте, и наоборот.
3. **Старые контракты** `specs/001…014/contracts/` остаются историей фич; в начало каждого — строка «актуальное
   описание — в сводном контракте».
4. **`CLAUDE.md`** (номера строк в этом пункте — в `CLAUDE.md`):
   - строка про актуальный контракт (`:36–38`) — указатель на сводный документ;
   - «каждое действие админа и бота пишет журнал» (`:111`) — неточно: `admin.rename` журнал не пишет, ответ в уже
     взятое обращение — тоже. Записать как есть или дождаться решения владельца (см. план, «Решения владельца»);
   - «423 до смены `ADMIN_SECRET`» (`:62`), «отметка от текущего `ADMIN_SECRET`» — код ссылки и отметка считаются
     с ключом `BOT_TOKEN` (`src/telegram.js:39–41`, `src/roles.js:18–27`): смена `BOT_TOKEN` тоже снимает
     блокировку. README это описывает, `CLAUDE.md` — нет;
   - «схема D1 (сейчас 11)» (`:101`) — 11 это версия схемы, файлов миграций 7: написать оба числа;
   - в блоке команд нет `npm run test:all`;
   - «полный набор артефактов» (`:10–11`) — у 013 нет `data-model.md`, у 015 нет `research.md`, `data-model.md`,
     `contracts/`: записать правило «по необходимости».
5. **Конституция**, принцип II: «письмо до 1000 слов» (`.specify/memory/constitution.md:96`) — в коде лимит 4000
   символов (`src/chat.js:9`). Править через `/speckit-constitution` с отчётом о синхронизации и сменой версии.
6. **README** (номера строк — в `README.md`):
   - `:414` — «за 2 дня до срока письма»; код напоминает за 2 дня, за день и в день срока, и только до жеребьёвки
     (`src/cron.js:62–66`);
   - `:581` — описание `npm test` без проверки слов; `npm run test:all` не упомянут;
   - версия Node — если шаг 1 её ещё не поправил.
7. **`tests/e2e.test.mjs:1`** — заголовок «Сценарии 001–008» устарел.

## Расхождения «контракт ↔ код», которые закрывает сводный документ

- `admin.game` по контракту 005 принимает `ring`; в коде кольцевую меняет `admin.ring`.
- В ответах есть недокументированные поля: `admin.transfer` → `events`; `admin.event.delete` → `notified`;
  `chat.get` → `writable`; `admin.state` → `me_member`, `other_events`, `removed[].username`.
- В `admin.state.settings` нет `owner_name` (контракт 002) и `has_history` (контракт 001); `owner_name` отдаёт
  `admin.users`.
- В таблице кодов нет 405, 404 «Событие не найдено.», 500 «Ошибка сервера…».
- Коды журнала `draw.cancel.force` и `support.open/take/pass/close/return` есть только в `data-model.md` фичи 012.
- Формат режима ответа `msg_<сторона>:<событие>:<собеседник>:<время>` описан только в `CLAUDE.md`.
- Тексты «владелец игры», «начал игру заново» в контрактах 001, 002, 004 в коде давно другие.

## Чего не делать

- Не менять код приложения и поведение. Найденное расхождение, которое выглядит ошибкой кода, — в раздел
  «Решения владельца» плана, а не в правку.
- Не переписывать старые спецификации и контракты.

## Приёмка

- Сводный контракт описывает все 59 действий; тест соответствия зелёный.
- Поиск по `CLAUDE.md` и README не находит утверждений из пунктов 4 и 6 в прежнем виде.
- Конституция: новая версия, отчёт о синхронизации, принцип II согласован с лимитом в коде.
- `npm test` зелёный (тест слов проверяет только `src/`; сводный контракт пишется для разработчика, слово
  «эвент» в нём допустимо, но для единообразия лучше «событие»).
