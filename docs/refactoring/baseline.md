## 6. Чтение писем там, где нужен только признак

`eventMembers` (`src/db.js:117`) возвращает `m.*` — вместе с текстами писем и адресами. Разбор ответа базы идёт в
Worker и входит в лимит CPU. Замер разбора JSON с письмами по 4000 символов:

| Участников | С письмами | Без писем |
|---|---|---|
| 50 | 357 КБ — 0,48 мс | 14 КБ — 0,02 мс |
| 100 | 715 КБ — 0,84 мс | 28 КБ — 0,05 мс |
| 200 | 1430 КБ — 1,94 мс | 56 КБ — 0,09 мс |

Кто читает письма без нужды: `event.get` — ради числа участников (`src/api.js:112`); `checkDraw` — ради списка
пустых писем (`src/pairs.js:53`, `:83`); `admin.state` — ради признаков «письмо есть», «адрес есть»
(`src/api.js:418`, `:425`); `finishEvent`, `announce`, `inviteFromEvent`, `deleteEvent`, `resetEvent` — ради
списка получателей.

Пустоту письма можно считать в базе с тем же результатом, что `trim()` в JS: `trim(X, набор пробельных символов)`
дал 0 расхождений на 253 948 пробах по всем символам U+0001–U+FFFF.

## 7. Как переснять

```powershell
npm test                              # раздел 1; запросы (раздел 3) и атомарность (раздел 4) проверяются здесь же
npm run test:e2e                      # раздел 1
npm run bench:draw                    # раздел 2 (другой вариант файла: npm run bench:draw -- <путь к draw.js>)
node tests/bench/queries.mjs [sql]    # раздел 3: таблица запросов на действие (и их SQL)
node --test tests/atomic.test.mjs     # раздел 4: 16 проверок «один результат» + 5 todo с номером шага
```

Замер жеребьёвки — на той же машине, от сети, без тяжёлых программ рядом; запускать дважды и брать диапазон.
