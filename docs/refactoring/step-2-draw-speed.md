# Шаг 2. Жеребьёвка быстрее при том же результате

Фича Spec Kit: следующий свободный номер (ожидается `017`), короткое имя `draw-speed`.
Шаг необязательный и ни от чего, кроме шага 1, не зависит: его можно пропустить или сделать позже.

**Статус: выполнен** (фича `017-draw-speed`, 2026-11-14). Правка применена, приёмка пройдена; `draw-speedup.patch` и
`draw-equivalence.mjs` удалены (прежние версии — в git до 017). Итоговые замеры — `baseline.md`, раздел 2, «После шага 2».

## Цель

Холодный вызов жеребьёвки на 30–40% быстрее. Пары при том же зерне, порядок вызовов `rng`, причины отказа и
бюджет шагов — прежние.

## Зачем

Лимит бесплатного тарифа — 10 мс CPU на вызов. Первый вызов в Worker обычно холодный. Сейчас на 200 человек
холодный вызов занимает 5,6–5,9 мс на машине владельца от сети и 9–12 мс от батареи — практический потолок около
150–200 человек (`baseline.md`, раздел 2).

Куда уходит время (200 человек, холодный вызов 5,8 мс):

- 1,4 мс — заполнение матрицы допустимости: `n²` вызовов функции правил (`src/draw.js:145`).
- 3,8 мс — первое паросочетание (`src/draw.js:152`): `n` перемешиваний списков, в каждом — перестановка через
  деструктуризацию `[a[i], a[j]] = [a[j], a[i]]` (`src/draw.js:12`). В непрогретом коде она создаёт массив на
  каждую перестановку.

## Что сделать

Правка готова и проверена: `docs/refactoring/prototypes/draw-speedup.patch` (применяется к `src/draw.js` коммита
`24b85d3` командой `git apply`).

1. **`shuffle`** (`src/draw.js:8–15`): перестановка через временную переменную вместо деструктуризации.
2. **`pairRules`** (`src/draw.js:197–213`): возвращаемая функция получает свойство `fillMatrix(ids, adj)`. Оно
   заполняет ту же матрицу без `n²` вызовов: всё единицами, затем нули по запретам, по столбцам закреплённых
   подопечных, по строкам закреплённых Сант (кроме их подопечного), по диагонали. Порядок шагов повторяет порядок
   проверок в функции правил: закреплённый Санта важнее запрета.
3. **`findAssignment`** (`src/draw.js:144–145`): если у функции правил есть `fillMatrix` — вызвать её, иначе
   прежний перебор. Произвольная функция без `fillMatrix` работает как раньше.

После правки обновить комментарии в `src/draw.js` (пометка фичи, как у правок 015) и строку про `src/draw.js` в
`CLAUDE.md`.

## Что измерено

Машина владельца, от сети, медианы (`bench-draw.mjs`):

| Человек | Холодный: было → стало, мс | Прогретый: было → стало, мс |
|---|---|---|
| 50 | 1,5 → 0,9 | 0,08 → 0,05 |
| 100 | 2,9–3,2 → 1,8–1,9 | 0,28–0,32 → 0,17–0,19 |
| 150 | 4,4–4,6 → 2,8–2,9 | 0,61–0,78 → 0,37–0,44 |
| 200 | 5,6–5,9 → 3,4–3,6 | 1,1–1,4 → 0,61–0,73 |

Совпадение результатов: 6000 случайных случаев (`draw-equivalence.mjs`), 0 расхождений; 42 теста
`tests/draw.test.mjs` проходят на изменённом файле.

Третья проверенная правка — один буфер `seen` на все вершины в `findMatching` вместо нового на каждую — дала
выигрыш в пределах погрешности. Не делать.

## Чего не делать

- Не менять алгоритм, порядок попыток, `DEFAULT_BUDGET`, число случайных кругов (30) и попыток перебора.
- Не делать «быструю попытку» — случайные круги до построения матрицы. Она меняет порядок вызовов `rng`, то есть
  пары при том же зерне. Это отдельное решение владельца (`docs/refactoring-roadmap.md`, раздел «Решения
  владельца»).
- Не трогать `src/pairs.js` и чтение данных для жеребьёвки — это шаг 4.

## Подводные камни

- `fillMatrix` должна давать ту же матрицу, когда правила называют людей не из списка `ids`. Запреты события
  могут относиться к участникам, которые ещё не ввели имя и в жеребьёвку не попали; при прямом вызове
  `findAssignment(ids, pairRules(…))` то же возможно для закреплённых пар. Запрет с таким человеком пропускается;
  строка закреплённого Санты, чей подопечный не в списке, — нули; столбец закреплённого подопечного, чей Санта не
  в списке, — нули. Патч это делает, сверка это проверяет.
- Свойство на функции теряется, если функцию обернуть (`(a, b) => rules(a, b)`). Все вызовы `findAssignment` в
  `src/` идут через `planDraw`, который передаёт результат `pairRules` напрямую (`src/draw.js:228`) — так и
  оставить.

## Приёмка

- Тест с эталонными результатами из шага 1 (`tests/draw-golden.test.mjs`) зелёный **без пересоздания эталона**.
- `node docs/refactoring/prototypes/draw-equivalence.mjs <исходный> src/draw.js` — 0 расхождений (исходный файл:
  `git show main:src/draw.js`).
- `npm run bench:draw` до и после на одной машине: холодная медиана на 200 человек меньше не менее чем на 25%,
  ни на одном размере медиана не выросла.
- `npm test` и `npm run test:e2e` зелёные.
- Новый тест: матрица из `fillMatrix` равна матрице из перебора на случайных правилах с закреплёнными парами,
  в том числе с людьми не из списка.
- `draw-speedup.patch` и `draw-equivalence.mjs` удалены, `baseline.md` (раздел 2) обновлён, шаг отмечен в плане.
