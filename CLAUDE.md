# CLAUDE.md — secret-santa-bot

Telegram-бот «Тайный Санта» для небольшой группы (все участники в Беларуси). Cloudflare Worker (бесплатный
тариф) + D1 + мини-приложение Telegram. Язык интерфейса и документации — русский.

## Обязательный процесс: Spec Kit

- Любое изменение поведения — через Spec Kit: `/speckit-specify` → (`/speckit-clarify`) → `/speckit-plan` →
  `/speckit-tasks` → `/speckit-implement`. Скилы лежат в `.claude/skills/speckit-*`.
- Спецификации — источник истины: `specs/NNN-имя/` (spec.md, plan.md, research.md, data-model.md, contracts/,
  quickstart.md, tasks.md). Активная фича записана в `.specify/feature.json`.
- Конституция: `.specify/memory/constitution.md` — проверяй каждый план по всем принципам.
- Скрипты Spec Kit — PowerShell (`.specify/scripts/powershell/`), платформа разработчика — Windows.
- Код и спецификация не должны расходиться: поменял поведение — обнови spec/contracts в той же ветке.

## Технологии

- JavaScript ES2022, ES-модули, Cloudflare Workers (workerd); без рантайм-зависимостей и без сборщика.
- Wrangler 4 (dev/deploy), Cloudflare D1 (SQLite), Cron Triggers (раз в минуту).
- Telegram Bot API (webhook `/tg`) + Telegram Mini Apps (`/app`, подпись `initData`).
- Тесты: `node:test`; e2e — `wrangler dev` + `tests/mock-telegram.mjs`; скриншоты — `playwright-core` + Chrome.

## Структура

- `src/index.js` — маршруты: `/tg`, `/app`, `/api/*`, `/setup`, `scheduled`; оборачивает `env` счётчиком запросов
  (`metered`) и один раз в конце вызова отправляет очередь (`afterRequest` → `flushOutbox`). `/setup` (010): GET — только
  форма, ключ — из POST-формы (из адреса не читается), после использования ссылки владельца — 423 до смены
  `ADMIN_SECRET`; заголовки `no-referrer`, `no-store`, `frame-ancestors 'none'`.
- `src/bot.js` — чат: `/start` (`inv_<код эвента>`/`adm_`), регистрация, меню со списком эвентов (один запрос),
  режим ответа в переписку (`msg:<сторона>:<eid>` → `pending = msg_<сторона>:<eid>:<собеседник>:<время>`, живёт час,
  сбрасывается любой командой).
- `src/api.js` — API мини-приложения: почти все действия с полем `event` (контракт: `specs/005-events-history/contracts/events.md`).
  От `bot.js` не зависит.
- Игровая логика (бывший `game.js`, разбит в 009):
  - `src/events.js` — эвент: создание, завершение, раскрытие (атомарные: захват + рассылка по условию), сброс,
    удаление, приглашение из эвента, напоминания, объявления; `CHAT_GRACE_MS`, `isFinished`, `chatWritable`.
  - `src/pairs.js` — проверка и проведение жеребьёвки (снимок состава в условии захвата), удаление/вписывание после
    жеребьёвки (версия пар — `draw_token`), отмена жеребьёвки.
  - `src/chat.js` — переписка Санты и подопечного: `MAX_CHARS`, отправка (только при живой паре), непрочитанные.
  - `src/roles.js` — владелец, админы, передача владения, перенос участия на новый аккаунт (только владелец, 010),
    ссылка владельца (`ownerLinkCode`, одноразовая: `claimOwnerLink`, `ownerLinkUsed` — отметка от текущего `ADMIN_SECRET`).
  - `src/vault.js` — служебный просмотр владельца (010): участник (`vaultPerson`) и все пары (`vaultPairs`); журнал до
    ответа, ни одного UPDATE статусов.
  - `src/membership.js` — вступление по ссылке (`joinByInvite`, одно правило для ссылки и ввода имени; `'removed'` при
    запрете возврата), заявки (принять — только при открытой регистрации), семьи (заморозка состава при идущей
    жеребьёвке — кроме владельца).
  - `src/outbox.js` — `flushOutbox` (захват строк `locked_until`, в пределах остатка бюджета запросов).
  - `src/format.js` — общие правила текста: `escapeHtml`, `displayName`, `shortTitle` (без разрыва эмодзи), даты,
    `adminRecipients`, кнопки приложения.
  - `src/budget.js` — счётчик внешних запросов на вызов (`metered`, `budgetLeft`, `reportBudget` → лог `budget exceeded`).
  - `src/telegram.js` — Bot API (с таймаутом и учётом в счётчике), проверка `initData`.
- `src/draw.js` — чистые функции жеребьёвки (тестируются в Node); поиск ограничен бюджетом шагов (`DEFAULT_BUDGET`,
  лимит CPU); `planDraw` — все попытки одной проверки (история, без истории, «мешают семьи») делят один бюджет.
- `src/cron.js` — шаги изолированы (`step`: уведомления → ежедневное → отправка очереди); уведомления об изменениях
  писем, автодействия расписания (`dueAutoAction`/`runAutoAction`) и напоминания — не больше одного тяжёлого действия за вызов.
- `migrations/` — схема D1 (сейчас 9): `0001_initial.sql` (схема 005), `0002_fixes.sql` (`users.blocked_at`,
  `outbox.locked_until`, `events.draw_token`), `0003_admin_tools.sql` (`announcements`, `audit`, поля расписания
  эвента, `pairs.gift_received`), `0004_delivery_families_requests.sql` (`members.delivery`, `families`,
  `family_members`, `join_requests`, параметры эвента `delivery_on`/`families_on`/`approval`), `0005_owner_rights.sql`
  (`events.rejoin`, `removed_members`). Отметка «ссылка владельца использована» — `settings.owner_link_used` (без
  миграции). Код таблицы не создаёт и не удаляет: `checkSchema` требует `REQUIRED_SCHEMA`.
  Новая схема → новый файл миграции + `REQUIRED_SCHEMA` в `src/db.js`.
- `src/db.js` — проверка схемы и запросы; `auditStmt`/`auditIfStmt` — запись журнала в том же batch, что и действие
  (каждое действие админа и бота пишет журнал; без пар, писем и текстов объявлений).
- `src/app.html` — мини-приложение; стили только из дизайн-системы.
- `design-system/` — `tokens.css`, `components.css`, `preview.html`, `README.md`.

## Жёсткие правила

1. **Тайна.** Никакой ответ API, кроме `ward.get` самому Санте и служебного просмотра владельца (`admin.vault.*`,
   `src/vault.js`), не содержит пар. Админ видит только статусы. Служебный просмотр (Конституция 2.0.0): только владелец,
   вход словом «ОТКРЫТЬ» в приложении, каждое открытие — журнал (`vault.person`/`vault.pairs`, без пар), статусы не
   меняются, админам сообщений нет; участникам честно сказано в README (с 011 — не в «Как это работает»; Конституция 2.1.0).
   Роли: владелец один (`settings.owner_id`, `resolveOwner`), только он назначает/снимает админов и переносит участие.
   **Владелец ⊇ админ (принцип VII).** Каждое `admin.*` доступно владельцу (e2e-автотест перебирает `case 'admin.…'`
   из `src/api.js`); ограничения «чтобы админ не вычислил пары» на владельца не действуют. Ссылка владельца одноразовая.
   Тексты уведомлений — без имени подопечного и без текста письма. Пользовательский текст — только через
   `textContent` / `escapeHtml`. Админ видит любой эвент (`event.get`), но `ward.get`/`chat.get` — только участникам.
   **Эвенты.** Данные одного эвента не влияют на другой. Завершённый эвент (`status='finished'`) — только чтение,
   кроме переписки в течение `CHAT_GRACE_MS` (7 суток); завершение необратимо, сброс завершённого запрещён.
   Кольцевая (`events.ring`) — без взаимных пар, в т.ч. при заменах (`src/draw.js`).
   Перенос участия на аккаунт админа/владельца запрещён (иначе админ получил бы чужие пары).
   **Адрес доставки** (`members.delivery`) отдаётся только самому участнику (`event.get`) и его Санте (`ward.get`);
   админу — только `has_delivery`. Семьи (`familyExclusions`) учитываются везде, где строятся пары.
   **Без косвенных утечек (009).** После жеребьёвки админ не меняет исключения эвента, состав семьи — пока идёт эвент с
   жеребьёвкой, где есть двое её затронутых членов; админ не вписывает себя; учтены ли прошлые пары, наружу не сообщается.
   **Набор (010).** Закрытая регистрация — никто не вступает: ни по ссылке, ни заявкой, ни по приглашению из эвента
   («Я участвую» админа — можно). При `events.rejoin = 0` удалённый организатором (`removed_members`) не возвращается
   по ссылке. Жеребьёвка записывается, только если участники, исключения и семьи (`familySnapshot`) не изменились.
   **Одно действие — один результат (009).** Рассылки раскрытия/завершения/жеребьёвки и изменения пар — в одном batch
   с захватом (`UPDATE … WHERE` прежнее состояние) и остальными операторами по условию (`enqueueIfStmt`/`auditIfStmt`).
2. **Дизайн-система.** В `src/app.html` — только классы `ds-*`, без `style`, без сырых цветов и px. Базовые стили
   элементов в `components.css` — только через `:where()`. Новый элемент:
   токен → компонент в `components.css` → показ в `preview.html` → строка в `design-system/README.md`. Тест
   `tests/design-system.test.mjs` это проверяет.
3. **Лимит текста** — `MAX_CHARS = 4000` (`src/chat.js`): письмо и сообщения переписки помещаются в одно сообщение Telegram (4096).
4. **Бесплатный тариф.** ≤ 10 мс CPU и ≤ 50 внешних запросов (вкл. D1) на вызов. Сообщения другим людям — только
   через `outbox` (`enqueueStmt`); отправляет очередь только `index.js` в конце вызова и cron (`flushOutbox`
   сам не берёт больше остатка `budgetLeft`). Тяжёлые вычисления — на клиенте. e2e проверяет журнал на `budget exceeded`.
5. **Секреты** (`BOT_TOKEN`, `ADMIN_SECRET`) — только `wrangler secret put`; `.dev.vars`, `.env*` не коммитить.
6. **Файлы.** Проект живёт в `C:\ClaudeProjects\secret-santa-bot\`. В самой `C:\ClaudeProjects\` ничего не создавать.
7. **README.** Фича меняет установку, настройку, секреты, команды, роли или использование → правь `README.md` в той же
   ветке (отдельная задача в `tasks.md`). Владелец проекта ещё не выкатывал бота — README должен вести от нуля до работы.
