# CLAUDE.md — secret-santa-bot

Telegram-бот «Тайный Санта» для небольшой группы (все участники в Беларуси). Cloudflare Worker (бесплатный
тариф) + D1 + мини-приложение Telegram. Язык интерфейса и документации — русский.

## Обязательный процесс: Spec Kit

- Любое изменение поведения — через Spec Kit: `/speckit-specify` → (`/speckit-clarify`) → `/speckit-plan` →
  `/speckit-tasks` → `/speckit-implement`. Скилы лежат в `.claude/skills/speckit-*`.
- Спецификации — источник истины: `specs/NNN-имя/` (spec.md, plan.md, research.md, data-model.md, contracts/,
  quickstart.md, tasks.md). Активная фича записана в `.specify/feature.json`.
- Конституция: `.specify/memory/constitution.md` — проверяй каждый план по всем принципам.
- Скрипты Spec Kit — PowerShell (`.specify/scripts/powershell/`), платформа разработчика — Windows.
- Код и спецификация не должны расходиться: поменял поведение — обнови spec/contracts в той же ветке.

## План рефакторинга

Рефакторинг архитектуры идёт по плану `docs/refactoring-roadmap.md`: 7 шагов, каждый — отдельная фича Spec Kit,
начиная с 016. Перед работой над шагом прочитай план и файл шага `docs/refactoring/step-N-….md` — в них
ограничения, порядок работы и приёмка. Базовые замеры для сравнения «до и после» — `docs/refactoring/baseline.md`.

## Технологии

- JavaScript ES2022, ES-модули, Cloudflare Workers (workerd); без рантайм-зависимостей и без сборщика.
- Wrangler 4 (dev/deploy), Cloudflare D1 (SQLite), Cron Triggers (раз в минуту).
- Telegram Bot API (webhook `/tg`) + Telegram Mini Apps (`/app`, подпись `initData`).
- Тесты: `node:test`, Node 22.15+ (`node:sqlite` без флага, `module.registerHooks`). Быстрые (`npm test`) — весь Worker в
  одном процессе («мир», `tests/support/world.mjs`): подмена D1 на `node:sqlite` со схемой из `migrations/`, Telegram —
  подмена `fetch` с правилами `tests/support/telegram-rules.mjs`; e2e — `wrangler dev` + `tests/mock-telegram.mjs` (те же
  правила); скриншоты — `playwright-core` + Chrome.

## Структура

- `src/index.js` — маршруты: `/tg`, `/app`, `/api/*`, `/setup`, `scheduled`; оборачивает `env` счётчиком запросов
  (`metered`) и один раз в конце вызова отправляет очередь (`afterRequest` → `flushOutbox`).
- `src/setup.js` — страница `/setup` (010; отдельный файл с 019): GET — только форма, ключ — из POST-формы (из адреса
  не читается), после использования ссылки владельца — 423 до смены `ADMIN_SECRET`; заголовки `no-referrer`, `no-store`,
  `frame-ancestors 'none'`.
- `src/bot.js` — чат: `/start` (`inv_<код эвента>`/`adm_`), регистрация, меню со списком эвентов (один запрос),
  режим ответа в переписку (`msg:<сторона>:<eid>` → `pending = msg_<сторона>:<eid>:<собеседник>:<время>`, живёт час,
  сбрасывается любой командой). Обращения (012): `sup:take|a:<обращение>`, `sup:u:<eid>` → `pending = sup_a:<id>:<время>` /
  `sup_u:<eid>:<время>` (те же правила: час, сброс командой). Сборка и разбор `pending` — `replyPending`, `supportPending`,
  `parsePending` (019; старый `msg_<сторона>:<eid>` без собеседника — «время ответа истекло»).
- `src/api.js` — API мини-приложения: почти все действия с полем `event` (контракт: `specs/005-events-history/contracts/events.md`).
  От `bot.js` не зависит. 019: таблица `ACTIONS` — строка на действие: `role` (`ROLES`: `ANY`, `USER`, `VIEWER` — участник
  или админ, `MEMBER`, `ADMIN`, `OWNER`), `event` (`true` / `'given'`), `finished` (у действия события обязательно: `true`
  или текст отказа), `owner` (отказ не владельцу, только при `OWNER`), `confirm` (слово и отказ), `run(ctx, body, ev,
  member)`; общие проверки — один конвейер в `handleApi` до обработчика, в прежнем порядке. **Новое действие — строка
  таблицы**; SQL здесь нет (`db.prepare` — только в модулях), условные права (зависят от данных) — в обработчике.
- `src/context.js` (019) — контекст вызова, первый параметр функций модулей: `openContext(env, userId)` (API и сообщение
  боту — пользователь и настройки одним пакетом), `makeContext(env, { me })` (нажатие кнопки, cron); `ctx.settings()`,
  `ctx.users()`, `ctx.ownerId()`, `ctx.isOwner()` — не больше одного чтения на вызов; `ctx.read({ …, users, settings })` —
  пакет именованных чтений (`readMany`), кэшируемые — в нём же.
- `src/status.js` (019, без импортов) — `CHAT_GRACE_MS`, `isFinished`, `chatUntil`, `chatWritable`, `publicEvent`.
- Игровая логика (бывший `game.js`, разбит в 009):
  - `src/events.js` — эвент: создание, завершение, раскрытие (атомарные: захват + рассылка по условию), сброс,
    удаление, приглашение из эвента, напоминания, объявления, параметры события (`saveEventSettings`, кольцевая,
    регистрация, ссылка, «не повторять пары»).
  - `src/pairs.js` — проверка и проведение жеребьёвки (снимок состава — `snapshotGuard` — в условии захвата),
    удаление/вписывание после жеребьёвки (версия пар — `draw_token`; `pairsVersion` → `{ a, version }`: построитель и
    оператор версии, уже первый в пакете), отмена жеребьёвки. Вписывание (012): только владелец, ранг Санты
    `insertRank` (0 — не открыл и без переписки, 1 — подарок не готов и не получен, иначе нельзя), группа выбранной пары —
    в условии захвата. Обе отмены — `undoDraw` (020): `cancelDraw` (никто не открыл, переписки нет) и `forceCancelDraw` —
    отмена владельцем до раскрытия (пары и переписка Сант удаляются, письма — нет).
  - `src/chat.js` — переписка Санты и подопечного: `MAX_CHARS`, `tooLong(n)`, отправка (только при живой паре),
    история (`chatHistory`), непрочитанные (запрос + разбор).
  - `src/constraints.js` (019) — исключения (`changeExclusions`), закреплённые пары (`changeFixed`), семьи как исключения
    (`familyExclusions(ev, ids, rows)` — чистая). Снимки правил — в `src/snapshots.js` (020).
  - `src/claim.js` (020) — помощник атомарных действий `atomic(db, cond, …args)`: условие и параметры — один раз
    (скобки проверяет `closedParens`), `and` — тот же пакет с добавочным условием, `enqueue`/`audit`/`where`/`select`/`add`
    в порядке вызовов, `claim(stmt)` — оператор исхода (один на пакет), `run()` → `{ won }`; `guard` — для построителей
    `REGISTRY`. Два вида условий: «захват мой» (случайная версия, отметка, опора удаляется последней; операторы — после
    захвата) и «по прежнему состоянию» (операторы — ПЕРЕД захватом, проверяют то, что он отменяет). Время и автор в
    условии «свой захват» не используются. Контракт — `specs/020-claims-snapshots/contracts/claims-snapshots.md`.
  - `src/snapshots.js` (020, без импортов) — снимки жеребьёвки `SNAPSHOTS.{members, exclusions, families, fixed}`: у
    каждого `js(data)` (по строкам, уже прочитанным `checkDraw`) и `sql` (один параметр — id события); суммы по модулю
    2^52, произведения — по модулю M = 1000003 (числа < 2^53); `drawSnapshot(ev, data)`, `snapshotGuard(eventId, snap)`.
    Меняешь формулу — меняй обе половины (паритет — `tests/snapshots.test.mjs`).
  - `src/participant.js` (019) — участник: «мои события» (`homeView`), экран события (`eventView`), письмо, адрес,
    подопечный, отметки подарка.
  - `src/panel.js` (019) — панель организатора: `adminState` (одним пакетом чтений, без текстов писем и адресов),
    письмо участника для админа, список пользователей.
  - `src/roles.js` — владелец, админы, передача владения, перенос участия на новый аккаунт (только владелец, 010),
    ссылка владельца (`ownerLinkCode`, одноразовая: `claimOwnerLink`, `ownerLinkUsed` — отметка от текущего `ADMIN_SECRET`).
  - `src/vault.js` — служебный просмотр владельца (010): участник (`vaultPerson`) и все пары (`vaultPairs`); журнал до
    ответа, ни одного UPDATE статусов.
  - `src/membership.js` — вступление по ссылке (`joinByInvite`, одно правило для ссылки и ввода имени; `'removed'` при
    запрете возврата), заявки (принять — только при открытой регистрации; `requestRejected`), семьи (заморозка состава
    при идущей жеребьёвке — кроме владельца), «Я участвую», возврат удалённых; `joinedNoticeStmts` — «… присоединяется».
  - `src/support.js` — обращения участника к организаторам (012): одно открытое на участника в эвенте (уникальный
    индекс), взять/ответить/передать/закрыть — по прежнему состоянию (020: `OPEN`, `LED_BY`, `LED_BY_OR_FREE`;
    уведомления и журнал — перед захватом, захват последним); ответ
    помечает прочитанными сообщения другой стороны; снятие прав админа возвращает его обращения в «ничьи»
    (`returnThreadsStmts`); счётчики для точек (`supportCountsQuery` + `supportCountsView`, `supportUnreadQuery` +
    `supportUnreadFrom`), список панели (`adminListQuery` + `adminListView`).
  - `src/outbox.js` — `flushOutbox` (захват строк `locked_until`, в пределах остатка бюджета запросов).
  - `src/format.js` — общие правила текста: `escapeHtml`, `displayName`, `shortTitle` (без разрыва эмодзи), даты,
    `adminRecipients`, кнопки приложения (`appKeyboard` — одна кнопка под сообщением), общие тексты (`NOT_REGISTERED`,
    `ADMIN_ONLY`, `NO_DRAW`, `PAIRS_RACE`; объединяются только побайтно одинаковые).
  - `src/budget.js` — счётчик внешних запросов на вызов (`metered`, `budgetLeft`, `reportBudget` → лог `budget exceeded`).
  - `src/telegram.js` — Bot API (с таймаутом и учётом в счётчике), проверка `initData`.
- `src/draw.js` — чистые функции жеребьёвки (тестируются в Node); поиск ограничен бюджетом шагов (`DEFAULT_BUDGET`,
  лимит CPU); `planDraw` — все попытки одной проверки (история, без истории, «мешают закреплённые пары», «мешают
  семьи») делят один бюджет; `pairRules(bans, fixed)` (014) — общее правило «кто кому может дарить» для жеребьёвки и
  замен: закреплённая пара важнее запретов; у правила есть `fillMatrix(ids, adj)` (017) — та же матрица допустимости
  по спискам запретов и закреплённых пар без `n²` вызовов (`findAssignment` берёт её, произвольная функция или обёртка —
  прежний перебор; правила передавать напрямую); `insertIntoAssignment(…, { rank })` — случайная связка внутри лучшей
  группы рангов (012).
- `src/cron.js` — шаги изолированы (`step`: уведомления → ежедневное → отправка очереди); уведомления об изменениях
  писем, автодействия расписания (`dueAutoAction`/`runAutoAction`) и напоминания — не больше одного тяжёлого действия за вызов.
- `migrations/` — схема D1 (сейчас 11): `0001_initial.sql` (схема 005), `0002_fixes.sql` (`users.blocked_at`,

## Жёсткие правила

1. **Тайна.** Никакой ответ API, кроме `ward.get` самому Санте и служебного просмотра владельца (`admin.vault.*`,
   `src/vault.js`), не содержит пар. Админ видит только статусы. Служебный просмотр (Конституция 2.0.0): только владелец,
   вход словом «ОТКРЫТЬ» в приложении, каждое открытие — журнал (`vault.person`/`vault.pairs`, без пар), статусы не
   меняются, админам сообщений нет; участникам честно сказано в README (с 011 — не в «Как это работает»; Конституция 2.1.0).
   Роли: владелец один (`settings.owner_id`, `resolveOwner`), только он назначает/снимает админов и переносит участие.
   **Владелец ⊇ админ (принцип VII).** Каждое `admin.*` доступно владельцу (e2e-автотест и тест прав берут список
   действий из таблицы `ACTIONS` в `src/api.js`; новое действие — строка таблицы с ролью, событием и «в завершённом»);
   ограничения «чтобы админ не вычислил пары» на владельца не действуют. Ссылка владельца одноразовая.
   Тексты уведомлений — без имени подопечного и без текста письма. Пользовательский текст — только через
   `textContent` / `escapeHtml`. Админ видит любой эвент (`event.get`), но `ward.get`/`chat.get` — только участникам.
   **Обращения (012, Конституция 2.2.0).** Переписку обращения видят автор; ничьё — все админы; взятое — только
   ответственный и владелец (остальным — кто, статус, ответственный, даты). Писать — ответственный (ничьё берётся
   ответом); владелец — после передачи себе. Список и журнал — без текстов. Вписывать после жеребьёвки и принудительно
   отменять её — только владелец (иначе админ вычислил бы пары по смене статусов).
   **Закреплённые пары (014, Конституция 2.3.0)** — `fixed_pairs`: видит и меняет только владелец (поле `fixed` в
   `admin.state` — только ему, `admin.fixed.*` — 403 админу), только до жеребьёвки; журнал `fixed.add/del` без имён;
   причина отказа жеребьёвки `fixed_block` — без имён, остальные причины считаются без закреплённых пар. `admin.ring`
   их не проверяет (отказ выдал бы админу их наличие). Уходят с человеком, переносятся с участием, сбрасываются со
   событием; образец их не копирует; снимок — в условии записи жеребьёвки (`SNAPSHOTS.fixed`, `src/snapshots.js`).
   **Эвенты.** Данные одного эвента не влияют на другой. Завершённый эвент (`status='finished'`) — только чтение,
   кроме переписки в течение `CHAT_GRACE_MS` (7 суток); завершение необратимо, сброс завершённого запрещён.
   Кольцевая (`events.ring`) — без взаимных пар, в т.ч. при заменах (`src/draw.js`).
   Перенос участия на аккаунт админа/владельца запрещён (иначе админ получил бы чужие пары).
   **Адрес доставки** (`members.delivery`) отдаётся только самому участнику (`event.get`) и его Санте (`ward.get`);
   админу — только `has_delivery`. Семьи (`familyExclusions`, `src/constraints.js`) учитываются везде, где строятся пары.
   **Без косвенных утечек (009).** После жеребьёвки админ не меняет исключения эвента, состав семьи — пока идёт эвент с
   жеребьёвкой, где есть двое её затронутых членов; вписывает после жеребьёвки только владелец (012); учтены ли прошлые
   пары, наружу не сообщается.
   **Набор (010).** Закрытая регистрация — никто не вступает: ни по ссылке, ни заявкой, ни по приглашению из эвента
   («Я участвую» админа — можно). При `events.rejoin = 0` удалённый организатором (`removed_members`) не возвращается
   по ссылке. Жеребьёвка записывается, только если участники, исключения, семьи и закреплённые пары не изменились
   (`drawSnapshot` / `snapshotGuard`, `src/snapshots.js`).
   **Одно действие — один результат (009).** Рассылки раскрытия/завершения/жеребьёвки и изменения пар — в одном batch
   с захватом (`UPDATE … WHERE` прежнее состояние) и остальными операторами по условию. С 020 такой пакет собирается
   только помощником `atomic` (`src/claim.js`); признак «захват мой» — не время и не автор (у двух нажатий одного
   человека в одну миллисекунду они совпадают): либо уникальное значение захвата, либо операторы перед захватом по
   прежнему состоянию. `enqueueIfStmt`/`auditIfStmt` напрямую — только вне атомарных действий (`chat.js`,
   `returnThreadsStmts`, `changeFixed`).
   **Данные события и человека (018).** Новая таблица или колонка с событием или человеком — сразу в `REGISTRY`
   (`src/db.js`; тест схемы падает, пока не описана). Каскады (удаление события, сброс, удаление участника, выход админа,
   перенос) — только построителями из списка, своих `DELETE`/`UPDATE … SET user_id` по таблицам событий и людей не писать.
   Условие у всех операторов, опора (событие / участник / старая запись) удаляется последней: выход админа — пока
   жеребьёвка не проведена, удаление участника — пока он участник, перенос — пока старая запись есть.
2. **Дизайн-система.** В `src/app.html` — только классы `ds-*`, без `style`, без сырых цветов и px. Базовые стили
   элементов в `components.css` — только через `:where()`. Новый элемент:
   токен → компонент в `components.css` → показ в `preview.html` → строка в `design-system/README.md`. Тест
   `tests/design-system.test.mjs` это проверяет.
3. **Слова (013).** В текстах для людей (бот, API, приложение, `/setup`, журнал) — «событие», никогда «эвент»; название
   в скобках или после запятой — без слова, после предлога — «событие» в нужном падеже, род средний
   (`specs/013-event-wording/research.md`, R1). Кнопки без «＋». Проверяет `tests/wording.test.mjs`. «Эвент» остаётся
   внутренним термином кода, комментариев и спецификаций.
4. **Лимит текста** — `MAX_CHARS = 4000` (`src/chat.js`): письмо, сообщения переписки и обращений помещаются в одно сообщение Telegram (4096).
5. **Бесплатный тариф.** ≤ 10 мс CPU и ≤ 50 внешних запросов (вкл. D1) на вызов. Сообщения другим людям — только
   через `outbox` (`enqueueStmt`); отправляет очередь только `index.js` в конце вызова и cron (`flushOutbox`
   сам не берёт больше остатка `budgetLeft`). Тяжёлые вычисления — на клиенте. e2e и `tests/queries.test.mjs` проверяют журнал на `budget exceeded`.
6. **Секреты** (`BOT_TOKEN`, `ADMIN_SECRET`) — только `wrangler secret put`; `.dev.vars`, `.env*` не коммитить.
7. **Файлы.** Проект живёт в `C:\ClaudeProjects\secret-santa-bot\`. В самой `C:\ClaudeProjects\` ничего не создавать.
8. **README.** Фича меняет установку, настройку, секреты, команды, роли или использование → правь `README.md` в той же
   ветке (отдельная задача в `tasks.md`). Владелец проекта ещё не выкатывал бота — README должен вести от нуля до работы.
