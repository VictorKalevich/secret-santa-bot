# CLAUDE.md — secret-santa-bot

Telegram-бот «Тайный Санта» для небольшой группы (все участники в Беларуси). Cloudflare Worker (бесплатный
тариф) + D1 + мини-приложение Telegram. Язык интерфейса и документации — русский.

## Обязательный процесс: Spec Kit

- Любое изменение поведения — через Spec Kit: `/speckit-specify` → (`/speckit-clarify`) → `/speckit-plan` →
  `/speckit-tasks` → `/speckit-implement`. Скилы лежат в `.claude/skills/speckit-*`.
- Спецификации — источник истины: `specs/NNN-имя/` — всегда spec.md, plan.md, tasks.md; research.md, data-model.md,
  contracts/, quickstart.md — по необходимости (у 013 нет `data-model.md`, у 015 — `research.md`, `data-model.md`,
  `contracts/`). Активная фича записана в `.specify/feature.json`.
- Конституция: `.specify/memory/constitution.md` — проверяй каждый план по всем принципам.
- Скрипты Spec Kit — PowerShell (`.specify/scripts/powershell/`), платформа разработчика — Windows.
- Код и спецификация не должны расходиться: поменял поведение — обнови spec/contracts в той же ветке.

## Боты: выкат, откат, копия, миграции

Один код — два бота, окружения Wrangler в `wrangler.toml` (`vars` и `d1_databases` не наследуются — дублируются в
`[env.second]`). Владелец называет бота словами из второго столбца. Не ясно, о каком боте речь, — спроси, сам не
выбирай. «Оба» — сначала второй, проверка, потом первый.

| Бот | Как называет владелец | Wrangler | Worker | База D1 | Аккаунт Cloudflare |
|---|---|---|---|---|---|
| @SantaFamilyBot | первый, основной, старый, семейный, SantaFamily | без `--env` (верх файла) | `secret-santa-bot` | `secret-santa-db` | `account_id` наверху |
| @PlaySecretSantaBot | второй, новый, Play | `--env second` | `secret-santa-bot-2` | `secret-santa-db-2` | `account_id` в `[env.second]` |

База, секреты, лимиты и история версий у ботов раздельные — команда для одного бота другого не трогает. Имя базы —
`database_name` в `wrangler.toml` (после восстановления из файла оно другое). Без `--env` Wrangler пишет «Multiple
environments are defined…» — для первого бота это нормально (в Bash-инструменте — `--env=""`). Команды ниже: `<env>` —
`--env second` или ничего, `<db>` — база бота; дата в имени файла — `$(Get-Date -Format yyyy-MM-dd-HHmm)` (PowerShell)
или `$(date +%Y-%m-%d-%H%M)` (Bash).

| Просьба | Что делать |
|---|---|
| «выкати …» | `npx wrangler deployments list <env>` — запомнить текущий Version ID (точка отката); `npx wrangler d1 migrations list <db> <env> --remote`; есть новые — копия базы и миграции (порядок «миграция ↔ выкат» — README «Обновление бота» и `quickstart.md` фичи); `npm run deploy` / `npm run deploy:second`; после — `/app` по адресу из вывода выката отвечает 200; назвать новый и прежний Version ID |
| «откати …» (код) | `npx wrangler rollback <Version ID> <env> -m "откат"` на прежнюю версию из `deployments list`; база не меняется. Без `-y`: на «The following secrets have changed since version …» — не соглашаться (вернулись бы старые `BOT_TOKEN`/`ADMIN_SECRET`), брать версию после последней смены секретов |
| «сделай копию базы …» | `npx wrangler d1 export <db> <env> --remote --output "backup-<db>-<дата>.sql"` в папке проекта (`*.sql` в git не попадает); в файле пары и письма — никуда не отправлять и не читать вслух |
| «миграция / примени миграции …» | `migrations list` → копия базы → `npx wrangler d1 migrations apply <db> <env> --remote` → `SELECT value FROM settings WHERE key = 'schema'` = `REQUIRED_SCHEMA`. Новая миграция в коде — в обе базы, каждой своей командой |
| «откати базу … на <время>» | Time Travel, ≤ 7 дней: `npx wrangler d1 time-travel info <db> <env> --timestamp="…+03:00"`, затем `restore` — только после явного «да» владельца (откатывается вся база бота); закладку «до» из ответа — владельцу. Старше 7 дней — README «Восстановить из файла» |
| «логи …» | `npx wrangler tail <env>` |

Секреты (`BOT_TOKEN`, `ADMIN_SECRET`) вводит только владелец в своём PowerShell (`npx wrangler secret put <ИМЯ> <env>`),
не в чат. `secret put` меняет последнюю версию Worker: если после выката заливалась версия без выката (`versions
upload`), сначала выкати бота заново. У второго бота `preview_urls = false`.

## Жёсткие правила

1. **Тайна.** Никакой ответ API, кроме `ward.get` самому Санте и служебного просмотра владельца (`admin.vault.*`,
   `src/vault.js`), не содержит пар. Админ видит только статусы. Служебный просмотр (Конституция 2.0.0, 3.0.0): только
   владелец компании в своей компании и владелец бота в любой,
   вход словом «ОТКРЫТЬ» (проверяют приложение и сервер — `confirm`, 025), каждое открытие — журнал (`vault.person`/`vault.pairs`, без пар), статусы не
   меняются, админам сообщений нет; участникам честно сказано в README (с 011 — не в «Как это работает»; Конституция 2.1.0).
   Роли (051): владелец бота один (`settings.owner_id`, `resolveOwner`); у компании — назначенный владелец
   (`companies.owner_id`) или 0 — её ведёт владелец бота. «Владелец» в правилах ниже — владелец компании события; он
   назначает/снимает админов своей компании. Переносит участие, создаёт и удаляет компании — только владелец бота.
   **Владелец бота ⊇ владелец компании ⊇ админ (принцип VII).** Каждое `admin.*` доступно владельцу (e2e-автотест и тест прав берут список
   действий из таблицы `ACTIONS` в `src/api.js`; новое действие — строка таблицы с ролью, событием и «в завершённом» и раздел в `docs/api.md`);
   ограничения «чтобы админ не вычислил пары» на владельца не действуют. Ссылка владельца одноразовая.
   Тексты уведомлений — без имени подопечного и без текста письма. Пользовательский текст — только через
   `textContent` / `escapeHtml`. Админ видит любой эвент (`event.get`), но `ward.get`/`chat.get` — только участникам.
   **Обращения (012, Конституция 2.2.0).** Переписку обращения видят автор; ничьё — все админы; взятое — только
   ответственный и владелец (остальным — кто, статус, ответственный, даты). Писать — ответственный (ничьё берётся
   ответом); владелец — после передачи себе. Список и журнал — без текстов. Вписывать после жеребьёвки, менять подопечных
   (048, без показа пар) и принудительно отменять её — только владелец (иначе админ вычислил бы пары по смене статусов).
   **Закреплённые пары (014, Конституция 2.3.0)** — `fixed_pairs`: видит и меняет только владелец (поле `fixed` в
   `admin.state` — только ему, `admin.fixed.*` — 403 админу), только до жеребьёвки; журнал `fixed.add/del` без имён;
   причина отказа жеребьёвки `fixed_block` — без имён, остальные причины считаются без закреплённых пар. `admin.ring`
   их не проверяет (отказ выдал бы админу их наличие). Уходят с человеком, переносятся с участием, сбрасываются со
   событием; образец их не копирует; снимок — в условии записи жеребьёвки (`SNAPSHOTS.fixed`, `src/snapshots.js`).
   **Эвенты.** Данные одного эвента не влияют на другой. Завершённый эвент (`status='finished'`) — только чтение,
   кроме переписки в течение `CHAT_GRACE_MS` (7 суток); завершение необратимо, сброс завершённого запрещён.
   Кольцевая (`events.ring`) — без взаимных пар, в т.ч. при заменах (`src/draw.js`).
   Перенос участия на аккаунт админа/владельца запрещён (иначе админ получил бы чужие пары).
   **Адрес доставки** (`members.delivery`) отдаётся только самому участнику (`event.get`) и его Санте (`ward.get`);
   админу — только `has_delivery`. Семьи (`familyExclusions`, `src/constraints.js`) учитываются везде, где строятся пары.
   **Без косвенных утечек (009).** После жеребьёвки админ не меняет исключения эвента, состав семьи — пока идёт эвент с
   жеребьёвкой, где есть двое её затронутых членов; вписывает после жеребьёвки только владелец (012); учтены ли прошлые
   пары, наружу не сообщается.
   **Набор (010).** Закрытая регистрация — никто не вступает: ни по ссылке, ни заявкой, ни по приглашению из эвента
   («Я участвую» админа — можно). При `events.rejoin = 0` удалённый организатором (`removed_members`) не возвращается
   по ссылке. Жеребьёвка записывается, только если участники, исключения, семьи и закреплённые пары не изменились
   (`drawSnapshot` / `snapshotGuard`, `src/snapshots.js`).
   **Одно действие — один результат (009).** Рассылки раскрытия/завершения/жеребьёвки и изменения пар — в одном batch
   с захватом (`UPDATE … WHERE` прежнее состояние) и остальными операторами по условию. С 020 такой пакет собирается
   только помощником `atomic` (`src/claim.js`); признак «захват мой» — не время и не автор (у двух нажатий одного
   человека в одну миллисекунду они совпадают): либо уникальное значение захвата, либо операторы перед захватом по
   прежнему состоянию. `enqueueIfStmt`/`auditIfStmt` напрямую — только вне атомарных действий (`chat.js`,
   `returnThreadsStmts` — условие передаёт вызывающий); закреплённые пары (`changeFixed`) с 023 — тоже через `atomic`,
   с 031 — с условием «сторона свободна» в пакете: ответ «успех» — только если закрепление сохранено.
   С 024 — и повторные вызовы: рассылки по желанию (объявление с тем же текстом, ручные напоминания, приглашение из
   события) — в событии не чаще раза в минуту (`REPEAT_MS`, `src/events.js`; опора — объявление или запись журнала,
   последней), назначение/снятие админа и передача владения — по прежнему состоянию, полный сброс — захват новым кодом
   приглашения; второй вызов — отказ. Кнопки приложения на время запроса недоступны (`busy` — с кнопкой или списком).
   **Данные события и человека (018).** Новая таблица или колонка с событием или человеком — сразу в `REGISTRY`
   (`src/db.js`; тест схемы падает, пока не описана). Каскады (удаление события, сброс, удаление участника, выход админа,
   перенос) — только построителями из списка, своих `DELETE`/`UPDATE … SET user_id` по таблицам событий и людей не писать.
   Условие у всех операторов, опора (событие / участник / старая запись) удаляется последней: выход админа — пока
   жеребьёвка не проведена, удаление участника — пока он участник, перенос — пока старая запись есть.
2. **Дизайн-система.** В частях приложения (`src/app/`) — только классы `ds-*`, без `style`, без сырых цветов и px
   (проверяется склейка целиком). Базовые стили
   элементов в `components.css` — только через `:where()`. Новый элемент:
   токен → компонент в `components.css` → показ в `preview.html` → строка в `design-system/README.md`. Тест
   `tests/design-system.test.mjs` это проверяет. Открытки (038) — фиксированные цвета, одинаковые в обеих темах; набор
   `POSTCARDS` = темы в дизайн-системе, контраст текста ≥ 4.5 (тест `looks`). **У каждой шторки — драгер (033):** шторку открывает только `openSheet`,
   он и ставит полосу (`sheetHandle`) — своя разметка шторки, свой или второй драгер, шторка без полосы в витрине —
   нарушение (тот же тест).
3. **Слова (013).** В текстах для людей (бот, API, приложение, `/setup`, журнал) — «событие», никогда «эвент»; название
   в скобках или после запятой — без слова, после предлога — «событие» в нужном падеже, род средний
   (`specs/013-event-wording/research.md`, R1). Кнопки без «＋». Проверяет `tests/wording.test.mjs`. «Эвент» остаётся
   внутренним термином кода, комментариев и спецификаций. То же с «комнатой» (059): в текстах для людей — «комната» в
   нужном падеже, никогда «компания» (сообщения `new Error(…)` — для разработчика, не в счёт); «компания» — внутренний
   термин кода, API, журнала, базы и спецификаций; список текстов — `specs/059-room-wording/contracts/texts.md`.
4. **Лимит текста** — `MAX_CHARS = 4000` (`src/chat.js`): письмо, сообщения переписки и обращений помещаются в одно сообщение Telegram (4096).
5. **Бесплатный тариф.** ≤ 10 мс CPU и ≤ 50 внешних запросов (вкл. D1) на вызов. Сообщения другим людям — только

   сам не берёт больше остатка `budgetLeft`). Тяжёлые вычисления — на клиенте. e2e и `tests/queries.test.mjs` проверяют журнал на `budget exceeded`.
6. **Секреты** (`BOT_TOKEN`, `ADMIN_SECRET`) — только `wrangler secret put`; `.dev.vars`, `.env*` не коммитить.
7. **Файлы.** Проект живёт в `C:\ClaudeProjects\secret-santa-bot\`. В самой `C:\ClaudeProjects\` ничего не создавать.
8. **README.** Фича меняет установку, настройку, секреты, команды, роли или использование → правь `README.md` в той же

9. **Компании (050).** Событие, семья и запись журнала принадлежат компании; права администратора — строка
   `company_members` компании. Модули работают только с привязанным контекстом (`ctx.in(ev.company_id)` или контекст
   общего действия из конвейера); права читаются из него (`ctx.me.is_admin`, `u.is_admin` из `ctx.users()`,
   `ctx.isOwner()`), общий признак `users.is_admin` — только первая проверка конвейера `admin.*`, меню бота, приветствие
   после регистрации и запрет цели переноса (тест `companies` ищет чтения `is_admin` в SQL). Чужое событие для
   организатора другой компании — как несуществующее (404 «Событие не найдено.»), чужая семья — «Семья не найдена.»,
   образец — «Образец не найден.». Новое общее `admin.*` без события — `company: true` в `ACTIONS` (тест `api-table`).
   Новая таблица с компанией — ключ `company` в `REGISTRY`; запись журнала — сфера «событие» или `{ company: id }`,
   ноль — ошибка. Права меняются по прежнему состоянию строки компании, затем `adminFlagStmt` (общий признак = «админ
   где-нибудь или владелец бота», инвариант I4). Человек входит в компанию (`joinCompanyStmt`) в том же пакете, где бот
   его принимает; строка не удаляется при выходе и удалении.
10. **Компании (051).** Названия компаний личные: `companies.name` видит только владелец бота, `company_members.label` —
   только сам человек; ни одно из них и ссылка владельца компании (`own_<код>`) не попадают в ответы и сообщения другим
   людям (тест `companies-manage` перебирает все ответы и сообщения сценария). Новые меняющие действия с компаниями —
   только через `atomic`. Тексты «кто может действие владельца» — через `ownerWord` (сервер — `ctx.ownerWord()`,
   приложение — `ownerWord()`); литерал «владелец бота» — только где речь всегда о владельце бота (список — тест
   `wording`). Слово «комната» (059; прежде «компания») видят только владелец бота и люди с двумя и больше видимыми
   компаниями (часть
   `04-companies` и перечисленные места — тест `app-companies`); человек с одной компанией видит прежние экраны. Общие
   действия организатора в приложении — только `capi` (поле `company` — компания открытого экрана), права в компании
   (`state.me.is_admin`, `is_owner`) пишет только `enterCompany`.
   **Открытый бот (052, Конституция 3.1.0).** Признак — только `openBot(env)`. Исключение из личных названий: у компании с
   `shared = 1` (создал человек открытого бота) `companies.name` видят люди этой компании (видимость 051) и владелец бота,
   больше никто (тест `open-bot`). Своих компаний во владении у человека — не больше `OWN_MAX` (условие в пакете записи;
   передача и ссылка лимит не проверяют), у владельца бота лимита нет. «‹» и корневой экран — только `withList()` и
   `listFirst()` (тест `app-companies`); в открытом боте экран «Компании» есть у всех.
11. **Тексты для людей — только в словаре (060).** В коде (`src/*.js`, `src/app/`) нет ни одной буквы кириллицы вне
   комментариев, `new Error(…)` и `console.*(…)` (тест `i18n`). Новый текст — строка в словаре своей области

   набор форм с `{n}`; ключи таблиц (`ACTIONS.finished`, `confirm`, `EVENT_PARAMS.beforeDraw`) — строки-ключи; семейство
   (`looks.card.<id>`, `pairs.reason.<тип>`…) — склейкой с префиксом-литералом `t('looks.card.' + id)`. Проверка во время
   правки — `node tests/support/i18n-check.mjs <файлы>`; тест `i18n` требует, чтобы ключи вызовов были в словаре, а ключи
   словаря использовались.
