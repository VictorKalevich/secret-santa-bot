# 🎅 Тайный Санта — Telegram-бот

Бот для игры в Тайного Санту с друзьями, семьёй или коллегами. Работает на телефонах (iOS, Android) и компьютерах через Telegram, ничего
устанавливать не нужно.

- вход без паролей; бот **закрытый** (по умолчанию: регистрация только по пригласительной ссылке, события создают
  владелец бота и те, кому он разрешил) или **открытый** (настройка `OPEN_BOT`: любой может назвать себя и создать своё
  событие) — см. [«Открытый бот»](#открытый-бот);
- **события**: несколько игр параллельно для разных групп людей, у каждой своя ссылка, письма и жеребьёвка;
  прошлые события остаются в истории — на следующий год можно открыть свои старые записи;
- **у каждого события свой владелец** — тот, кто его создал, — и свои администраторы: их назначает владелец из
  участников события. Администратор одного события не видит другие, если сам в них не участвует. Создать можно не больше 10 событий за
  12 месяцев (у владельца бота ограничения нет);
- письмо Санте до 4000 символов (столько помещается в одно сообщение Telegram) — менять можно до завершения события;
- исключения «кто кому не может достаться» и жеребьёвка одной кнопкой; **кольцевая жеребьёвка** (по умолчанию):
  если A дарит Б, то Б не дарит A;
- **закреплённые пары**: владелец может заранее решить, кто кому дарит (при кольцевой — только в одну сторону);
  админы их не видят;
- Санта в любой момент видит письмо подопечного (изменения подсвечены) и получает уведомление, когда тот его правит;
- только владелец события (а владелец бота — в любом событии) может открыть пары в служебном просмотре, если что-то
  пошло не так, — и каждое открытие записывается в журнал;
- переписка Санты и подопечного прямо в приложении (Санта остаётся анонимным) с уведомлениями в Telegram;
- напоминания о письме, раскрытие Сант после праздника, автозавершение события на 3-й день после вручения;
- вступление по заявке с одобрением владельца или администратора;
- **обращение по событию** прямо из приложения: его видят владелец и администраторы, первый откликнувшийся берёт его себе;
- для владельца и администраторов: объявления всем участникам, расписание (автожеребьёвка, авто-раскрытие, автозавершение),
  событие по образцу прошлого, отмена жеребьёвки (до первых просмотров — владельцем или администратором, позже — владельцем), журнал действий.

Хостинг — бесплатный тариф Cloudflare (без банковской карты). Требования и решения — в [`specs/`](specs/)
(начало — [`001`](specs/001-secret-santa-bot/spec.md), события и история — [`005`](specs/005-events-history/spec.md)).

## Установка и настройка

≈ 20 минут, Windows. Все команды выполняются в **PowerShell**. Что понадобится: компьютер с Windows, аккаунт Telegram
и почта для регистрации в Cloudflare. Платить ни за что не нужно.

Коротко, что предстоит (подробности — в шагах ниже):

| Шаг | Что делаем | Результат |
|---|---|---|
| 1 | ставим Node.js и Git | работают `node -v` и `git --version` |
| 2 | создаём бота у @BotFather | токен бота |
| 3 | регистрируемся в Cloudflare | аккаунт |
| 4 | скачиваем проект, `npm install`, `npx wrangler login` | папка проекта, вход в Cloudflare |
| 5 | создаём базу D1 и применяем миграции | `database_id` в `wrangler.toml`, таблицы созданы |
| 6 | `npm run deploy` | адрес `https://secret-santa-bot.<поддомен>.workers.dev` |
| 7 | задаём секреты `BOT_TOKEN` и `ADMIN_SECRET` | бот может говорить с Telegram |
| 8 | открываем `/setup` | webhook, меню и ссылка владельца |
| 9 | переходим по ссылке владельца, создаём событие | можно приглашать людей |

### 1. Установите Node.js и Git

- **Node.js** — скачайте LTS-версию с [nodejs.org](https://nodejs.org) и установите. Проверка: `node -v` (нужна 22.15 или новее; текущая LTS подходит).
- **Git** — скачайте с [git-scm.com](https://git-scm.com/download/win) и установите с настройками по умолчанию.
  Проверка: `git --version`.

После установки закройте и снова откройте PowerShell.

Разрешите PowerShell запускать `npm` и `npx` (один раз, права администратора не нужны):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

На вопрос ответьте `Y`. Без этого `npm install` падает с ошибкой «Невозможно загрузить файл …\npm.ps1, так как
выполнение сценариев отключено в этой системе». Другой путь — писать `npm.cmd` и `npx.cmd` вместо `npm` и `npx`
во всех командах ниже.

### 2. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте название (например, «Тайный Санта 2026») и имя пользователя, оканчивающееся на `bot`.
3. BotFather пришлёт **токен** вида `1234567890:AA…`. Никому его не показывайте.

### 3. Создайте аккаунт Cloudflare

Зарегистрируйтесь на [dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) (нужна только почта)
и подтвердите адрес.

### 4. Скачайте проект, установите зависимости и войдите в Cloudflare

```powershell
git clone https://github.com/VictorKalevich/secret-santa-bot.git C:\ClaudeProjects\secret-santa-bot
cd C:\ClaudeProjects\secret-santa-bot
npm install
npx wrangler login
```

Папку можно выбрать любую — тогда во всех командах ниже подставляйте свой путь. Если проект уже лежит на компьютере,
`git clone` пропустите и просто перейдите в его папку. Все дальнейшие команды выполняются **в папке проекта**.

После `npx wrangler login` откроется браузер — нажмите «Allow».

### 5. Создайте базу данных

```powershell
npx wrangler d1 create secret-santa-db
```

Если Wrangler предложит сам добавить настройки в конфигурацию — откажитесь и сделайте вручную:
скопируйте из ответа значение `database_id` и вставьте его в `wrangler.toml` в строку `database_id = "…"` вместо
того, что там стоит (в репозитории — id базы автора проекта, в вашем аккаунте Cloudflare её нет).
Потеряли значение — `npx wrangler d1 list` покажет его снова. `database_id` — не секрет, но это настройка именно вашей
установки. Так же и строка `account_id = "…"` в начале `wrangler.toml`: впишите id своего аккаунта (его показывает
`npx wrangler whoami`) или удалите строку.

Создайте таблицы — примените миграции (папка `migrations/`):

```powershell
npx wrangler d1 migrations apply secret-santa-db --remote
```

Wrangler покажет список миграций и спросит подтверждение — ответьте `y`. Бот сам таблицы не создаёт: без этого шага
он отвечает «База не подготовлена».

### 6. Опубликуйте бота

```powershell
npm run deploy
```

При первом запуске Cloudflare попросит выбрать имя поддомена `workers.dev` — введите любое. В конце появится адрес
вида `https://secret-santa-bot.<ваш-поддомен>.workers.dev` — запишите его.

### 7. Добавьте секреты

```powershell
npx wrangler secret put BOT_TOKEN
npx wrangler secret put ADMIN_SECRET
```

На первый вопрос вставьте токен от BotFather, на второй — придумайте пароль администратора (лучше 16+ символов,
латиница и цифры; короче 8 символов бот не примет). Он нужен только для страницы настройки — это ключ к правам
владельца, храните его как пароль. Секреты хранятся в Cloudflare, в файлы проекта и в git они не попадают; заново
публиковать бота после `secret put` не нужно.

Проверка: откройте адрес из шага 6 в браузере — должно быть «🎄 Бот Тайного Санты работает.» Если видите «Не задан
секрет BOT_TOKEN» — повторите команду с `BOT_TOKEN`; «База не подготовлена» — вернитесь к миграциям из шага 5.

### 8. Настройте бота

Откройте в браузере:

```
https://secret-santa-bot.<ваш-поддомен>.workers.dev/setup
```

**Что вы увидите сначала.** Страница «🎄 Настройка бота» с одним полем — «Ключ настройки (значение секрета
ADMIN_SECRET)» — и кнопкой «Настроить бота». Пока ключ не введён, страница ничего не настраивает и ничего не показывает.

Введите в поле тот пароль, который задали на шаге 7 командой `npx wrangler secret put ADMIN_SECRET`, и нажмите
«Настроить бота». Ключ вводится только в форму: в адресе страницы его нет, в историю браузера он не попадёт.

**Что будет после ввода ключа:**

- ключ верный — страница «✅ Бот настроен» со списком проверок: «Токен бота» (с именем вашего бота), «Webhook»,
  «Команды», «Кнопка приложения». Все пункты должны быть с ✔. Ниже — **ссылка владельца**;
- ключ неверный — «Неверный ключ» и та же форма: проверьте пароль и введите ещё раз. Забыли пароль — задайте новый
  (`npx wrangler secret put ADMIN_SECRET`) и откройте `/setup` снова;
- «Нужен ADMIN_SECRET» вместо формы — секрет не задан или короче 8 символов: вернитесь к шагу 7.

Ссылку владельца откройте в своём Telegram и **никому не пересылайте**. Пригласительных ссылок на этой странице нет:
у каждого события своя, она появляется в приложении.

**Ссылка владельца срабатывает один раз.** Пока по ней не перешли, страницу можно открывать снова (например, если
закрыли вкладку). После перехода страница блокируется: не настраивает бота и не показывает ссылку, пока вы не смените
`ADMIN_SECRET`. Нужна новая ссылка (утекла старая, потерян доступ к Telegram) — смените секрет:

```powershell
npx wrangler secret put ADMIN_SECRET
```

откройте `/setup` снова, введите новый ключ и перейдите по новой ссылке. Старая ссылка перестанет работать.

### 9. Создайте событие и начинайте игру

1. Перейдите по ссылке владельца и нажмите «✅ Продолжить как …» — бот возьмёт имя из Telegram. Хотите другое — «✏️ Изменить
   имя» или просто напишите его боту.
2. Нажмите «🎁 Санта» (кнопка у поля ввода) → внизу экрана «🎄 Создать событие» → название, например «Новый год
   2026 — семья» → «Создать». Галочка «Я тоже участвую» включена: если вы только ведёте событие, а сами не играете,
   снимите её.
3. Откроется вкладка «Управление» нового события — вы его владелец. Заполните бюджет, даты и место (раздел «Параметры»).
4. Отправьте пригласительную ссылку события в общий чат (кнопка «📤 Отправить в чат»).
5. Когда все зарегистрируются — добавьте исключения и нажмите «🎲 Провести жеребьёвку». Нужны помощники — назначьте их
   из участников: «Управление» → «Владелец и администраторы».
6. Раскрыть Сант (по желанию) — галочка «Раскрыть Сант на следующий день после вручения» в «Параметрах»: бот сам
   напишет каждому, кто был его Сантой. Событие с датой вручения бот завершит сам на 3-й день после неё (см. «События и
   история»).

Бот по умолчанию закрытый: кроме вас, события никто не создаёт. Разрешить кому-то заводить свои события — «⚙️
Настройки» → «✍️ Кто может создавать события» (см. [«Создание событий и права»](#создание-событий-и-права)).

Перед настоящей игрой стоит сделать тестовый прогон: создайте отдельное событие, пройдите его с парой друзей и удалите
(«Опасная зона» → «🗑 Удалить событие»).

## Настройки бота

Несекретные настройки лежат в `wrangler.toml`, раздел `[vars]`. Поменяли значение — выполните `npm run deploy`.

| Настройка | По умолчанию | Что значит |
|---|---|---|
| `TIMEZONE_OFFSET_HOURS` | `3` (Минск, UTC+3) | часовой пояс: по нему считаются даты события, час напоминаний и время в сообщениях |
| `REMINDER_HOUR` | `10` | с какого часа по местному времени бот шлёт ежедневные напоминания и выполняет расписание событий |
| `NOTIFY_DELAY_MINUTES` | `10` | сколько минут после последней правки письма бот ждёт, прежде чем сообщить Санте (чтобы не слать сообщение на каждую правку) |
| `OPEN_BOT` | не задано (бот закрытый); у второго бота — `"1"` | `"1"` — [открытый бот](#открытый-бот): человек без ссылки регистрируется, назвав имя, и любой может создать своё событие. Убрать строку и выкатить заново — бот снова закрытый: созданные события остаются у своих владельцев, а новые создают только владелец бота и те, кому он разрешил |

Секреты задаются только командой `npx wrangler secret put <ИМЯ>` — в `wrangler.toml` их писать нельзя:

| Секрет | Что это | Когда менять |
|---|---|---|
| `BOT_TOKEN` | токен бота от @BotFather | если токен утёк: `/revoke` у @BotFather, новый токен → `secret put BOT_TOKEN` → снова открыть `/setup` (до этого бот не отвечает) и перейти по новой ссылке владельца — прежняя перестаёт работать |
| `ADMIN_SECRET` | пароль для страницы `/setup` (от 8 символов) | когда нужна новая ссылка владельца или старый пароль мог кто-то узнать |

Остальное (бюджет, даты, место, регистрация, расписание) настраивается в приложении отдельно
для каждого события — вкладка «Управление».

Имя и аватар бота меняются у @BotFather (`/mybots`); команды (`/start`, `/language`, `/cancel`), кнопку «🎁 Санта» и
описание бот выставляет сам — на каждом своём языке (061). Начинает при настройке на странице `/setup`, а что не
поместилось в один запрос (всего 60 вызовов Telegram), досылает понемногу после обычных обращений людей к боту. Тексты
профиля поменялись в новой версии — бот сам отправит их заново, открывать `/setup` не нужно.

### Второй бот на отдельном аккаунте Cloudflare

Тот же код можно запустить вторым ботом: другое имя в Telegram, свои люди и события, свой владелец. Код один — папка и
git те же, а у второго бота свой Worker, своя база и свои секреты в окружении `second` (`wrangler.toml`, раздел
`[env.second]`). Если он живёт на отдельном аккаунте Cloudflare, бесплатные лимиты (запросы, база, cron) у него свои,
они считаются на аккаунт. Бот сам узнаёт своё имя и адрес на странице `/setup`, поэтому в коде менять ничего не надо.
Нужна просто ещё одна группа людей в том же боте — это ещё одно событие со своим владельцем и администраторами
([«Создание событий и права»](#создание-событий-и-права)), второй бот для этого не нужен.

**Один раз:**

1. У @BotFather — `/newbot`, запишите токен второго бота.
2. Зарегистрируйте второй аккаунт Cloudflare на другую почту и подтвердите адрес. В нём откройте **Workers & Pages** и,
   если попросит, выберите поддомен `workers.dev` (любой свободный).
3. Во втором аккаунте: **Manage Account → Members → Invite** — пригласите почту основного аккаунта с ролью
   **Super Administrator**, примите приглашение из письма. Теперь один вход Wrangler видит оба аккаунта:
   `npx wrangler whoami` покажет два Account ID (если второго нет — `npx wrangler login` ещё раз).
4. Впишите Account ID второго аккаунта в `[env.second]` → `account_id`. У первого бота `account_id` наверху файла
   должен быть заполнен — иначе Wrangler, видя два аккаунта, спросит, куда выкатывать.
5. База, таблицы, выкат — во втором аккаунте (это делает `--env second`):

   ```powershell
   npx wrangler d1 create secret-santa-db-2 --env second
   # database_id из ответа → [[env.second.d1_databases]] в wrangler.toml
   npx wrangler d1 migrations apply secret-santa-db-2 --env second --remote
   npm run deploy:second
   ```

6. Секреты второго бота — свои, пароль `ADMIN_SECRET` — не такой, как у первого:

   ```powershell
   npx wrangler secret put BOT_TOKEN --env second
   npx wrangler secret put ADMIN_SECRET --env second
   ```

7. Откройте `https://secret-santa-bot-2.<поддомен второго аккаунта>.workers.dev/setup`, введите `ADMIN_SECRET` второго
   бота и перейдите по ссылке владельца в Telegram — дальше как в шагах 8–9 выше.

**Дальше** каждая команда из этого README для второго бота — с `--env second` и базой `secret-santa-db-2` вместо
`secret-santa-db`: `npm run deploy:second` вместо `npm run deploy`, копия базы, миграции, `deployments list`,
`rollback`, `secret put` (шпаргалка — [ниже](#команды-для-каждого-бота)). Команды без `--env` относятся к первому
боту; Wrangler при этом пишет «Multiple environments are defined…» — это предупреждение, для первого бота так и должно
быть. Настройки `[vars]` у второго бота свои (`[env.second.vars]`): поменяли наверху — поменяйте и там. Второй бот
**открытый** — у него в `[env.second.vars]` есть `OPEN_BOT = "1"` (у первого этой строки нет); сделать его закрытым —
удалить строку и выполнить `npm run deploy:second`.

### Команды для каждого бота

У каждого бота свой Worker, своя база, свои секреты и своя история версий: команда для одного бота другого не трогает.

| | Первый бот | Второй бот |
|---|---|---|
| Окружение Wrangler | без `--env` (верх `wrangler.toml`) | `--env second` (`[env.second]`) |
| Worker | `secret-santa-bot` | `secret-santa-bot-2` |
| База D1 | `secret-santa-db` | `secret-santa-db-2` |
| Выкат | `npm run deploy` | `npm run deploy:second` |

Первый бот:

```powershell
npm run deploy                                               # выкатить код
npx wrangler deployments list                                # версии: запишите Version ID текущей — точка отката
npx wrangler rollback <Version ID> -m "откат"                # откатить код (база не меняется)
npx wrangler d1 migrations list secret-santa-db --remote     # есть ли новые миграции
npx wrangler d1 migrations apply secret-santa-db --remote    # применить их (перед этим — копия базы)
npx wrangler d1 export secret-santa-db --remote --output "backup-secret-santa-db-$(Get-Date -Format yyyy-MM-dd-HHmm).sql"
npx wrangler d1 time-travel restore secret-santa-db --timestamp="2026-12-20T18:00:00+03:00"   # вся база — на момент
npx wrangler tail                                            # логи в реальном времени
```

Второй бот:

```powershell
npm run deploy:second
npx wrangler deployments list --env second
npx wrangler rollback <Version ID> --env second -m "откат"
npx wrangler d1 migrations list secret-santa-db-2 --env second --remote
npx wrangler d1 migrations apply secret-santa-db-2 --env second --remote
npx wrangler d1 export secret-santa-db-2 --env second --remote --output "backup-secret-santa-db-2-$(Get-Date -Format yyyy-MM-dd-HHmm).sql"
npx wrangler d1 time-travel restore secret-santa-db-2 --env second --timestamp="2026-12-20T18:00:00+03:00"
npx wrangler tail --env second
```

- **Миграции** применяются к каждой базе отдельно. Новый код без своей миграции пишет «База не подготовлена» — порядок
  «миграция ↔ выкат» для конкретного обновления описан в [«Обновлении бота»](#обновление-бота).
- **Обновить оба бота:** сначала второй, проверить его в Telegram, затем первый.
- **Откат кода** базу не меняет. Если Wrangler при откате пишет «The following secrets have changed since version …»,
  ответьте `n`: у той версии прежние секреты, и бот вернулся бы к старому токену или паролю. Выберите версию, выкаченную
  после последней смены секретов.
- **Откат базы** (`time-travel restore`) возвращает всю базу одного бота — всё, что сделано после того момента, пропадёт;
  база другого бота не меняется. Сначала прочитайте [«Резервную копию и восстановление»](#резервная-копия-и-восстановление).

## Как играть

**Вступление.** Участник переходит по пригласительной ссылке события и нажимает «Запустить». Бот предложит имя из
Telegram: «✅ Участвовать как Анна» — одно нажатие, и человек в событии (если включено вступление по одобрению — его
заявка уходит владельцу и администраторам). «✏️ Изменить имя» — написать другое имя одним сообщением, до 40 символов;
его можно прислать и без кнопки. Имя видят Санта, владелец и администраторы; сменить его потом — в приложении,
«⚙️ Настройки» → «Профиль». В [открытом боте](#открытый-бот) можно и без ссылки: «Запустить» → имя → в приложении
«🎄 Создать событие» (или попросить у знакомых пригласительную ссылку на событие).

**Черновики писем** включаются для отдельного события. Во вкладке «Управление» → «Параметры» отметьте «Черновики писем» и нажмите
«Сохранить». На вкладке «Письмо» участник видит статус и продолжает писать с места остановки. Санта увидит текст после
нажатия «Опубликовать письмо» или «Опубликовать изменения». Прежнюю публикацию можно посмотреть из редактора.
Черновик сохраняется сам: пока участник печатает — не чаще раза в 5 секунд, а если он свернёт приложение или уйдёт на
другую вкладку — сразу, без вопроса «Уйти без сохранения?». Если снять флажок, снова откроется обычный редактор с кнопкой «Сохранить». При повторном включении автор сможет
вернуться к своему черновику. По умолчанию настройка выключена.

Приложение открывается кнопкой «🎁 Санта». Главный экран — **«Мои события»**: события, где вы участник, администратор
или владелец. Сверху — «Идут» (ближайшая дата вручения первой, без даты — в конце), ниже свёрнутая строка «Завершённые ·
N» — нажмите, чтобы раскрыть. В строке события — название, ваша роль («👑 владелец», «🛠 администратор»; у участника
метки нет), дата вручения, «ты не участвуешь», если вы ведёте событие без участия, и число непрочитанных сообщений.
Внизу экрана, не уезжая при прокрутке, — «🎄 Создать событие» (у тех, кто может создавать события). ⚙️ в шапке —
[«Настройки»](#настройки). Кнопка под сообщением бота открывает сразу нужное событие; «‹» в шапке события ведёт к списку.
Внутри события — вкладки:

| Кто | Что делает |
|---|---|
| Участник | «Письмо» — пишет и правит письмо (до 4000 символов) и выбирает для него открытку, кнопка «💬 Написать Санте»; «Подопечный» — кому дарит, его письмо, кнопка «💬 Написать подопечному»; «Инфо» — бюджет, даты, место, владелец и администраторы, список участников с @username (до жеребьёвки — сколько написали письма), «📨 Пригласить друга», объявления, «💬 Задать вопрос», внизу — выход из события |
| Владелец и администраторы события | «Управление» — ссылка-приглашение, «Я участвую», объявление, участники и их статусы (действия с участником — кнопка «⋯»), исключения, кольцевая жеребьёвка, жеребьёвка и её отмена, напоминание о письме, параметры и расписание (в том числе раскрытие Сант), обращения участников, журнал, «Владелец и администраторы»; у владельца — назначение и снятие администраторов, передача владения, закреплённые пары, вписывание в жеребьёвку после неё, обмен подопечных, служебный просмотр, принудительная отмена жеребьёвки, удаление события |

Владелец и администраторы могут открыть чужое письмо через «⋯» → «👁 Открыть письмо» с подтверждением, и это записывается в
журнал действий. Пар «кто кому дарит» админы не видят вообще — ни в текущих событиях, ни в истории. Исключение — владелец
события и владелец бота (см. «Служебный просмотр владельца»); владелец события — тот, кто его создал, или тот, кому он
передал владение. В приложении об этом не пишется — если хотите, чтобы участники знали,
расскажите им сами (например, в объявлении события).

Если владелец или администратор сам участвует в событии, оно открывается на вкладке «Письмо» (а не «Подопечный»): пока ни один Санта не
открыл подопечного, жеребьёвку ещё можно отменить.

Окна, которые выезжают снизу (журнал, переписка, меню участника, календарь и другие), закрываются крестиком, кнопкой
«Назад» Telegram или свайпом вниз за полоску сверху окна; короткий свайп возвращает окно на место. Если в переписке
набран и не отправлен текст, приложение сначала спросит, закрывать ли. Пока такое окно открыто, свайп вниз не сворачивает
всё приложение.

Открытая переписка и обращения обновляются сами — раз в несколько секунд, пока приложение на экране; свёрнутое приложение
сервер не опрашивает и при возвращении сразу обновляет окно. Во втором (открытом) боте, если долго нет новых сообщений,
окно обновляется всё реже, а через 5 минут тишины перестаёт — до касания окна, своего сообщения или возвращения в
приложение. О новом сообщении бот всё равно пишет в Telegram.

### Кто ещё играет

- **Участники** — вкладка «Инфо» → раздел «Участники» сразу под «О событии»: все, кто вступил и подтвердил имя, по алфавиту,
  по строке на человека — имя и @username (если он есть в Telegram); своя строка — с «(ты)», метки ролей в этом событии —
  «👑 владелец» и «🛠 администратор». Список виден целиком. Видят участники, владелец и администраторы. Строки не
  нажимаются: написать человеку можно в Telegram по его @username. Учтите: Санта, который напишет подопечному сам, а не
  через «💬 Написать подопечному», раскроет себя.
- **Общий прогресс** над списком — без имён и только до жеребьёвки: «✉️ Письма написали X из N». Кто именно написал
  письмо, участникам не видно.
- **«О событии»** показывает отдельные строки «Владелец» и «Администраторы» и, пока жеребьёвки нет,
  «Автожеребьёвка»: дату или «не установлена».
- **«📨 Пригласить друга»** — под списком, пока регистрация открыта и событие идёт: откроется выбор чата Telegram с готовым
  сообщением и пригласительной ссылкой события (той же, что во вкладке «Управление»; «🔄 Новая ссылка» отменяет и её). Если
  вступление по одобрению, друг отправит заявку, и её рассмотрит владелец или администратор.

### События и история

- **Новое событие** — главный экран → «🎄 Создать событие» (кто может — [«Создание событий и права»](#создание-событий-и-права)).
  У события свои владелец, администраторы, участники, пригласительная ссылка, письма, исключения, жеребьёвка и переписка.
  Событий может идти несколько одновременно — для разных групп людей.
  Один человек может участвовать в нескольких: имя подтверждается один раз, дальше достаточно перейти по ссылке события.
- **Пригласить тех же людей на следующий год** — «Управление» нового события → «Пригласить участников прошлого события» →
  выберите событие (из тех, где вы владелец или администратор) → «📨 Пригласить участников». Каждый получит в Telegram
  сообщение с кнопкой вступления.
- **«Не повторять пары прошлого события»** (раздел «Жеребьёвка», включено по умолчанию) — бот постарается не повторить
  пары прошлого события того же владельца, где больше всего тех же людей. Если иначе не получается, проведёт жеребьёвку
  без этого правила — молча: по такой подсказке можно было бы вычислить прошлогодние пары.
- **Кольцевая жеребьёвка** (раздел «Жеребьёвка», включена по умолчанию) — если A дарит Б, то Б не дарит A. Меняется только
  до жеребьёвки владельцем или администратором. Для неё нужно минимум 3 участника. Если бот не нашёл распределения без взаимных пар,
  он скажет «Похоже, без взаимных пар … не обойтись» — нажмите ещё раз; не вышло — уберите часть исключений или
  выключите кольцевую.
- **Если во время жеребьёвки кто-то вступил** (или поменялись исключения), бот ничего не запишет и попросит нажать ещё
  раз: пары всегда строятся по актуальному составу.
- **Раскрыть Сант** — только по расписанию: галочка «Раскрыть Сант на следующий день после вручения» в «Параметрах»
  (кнопки нет с обновления 065). Бот пишет каждому участнику, кто был его Сантой, — один раз; полной таблицы пар никто
  не получает. После раскрытия нельзя отменить жеребьёвку и поменять подопечных.
- **Завершение события** — кнопки «Завершить» нет: событие с датой вручения бот завершает сам на **3-й день** после неё
  (в час ежедневных напоминаний); событие без даты — по правилам [«Брошенные события»](#брошенные-события). Отменить
  завершение нельзя. После завершения письма только для чтения, регистрация закрыта; переписка открыта ещё **7 дней**,
  потом — только чтение. Событие остаётся в истории: участники в любой момент откроют своё письмо, письмо подопечного и
  переписку. Перенести завершение — поменять дату вручения в «Параметрах».
- Владелец и администраторы видят своё событие в списке, даже если сами в нём не участвуют (метка «ты не участвуешь»).
  Чужие события им не видны. Все события бота видит только владелец бота — «⚙️ Настройки» → «🗂 Все события». Пары и
  чужую переписку может открыть владелец события (и владелец бота) в служебном просмотре.

### Управление событием

- **Объявление** — «Управление» → «Объявление»: текст до 2000 символов бот отправит всем участникам события, а в приложении он
  останется во вкладке «Инфо» (новые сверху, с автором).
- **Расписание** — «Параметры»: «Автожеребьёвка» (дата; задаётся до жеребьёвки — в своём календаре приложения: день
  выбирается явно, пока он не выбран, «Готово» недоступна; «Сбросить» снимает дату, без даты на её месте — «Закрыть»;
  свайп вниз за полоску сверху тоже закрывает календарь, как и любое окно приложения; сохраняется кнопкой «Сохранить»), «Раскрыть Сант на следующий
  день после вручения» (только при указанной дате вручения, иначе приложение предупредит). Бот выполняет их в час ежедневных напоминаний (10:00 по
  Минску) или в течение минуты, если дата уже наступила. Если автожеребьёвка невозможна (например, мешают исключения),
  бот сообщит владельцу и администраторам причину и снимет дату — проведите жеребьёвку вручную.
- **Статусы участников** — метка «👀 не открыл подопечного» (Санта ещё не заглянул во вкладку «Подопечный» — стоит
  напомнить). Пар она не раскрывает.
- **Событие по образцу** — «🎄 Создать событие» → «По образцу: …» (образец — событие, где вы владелец или
  администратор): копируются бюджет, место, заметки, кольцевая, «не повторять
  пары», авто-раскрытие, вступление по одобрению, возврат удалённых и исключения (даты — нет). Галочка
  «Пригласить участников образца» разошлёт им приглашения. Исключение начнёт действовать, когда оба человека вступят в
  новое событие. Прошлые пары новое событие берёт из событий своего владельца — то есть вашего.
- **Отмена жеребьёвки** — «↩️ Отменить жеребьёвку» видна, пока ни один Санта не открыл подопечного и переписки нет. Пары
  удаляются, письма остаются, регистрация открывается снова, участники получают уведомление. Удобно, если кто-то не
  успел вступить. Позже отменить может только владелец — «Опасная зона» → «↩️ Отменить жеребьёвку» со словом «ОТМЕНА»
  (см. «Участники» ниже).
- **Обращения участников** — «Управление» → «Обращения» (см. «Обращения по событию» ниже): кто ждёт ответа, кто ведёт,
  «🙋 Взять», ответ, «↪️ Передать», «✅ Закрыть обращение».
- **Журнал действий** — «Управление» → «📜 Журнал действий»: всё, что было в этом событии (доступен и для
  завершённого), в том числе назначение и снятие администраторов и передача владения. Видны действия владельца,
  администраторов и бота, в том числе кто открывал чужие письма. Пар, писем и текстов объявлений в журнале нет. После
  удаления события журнал открыть негде — в журнале бота остаётся запись «🗑 Событие
  удалено» с названием и числом участников. Общего журнала у владельцев и администраторов событий нет; журнал бота
  видит только владелец бота ([ниже](#создание-событий-и-права)).

### Исключения, заявки

- **Адреса доставки нет** (с обновления 064): если подарки отправляют почтой, участник пишет, куда отправить, в своём
  письме Санте. Адреса, указанные раньше, никому не показываются.
- **Исключения** — «Управление» → «Исключения»: кто кому не дарит в этом событии (например, муж и жена — в обе стороны).
  Событие по образцу берёт исключения образца. Отдельных «семей» нет: прежние семьи событий, где было включено
  «Учитывать семьи», при обновлении стали исключениями этих событий (обновление 062).
- **После жеребьёвки админы не меняют исключения**: по тому, у кого после правки сменился бы подопечный, можно
  было бы вычислить пары. Исключения события после жеребьёвки для админа — только для чтения (чтобы поменять, отмените
  жеребьёвку, пока это возможно). На **владельца** это ограничение не действует: он и
  так может открыть пары. Изменения после жеребьёвки касаются только будущих замен — текущие пары не меняются.
- **Закреплённые пары** (только владелец) — «Управление» → блок «Закреплённые пары» под «Исключениями»: выберите, кто
  дарит и кому, и нажмите «Закрепить пару». Жеребьёвка обязательно сведёт этих людей, остальные пары — случайно.
  Закреплённая пара важнее исключений и «не повторять пары». При кольцевой жеребьёвке пару можно закрепить только
  в одну сторону; без кольцевой — и «в обе стороны». У человека — не больше одного закреплённого подопечного и одного
  закреплённого Санты (если закрепить две спорящие пары одновременно с двух устройств, сохранится одна, а вторая получит
  отказ с причиной). Меняются только до жеребьёвки (чтобы поменять после — отмените жеребьёвку); удаление и вписывание
  участников закреплённые пары не ломают. **Админы блок не видят**: в журнале — только «📌 Пара закреплена» без имён, а
  если жеребьёвка из-за закреплённых пар невозможна, бот скажет об этом без имён. Если кольцевую включили, когда уже
  есть пара «в обе стороны», жеребьёвка не пройдёт — владелец увидит в блоке, какую пару поправить.
- **Вступление по одобрению** — «Управление» → «Приглашение» → «Вступление по одобрению». Тогда по ссылке человек не вступает
  сразу, а подаёт заявку: админам приходит сообщение с кнопками «✅ Принять» / «❌ Отклонить», заявки видны и в панели
  события («Заявки»). Человек получает ответ. Админы вступают без заявки («Я участвую»). Если событие завершилось, а
  заявка осталась, её можно отклонить в панели завершённого события (принять — нельзя).
- **Регистрация закрыта — значит никто.** Пока переключатель «Регистрация открыта» выключен, по ссылке не вступить,
  заявку не принять (она ждёт открытия; отклонить можно) и участников прошлого события не пригласить. Админ может
  включить «Я участвую» и при закрытой регистрации (до жеребьёвки).
- **Удалённые могут вернуться по ссылке** — настройка в «Управление» → «Приглашение», по умолчанию включена. Выключите — и тот,
  кого удалили из события, по той же ссылке (и заявкой, и по приглашению из прошлого события) не вернётся: бот ответит
  ему «Тебя удалили из события… — вернуться по ссылке нельзя», админам ничего не придёт. В панели появится список
  «Удалённые» с кнопкой «Разрешить вернуться». Выход через «Я участвую» и перенос участия удалением не
  считаются. Событие по образцу копирует настройку.

### Участники: удаление, перенос и удаление события

- **Удалить участника из события** — «Управление» → «⋯» у участника → «🗑 Удалить из события». Работает и для недорегистрированных
  записей («регистрируется…»). После жеребьёвки бот поменяет подопечного у одного-трёх участников (обычно только у Санты
  удалённого; больше — если мешают исключения или кольцевая). В других событиях человек остаётся. Администратора
  удалить из события может только владелец; права администратора удаление не снимает — их снимают отдельно, в
  «Владелец и администраторы».
- **Вписать в жеребьёвку** того, кто вступил после неё (откройте регистрацию, пусть человек зайдёт по ссылке), —
  кнопка «Вписать в жеребьёвку» под участником, **только у владельца** события (иначе админ по смене статусов мог бы
  вычислить пары; админы видят подсказку «Вписать в жеребьёвку может владелец»). Новичок встаёт в цепочку: у одного Санты
  меняется подопечный (теперь это новичок), а новичок дарит его прежнему подопечному. Чей подопечный сменится, бот
  выбирает случайно, но по порядку: сначала среди Сант, которые ещё не открыли подопечного и не переписывались с ним;
  если таких нет — среди остальных (отметки «подарок готов», поставленные до обновления 064, по-прежнему учитываются:
  у таких Сант подопечный не меняется). Если сменить подопечного не у кого (или мешают исключения), бот откажет: «Не получается вписать участника, не нарушив
  правила…» — тогда можно провести жеребьёвку заново (принудительная отмена ниже). Если два действия с парами совпали по
  времени, второе получит «Пары изменились одновременно…» — просто повторите.
- **Принудительная отмена жеребьёвки** (только владелец, «Опасная зона» → «↩️ Отменить жеребьёвку», слово «ОТМЕНА») —
  когда подопечных уже открыли и обычная отмена недоступна. Работает до раскрытия Сант и завершения события. Удаляются
  пары и переписка Сант с подопечными; письма, исключения и обращения
  остаются, регистрация открывается снова. Каждый Санта получает уведомление (без имён). После этого — новая
  жеребьёвка обычным порядком.
- **Человек потерял доступ к аккаунту и зарегистрировался заново** — не удаляйте старую запись, а перенесите её
  (**только владелец бота**: иначе организатор мог бы перенести игрока на свой второй аккаунт и увидеть его пары):
  откройте регистрацию (если закрыта), пусть человек зайдёт по пригласительной ссылке с нового аккаунта; затем
  «⋯» у старой записи → «🔁 Перенести на новый аккаунт» → выберите новую запись. Перенос действует **во всех событиях**:
  новый аккаунт получит письма, подопечных, своих Сант, переписку и историю, а также владение событиями, права
  администратора и счёт созданных событий; пары остальных не изменятся. Если новый
  аккаунт уже успел написать письмо в том же событии, сохранится оно, иначе — прежнее. Всё, что человек делал
  при управлении событиями (записи журнала, объявления, решения по заявкам), после переноса подписано его новым аккаунтом.
  На аккаунт, который сам владелец или администратор какого-либо события, перенести нельзя.
- **Переименовать участника** — «⋯» → «✏️ Переименовать», **только владелец бота** (запись — в журнале бота). Своё имя
  каждый меняет сам: «⚙️ Настройки» → «Профиль».
- **Полного сброса нет** (с обновления 064): чтобы начать заново, удалите событие и создайте новое — по образцу
  прежнего, если нужны те же параметры и исключения.
- **Удалить событие** (только владелец, «Опасная зона») — событие пропадает целиком, в том числе из истории у всех участников.
  Подтверждение — слово «УДАЛИТЬ». Удобно после тестового прогона. Двойное нажатие не разошлёт уведомления дважды. Место в
  лимите создания событий удаление не освобождает.

### Обмен подопечных (владелец)

Когда после жеребьёвки нужно поменять подопечных у двух участников (например, двое живут далеко друг от друга), владелец
(события или бота) открывает в панели события раздел «Обмен подопечными» → «🔀 Открыть меню обмена». Раздел есть
после жеребьёвки и до раскрытия Сант, в завершённом событии его нет; админы его не видят.

- В шторке — только список участников жеребьёвки, без пар: кто кому дарит, не видно (владелец может играть сам).
  Отметьте двоих и нажмите «🔀 Поменять подопечных»: если А дарил 1, а Б дарил 2, станет А → 2 и Б → 1. Остальные пары не
  меняются.
- Под именем того, кто ещё не открыл своего подопечного, — метка «👀 не открыл подопечного» (как в «Участниках»): такой
  Санта не знает, кому дарит, и обмен для него пройдёт незаметно.
- Если обмен ничего не нарушает — обычное окно подтверждения с именами двоих.
- Если нарушает правила жеребьёвки (исключения, кольцевая — взаимная пара, закреплённые пары, «не повторять пары
  прошлого события») — плашка «Обмен нарушает один из принципов жеребьёвки», под ней свёрнутый блок «Подробнее»: какое
  правило нарушится, без имён. Поменять можно, только поставив галочку «Согласен — всё равно поменять».
- Если один из двоих дарит другому, поменять нельзя (кто-то дарил бы сам себе) — выберите другую пару.

После обмена бот пишет, что подопечный сменился, только тем из двоих, кто уже открывал прежнего подопечного (без имён);
не открывшему, подопечным и админам сообщений нет. Две прежние пары удаляются вместе с перепиской, у новых — с чистого
листа; письма не трогаются. В журнал события пишется «🔀 Подопечные поменялись» без имён. Если владелец сам в жеребьёвке,
шторка предупредит: выбрав себя, по предупреждению о правилах или отказу он может догадаться, кто его Санта. Если пары
успели измениться (вписывание, удаление, другой обмен), бот попросит открыть обмен заново.

### Служебный просмотр владельца

Если что-то пошло не так («мой Санта молчит», спор, нужно проверить письмо), владелец события (владелец бота — в любом
событии) открывает внизу панели события
раздел «🔐 Служебный просмотр» и вводит слово «ОТКРЫТЬ» (его проверяет и сервер: без слова данные не откроются). Дальше:

- выберите участника → видно, кому он дарит, кто его Санта, письмо и переписку с Сантой и с подопечным с датами;
- «📋 Показать все пары» (с подтверждением) — вся таблица «Санта → подопечный».

Каждое открытие записывается в журнал события (кто, когда, чьи данные или «все пары» — без самих пар); журнал видят все
админы, отдельных сообщений им не приходит. Просмотр не меняет статусы: «не открыл подопечного», возможность отменить
жеребьёвку и непрочитанные остаются как были. Работает и в завершённых событиях. Если владелец сам участвует в событии,
приложение предупредит: в полной таблице он увидит своего Санту — лучше смотреть по одному участнику.

### Переписка Санты и подопечного

- Санта: вкладка «Подопечный» → «💬 Написать подопечному». Подопечный: вкладка «Письмо» → «💬 Написать Санте».
- Подопечный видит Санту только как «Тайный Санта». Санта знает, кому пишет.
- Каждое сообщение приходит в Telegram от бота с кнопками «↩️ Ответить» (ответить прямо в чате с ботом) и
  «💬 Вся переписка» (открыть историю в приложении). Число непрочитанных видно на кнопке, точка — на вкладке.
- «↩️ Ответить» включает режим ответа **на час**: следующее ваше сообщение боту уйдёт собеседнику. Любая команда
  (например, `/start`) режим выключает. Если час прошёл или у Санты за это время сменился подопечный, сообщение не
  уйдёт — бот так и скажет; нажмите «↩️ Ответить» ещё раз.
- Сообщение — до 4000 символов. Переписку видят эти двое. Владелец может открыть её в служебном просмотре.
- Если у Санты сменился подопечный (кто-то выбыл), старая переписка этой пары удаляется.
- Переписка у каждого события своя. После завершения события писать можно ещё 7 дней, потом — только читать.

### Обращения по событию

- Участник: вкладка «Инфо» → «Нужна помощь?» → «💬 Задать вопрос». Обращение привязано к событию; сообщение — до
  4000 символов. Кто твой подопечный, писать не нужно (и не стоит).
- Владелец и администраторы, кроме автора, получают «🆘 … просит помощи» с текстом и кнопками «🙋 Взять» и «💬 Открыть». Кто первым
  нажал «Взять» (или сразу ответил), тот и ведёт обращение; другим получателям бот сообщит, кто взял, участнику — кто
  ему ответит. Двое нажали одновременно — обращение достанется одному, второй увидит «уже взял(а) …».
- Пока обращение свободно, переписку видят владелец и администраторы. Потом переписка доступна взявшему обращение и
  владельцу. Другие администраторы видят в разделе «Обращения» автора, время и имя ответственного.
- Отвечать можно в приложении или прямо в чате с ботом кнопкой «↩️ Ответить» (режим ответа на час, как в переписке
  Санты). Новые ответы отмечены точкой на вкладке «Инфо» (у владельца и администраторов — на вкладке «Управление»).
- «↪️ Передать» — тот, кто ведёт обращение, или владелец выбирает нового ответственного из владельца и администраторов. Владелец может взять обращение себе.
- Обращение можно закрыть кнопкой «✅ Вопрос решён» у участника или «✅ Закрыть обращение» у ответственного и владельца.
  Следующее сообщение создаст новое обращение для владельца и администраторов.
- Если у ответственного сняли права администратора, обращение освобождается. Владельцу и другим администраторам придёт
  «🔄 … снова ничьё».
  Удалили участника из события — его обращения в этом событии удаляются; перенос участия переносит и обращения.
- В журнал события пишется, кто открыл, взял, передал и закрыл обращение и каждый ответ на обращение («💬 Ответ в
  обращение») — без текстов.
- После завершения события писать в обращения можно ещё 7 дней, потом — только читать.

### Своё имя, открытка и выход из события

- **Сменить имя** — «⚙️ Настройки» → «Профиль» → «✏️ Изменить имя». Имя одно во всех событиях (до 40 символов, как при
  регистрации); его видят владелец, администраторы и ваш Санта, а при раскрытии — подопечный. В журналы смена своего
  имени не пишется. В чате с ботом команды для этого нет — только приложение.
  Эмодзи можно добавить в текст имени в том же поле.
- **Открытка для письма** — вкладка «Письмо» → «🎨 Раскрасить письмо»: одна из 15 открыток («Снегопад», «Ёлочки», «Звёздная
  ночь», «Леденец», «Авиапочта»…) или «Без открытки». Письмо пишется прямо на открытке, и так же его видят ваш Санта и
  владелец или администратор, открывший письмо. Открытка своя у письма в каждом событии; менять можно, пока событие идёт (в
  завершённом — только просмотр). Смена открытки не считается изменением письма: Санте бот не пишет, время изменения
  письма прежнее, несохранённый текст в поле остаётся. Открытки выглядят одинаково в светлой и тёмной теме Telegram.
- **Выйти из события** — вкладка «Инфо» → внизу «Выход из события» → «🚪 Выйти из события», затем ввести слово «ВЫЙТИ».
  Можно, **только пока не проведена жеребьёвка**: удаляются письмо и обращения в этом событии, в других
  событиях вы остаётесь. Владелец или администратор, который так выходит, перестаёт быть участником, но событие и права
  в нём за ним остаются. Владелец и администраторы, кроме того, кто выходит, получают сообщение со звуком «🚪 …
  выходит из события» с кнопкой «🛠 Открыть событие»; в журнале события — «🚪 Выход из события». Вернуться можно по
  пригласительной ссылке, пока регистрация открыта (запрет возврата удалённых на тех, кто вышел сам, не действует).
- **После жеребьёвки** выйти самому нельзя — иначе пришлось бы менять пары. На «Инфо» вместо кнопки — подсказка и
  «💬 Задать вопрос»: владелец или администратор может удалить участника из события (бот сам поменяет подопечного у его Санты). В
  завершённом событии выхода нет.
- **Владелец и администратор, которые сами участвуют**, после жеребьёвки видят на «Инфо» подсказки по своим ролям. Администратора удалить из события
  может только владелец — администратор может обратиться к нему через «Задать вопрос». Владельца не
  может удалить никто: выйти он может, только отменив жеребьёвку («Управление» → «Опасная зона» → «↩️ Отменить жеребьёвку»,
  пары удалятся у всех), затем выключив «Я участвую» и проведя жеребьёвку заново. После раскрытия Сант жеребьёвку уже не
  отменить, и владелец из события не выйдет. Перестать быть владельцем можно только передачей владения («Владелец и
  администраторы») или удалением события.

### Настройки

⚙️ в шапке главного экрана открывает «Настройки»; «‹» возвращает к списку событий.

- **Профиль** — ваше имя и «✏️ Изменить имя», под ним «🌐 Язык» (см. [ниже](#язык)).
- **Уведомления** — «🔔 Звук», «🔕 Тихо» или «🚫 Выкл». Относится к сообщению «подопечный обновил письмо».
- **Нравится бот?** — только в открытом боте: поддержать проект.
- **Владелец бота** — только у владельца бота: «🗂 Все события», «✍️ Кто может создавать события» (в закрытом боте),
  «📜 Журнал бота», «👑 Передать права владельца бота» — см. [«Создание событий и права»](#создание-событий-и-права).

### Язык

Бот и приложение говорят на 11 языках: русский, English, Español, Português (Brasil), Français, Deutsch, 中文（简体）,
Italiano, Türkçe, Bahasa Indonesia, Polski. Язык выбирается так:

1. Язык, который человек выбрал сам: «⚙️ Настройки» → «🌐 Язык», или команда `/language` в чате с ботом.
   Там же можно вернуть «Как в Telegram».
2. Иначе — язык его Telegram, если он есть в боте (португальский Бразилии — Português, китайский любой — 中文).
3. Иначе — русский для белорусского, украинского, казахского, киргизского, таджикского, узбекского, армянского,
   азербайджанского и туркменского Telegram.
4. Иначе — английский.

Язык Telegram бот запоминает, когда человек ему пишет, нажимает кнопку или открывает приложение, — сообщения бота (о
жеребьёвке, переписке, напоминания) приходят каждому на его языке. Слова подтверждения («ВЫЙТИ», «УДАЛИТЬ», «ОТКРЫТЬ»…)
тоже на языке человека, регистр и надстрочные знаки не важны. Кнопка меню чата и подсказки команд — на языке человека.
Журнал событий показывается на языке того, кто его открыл (записи до обновления — по-русски, как были записаны).
Имена людей и названия событий не переводятся.

### Роли

| Роль | Как получить | Что может |
|---|---|---|
| 👑 Владелец бота (один) | ссылка владельца со страницы `/setup` (одноразовая) или передача прав от текущего владельца бота | всё, что владелец события, — в любом событии; видеть все события бота; создавать события без ограничения; в закрытом боте — решать, кто ещё создаёт события; переименовывать людей; переносить участие на новый аккаунт; передавать права владельца бота; журнал бота |
| 👑 Владелец события | создать событие («🎄 Создать событие») или получить владение от прежнего владельца | в своём событии — всё, что администратор, и больше: назначать и снимать администраторов, передавать владение, удалять администраторов из события, удаление события, служебный просмотр пар, закреплённые пары, вписывание в жеребьёвку после неё, обмен подопечных, принудительная отмена жеребьёвки; ограничения «чтобы администратор не вычислил пары» (заморозка исключений) на него не действуют |
| 🛠 Администратор события | назначает владелец события из участников: «Управление» → «Владелец и администраторы» → «🛠 Назначить администратором» | в этом событии — вести его: приглашения, объявления, участники (удаление, «разрешить вернуться»), исключения, кольцевая, жеребьёвка и её отмена (пока никто не открыл подопечного), расписание, напоминание о письме, обращения участников, журнал; пар не видит |
| Участник | пригласительная ссылка события (в открытом боте зарегистрироваться можно и без неё, но в событие — только по ссылке) | письмо, подопечный, переписка с Сантой и подопечным, обращение по событию; история своих событий |

Роли — в пределах события: администратор одного события в другом — обычный участник, а событие, где он не участвует и
не назначен, ему вообще не видно. «Владелец» и «администраторы» в этом README — владелец и администраторы конкретного
события. Создавать свои события может и участник — в открытом боте любой, в закрытом — с разрешения владельца бота
([ниже](#создание-событий-и-права)).

Владельцу события доступны все действия администратора, владельцу бота — все действия владельца в любом событии. Это
проверяет автотест.

Владелец события передаёт владение в «Управление» → «Владелец и администраторы»: 👑 у администратора или «👑 Передать
владение» для участника; прежний владелец остаётся администратором. Владелец бота передаёт свои права в «⚙️ Настройки» →
«👑 Передать права владельца бота»: его события остаются за ним, но создавать новые он будет уже с ограничением, как все.
Если владелец бота потерял доступ, хозяин `ADMIN_SECRET` меняет секрет (`npx wrangler secret put ADMIN_SECRET`),
открывает `/setup`, вводит новый ключ и переходит по новой ссылке владельца: права вернутся к нему, прежний владелец
получит предупреждение.

### Создание событий и права

Каждое событие живёт само по себе: у него свой владелец, свои администраторы, участники и журнал. Что происходит в
одном событии, организаторы другого не видят. (До обновления 063 события группировались в «комнаты»; как права из них
перешли в события — в [«Обновлении бота»](#обновление-бота).)

- **Кто создаёт.** В открытом боте — любой зарегистрированный человек ([ниже](#открытый-бот)). В закрытом — владелец бота
  и те, кому он разрешил. Без разрешения кнопки «🎄 Создать событие» нет, а попытка создать получит ответ «Создавать
  события в этом боте может владелец бота и те, кому он разрешил.»
- **Как.** «🎄 Создать событие» внизу главного экрана → шторка «Новое событие»: название (до 80 символов), по желанию
  образец «По образцу: …» с галочкой «Пригласить участников образца» (образец — событие, где вы владелец или
  администратор) и галочка «Я тоже участвую» (включена) → «Создать». Вы — владелец нового события, приложение сразу
  открывает его «Управление». Если галочку «Я тоже участвую» снять, вы ведёте событие без участия; вступить можно позже —
  «Я участвую» в «Управлении».
- **Лимит — 10 событий за 12 месяцев** (скользящие 365 суток). Считаются все созданные вами события, в том числе
  удалённые и переданные другому владельцу: место от этого не освобождается. В шторке видно, сколько ещё можно создать;
  когда лимит исчерпан, кнопка недоступна и написано, с какой даты можно создать следующее. У владельца бота ограничения
  нет. События, созданные до обновления 063, считаются по их создателю и дате создания.
- **Кто может создавать события** (закрытый бот, только владелец бота) — «⚙️ Настройки» → «✍️ Кто может создавать
  события»: список людей бота с переключателями. Человек получает сообщение, что ему разрешили или больше не разрешают
  создавать события, в журнале бота — запись. Уже созданные события остаются за ним. В открытом боте этого раздела нет.
- **Владелец и администраторы события** — «Управление» → раздел «Владелец и администраторы» (над «Опасной зоной»):
  владелец (👑) и администраторы (🛠). Владелец назначает администратора из участников события («Кого назначить…» →
  «🛠 Назначить администратором»), снимает права (✕) и передаёт владение (👑 у администратора или «Кого сделать
  владельцем…» → «👑 Передать владение» для участника); прежний владелец остаётся администратором. Назначенный, снятый и
  новый владелец получают сообщение, остальные организаторы события — без звука; в журнале события — запись. Снятие
  возвращает обращения, которые вёл администратор, в «ничьи». Назначенный может потом выключить «Я участвую» и остаться
  администратором. Остальным в разделе видно, кто назначает: «Назначает администраторов владелец события — <имя>.»
- **Владелец бота** видит на главном экране только свои события, а в «⚙️ Настройках» у него есть раздел «Владелец бота»:
  - «🗂 Все события» — все события бота, новые первыми, по 50 («Показать ещё»): название, идёт или завершено, владелец и
    число участников. Нажатие открывает событие со всеми правами владельца. В чужом событии владелец бота — гость:
    плашка «Ты здесь как владелец бота…», его нет в списках людей события и в рассылках администраторам, его изменения
    записываются в журнал события под его именем;
  - «✍️ Кто может создавать события» — только в закрытом боте (см. выше);
  - «📜 Журнал бота» — создание событий (кто, название) и их удаление (кто, название, сколько было участников),
    разрешения создавать события, передача прав владельца бота и ссылка владельца, перенос участия, переименования
    людей (переименовывает тоже только владелец бота: «⋯» у участника → «✏️ Переименовать»);
  - «👑 Передать права владельца бота» — выберите человека; ему — сообщение, в журнал бота — запись. Ваши события
    остаются за вами, создавать новые вы сможете, но уже с лимитом.

#### Открытый бот

Бот открытый, если в его настройках `OPEN_BOT = "1"` ([«Настройки бота»](#настройки-бота); у второго бота так и есть).
Что меняется:

- **Без ссылки.** Человек, который просто нашёл бота и нажал «Запустить», называет имя (бот предложит имя из Telegram), и
  бот предлагает создать первое событие в приложении. В приложении — пустой список «Мои события» с подсказкой создать своё
  событие или попросить пригласительную ссылку и кнопкой «🎄 Создать событие» внизу. В закрытом боте такой человек
  по-прежнему получает ответ «Это закрытый бот… попроси пригласительную ссылку».
- **Своё событие.** Создать событие может любой зарегистрированный человек, в том числе пришедший по ссылке в чужое
  событие. Создатель — **владелец события** со всеми правами владельца (администраторы, удаление, закреплённые
  пары, **служебный просмотр пар**). Лимит — 10 событий за 12 месяцев ([выше](#создание-событий-и-права)).
- **Чужие события** не видны: каталога событий нет, человек видит только свои (где он участник, администратор или
  владелец). Вступление в событие — как раньше: по пригласительной ссылке, с регистрацией или заявками, как настроили
  организаторы.
- **Поддержать проект.** На вкладке «Инфо» любого события, под «Нужна помощь?», и в «⚙️ Настройки» — раздел
  «Нравится бот?» с кнопкой
  «❤️ Поддержать через DonationAlerts»: она открывает страницу сбора в браузере, приложение остаётся открытым. Видят все
  (участники и организаторы, в том числе в завершённых событиях); в закрытом боте раздела нет. Адрес страницы —
  `DONATE_URL` в `src/app/05-event.js.txt`: поменять его — правка этой строки и выкат бота.

**Честно о доверии в открытом боте.** Владелец события — это любой, кто его создал (или кому он передал владение), а
владелец может открыть пары своего события в служебном просмотре (каждое открытие пишется в журнал, но участникам
приложение об этом не сообщает). Владелец бота может открыть пары **любого** события, видит в «🗂 Все события» все
события бота с их владельцами, а в «📜 Журнале бота» — кто какие события создавал и удалял. Скажите об этом людям,
которые играют в чужих событиях. Кроме того, открытым ботом может
пользоваться кто угодно, кто его найдёт, — все они расходуют бесплатные лимиты Cloudflare аккаунта этого бота.

Бот сам напоминает (в 10:00 по Минску) в каждом идущем событии: за 2 дня, за день и в день срока письма — тем, у кого
оно пустое (только пока жеребьёвка не проведена). Напоминаний Сантам о подарках нет. Во всех сообщениях бота указано
название события.

### Брошенные события

В обоих ботах (с обновления 064) раз в сутки, в час напоминаний, бот проверяет каждое идущее событие **без даты
вручения** (событие с датой завершается само на 3-й день после неё):

- жеребьёвки нет и в событие никто не вступил, кроме владельца и администраторов события (и владельца бота), — на **23-й
  день** с создания;
- иначе — на **53-й день** с создания (участники есть, жеребьёвка может быть проведена).

Подходит — владелец и администраторы события получают «⏳ Событие … завершится автоматически <дата>» с причиной,
подсказкой и кнопкой «⚙️ Открыть событие». Чтобы оставить событие, достаточно указать дату вручения в «Управление» →
«Параметры» (для пустого события — ещё пригласить участников): на следующий день отметка предупреждения снимается
молча, а если событие снова станет брошенным — придёт новое предупреждение. Ничего не изменилось — через **7 дней**
после предупреждения (то есть на 30-й или 60-й день) событие завершается как обычно: участникам — «🏁 Событие …
завершено», переписка открыта ещё 7 дней, пары не раскрываются. В журнале события — «⏳ Предупреждение об
автозавершении» и завершение от бота. Так забытые события не расходуют бесплатные лимиты Cloudflare.

| «Эта ссылка больше не действует…» по старой ссылке владельца комнаты | комнат больше нет (обновление 063): попросите у владельца бота разрешение создавать события или пригласительную ссылку на событие |

| Человек пишет, что ссылка «закрыта» | регистрация в событии выключена или событие завершено: «Управление» → «Регистрация открыта» |
| «Для кольцевой жеребьёвки нужно минимум 3 участника» | добавьте участников или выключите «🔁 Кольцевая жеребьёвка» в разделе «Жеребьёвка» |
| Кто-то выбыл после жеребьёвки | «Управление» → «⋯» у участника → «🗑 Удалить из события»: бот поменяет подопечного у одного-трёх участников |
| Человек потерял аккаунт и зарегистрировался заново | владелец бота: «⋯» у старой записи → «🔁 Перенести на новый аккаунт» (см. «Участники» выше) |
| Тестовый прогон перед настоящей игрой | создайте отдельное тестовое событие, после проверки — «Опасная зона» → «🗑 Удалить событие» |
| «База не подготовлена: примени миграции» | `npx wrangler d1 migrations apply secret-santa-db --remote` (для `npm run dev` — с `--local`) |
| У участника метка «🚫 не получает сообщения» | он заблокировал бота или удалил чат: попросите открыть бота и нажать «Запустить»; метка снимется сама |
| Человек по ссылке «отправил заявку», но не вступил | включено «Вступление по одобрению»: примите заявку в «Управление» → «Заявки» или кнопкой в сообщении бота |
| «⚠️ Автожеребьёвка … не прошла» | бот снял дату: поправьте исключения или состав и нажмите «🎲 Провести жеребьёвку» |
| Нет кнопки «↩️ Отменить жеребьёвку» в разделе «Жеребьёвка» | кто-то уже открыл подопечного или началась переписка: выбывших удаляйте, новых вписывает владелец; переиграть всё может только владелец — «Опасная зона» → «↩️ Отменить жеребьёвку» |
| Нет кнопки «Вписать в жеребьёвку» / «Вписать в жеребьёвку может владелец» | вписывать после жеребьёвки может только владелец события (или владелец бота) |
| Нет раздела «Обмен подопечными» | он только у владельца события (или владельца бота) и только после жеребьёвки до раскрытия Сант, не в завершённом событии |
| «Не получается вписать участника, не нарушив правила» | сменить подопечного не у кого (все Санты отмечены как готовые до обновления 064) или мешают исключения: владелец может отменить жеребьёвку («Опасная зона») и провести её заново |
| «Сейчас некому ответить на обращение» | владелец события может назначить администратора из участников: «Управление» → «Владелец и администраторы» |
| Администратор пишет, что событие пропало («Событие не найдено.») | с него сняли права администратора, а участником события он не был — или событие удалили |
| «Обращение ведёт … — переписку видят он(а) и владелец» | обращение взял другой админ; если он не отвечает, владелец может передать обращение («↪️ Передать») |
| «Не удалось быстро подобрать распределение» | нажмите «Проверить» ещё раз; не помогло — уберите часть исключений или выключите кольцевую жеребьёвку |
| «Пары изменились одновременно…» / «Участники или исключения изменились во время жеребьёвки» | кто-то менял событие в ту же секунду — повторите действие |
| «Время ответа истекло» / «Пара изменилась после нажатия «Ответить»» | сообщение не отправлено: нажмите «↩️ Ответить» под сообщением ещё раз и напишите снова |

параметр «Участники могут писать друг другу» (@username на «Инфо» теперь виден всегда), кнопки «Завершить» и «Полный
сброс». Колонки этих данных в базе остались ради отката, код их не читает. Сразу после выката учтите: в первую же
ежедневную проверку (10:00 по Минску) бот **завершит** каждое идущее событие, дата вручения которого прошла 3 и больше
дней назад, а события без даты в обоих ботах начнут получать предупреждения ([«Брошенные события»](#брошенные-события)).
Откат кода на 063 безопасен: прежние данные на месте, но события, завершённые новым кодом, завершёнными и останутся.
Проверка — `specs/064-texts-cleanup/quickstart.md`.

После выката откройте приложение в Telegram (лучше на телефоне) и пройдитесь по главному экрану и своему событию. Если
приложение открылось пустым, с вечной «Загрузка…» или без оформления, верните прежнюю версию:

```powershell
npx wrangler rollback <Version ID прежней версии> -m "откат"
```

Откат возвращает только код Worker, база остаётся как есть. Подробные шаги проверки и отката для конкретного обновления
— в `quickstart.md` его фичи в `specs/` (например, для политики страницы — `specs/032-app-csp/quickstart.md`).

Второй бот ([отдельный аккаунт](#второй-бот-на-отдельном-аккаунте-cloudflare)) обновляется так же, отдельно: те же
команды с `--env second` и базой `secret-santa-db-2`, вместо `npm run deploy` — `npm run deploy:second`. Удобно сначала
обновить второго бота, проверить его и только потом первого.

### Резервная копия и восстановление

Всё, что происходит в боте, — участники, события, письма, пары, переписка, журнал — хранится в базе D1 в Cloudflare.
Код бота и секреты (`BOT_TOKEN`, `ADMIN_SECRET`) — отдельно: `npm run deploy` базу не трогает, а в копии базы секретов
нет.

Страховки две:

| | Что это | Когда выручит |
|---|---|---|
| **История Cloudflare** (Time Travel) | Cloudflare сам помнит базу поминутно за последние 7 дней (бесплатный тариф). Делать ничего не нужно | что-то удалили или сломали недавно — откатить базу на нужную минуту |
| **Копия в файл** | вся база в один файл `.sql` на вашем компьютере | прошло больше 7 дней, база удалена, перенос в другой аккаунт Cloudflare |

#### Сделать копию в файл

В PowerShell в папке проекта:

```powershell
npx wrangler d1 export secret-santa-db --remote --output "backup-secret-santa-db-$(Get-Date -Format yyyy-MM-dd-HHmm).sql"
```

- Появится файл вида `backup-secret-santa-db-2026-12-01-1800.sql` (имя базы, дата и время). Спросит подтверждение —
  ответьте `y`.
- Пока идёт выгрузка (обычно несколько секунд), база занята: бот в это время может не ответить — повторите действие.
- Когда делать: перед обновлением бота с новыми миграциями; раз в неделю, пока идёт событие, если хотите страховку дольше
  7 дней; после завершения события — на память.
- **В файле — все письма, переписка, пары и адреса**: кто откроет файл, узнает, кто чей Санта. Не пересылайте его в
  мессенджеры и почту, храните на своём компьютере или на флешке. Git файлы `*.sql` вне `migrations/` не берёт
  (`.gitignore`), так что копия в папке проекта в коммит не уйдёт.
- Проверить копию: откройте файл в Блокноте — внутри строки `CREATE TABLE …` и `INSERT INTO …`. Пустой файл или
  сообщение об ошибке вместо них — копия не получилась.

#### Откатить базу на момент в прошлом (до 7 дней)

Например, случайно удалили событие или участника. Откатывается **вся база** — все события сразу: всё, что
участники написали и сделали после этого момента, пропадёт.

1. Проверьте, что момент доступен (время — минское, отсюда `+03:00`):

   ```powershell
   npx wrangler d1 time-travel info secret-santa-db --timestamp="2026-12-20T18:00:00+03:00"
   ```

   Ответ с закладкой (`bookmark`) — момент есть в истории.
2. Откатите:

   ```powershell
   npx wrangler d1 time-travel restore secret-santa-db --timestamp="2026-12-20T18:00:00+03:00"
   ```

   Спросит подтверждение — `y`. На пару секунд бот может не ответить. Выкатывать заново ничего не нужно.
3. Wrangler напечатает закладку состояния **до** отката — сохраните её. Передумали — верните как было:

   ```powershell
   npx wrangler d1 time-travel restore secret-santa-db --bookmark=<закладка из ответа>
   ```

#### Восстановить из файла

Когда нужный момент старше 7 дней или базы больше нет. Копия загружается **только в пустую базу**: в рабочую не
загрузится (ошибка `UNIQUE constraint failed`). Поэтому создаём новую базу и переключаем бота на неё; старая остаётся
нетронутой — если что-то пойдёт не так, можно вернуться к ней.

1. Создайте новую базу:

   ```powershell
   npx wrangler d1 create secret-santa-db-restored
   ```

   Предложит сам добавить настройки — откажитесь. Скопируйте из ответа `database_id`.
2. В `wrangler.toml`, в разделе `[[d1_databases]]`, замените две строки (`binding = "DB"` не трогайте):

   ```toml
   database_name = "secret-santa-db-restored"
   database_id = "<database_id из шага 1>"
   ```

3. Загрузите копию (подставьте имя своего файла), подтвердите `y`:

   ```powershell
   npx wrangler d1 execute secret-santa-db-restored --remote --file "backup-secret-santa-db-2026-12-01-1800.sql"
   ```

   Миграции заново применять не нужно: копия помнит, какие уже применены. Если копия сделана до обновления с новыми
   миграциями — примените их: `npx wrangler d1 migrations apply secret-santa-db-restored --remote`.
4. Опубликуйте бота: `npm run deploy`. Откройте бота и проверьте, что события на месте. `/setup` повторять не нужно:
   адрес бота и секреты не менялись.
5. Дальше во всех командах этого README пишите `secret-santa-db-restored` вместо `secret-santa-db`.
6. Старую базу удалите, только когда убедитесь, что всё работает: `npx wrangler d1 delete secret-santa-db`.
   Удаление необратимо — вместе с базой пропадает и её 7-дневная история.

Второй бот восстанавливается так же: в каждой команде `--env second`, новая база — `secret-santa-db-2-restored`,
строки меняются в разделе `[[env.second.d1_databases]]`, выкат — `npm run deploy:second`, старая база —
`secret-santa-db-2`. Имя `secret-santa-db-2` для новой базы первого бота не берите — так называется база второго.

После любого восстановления бот продолжает с того состояния: напоминания и сообщения, которые после этого момента уже
ушли, могут прийти ещё раз. Если бот пишет «База не подготовлена» — база старее кода: примените миграции (команда из
«Обновления бота», для новой базы — с её именем).

**О тайне.** Бот показывает пары только самому Санте (его подопечного) и в служебном просмотре — владельцу события (в
своём событии) и владельцу бота (в любом) — с записью
каждого открытия в журнал. Админы пар не видят. Технически владелец аккаунта Cloudflare может открыть базу данных в панели
Cloudflare — просто не делайте этого 🙂

**Защита страницы приложения.** Страница мини-приложения отдаётся с политикой безопасности (заголовок
`Content-Security-Policy`): браузер выполняет только её собственный скрипт и скрипт Telegram, отправляет запросы только
этому боту, а встроить страницу в себя может только веб-версия Telegram. Даже если в страницу когда-нибудь попадёт чужая
разметка, её код не выполнится и никуда не отправит пары и письма.

**Какие данные хранятся:** Telegram ID, имя и ник, письма, адреса доставки (только в событиях, где они включены),
переписка Санты и подопечного, обращения по событиям и их переписка, заявки на вступление, отметки «удалён из события», закреплённые пары владельца, владелец и администраторы каждого события, факты создания событий (кто и когда — для лимита; остаются после удаления и передачи события), разрешение создавать события (закрытый бот), журнал действий админов и бота (без пар, писем и текстов), язык интерфейса, язык Telegram и язык кнопки меню чата. События
хранятся, пока владелец их не удалит.

**Бесплатные лимиты** Cloudflare: 100 000 запросов в сутки — для группы до ~40 человек с огромным запасом.

## Для разработки

```powershell
npm test               # быстрые тесты (секунды): весь Worker в одном процессе + жеребьёвка, дизайн-система, слова
npm run test:e2e       # полный сценарий (события, жеребьёвка, переписка, обращения, история) на локальном Worker с имитацией Telegram
npm run test:all       # npm test и npm run test:e2e подряд — перед слиянием ветки и выкатом
npm run bench:draw     # замер скорости жеребьёвки на 50–200 человек (в npm test не входит)
npm run screenshots    # скриншоты мини-приложения в test-results/ (нужен Google Chrome)
npm run dev            # локальный Worker на http://127.0.0.1:8787
```

`npm test` — перед каждым коммитом. Он запускает настоящий код Worker на встроенной в Node базе SQLite (`node:sqlite`,
схема — из `migrations/`) с поддельным Telegram, без `wrangler` и без новых зависимостей, и проверяет:

- **тайну пар** — перестановка пар в базе и замена писем и адресов не меняют ответы API для владельца и администраторов. Уведомления сохраняют имя подопечного и текст письма в тайне;
- **права** — каждое действие администратора: участнику — отказ, админу — отказ ровно на действиях владельца,
  владельцу бота — ни одного отказа, владельцу события в своём событии — отказ только на действиях владельца бота
  (перенос участия, переименование, `bot.*`), администратору другого события — «Событие не найдено.» на каждом; список
  действий берётся из таблицы действий API (`ACTIONS` в `src/api.js`): новое
  действие — одна строка с ролью, нужным событием и тем, можно ли его в завершённом событии;
- **отказы** — ответы без прав, на несуществующее и на завершённое событие (код и текст) совпадают с эталоном
  `tests/fixtures/api-refusals.json`;
- **одновременные вызовы** — два одинаковых действия в навязанном порядке «оба прочитали, затем оба пишут» дают один
  результат, в том числе два нажатия одного человека в одну и ту же миллисекунду: одно сообщение, одна запись журнала
  (`tests/atomic.test.mjs`; помощник таких действий — `src/claim.js`, его проверки — `tests/claims.test.mjs`, там же
  проверка, что в условиях SQL нет незакрытых скобок);
- **снимки жеребьёвки** — пары записываются, только если участники, исключения и закреплённые пары не изменились
  с момента расчёта; формула снимка в коде и в базе совпадает на случайных данных, перестановка партнёров в исключениях
  замечается (`tests/snapshots.test.mjs`);
- **число запросов** — ни одно действие не делает больше запросов к базе, чем в базовом замере, и укладывается в лимит
  бесплатного тарифа (50 на вызов);
- **жеребьёвку** — при том же зерне результат совпадает с эталоном `tests/fixtures/draw-golden.json`;
- **мини-приложение** — страница собирается из частей `src/app/` (порядок — в `src/app-page.js`): правила дизайн-системы
  и слов проверяются по собранной странице, а `tests/app-parts.test.mjs` замечает файл части, не включённый в сборку,
  сломанный скрипт и неверный порядок;
- **политику страницы** — заголовок `Content-Security-Policy` у `/app` (`src/csp.js`) пускает только встроенный скрипт
  страницы (по отпечатку, который сервер считает сам) и скрипт Telegram; `tests/app-csp.test.mjs` проверяет заголовок и
  что в коде приложения нет того, что политика заблокирует (`eval`, обработчики событий в разметке, второй встроенный
  скрипт, скрипт с нового адреса);
- **описание API** — [`docs/api.md`](docs/api.md) описывает каждое действие из таблицы `ACTIONS` с той же ролью, событием,
  поведением в завершённом событии и текстами отказов владельца, а таблица кодов журнала — ровно те коды, которые пишет
  сервер (`tests/api-doc.test.mjs`): новое действие без описания роняет `npm test`.
- **тексты** — все тексты для людей лежат в словаре `src/i18n/ru/` (файл на область: модуль сервера или часть
  приложения); в коде их нет, ключи в коде есть в словаре, а ключи словаря используются (`tests/i18n.test.mjs`). Новый
  текст — строка в словаре своей области и вызов по ключу; во время правки файл проверяет
  `node tests/support/i18n-check.mjs <файл>`.

`npm run test:e2e` — перед выкатом: настоящий `wrangler dev`, миграции, имитация Telegram по HTTP (около трёх минут).
Тестам настоящий бот и аккаунт Cloudflare не нужны. Для скриншотов нужен Google Chrome (или путь к нему в переменной
окружения `CHROME_PATH`); `npm run screenshots` заодно проверяет, что ни на одном экране браузер не блокирует ничего по
политике страницы, а внедрённый код и запросы на чужие адреса блокируются (с сетью — и с настоящим скриптом Telegram во
фрейме веб-клиента).

Для ручного запуска `npm run dev` создайте в папке проекта файл `.dev.vars` (он в `.gitignore`, коммитить его нельзя):

```text
BOT_TOKEN=<токен тестового бота>
ADMIN_SECRET=<любой пароль от 8 символов>
```

Перед первым `npm run dev` создайте локальную базу: `npx wrangler d1 migrations apply DB --local`.
Telegram до локального адреса не достучится, поэтому вживую бот проверяется после `npm run deploy`, а локально —
тестами.
Меняете схему — добавьте файл `migrations/NNNN_имя.sql` и поднимите `REQUIRED_SCHEMA` в `src/db.js`
(и `schema` в самой миграции); e2e-тесты применяют миграции сами. Миграция только с индексами, от которых код не
зависит (как `0008`), версию не поднимает: тогда бот работает и до её применения.

Витрина интерфейса: откройте `design-system/preview.html` в браузере.

tools/           служебные SQL для владельца — сверки после выката: rooms-reconcile.sql (063),
                 masks-families-reconcile.sql (062), notify-reconcile.sql (057)
tests/           быстрые тесты (*.test.mjs), e2e (e2e.test.mjs), скриншоты
  support/       «мир»: весь Worker в одном процессе, подмена D1 на node:sqlite, поддельный Telegram
  fixtures/      эталоны жеребьёвки и отказов API (не пересоздаются)
  bench/         замеры: скорость жеребьёвки, запросы на действие
specs/           спецификации Spec Kit (требования, план, задачи) — источник истины

### Как менять проект

Проект ведётся по [Spec Kit](https://github.com/github/spec-kit): сначала требования, потом код. В Claude Code
в этой папке:

1. `/speckit-specify <что нужно изменить>` — новая спецификация и ветка `NNN-имя`;
2. `/speckit-clarify` (по желанию) → `/speckit-plan` → `/speckit-tasks`;
3. `/speckit-implement` — реализация по задачам;
4. `npm run test:all` (`npm test` и `npm run test:e2e`), затем `npm run deploy`.

Правила проекта — в [`.specify/memory/constitution.md`](.specify/memory/constitution.md), подсказки для агента — в [`CLAUDE.md`](CLAUDE.md),
описание API мини-приложения, кнопок бота и журнала — в [`docs/api.md`](docs/api.md) (меняете API — правьте и его).
