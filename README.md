# 🎅 Тайный Санта — Telegram-бот

Закрытый бот для игры в Тайного Санту в своей компании. Работает на телефонах (iOS, Android) и компьютерах через
Telegram, ничего устанавливать не нужно.

- вход без паролей, регистрация только по пригласительной ссылке;
- **события**: несколько игр параллельно для разных компаний, у каждой своя ссылка, письма и жеребьёвка;
  прошлые события остаются в истории — на следующий год можно открыть свои старые записи;
- письмо Санте до 4000 символов (столько помещается в одно сообщение Telegram) — менять можно до завершения события;
- исключения «кто кому не может достаться» и жеребьёвка одной кнопкой; **кольцевая жеребьёвка** (по умолчанию):
  если A дарит Б, то Б не дарит A;
- **закреплённые пары**: владелец бота может заранее решить, кто кому дарит (при кольцевой — только в одну сторону);
  админы их не видят;
- Санта в любой момент видит письмо подопечного (изменения подсвечены) и получает уведомление, когда тот его правит;
- организаторы не видят, кто кому дарит; только владелец бота может открыть пары в служебном просмотре, если что-то
  пошло не так, — и каждое открытие записывается в журнал;
- переписка Санты и подопечного прямо в приложении (Санта остаётся анонимным) с уведомлениями в Telegram;
- напоминания, «подарок готов» и «подарок получен», раскрытие Сант после праздника;
- адрес доставки для удалённого обмена — его видит только твой Санта;
- «семьи» — постоянные исключения для всех событий; вступление по заявке с одобрением админа;
- **вопрос организатору** прямо из приложения: обращение видят все админы, первый откликнувшийся берёт его себе;
- для организатора: объявления всем участникам, расписание (автожеребьёвка, авто-раскрытие, автозавершение),
  событие по образцу прошлого, отмена жеребьёвки (до первых просмотров — админом, позже — владельцем), журнал действий.

Хостинг — бесплатный тариф Cloudflare (без банковской карты). Требования и решения — в [`specs/`](specs/)
(начало — [`001`](specs/001-secret-santa-bot/spec.md), события и история — [`005`](specs/005-events-history/spec.md)).

## Установка и настройка

≈ 20 минут, Windows. Все команды выполняются в **PowerShell**. Что понадобится: компьютер с Windows, аккаунт Telegram
и почта для регистрации в Cloudflare. Платить ни за что не нужно.

Коротко, что предстоит (подробности — в шагах ниже):

| Шаг | Что делаем | Результат |
|---|---|---|
| 1 | ставим Node.js и Git | работают `node -v` и `git --version` |
| 2 | создаём бота у @BotFather | токен бота |
| 3 | регистрируемся в Cloudflare | аккаунт |
| 4 | скачиваем проект, `npm install`, `npx wrangler login` | папка проекта, вход в Cloudflare |
| 5 | создаём базу D1 и применяем миграции | `database_id` в `wrangler.toml`, таблицы созданы |
| 6 | `npm run deploy` | адрес `https://secret-santa-bot.<поддомен>.workers.dev` |
| 7 | задаём секреты `BOT_TOKEN` и `ADMIN_SECRET` | бот может говорить с Telegram |
| 8 | открываем `/setup` | webhook, меню и ссылка владельца |
| 9 | переходим по ссылке владельца, создаём событие | можно приглашать людей |

### 1. Установите Node.js и Git

- **Node.js** — скачайте LTS-версию с [nodejs.org](https://nodejs.org) и установите. Проверка: `node -v` (нужна 22.15 или новее; текущая LTS подходит).
- **Git** — скачайте с [git-scm.com](https://git-scm.com/download/win) и установите с настройками по умолчанию.
  Проверка: `git --version`.

После установки закройте и снова откройте PowerShell.

Разрешите PowerShell запускать `npm` и `npx` (один раз, права администратора не нужны):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

На вопрос ответьте `Y`. Без этого `npm install` падает с ошибкой «Невозможно загрузить файл …\npm.ps1, так как
выполнение сценариев отключено в этой системе». Другой путь — писать `npm.cmd` и `npx.cmd` вместо `npm` и `npx`
во всех командах ниже.

### 2. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте название (например, «Тайный Санта 2026») и имя пользователя, оканчивающееся на `bot`.
3. BotFather пришлёт **токен** вида `1234567890:AA…`. Никому его не показывайте.

### 3. Создайте аккаунт Cloudflare

Зарегистрируйтесь на [dash.cloudflare.com/sign-up](https://dash.cloudflare.com/sign-up) (нужна только почта)
и подтвердите адрес.

### 4. Скачайте проект, установите зависимости и войдите в Cloudflare

```powershell
git clone https://github.com/VictorKalevich/secret-santa-bot.git C:\ClaudeProjects\secret-santa-bot
cd C:\ClaudeProjects\secret-santa-bot
npm install
npx wrangler login
```

Папку можно выбрать любую — тогда во всех командах ниже подставляйте свой путь. Если проект уже лежит на компьютере,
`git clone` пропустите и просто перейдите в его папку. Все дальнейшие команды выполняются **в папке проекта**.

После `npx wrangler login` откроется браузер — нажмите «Allow».

### 5. Создайте базу данных

```powershell
npx wrangler d1 create secret-santa-db
```

Если Wrangler предложит сам добавить настройки в конфигурацию — откажитесь и сделайте вручную:
скопируйте из ответа значение `database_id` и вставьте его в `wrangler.toml` в строку `database_id = "…"` вместо
того, что там стоит (в репозитории — id базы автора проекта, в вашем аккаунте Cloudflare её нет).
Потеряли значение — `npx wrangler d1 list` покажет его снова. `database_id` — не секрет, но это настройка именно вашей
установки.

Создайте таблицы — примените миграции (папка `migrations/`):

```powershell
npx wrangler d1 migrations apply secret-santa-db --remote
```

Wrangler покажет список миграций и спросит подтверждение — ответьте `y`. Бот сам таблицы не создаёт: без этого шага
он отвечает «База не подготовлена».

### 6. Опубликуйте бота

```powershell
npm run deploy
```

При первом запуске Cloudflare попросит выбрать имя поддомена `workers.dev` — введите любое. В конце появится адрес
вида `https://secret-santa-bot.<ваш-поддомен>.workers.dev` — запишите его.

### 7. Добавьте секреты

```powershell
npx wrangler secret put BOT_TOKEN
npx wrangler secret put ADMIN_SECRET
```

На первый вопрос вставьте токен от BotFather, на второй — придумайте пароль администратора (лучше 16+ символов,
латиница и цифры; короче 8 символов бот не примет). Он нужен только для страницы настройки — это ключ к правам
владельца, храните его как пароль. Секреты хранятся в Cloudflare, в файлы проекта и в git они не попадают; заново
публиковать бота после `secret put` не нужно.

Проверка: откройте адрес из шага 6 в браузере — должно быть «🎄 Бот Тайного Санты работает.» Если видите «Не задан
секрет BOT_TOKEN» — повторите команду с `BOT_TOKEN`; «База не подготовлена» — вернитесь к миграциям из шага 5.

### 8. Настройте бота

Откройте в браузере:

```
https://secret-santa-bot.<ваш-поддомен>.workers.dev/setup
```

**Что вы увидите сначала.** Страница «🎄 Настройка бота» с одним полем — «Ключ настройки (значение секрета
ADMIN_SECRET)» — и кнопкой «Настроить бота». Пока ключ не введён, страница ничего не настраивает и ничего не показывает.

Введите в поле тот пароль, который задали на шаге 7 командой `npx wrangler secret put ADMIN_SECRET`, и нажмите
«Настроить бота». Ключ вводится только в форму: в адресе страницы его нет, в историю браузера он не попадёт.

**Что будет после ввода ключа:**

- ключ верный — страница «✅ Бот настроен» со списком проверок: «Токен бота» (с именем вашего бота), «Webhook»,
  «Команды», «Кнопка приложения». Все пункты должны быть с ✔. Ниже — **ссылка владельца**;
- ключ неверный — «Неверный ключ» и та же форма: проверьте пароль и введите ещё раз. Забыли пароль — задайте новый
  (`npx wrangler secret put ADMIN_SECRET`) и откройте `/setup` снова;
- «Нужен ADMIN_SECRET» вместо формы — секрет не задан или короче 8 символов: вернитесь к шагу 7.

Ссылку владельца откройте в своём Telegram и **никому не пересылайте**. Пригласительных ссылок на этой странице нет:
у каждого события своя, она появляется в приложении.

**Ссылка владельца срабатывает один раз.** Пока по ней не перешли, страницу можно открывать снова (например, если
закрыли вкладку). После перехода страница блокируется: не настраивает бота и не показывает ссылку, пока вы не смените
`ADMIN_SECRET`. Нужна новая ссылка (утекла старая, потерян доступ к Telegram) — смените секрет:

```powershell
npx wrangler secret put ADMIN_SECRET
```

откройте `/setup` снова, введите новый ключ и перейдите по новой ссылке. Старая ссылка перестанет работать.

### 9. Создайте событие и начинайте игру

1. Перейдите по ссылке владельца и напишите боту своё имя.
2. Нажмите «🎁 Санта» (кнопка у поля ввода) → «🎄 Создать» → название, например «Новый год 2026 — семья».
3. Откроется вкладка «Админ» события: включите «Я участвую», если играете сами, и заполните бюджет, даты и место
   (раздел «Параметры»).
4. Отправьте пригласительную ссылку события в общий чат (кнопка «📤 Отправить в чат»).
5. Когда все зарегистрируются — добавьте исключения и нажмите «🎲 Провести жеребьёвку».
6. После праздника — «🎅 Раскрыть Сант» (по желанию) и «🏁 Завершить». Или заранее включите это
   в «Параметрах» — бот сделает сам (см. «Инструменты организатора»).

Перед настоящей игрой стоит сделать тестовый прогон: создайте отдельное событие, пройдите его с парой друзей и удалите
(«Опасная зона» → «🗑 Удалить событие»).

## Настройки бота

Несекретные настройки лежат в `wrangler.toml`, раздел `[vars]`. Поменяли значение — выполните `npm run deploy`.

| Настройка | По умолчанию | Что значит |
|---|---|---|
| `TIMEZONE_OFFSET_HOURS` | `3` (Минск, UTC+3) | часовой пояс: по нему считаются даты события, час напоминаний и время в сообщениях |
| `REMINDER_HOUR` | `10` | с какого часа по местному времени бот шлёт ежедневные напоминания и выполняет расписание событий |
| `NOTIFY_DELAY_MINUTES` | `10` | сколько минут после последней правки письма бот ждёт, прежде чем сообщить Санте (чтобы не слать сообщение на каждую правку) |

Секреты задаются только командой `npx wrangler secret put <ИМЯ>` — в `wrangler.toml` их писать нельзя:

| Секрет | Что это | Когда менять |
|---|---|---|
| `BOT_TOKEN` | токен бота от @BotFather | если токен утёк: `/revoke` у @BotFather, новый токен → `secret put BOT_TOKEN` → снова открыть `/setup` (до этого бот не отвечает) и перейти по новой ссылке владельца — прежняя перестаёт работать |
| `ADMIN_SECRET` | пароль для страницы `/setup` (от 8 символов) | когда нужна новая ссылка владельца или старый пароль мог кто-то узнать |

Остальное (бюджет, даты, место, регистрация, расписание, адрес доставки, семьи) настраивается в приложении отдельно
для каждого события — вкладка «Админ».

Имя и аватар бота меняются у @BotFather (`/mybots`); команды, кнопку «🎁 Санта» и описание бот выставляет сам при
настройке на странице `/setup`.

## Как играть

Приложение открывается кнопкой «🎁 Санта». На главном экране — **список событий**: «Мои события» (где вы участник,
включая завершённые) и у админов «Другие события» (где вы не участвуете). Если вы участник единственного события,
оно откроется сразу. Внутри события — вкладки:

| Кто | Что делает |
|---|---|
| Участник | «Письмо» — пишет и правит письмо (до 4000 символов), кнопка «💬 Написать Санте», отметка «🎁 Я получил(а) подарок»; «Подопечный» — кому дарит, его письмо, кнопка «💬 Написать подопечному», отметка «подарок готов»; «Инфо» — бюджет, даты, место, объявления организатора, «💬 Написать организатору» |
| Организатор | «Админ» — ссылка-приглашение, «Я участвую», объявление, участники и их статусы (действия с участником — кнопка «⋯»), исключения, кольцевая жеребьёвка, жеребьёвка и её отмена, напоминания, раскрытие Сант, завершение события, параметры и расписание, обращения участников, журнал; у владельца — закреплённые пары, вписывание в жеребьёвку после неё, служебный просмотр, принудительная отмена жеребьёвки, сброс и удаление события |

Чужое письмо организатор может открыть только через «⋯» → «👁 Открыть письмо» с подтверждением, и это записывается в
журнал действий. Пар «кто кому дарит» админы не видят вообще — ни в текущих событиях, ни в истории. Исключение — владелец
бота (см. «Служебный просмотр владельца»). В приложении об этом не пишется — если хотите, чтобы участники знали,
расскажите им сами (например, в объявлении события).

Организатор, который сам участвует в событии, открывает его на вкладке «Письмо» (а не «Подопечный»): пока ни один Санта не
открыл подопечного, жеребьёвку ещё можно отменить.

### События и история

- **Новое событие** — главный экран → «🎄 Создать» (владелец и админы). У события свои участники, пригласительная
  ссылка, письма, исключения, жеребьёвка и переписка. Событий может идти несколько одновременно — для разных компаний.
  Один человек может участвовать в нескольких: имя вводится один раз, дальше достаточно перейти по ссылке события.
- **Пригласить ту же компанию на следующий год** — «Админ» нового события → «Пригласить участников прошлого события» →
  выберите событие → «📨 Пригласить участников». Каждый получит в Telegram сообщение с кнопкой вступления.
- **«Не повторять пары прошлого события»** (раздел «Жеребьёвка», включено по умолчанию) — бот постарается не повторить пары прошлого события,
  где больше всего тех же людей. Если иначе не получается, проведёт жеребьёвку без этого правила — молча: по такой
  подсказке можно было бы вычислить прошлогодние пары.
- **Кольцевая жеребьёвка** (раздел «Жеребьёвка», включена по умолчанию) — если A дарит Б, то Б не дарит A. Меняется только
  до жеребьёвки, только админом. Для неё нужно минимум 3 участника. Если бот не нашёл распределения без взаимных пар,
  он скажет «Похоже, без взаимных пар … не обойтись» — нажмите ещё раз; не вышло — уберите часть исключений или
  выключите кольцевую.
- **Если во время жеребьёвки кто-то вступил** (или поменялись исключения), бот ничего не запишет и попросит нажать ещё
  раз: пары всегда строятся по актуальному составу.
- **Раскрыть Сант** и **Завершить** срабатывают один раз, даже если админ нажал одновременно с другим админом или с
  расписанием: каждый участник получит одно сообщение, второй нажавший — «Тайна уже раскрыта» / «Событие уже завершено».
- **Завершить событие** — «Админ» → «🏁 Завершить» после праздника. Отменить нельзя. После завершения письма и отметки
  «подарок готов» только для чтения, регистрация закрыта; переписка открыта ещё **7 дней**, потом — только чтение.
  Событие остаётся в истории: участники в любой момент откроют своё письмо, письмо подопечного и переписку.
- Админы и владелец видят все события, даже где не участвуют (вкладки «Инфо» и «Админ»), но пары и чужую переписку — нет.

### Инструменты организатора

- **Объявление** — «Админ» → «Объявление»: текст до 2000 символов бот отправит всем участникам события, а в приложении он
  останется во вкладке «Инфо» (новые сверху, с автором).
- **Расписание** — «Параметры»: «Автожеребьёвка» (дата; задаётся до жеребьёвки), «Раскрыть Сант на следующий день
  после вручения», «Завершить через 3 дня после вручения» (два последних — только при указанной дате вручения,
  иначе приложение предупредит). Бот выполняет их в час ежедневных напоминаний (10:00 по
  Минску) или в течение минуты, если дата уже наступила. Если автожеребьёвка невозможна (например, мешают исключения),
  бот напишет админам причину и снимет дату — проведите жеребьёвку вручную.
- **Статусы участников** — метки «📦 получил» (подопечный отметил «Я получил(а) подарок»; его Санта получает одно
  сообщение «подопечный получил подарок» без имени) и «👀 не открыл подопечного» (Санта ещё не заглянул во вкладку
  «Подопечный» — стоит напомнить). Счётчик «получено X из N» — в разделе «Жеребьёвка». Пар эти метки не раскрывают.
- **Событие по образцу** — «🎄 Создать» → «По образцу: …»: копируются бюджет, место, заметки, кольцевая, «не повторять
  пары», авто-раскрытие, автозавершение и исключения (даты — нет). Галочка «Пригласить участников образца» разошлёт им
  приглашения. Исключение начнёт действовать, когда оба человека вступят в новое событие.
- **Отмена жеребьёвки** — «↩️ Отменить жеребьёвку» видна, пока ни один Санта не открыл подопечного и переписки нет. Пары
  удаляются, письма остаются, регистрация открывается снова, участники получают уведомление. Удобно, если кто-то не
  успел вступить. Позже отменить может только владелец — «Опасная зона» → «↩️ Отменить жеребьёвку» со словом «ОТМЕНА»
  (см. «Участники» ниже).
- **Обращения участников** — «Админ» → «Обращения» (см. «Вопрос организатору» ниже): кто ждёт ответа, кто ведёт,
  «🙋 Взять», ответ, «↪️ Передать», «✅ Закрыть обращение».
- **Журнал действий** — «Админ» → «📜 Журнал действий» (по событию, доступен и для завершённого) и главный экран →
  «Администраторы» → «📜 Журнал действий» (роли, перенос участия, удалённые события). Видно, кто из админов что сделал и
  что бот сделал сам, в том числе кто открывал чужие письма. Пар, писем и текстов объявлений в журнале нет. Журнал
  сохраняется после сброса и удаления события.

### Адрес доставки, семьи, заявки

- **Адрес доставки** — если подарки отправляют почтой или курьером, включите в «Параметрах» «Подарки отправляют —
  спросить адрес доставки». У участников во вкладке «Письмо» появится «Как передать подарок» (до 500 символов), Санта
  увидит его во вкладке «Подопечный». Организатор адрес **не видит** — только метку «📍 адрес указан / адреса нет».
  В новом событии поле заполняется последним указанным адресом. Если подопечный изменил адрес, Санта получит уведомление
  (без текста адреса).
- **Семьи** — главный экран → «Семьи» → «Новая семья»: название и состав (2–20 человек, каждый — не больше чем в одной
  семье). Члены семьи не дарят друг другу ни в одном событии, где включено «👪 Учитывать семьи» (раздел «Исключения»,
  по умолчанию включено; меняется до жеребьёвки). Заводятся один раз — на следующий год исключения вносить не нужно.
  Если семьи делают жеребьёвку невозможной, бот так и скажет. Перенос участия на новый аккаунт переносит и семью.
- **После жеребьёвки админы не меняют исключения и семьи**: по тому, у кого после правки сменился бы подопечный, можно
  было бы вычислить пары. Исключения события после жеребьёвки для админа — только для чтения (чтобы поменять, отмените
  жеребьёвку, пока это возможно). Состав семьи нельзя менять, пока идёт событие с проведённой жеребьёвкой, где участвуют
  хотя бы двое из затронутых людей; переименовать семью можно всегда. На **владельца** эти ограничения не действуют: он и
  так может открыть пары. Изменения после жеребьёвки касаются только будущих замен — текущие пары не меняются.
- **Закреплённые пары** (только владелец бота) — «Админ» → блок «Закреплённые пары» под «Исключениями»: выберите, кто
  дарит и кому, и нажмите «Закрепить пару». Жеребьёвка обязательно сведёт этих людей, остальные пары — случайно.
  Закреплённая пара важнее исключений, семей и «не повторять пары». При кольцевой жеребьёвке пару можно закрепить только
  в одну сторону; без кольцевой — и «в обе стороны». У человека — не больше одного закреплённого подопечного и одного
  закреплённого Санты. Меняются только до жеребьёвки (чтобы поменять после — отмените жеребьёвку); удаление и вписывание
  участников закреплённые пары не ломают. **Админы блок не видят**: в журнале — только «📌 Пара закреплена» без имён, а
  если жеребьёвка из-за закреплённых пар невозможна, бот скажет об этом без имён. Если кольцевую включили, когда уже
  есть пара «в обе стороны», жеребьёвка не пройдёт — владелец увидит в блоке, какую пару поправить.
- **Вступление по одобрению** — «Админ» → «Приглашение» → «Вступление по одобрению». Тогда по ссылке человек не вступает
  сразу, а подаёт заявку: админам приходит сообщение с кнопками «✅ Принять» / «❌ Отклонить», заявки видны и в панели
  события («Заявки»). Человек получает ответ. Админы вступают без заявки («Я участвую»).
- **Регистрация закрыта — значит никто.** Пока переключатель «Регистрация открыта» выключен, по ссылке не вступить,
  заявку не принять (она ждёт открытия; отклонить можно) и участников прошлого события не пригласить. Админ может
  включить «Я участвую» и при закрытой регистрации (до жеребьёвки).
- **Удалённые могут вернуться по ссылке** — настройка в «Админ» → «Приглашение», по умолчанию включена. Выключите — и тот,
  кого удалил организатор, по той же ссылке (и заявкой, и по приглашению из прошлого события) не вернётся: бот ответит
  ему «Организатор удалил тебя… — вернуться по ссылке нельзя», админам ничего не придёт. В панели появится список
  «Удалённые» с кнопкой «Разрешить вернуться». Выход через «Я участвую», полный сброс и перенос участия удалением не
  считаются. Событие по образцу копирует настройку.

### Участники: удаление, перенос, сброс и удаление события

- **Удалить участника из события** — «Админ» → «⋯» у участника → «🗑 Удалить из события». Работает и для недорегистрированных
  записей («регистрируется…»). После жеребьёвки бот поменяет подопечного у одного-трёх участников (обычно только у Санты
  удалённого; больше — если мешают исключения или кольцевая). В других событиях человек остаётся.
- **Вписать в жеребьёвку** того, кто вступил после неё (откройте регистрацию, пусть человек зайдёт по ссылке), —
  кнопка «Вписать в жеребьёвку» под участником, **только у владельца** (иначе админ по смене статусов мог бы вычислить
  пары; админы видят подсказку «Вписать в жеребьёвку может владелец бота»). Новичок встаёт в цепочку: у одного Санты
  меняется подопечный (теперь это новичок), а новичок дарит его прежнему подопечному. Чей подопечный сменится, бот
  выбирает случайно, но по порядку: сначала среди Сант, которые ещё не открыли подопечного и не переписывались с ним;
  если таких нет — среди тех, у кого подарок не отмечен как готовый (и не получен). Если подарки готовы у всех, кому
  мог бы смениться подопечный (или мешают исключения), бот откажет: «Не получается вписать участника, не нарушив
  правила…» — тогда можно провести жеребьёвку заново (принудительная отмена ниже). Если два действия с парами совпали по
  времени, второе получит «Пары изменились одновременно…» — просто повторите.
- **Принудительная отмена жеребьёвки** (только владелец, «Опасная зона» → «↩️ Отменить жеребьёвку», слово «ОТМЕНА») —
  когда подопечных уже открыли и обычная отмена недоступна. Работает до раскрытия Сант и завершения события. Удаляются
  пары, отметки «подарок готов/получен» и переписка Сант с подопечными; письма, адреса, исключения, семьи и обращения
  остаются, регистрация открывается снова. Каждый Санта получает уведомление (без имён). После этого — новая
  жеребьёвка обычным порядком.
- **Человек потерял доступ к аккаунту и зарегистрировался заново** — не удаляйте старую запись, а перенесите её
  (**только владелец**: иначе админ мог бы перенести игрока на свой второй аккаунт и увидеть его пары):
  откройте регистрацию (если закрыта), пусть человек зайдёт по пригласительной ссылке с нового аккаунта; затем
  «⋯» у старой записи → «🔁 Перенести на новый аккаунт» → выберите новую запись. Перенос действует **во всех событиях**:
  новый аккаунт получит письма, подопечных, своих Сант, переписку и историю; пары остальных не изменятся. Если новый
  аккаунт уже успел написать письмо или адрес в том же событии, сохранятся они, иначе — прежние.
- **Полный сброс** (только владелец, «Опасная зона») — удаляет из этого события всех, кроме владельца, письма, пары,
  исключения, переписку и параметры; создаёт новую пригласительную ссылку (старая перестаёт работать). Другие события не
  затрагиваются. Подтверждение — слово «СБРОС». Завершённое событие сбросить нельзя — только удалить.
- **Удалить событие** (только владелец, «Опасная зона») — событие пропадает целиком, в том числе из истории у всех участников.
  Подтверждение — слово «УДАЛИТЬ». Удобно после тестового прогона. Двойное нажатие не разошлёт уведомления дважды.

### Служебный просмотр владельца

Если что-то пошло не так («мой Санта молчит», спор, нужно проверить письмо), владелец бота открывает внизу панели события
раздел «🔐 Служебный просмотр» и вводит слово «ОТКРЫТЬ». Дальше:

- выберите участника → видно, кому он дарит, кто его Санта, письмо, адрес доставки (если событие его спрашивает) и
  переписку с Сантой и с подопечным с датами;
- «📋 Показать все пары» (с подтверждением) — вся таблица «Санта → подопечный».

Каждое открытие записывается в журнал события (кто, когда, чьи данные или «все пары» — без самих пар); журнал видят все
админы, отдельных сообщений им не приходит. Просмотр не меняет статусы: «не открыл подопечного», возможность отменить
жеребьёвку и непрочитанные остаются как были. Работает и в завершённых событиях. Если владелец сам участвует в событии,
приложение предупредит: в полной таблице он увидит своего Санту — лучше смотреть по одному участнику.

### Переписка Санты и подопечного

- Санта: вкладка «Подопечный» → «💬 Написать подопечному». Подопечный: вкладка «Письмо» → «💬 Написать Санте».
- Подопечный видит Санту только как «Тайный Санта». Санта знает, кому пишет.
- Каждое сообщение приходит в Telegram от бота с кнопками «↩️ Ответить» (ответить прямо в чате с ботом) и
  «💬 Вся переписка» (открыть историю в приложении). Число непрочитанных видно на кнопке, точка — на вкладке.
- «↩️ Ответить» включает режим ответа **на час**: следующее ваше сообщение боту уйдёт собеседнику. Любая команда
  (например, `/start`) режим выключает. Если час прошёл или у Санты за это время сменился подопечный, сообщение не
  уйдёт — бот так и скажет; нажмите «↩️ Ответить» ещё раз.
- Сообщение — до 4000 символов. Переписку видят только эти двое; организатор её не видит.
- Если у Санты сменился подопечный (кто-то выбыл), старая переписка этой пары удаляется.
- Переписка у каждого события своя. После завершения события писать можно ещё 7 дней, потом — только читать.

### Вопрос организатору

- Участник: вкладка «Инфо» → «Нужна помощь?» → «💬 Написать организатору». Обращение привязано к событию; сообщение — до
  4000 символов. Кто твой подопечный, писать не нужно (и не стоит).
- Все админы, кроме автора, получают «🆘 … просит помощи» с текстом и кнопками «🙋 Взять» и «💬 Открыть». Кто первым
  нажал «Взять» (или сразу ответил), тот и ведёт обращение; остальным админам бот сообщит, кто взял, участнику — кто
  ему ответит. Двое нажали одновременно — обращение достанется одному, второй увидит «уже взял(а) …».
- Переписка: до того, как обращение взяли, её видят все админы; после — только взявший и владелец бота. Остальные
  админы видят в «Админ» → «Обращения» лишь кто, когда и кто ведёт.
- Отвечать можно в приложении или прямо в чате с ботом кнопкой «↩️ Ответить» (режим ответа на час, как в переписке
  Санты). Новые ответы отмечены точкой на вкладке «Инфо» (у админа — на «Админ»).
- «↪️ Передать» — ведущий админ или владелец отдаёт обращение другому админу; владелец может передать и себе.
- «✅ Вопрос решён» у участника или «✅ Закрыть обращение» у ведущего админа (или владельца) закрывает обращение. Новое сообщение после
  закрытия — новое обращение (снова всем админам).
- Если у ведущего сняли права админа, обращение снова становится ничьим — админам придёт «🔄 … снова ничьё».
  Удалили участника из события — его обращения в этом событии удаляются; перенос участия переносит и обращения.
- В журнал события пишется, кто открыл, взял, передал и закрыл обращение — без текстов.
- После завершения события писать в обращения можно ещё 7 дней, потом — только читать.

### Роли

| Роль | Как получить | Что может |
|---|---|---|
| 👑 Владелец (один) | ссылка владельца со страницы `/setup` (одноразовая) или передача прав от текущего владельца | всё, что админ, и больше: назначать и снимать админов, передавать права владельца, удалять админов из событий, переносить участие на новый аккаунт, сброс и удаление событий, служебный просмотр пар, вписывание в жеребьёвку после неё, принудительная отмена жеребьёвки; ограничения «чтобы админ не вычислил пары» (заморозка исключений и семей) на него не действуют |
| 🛠 Админ | назначает владелец: главный экран → «Администраторы» → «Назначить админом» | создавать и вести события: приглашения, объявления, участники (удаление, «разрешить вернуться»), исключения, кольцевая, жеребьёвка и её отмена (пока никто не открыл подопечного), расписание, напоминания, завершение, обращения участников, журнал; пар не видит |
| Участник | пригласительная ссылка события | письмо, подопечный, переписка с Сантой и подопечным, вопрос организатору; история своих событий |

Роли общие для всего бота, а не для одного события.

Всё, что появляется у админа, сразу доступно и владельцу — это проверяет автотест.

Владельца нельзя удалить или лишить прав из приложения — только передать права (👑 у админа в списке). Если владелец
потерял доступ, хозяин `ADMIN_SECRET` меняет секрет (`npx wrangler secret put ADMIN_SECRET`), открывает `/setup`,
вводит новый ключ и переходит по новой ссылке владельца: права вернутся к нему, прежний владелец получит предупреждение.

Бот сам напоминает (в 10:00 по Минску) в каждом идущем событии: за 2 дня до срока письма — тем, у кого оно пустое;
за 2 дня и в день вручения — Сантам без отметки «подарок готов». Во всех сообщениях бота указано название события.

## Если что-то не так

| Проблема | Решение |
|---|---|
| PowerShell: «выполнение сценариев отключено» | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или используйте `npx.cmd` вместо `npx` |
| На `/setup` пункт с ✘ | проверьте `BOT_TOKEN` (`npx wrangler secret put BOT_TOKEN` ещё раз) и откройте `/setup` снова |
| Бот не отвечает | откройте `/setup` ещё раз; посмотрите логи: `npx wrangler tail` |
| «Не удалось проверить вход» в приложении | закройте приложение и откройте снова из чата с ботом |
| Пригласительная ссылка ушла не туда | «Админ» события → «🔄 Новая ссылка» (старая перестанет работать) |
| Человек пишет, что ссылка «закрыта» | регистрация в событии выключена или событие завершено: «Админ» → «Регистрация открыта» |
| «Для кольцевой жеребьёвки нужно минимум 3 участника» | добавьте участников или выключите «🔁 Кольцевая жеребьёвка» в разделе «Жеребьёвка» |
| Кто-то выбыл после жеребьёвки | «Админ» → «⋯» у участника → «🗑 Удалить из события»: бот поменяет подопечного у одного-трёх участников |
| Человек потерял аккаунт и зарегистрировался заново | «⋯» у старой записи → «🔁 Перенести на новый аккаунт» (см. «Участники» выше) |
| Тестовый прогон перед настоящей игрой | создайте отдельное тестовое событие, после проверки — «Опасная зона» → «🗑 Удалить событие» |
| «База не подготовлена: примени миграции» | `npx wrangler d1 migrations apply secret-santa-db --remote` (для `npm run dev` — с `--local`) |
| У участника метка «🚫 не получает сообщения» | он заблокировал бота или удалил чат: попросите открыть бота и нажать «Запустить»; метка снимется сама |
| «Мешают семьи» при жеребьёвке | выключите «👪 Учитывать семьи» в разделе «Исключения» этого события или кольцевую жеребьёвку |
| Человек по ссылке «отправил заявку», но не вступил | включено «Вступление по одобрению»: примите заявку в «Админ» → «Заявки» или кнопкой в сообщении бота |
| «⚠️ Автожеребьёвка … не прошла» | бот снял дату: поправьте исключения или состав и нажмите «🎲 Провести жеребьёвку» |
| Нет кнопки «↩️ Отменить жеребьёвку» в разделе «Жеребьёвка» | кто-то уже открыл подопечного или началась переписка: выбывших удаляйте, новых вписывает владелец; переиграть всё может только владелец — «Опасная зона» → «↩️ Отменить жеребьёвку» |
| Нет кнопки «Вписать в жеребьёвку» / «… может владелец бота» | вписывать после жеребьёвки может только владелец бота |
| «Не получается вписать участника, не нарушив правила» | подарки готовы у всех, кому мог бы смениться подопечный, или мешают исключения: владелец может отменить жеребьёвку («Опасная зона») и провести её заново |
| «Сейчас некому написать» у участника | в боте нет других админов, кроме него самого: владелец назначает админов на главном экране → «Администраторы» |
| «Обращение ведёт … — переписку видят он(а) и владелец» | обращение взял другой админ; если он не отвечает, владелец может передать обращение («↪️ Передать») |
| «Не удалось быстро подобрать распределение» | нажмите «Проверить» ещё раз; не помогло — уберите часть исключений или выключите кольцевую жеребьёвку |
| «Пары изменились одновременно…» / «Участники, исключения или семьи изменились во время жеребьёвки» | кто-то менял событие или семьи в ту же секунду — повторите действие |
| «Время ответа истекло» / «Пара изменилась после нажатия «Ответить»» | сообщение не отправлено: нажмите «↩️ Ответить» под сообщением ещё раз и напишите снова |
| Не получается изменить исключения или семью | после жеребьёвки они заморожены для админов (см. «Адрес доставки, семьи, заявки»); попросите владельца или отмените жеребьёвку, пока это возможно |
| «Ссылка владельца уже использована» / «Страница заблокирована» на `/setup` | ссылка одноразовая: `npx wrangler secret put ADMIN_SECRET` с новым паролем, откройте `/setup`, введите новый ключ и перейдите по новой ссылке |
| Ссылка владельца попала не туда | смените `ADMIN_SECRET` (см. строку выше) и перейдите по новой ссылке — права вернутся к вам, старая ссылка перестанет работать |
| «Регистрация … закрыта — открой её, чтобы принять заявку» | закрытая регистрация закрывает и заявки, и приглашения: «Админ» → «Регистрация открыта» |
| Удалённый пишет, что «вернуться по ссылке нельзя» | выключена настройка «Удалённые могут вернуться по ссылке»: «Админ» → «Удалённые» → «Разрешить вернуться» |
| Нет кнопки «🔁 Перенести на новый аккаунт» | перенос участия делает только владелец бота |

### Обновление бота

Когда в проекте появились изменения (новая версия из git):

```powershell
git pull
npm install
npx wrangler d1 migrations list secret-santa-db --remote    # есть ли новые миграции
# если есть — копия базы и миграции:
npx wrangler d1 export secret-santa-db --remote --output "backup-$(Get-Date -Format yyyy-MM-dd-HHmm).sql"
npx wrangler d1 migrations apply secret-santa-db --remote
npm run deploy
```

`migrations list` показывает ещё не применённые миграции; ответ «No migrations to apply» — применять нечего, две
следующие команды пропустите. Обновление без новых миграций (только код и оформление) базу не трогает — хватит
`npm run deploy`. Миграции только добавляют таблицы и поля и никогда не удаляют данные молча; уже применённые Wrangler
пропускает. Про копию — [ниже](#резервная-копия-и-восстановление).

### Резервная копия и восстановление

Всё, что происходит в боте, — участники, события, письма, пары, переписка, журнал — хранится в базе D1 в Cloudflare.
Код бота и секреты (`BOT_TOKEN`, `ADMIN_SECRET`) — отдельно: `npm run deploy` базу не трогает, а в копии базы секретов
нет.

Страховки две:

| | Что это | Когда выручит |
|---|---|---|
| **История Cloudflare** (Time Travel) | Cloudflare сам помнит базу поминутно за последние 7 дней (бесплатный тариф). Делать ничего не нужно | что-то удалили или сломали недавно — откатить базу на нужную минуту |
| **Копия в файл** | вся база в один файл `.sql` на вашем компьютере | прошло больше 7 дней, база удалена, перенос в другой аккаунт Cloudflare |

#### Сделать копию в файл

В PowerShell в папке проекта:

```powershell
npx wrangler d1 export secret-santa-db --remote --output "backup-$(Get-Date -Format yyyy-MM-dd-HHmm).sql"
```

- Появится файл вида `backup-2026-12-01-1800.sql` (дата и время в имени). Спросит подтверждение — ответьте `y`.
- Пока идёт выгрузка (обычно несколько секунд), база занята: бот в это время может не ответить — повторите действие.
- Когда делать: перед обновлением бота с новыми миграциями; раз в неделю, пока идёт событие, если хотите страховку дольше
  7 дней; после завершения события — на память.
- **В файле — все письма, переписка, пары и адреса**: кто откроет файл, узнает, кто чей Санта. Не пересылайте его в
  мессенджеры и почту, храните на своём компьютере или на флешке. Git файлы `*.sql` вне `migrations/` не берёт
  (`.gitignore`), так что копия в папке проекта в коммит не уйдёт.
- Проверить копию: откройте файл в Блокноте — внутри строки `CREATE TABLE …` и `INSERT INTO …`. Пустой файл или
  сообщение об ошибке вместо них — копия не получилась.

#### Откатить базу на момент в прошлом (до 7 дней)

Например, случайно удалили событие или сделали полный сброс. Откатывается **вся база** — все события сразу: всё, что
участники написали и сделали после этого момента, пропадёт.

1. Проверьте, что момент доступен (время — минское, отсюда `+03:00`):

   ```powershell
   npx wrangler d1 time-travel info secret-santa-db --timestamp="2026-12-20T18:00:00+03:00"
   ```

   Ответ с закладкой (`bookmark`) — момент есть в истории.
2. Откатите:

   ```powershell
   npx wrangler d1 time-travel restore secret-santa-db --timestamp="2026-12-20T18:00:00+03:00"
   ```

   Спросит подтверждение — `y`. На пару секунд бот может не ответить. Выкатывать заново ничего не нужно.
3. Wrangler напечатает закладку состояния **до** отката — сохраните её. Передумали — верните как было:

   ```powershell
   npx wrangler d1 time-travel restore secret-santa-db --bookmark=<закладка из ответа>
   ```

#### Восстановить из файла

Когда нужный момент старше 7 дней или базы больше нет. Копия загружается **только в пустую базу**: в рабочую не
загрузится (ошибка `UNIQUE constraint failed`). Поэтому создаём новую базу и переключаем бота на неё; старая остаётся
нетронутой — если что-то пойдёт не так, можно вернуться к ней.

1. Создайте новую базу:

   ```powershell
   npx wrangler d1 create secret-santa-db-2
   ```

   Предложит сам добавить настройки — откажитесь. Скопируйте из ответа `database_id`.
2. В `wrangler.toml`, в разделе `[[d1_databases]]`, замените две строки (`binding = "DB"` не трогайте):

   ```toml
   database_name = "secret-santa-db-2"
   database_id = "<database_id из шага 1>"
   ```

3. Загрузите копию (подставьте имя своего файла), подтвердите `y`:

   ```powershell
   npx wrangler d1 execute secret-santa-db-2 --remote --file "backup-2026-12-01-1800.sql"
   ```

   Миграции заново применять не нужно: копия помнит, какие уже применены. Если копия сделана до обновления с новыми
   миграциями — примените их: `npx wrangler d1 migrations apply secret-santa-db-2 --remote`.
4. Опубликуйте бота: `npm run deploy`. Откройте бота и проверьте, что события на месте. `/setup` повторять не нужно:
   адрес бота и секреты не менялись.
5. Дальше во всех командах этого README пишите `secret-santa-db-2` вместо `secret-santa-db`.
6. Старую базу удалите, только когда убедитесь, что всё работает: `npx wrangler d1 delete secret-santa-db`.
   Удаление необратимо — вместе с базой пропадает и её 7-дневная история.

После любого восстановления бот продолжает с того состояния: напоминания и сообщения, которые после этого момента уже
ушли, могут прийти ещё раз. Если бот пишет «База не подготовлена» — база старее кода: примените миграции (команда из
«Обновления бота», для новой базы — с её именем).

**О тайне.** Бот показывает пары только самому Санте (его подопечного) и владельцу бота в служебном просмотре — с записью
каждого открытия в журнал. Админы пар не видят. Технически владелец аккаунта Cloudflare может открыть базу данных в панели
Cloudflare — просто не делайте этого 🙂

**Какие данные хранятся:** Telegram ID, имя и ник, письма, адреса доставки (только в событиях, где они включены),
переписка Санты и подопечного, семьи, заявки на вступление, отметки «удалён организатором», журнал действий админов.
События хранятся, пока владелец их не удалит.

**Бесплатные лимиты** Cloudflare: 100 000 запросов в сутки — для компании до ~40 человек с огромным запасом.

## Для разработки

```powershell
npm test               # быстрые тесты (секунды): весь Worker в одном процессе + жеребьёвка, дизайн-система, слова
npm run test:e2e       # полный сценарий (события, жеребьёвка, переписка, обращения, история) на локальном Worker с имитацией Telegram
npm run bench:draw     # замер скорости жеребьёвки на 50–200 человек (в npm test не входит)
npm run screenshots    # скриншоты мини-приложения в test-results/ (нужен Google Chrome)
npm run dev            # локальный Worker на http://127.0.0.1:8787
```

`npm test` — перед каждым коммитом. Он запускает настоящий код Worker на встроенной в Node базе SQLite (`node:sqlite`,
схема — из `migrations/`) с поддельным Telegram, без `wrangler` и без новых зависимостей, и проверяет:

- **тайну пар** — перестановка пар в базе и замена писем и адресов не меняют ни одного ответа организаторам, ни одно
  сообщение не называет подопечного и не содержит письма;
- **права** — каждое действие администратора: участнику — отказ, админу — отказ ровно на действиях владельца,
  владельцу — ни одного отказа; список действий берётся из таблицы действий API (`ACTIONS` в `src/api.js`): новое
  действие — одна строка с ролью, нужным событием и тем, можно ли его в завершённом событии;
- **отказы** — ответы без прав, на несуществующее и на завершённое событие (код и текст) совпадают с эталоном
  `tests/fixtures/api-refusals.json`;
- **одновременные вызовы** — два одинаковых действия в навязанном порядке «оба прочитали, затем оба пишут» дают один
  результат, в том числе два нажатия одного человека в одну и ту же миллисекунду: одно сообщение, одна запись журнала
  (`tests/atomic.test.mjs`; помощник таких действий — `src/claim.js`, его проверки — `tests/claims.test.mjs`, там же
  проверка, что в условиях SQL нет незакрытых скобок);
- **снимки жеребьёвки** — пары записываются, только если участники, исключения, семьи и закреплённые пары не изменились
  с момента расчёта; формула снимка в коде и в базе совпадает на случайных данных, перестановка партнёров в исключениях
  замечается (`tests/snapshots.test.mjs`);
- **число запросов** — ни одно действие не делает больше запросов к базе, чем в базовом замере, и укладывается в лимит
  бесплатного тарифа (50 на вызов);
- **жеребьёвку** — при том же зерне результат совпадает с эталоном `tests/fixtures/draw-golden.json`.

`npm run test:e2e` — перед выкатом: настоящий `wrangler dev`, миграции, имитация Telegram по HTTP (около трёх минут).
Тестам настоящий бот и аккаунт Cloudflare не нужны. Для скриншотов нужен Google Chrome (или путь к нему в переменной
окружения `CHROME_PATH`).

Для ручного запуска `npm run dev` создайте в папке проекта файл `.dev.vars` (он в `.gitignore`, коммитить его нельзя):

```text
BOT_TOKEN=<токен тестового бота>
ADMIN_SECRET=<любой пароль от 8 символов>
```

Перед первым `npm run dev` создайте локальную базу: `npx wrangler d1 migrations apply DB --local`.
Telegram до локального адреса не достучится, поэтому вживую бот проверяется после `npm run deploy`, а локально —
тестами.
Меняете схему — добавьте файл `migrations/NNNN_имя.sql` и поднимите `REQUIRED_SCHEMA` в `src/db.js`
(и `schema` в самой миграции); e2e-тесты применяют миграции сами.

Витрина интерфейса: откройте `design-system/preview.html` в браузере.

### Структура

```text
migrations/      миграции базы D1 (схема — только через них)
src/             код Worker: бот, API, мини-приложение (app.html), жеребьёвка, cron
design-system/   дизайн-система: токены, компоненты, витрина, правила
tests/           быстрые тесты (*.test.mjs), e2e (e2e.test.mjs), скриншоты
  support/       «мир»: весь Worker в одном процессе, подмена D1 на node:sqlite, поддельный Telegram
  fixtures/      эталоны жеребьёвки и отказов API (не пересоздаются)
  bench/         замеры: скорость жеребьёвки, запросы на действие
specs/           спецификации Spec Kit (требования, план, задачи) — источник истины
.specify/        Spec Kit: конституция проекта, шаблоны, скрипты PowerShell
.claude/skills/  команды Spec Kit для Claude Code (/speckit-*)
```

### Как менять проект

Проект ведётся по [Spec Kit](https://github.com/github/spec-kit): сначала требования, потом код. В Claude Code
в этой папке:

1. `/speckit-specify <что нужно изменить>` — новая спецификация и ветка `NNN-имя`;
2. `/speckit-clarify` (по желанию) → `/speckit-plan` → `/speckit-tasks`;
3. `/speckit-implement` — реализация по задачам;
4. `npm test` и `npm run test:e2e`, затем `npm run deploy`.

Правила проекта — в [`.specify/memory/constitution.md`](.specify/memory/constitution.md), подсказки для агента — в [`CLAUDE.md`](CLAUDE.md).
