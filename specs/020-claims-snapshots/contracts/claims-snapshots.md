# Внутренний контракт: захваты и снимки жеребьёвки (020)

Внешний API (ответы, коды, тексты, сообщения) не меняется — контракты 005–019 действуют. Здесь — правила для
разработчика, который пишет или меняет действие, обязанное дать один результат при одновременных вызовах.

## 1. Когда нужен помощник

Действие рассылает сообщения, пишет журнал или меняет несколько таблиц **по итогу** изменения состояния (жеребьёвка,
отмена, раскрытие, завершение, удаление, взятие обращения, решение по заявке…). Пакет собирается только через
`atomic()` из `src/claim.js`; `enqueueIfStmt`/`auditIfStmt` напрямую в таких действиях не вызываются.

## 2. API

```js
import { atomic } from './claim.js';

const a = atomic(db, "EXISTS (SELECT 1 FROM support_threads WHERE id = ? AND status = 'open')", t.id);
const free = a.and('EXISTS (SELECT 1 FROM support_threads WHERE id = ? AND assignee = ?)', t.id, 0);
free.enqueue(chatId, payload);                       // INSERT INTO outbox … WHERE (cond)
free.audit(eventId, actor, 'support.take', details); // INSERT INTO audit … WHERE (cond)
a.where('UPDATE x SET y = ? WHERE id = ?', y, id);   // … AND (cond)
a.select('INSERT INTO x (a, b) SELECT ?, ?', 1, 2);  // … WHERE (cond)
a.add(...memberDataDeleteStmts(db, ev.id, uid, ...a.guard)); // свои условия; guard = [sql, ...args]
free.claim(db.prepare("UPDATE support_threads SET … WHERE id = ? AND status = 'open' AND assignee = 0").bind(…));
const { won, claim, results } = await a.run();       // любой построитель из and() запускает общий пакет
```

- `cond` — выражение с **закрытыми скобками** (строки в кавычках не считаются); иначе `atomic`/`and` бросают `Error`.
- Порядок операторов в пакете — порядок вызовов.
- `claim(stmt)` — один раз на пакет; `won` — `meta.changes > 0` или вернувшаяся строка (`RETURNING`). Без `claim`
  `won` — `null`.

## 3. Два вида условий

1. **«Захват мой»** — у захвата есть уникальное значение этого вызова (случайная версия пар `draw_token`, случайная
   отметка `revealed`) или признак, который второй вызов не повторит («завершено, и записи журнала `finish` ещё нет» —
   запись последней; существование опоры — опора удаляется последней). Захват (или опора) стоит там, где стоял.
2. **«По прежнему состоянию»** — уникального значения нет (только `now` и автор — у двух нажатий одного человека в одну
   миллисекунду они совпадают). Операторы по условию стоят **перед** захватом и проверяют состояние, которое захват
   отменяет; условие повторяет **все** условия захвата. Пакет — одна транзакция, транзакции записи идут по очереди:
   второй вызов видит изменённое состояние.

Время (`now`) и автор в условиях «свой захват» **не используются**.

## 5. Снимки жеребьёвки (`src/snapshots.js`)

```js
import { SNAPSHOTS, drawSnapshot, snapshotGuard } from './snapshots.js';
const snap = drawSnapshot(ev, { ids, exclusions, families, fixed }); // строки, без запросов
const g = snapshotGuard(ev.id, snap);   // { sql: '… = ? AND … = ? AND (? = \'\' OR … = ?) AND … = ?', args }
db.prepare(`UPDATE events … WHERE … AND ${g.sql}`).bind(…, ...g.args);
```

- У каждого снимка `js(data)` и `sql` (один параметр — id события) — **рядом**, меняются вместе; паритет проверяет
  `tests/snapshots.test.mjs` на случайных данных.
- Числа < 2^53 по построению: суммы — по модулю 2^52, произведения — сомножители по модулю 1000003.
- Новое правило пар, влияющее на жеребьёвку, — новый снимок в `SNAPSHOTS` и в паритетном тесте.
