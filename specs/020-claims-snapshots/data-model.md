# Data Model: Захваты и снимки жеребьёвки (020)

Схема базы не меняется (11, миграции не добавляются). Ниже — внутренние сущности кода.

## Построитель атомарного действия (`atomic`, `src/claim.js`)

| Поле / метод | Что это |
|---|---|
| `sql` | условие в скобках `(cond)`; `cond` — выражение с закрытыми скобками (иначе `Error` при создании) |
| `args` | параметры условия (в порядке `?` в `cond`) |
| `guard` | `[sql, ...args]` — для построителей с параметрами `(guard, ...args)` |
| `and(more, ...moreArgs)` | построитель над тем же списком операторов с условием `(cond) AND (more)` |
| `enqueue(chatId, payload)` | сообщение в очередь при условии (`enqueueIfStmt`) |
| `audit(eventId, actor, action, details)` | запись журнала при условии (`auditIfStmt`) |
| `where(sql, ...params)` | оператор, текст которого оканчивается условием WHERE: `sql AND (cond)` |
| `select(sql, ...params)` | `INSERT … SELECT …` без WHERE: `sql WHERE (cond)` |
| `add(...stmts)` | операторы со своими условиями (построители `REGISTRY`, захват без условия помощника) |
| `claim(stmt)` | отметить оператор захвата (добавить, если его ещё нет); один на пакет |
| `run()` | `db.batch(операторы в порядке вызовов)` → `{ won, claim, results }`: `won` — захват изменил строки или вернул строку; `claim` — его результат |

Каждый метод добавления возвращает добавленный оператор (его можно отметить захватом). Порядок операторов в пакете —
порядок вызовов методов любого из построителей, полученных через `and()`.

**Правило порядка**: условие «по прежнему состоянию» — операторы **до** `claim`; условие «захват мой» (случайная версия,
отметка раскрытия, «завершено и записи `finish` нет», существование опоры) — операторы **после** захвата или опора —
последней.

## Условия атомарных действий

| Действие | Условие построителя | Где захват | Исход |
|---|---|---|---|
| `runDraw` | событие с `draw_token = <новый>` | первый: `UPDATE events … draw_done = 0 … AND <снимок>` | захват |
| `undoDraw` (обе отмены) | `draw_done = 0 AND draw_token = <новый>` | первый: `UPDATE events … draw_token = <прежний> … [AND CANCEL_COND]` | захват |
| `pairsVersion` после жеребьёвки | `draw_token = <новый>` | версия — первым оператором | `insertMember`: версия; `removeMember`: строка участника (последней) |
| `pairsVersion` до жеребьёвки | `draw_done = 0` | — | `removeMember`: строка участника (последней) |
| `removeMember` (остальное) | `and`: участник ещё в событии | — | строка участника |
| `revealAll` | `revealed = <случайное>` | первый: `UPDATE events SET revealed …` | захват |
| `finishEvent` | `status = 'finished' AND finished_at = now` и нет записи `finish` | первый | захват; запись `finish` — последней |
| `deleteEvent` | событие существует | строка события — последней | она |
| `transferAccount` | старая запись существует | запись старого аккаунта — последней | она |
| `participate` (выход) | `draw_done = 0` | запись журнала — первой | она |
| `decideRequest` | заявка `pending` (+ «принять»: регистрация открыта, событие идёт) | `UPDATE join_requests` — **последним** | захват |
| `setGiftReceived` | у пары подопечного `gift_received_at = 0` | `UPDATE pairs` — **последним** | — (ответ — успех) |
| `changeExclusions` | «до жеребьёвки» (владельцу — всегда) | — | — (повторное чтение события) |
| …журнал исключений | `and`: хотя бы одной добавляемой строки нет / удаляемая есть | перед изменениями | — |
| `take` | обращение открыто, `and`: ничьё | `UPDATE … assignee = 0` — **последним** | захват |
| `pass` | открыто, `and`: ведёт прежний | `UPDATE … assignee = <прежний>` — **последним** | захват |
| `closeByAdmin` / `closeByUser` | открыто (уведомления участника — `and`: ничьё или ведёт получатель) | `UPDATE … status = 'open'` — **последним** | захват |
| `sendFromAdmin` | открыто; взятие — `and`: ничьё; ответ — `and`: ведёт отвечающий | вставка ответа — **последней** (`RETURNING`) | строка ответа |
| `sendFromUser` | открыто (уведомления — `and`: ведёт 0 / ведёт получатель) | вставка сообщения — **последней** (`RETURNING`) | строка сообщения |

## Снимок жеребьёвки (`SNAPSHOTS`, `src/snapshots.js`)

Вход `data` (прочитан `checkDraw` одним пакетом): `ids` — зарегистрированные участники; `exclusions` — все исключения
события; `families` — все строки «человек — семья»; `fixed` — закреплённые пары события.

| Ключ | `js(data)` | `sql` (параметр — id события) |
|---|---|---|
| `members` | `n : Σ id` | зарегистрированные участники события |
| `exclusions` | `n : Σ giver : Σ receiver : Σ (giver mod M)(receiver mod M)` | `exclusions` события |
| `families` | `n : Σ (user mod M)(family mod M) : Σ family` по строкам людей из `ids` | `family_members` зарегистрированных участников |
| `fixed` | как `exclusions` | `fixed_pairs` события |

Суммы — по модулю `2^52` (JS: на каждом шаге; SQL: `COALESCE(SUM(x), 0) % 2^52`), `M = 1000003`. Пустой набор —
`0:0…`. `drawSnapshot(ev, data)` → `{ members, exclusions, families: ev.families_on ? … : '', fixed }`;
`snapshotGuard(eventId, snap)` → `{ sql, args }`: все четыре сравнения через `AND`, семьи — `(? = '' OR <sql> = ?)`.
