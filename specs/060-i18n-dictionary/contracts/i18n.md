# Контракт: тексты из словаря (060)

Действует для всего кода с 060. Источник истины о текстах для людей — словари `src/i18n/<язык>/`. Формат словарей,
отложенный текст, поля `me` — `data-model.md`.

## 1. Модуль `src/i18n/index.js`

| Имя | Что |
|---|---|
| `DEFAULT_LANG` | `'ru'` |
| `LANGUAGES` | список кодов языков с словарями (шаг 1: `['ru']`) |
| `DICTIONARIES` | `{ [язык]: { server, app, plural?, locale } }` — словари (тесты добавляют `xx`, R10) |
| `langOf(user)` | язык человека: `user?.lang` из `DICTIONARIES`, иначе `DEFAULT_LANG` |
| `t(lang, key, params)` | строка (правила — раздел 2) |
| `tl(lang, key)` | список строк (месяцы, дни недели) |
| `translator(lang)` | `(key, params) => t(lang, key, params)` с полями `lang`, `list(key)` |
| `tx(key, params)` | отложенный текст `{ $t, $p }` |
| `tdate(iso)` / `tdate(ms, offsetHours)` | отложенная дата `{ $d[, $o] }` |
| `tjoin(sep, parts)` | отложенная склейка `{ $j, $s }` |
| `render(value, lang)` | собрать отложенное в строках, массивах и объектах (строки и прочее — как есть) |
| `appTexts(lang)` | `{ version, texts }` — словарь `app.*` и его версия (готовится раз на экземпляр) |
| `bootTexts(lang)` | `{ ключ: значение }` для `app.boot.*` |

Импорты модуля — только словари; `format.js` берёт из него месяцы и общие тексты.

## 2. Сборка строки — `t`

1. Значение: `DICTIONARIES[lang]` (`server`, затем `app`) → то же у `DEFAULT_LANG` → иначе `console.error('i18n: нет
   ключа <key>')` и сам ключ.
2. Набор форм: категория `new Intl.PluralRules(plural ?? lang).select(params.n)`; нет формы — `other`; нет `n` —
   `console.error('i18n: …')` и `other`/первая форма.
3. Подстановки `{имя}` (имя — `[A-Za-z0-9_]+`): значение из `params` как строка; нет значения — `console.error` и `{имя}`
   как есть; лишний параметр (кроме `n` у набора форм) — `console.error`. Значение подстановки не экранируется —
   экранирует вызывающий (как сейчас).
4. Фигурные скобки без имени (`{`, `}` в тексте) — не подстановка.

`console.error('i18n: …')` у людей — только журнал Worker; в быстрых тестах «мир» бросает на нём исключение.

## 3. Где какой язык

| Где | Как |
|---|---|
| ответ API, отказ конвейера и обработчика | `ctx.t(key, params)` — язык вызывающего (`ctx.lang`); помощник без контекста — переводчик параметром |
| ответ бота в чате, `answerCallbackQuery` | `c.t` / `ctx.t` — язык того, кто пишет боту |
| сообщение другому человеку (`outbox`) | только отложенный текст: `msg(tx(…), appKeyboard(settings, tx(…), params))`; дата — `tdate`; собирается при отправке на языке получателя |
| подробность журнала (`audit…Stmt`, `.audit(…)`) | отложенный текст, собирается на `DEFAULT_LANG` при записи |
| страница `/setup`, команды и описание бота | `t(DEFAULT_LANG, …)` |
| cron | только очередь и журнал (отложенные тексты) |

Нельзя: `ctx.t` в тексте, который уходит другому человеку; готовая строка с текстом для людей в `enqueue`.

## 4. Контекст

`makeContext` (и `openContext`) добавляет `ctx.lang = langOf(me)` и `ctx.t`; привязанный контекст (`ctx.in`)
наследует их. Контекст без человека (cron) — `DEFAULT_LANG`.

## 5. Таблицы и семейства

- `ACTIONS` (`src/api.js`): `finished` — `true` или ключ отказа; `confirm` — `[ключ слова, ключ отказа]`; отказ не
  владельцу — ключ. Конвейер: `ctx.t(row.finished)`, слово — `confirmed(body, ctx.t(row.confirm[0]))`.
- `EVENT_PARAMS.beforeDraw` — ключ. `SWAP_RULES` — ключи `pairs.swapRule.<правило>`. Причины отказа жеребьёвки —
  `pairs.reason.<причина>`.
- `POSTCARDS`, `MASKS` (`src/looks.js`): у строки нет `title` — название `looks.card.<id>` / `looks.mask.<id>`;
  `maskLabel(id, t)`; `me.looks` отдаёт названия на языке вызывающего.
- Подписи журнала в приложении — `app.vault.audit.<код действия>` (коды — `docs/api.md`, «Коды журнала»).
- Семейство в коде пишется шаблоном с префиксом-литералом: `` t(`looks.card.${id}`) `` — проверка знает префикс и
  список кодов.

## 6. Приложение

- `02-core`: `let TEXTS = BOOT_TEXTS` (`const BOOT_TEXTS = /*@boot-texts*/null;` — сервер подставляет объект);
  `t(key, params)` — те же правила, что раздел 2 (нет ключа — сам ключ; ошибки — `console.error('i18n: …')`);
  `tl(key)` — список; `setTexts(d)` — из ответа `me` (`d.texts` → `TEXTS`, `d.texts_version` → `state.textsVersion`,
  `d.lang` → `state.lang`).
- `reloadMe` передаёт `{ texts: state.textsVersion }` и вызывает `setTexts(d)` до любого рендера.
- Разметка `01-shell.html` без текстов; заголовок, «Загрузка…», подпись «‹» ставит скрипт из `app.boot.*` до первого
  рендера.
- Тексты по-прежнему — только `textContent`/`h()`; значения словаря приложения — без HTML.
- `plural(n, one, few, many)` упраздняется — формы числа в словаре; `ownerWord()` — ключи `app.core.owner.*`
  (`nom`/`gen`/`dat`/`ins` × «владелец»/«владелец бота»).
- Версия `texts_version` не хранится между сеансами.

## 7. Правила переноса (как писать)

1. Ключ — по смыслу, область — файл кода (`pairs.swapNotice` в `src/i18n/ru/pairs.js`, `app.admin.drawConfirm` в
   `src/i18n/ru/app-admin.js`); одинаковый смысл в разных местах побайтно одинаковым текстом — один ключ (общие —
   `common.*` / `app.core.*`); ключ живёт в файле своей области, пользоваться им может любой модуль.
2. Текст словаря — побайтно прежний итог: пробелы, неразрывные пробелы, `«»`, `—`, эмодзи, `\n`.
3. Склейку из частей с условием — либо разные ключи на варианты, либо подстановка `{tail}` с вложенным текстом; не
   резать предложение на куски без смысла, если вариантов мало.
4. Формы числа — набор форм с `{n}`; число в тексте — тоже `{n}`.
5. Данные людей (названия, имена, письма, адреса) — только подстановкой, экранирование — как было.
6. Комментарии, `new Error(…)`, `console.*(…)` — не тексты для людей, остаются в коде.
7. Псевдоязык (R10) не должен ломаться: текст, который сравнивают с вводом человека (слово подтверждения), берётся из
   словаря в обоих местах.
