# Feature Specification: Тексты — из словаря (шаг 1 локализации)

**Feature Branch**: `060-i18n-dictionary`

**Created**: 2026-11-25

**Status**: Draft

**Input**: User description: "Шаг 1 локализации: все тексты для людей (бот, отказы и ответы API, сообщения очереди,
журнал, мини-приложение, /setup, команды и описание бота, наборы открыток и масок) выносятся из кода в словарь русского
языка; код берёт тексты только из словаря по ключу (с подстановками и формами множественного числа). Поведение и тексты
побайтно прежние — это проверяют существующие эталоны и тесты. Устройство рассчитано на 11 языков шага 2 (ru, en, es,
pt, fr, de, zh, it, tr, id, pl): язык — у вызова (у получателя сообщения), приложение получает словарь только своего
языка, а не все сразу. Тесты-страховки: кириллицы нет вне словарей, ключи используются и существуют. Язык человека,
выбор языка и переводы — шаг 2 (отдельная фича)."

Решения владельца (2026-11-25), которые определяют устройство, но выполняются в шаге 2: языки — русский, английский,
испанский, португальский, французский, немецкий, китайский (упрощённый), итальянский, турецкий, индонезийский,
польский; без языков с письмом справа налево и без хинди. Язык человека: выбранный им самим → язык Telegram, если он
есть в боте → русский для языков стран, где обычно понимают русский (белорусский, украинский, казахский и т. п.) →
английский для остальных. Нынешние люди без своего выбора получают язык Telegram — это нормально.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Для людей ничего не меняется (Priority: P1)

Участник, организатор, владелец комнаты и владелец бота после выката видят тот же бот и то же приложение: те же
сообщения, кнопки, подсказки, отказы, окна подтверждения, записи журнала, открытки и маски, страницу `/setup`, команды
и описание бота — слово в слово, с теми же формами множественного числа и датами.

**Why this priority**: шаг 1 — перестройка ради будущих языков; ни один человек не должен её заметить.

**Independent Test**: прогнать все существующие проверки (быстрые тесты, сквозной сценарий, проверки в Chrome) без
единой правки ожидаемых текстов — эталон отказов, тексты сообщений и экранов совпадают побайтно.

**Acceptance Scenarios**:

1. **Given** эталон отказов API (все ответы «без прав / нет события / завершено» и ключи 035–052), **When** прогон
   после переноса текстов, **Then** каждый ответ — тот же код и тот же текст побайтно, файл эталона не меняется.
2. **Given** сценарии бота (регистрация, приглашение, жеребьёвка, переписка, обращения, раскрытие, завершение,
   автодействия), **When** сообщения уходят из очереди, **Then** их текст, разметка и кнопки — прежние.
3. **Given** приложение в Chrome (все экраны прогона), **When** человек проходит прежние сценарии, **Then** подписи,
   подсказки, всплывающие сообщения и окна — прежние.
4. **Given** сообщения, поставленные в очередь прежней версией до выката, **When** их отправляет новая, **Then** они
   уходят как были.

---

### User Story 2 — Каждый текст для людей — в словаре (Priority: P1)

Разработчик (Claude) в следующих фичах — и в шаге 2 — добавляет или меняет текст только в словаре: в коде нет ни одного
текста для людей, только ключ и подстановки. Проверка падает и называет место, если текст для людей написан прямо в
коде, если код зовёт несуществующий ключ, если ключ словаря никем не используется или если подстановки ключа и вызова
не совпадают.

**Why this priority**: без полного переноса шаг 2 оставит часть экранов и сообщений по-русски у англоязычных людей;
без проверки тексты вернутся в код с первой же новой фичей.

**Independent Test**: вписать в часть приложения или модуль сервера строку с русским текстом, позвать ключ, которого
нет, или оставить ключ без использования — `npm test` падает и показывает файл и строку; убрать — проходит.

**Acceptance Scenarios**:

1. **Given** строка `ui.hint('Название события')` в части приложения, **When** `npm test`, **Then** проверка падает с
   местом (часть и строка).
2. **Given** русский текст только в комментарии, в сообщении исключения для разработчика или в данных базы (название
   «Основная» в миграции), **Then** проверка проходит.
3. **Given** вызов ключа, которого нет в словаре, или ключ словаря, который никто не зовёт, **Then** проверка падает и
   называет ключ.
4. **Given** вызов передаёт подстановки, которых нет в тексте ключа (или не передаёт нужную), **Then** проверка
   падает.
5. **Given** правила слов (013 — «событие», 059 — «комната»), **When** их проверяют, **Then** проверяются тексты
   словаря, место нарушения — ключ.

---

### User Story 3 — Язык у каждого вызова и получателя (Priority: P2)

Устройство готово к шагу 2: ответ приложению и боту собирается на языке того, кто обратился; сообщение другому
человеку — на языке получателя в момент отправки из очереди; приложение получает от сервера словарь только своего
языка. Язык человека хранится у него; пока его никто не ставит, у всех — русский. Новый язык — это файлы словаря и
строка в списке языков, без правки кода.

**Why this priority**: иначе шаг 2 снова прошёл бы по всем местам с текстами; сама по себе людям ничего не даёт.

**Independent Test**: в тестах завести служебный псевдоязык, где каждый текст словаря помечен, и поставить его одному
человеку: всё, что этот человек видит (экраны приложения, отказы, сообщения бота ему, кнопки), — помеченные тексты, кроме
данных людей (имена, названия, письма); остальные люди в том же сценарии видят русский.

**Acceptance Scenarios**:

1. **Given** у Ани псевдоязык, у Бори — нет, **When** проходит жеребьёвка, **Then** Аня получает помеченное сообщение и
   помеченную кнопку, Боря — прежнее русское.
2. **Given** у организатора псевдоязык, **When** он делает запрещённое действие, **Then** отказ — помеченный.
3. **Given** у Ани псевдоязык, **When** она открывает приложение, **Then** сервер отдаёт словарь только этого языка, а
   все подписи экрана — помеченные; повторные запросы того же сеанса словарь не повторяют.
4. **Given** человеку поставлен язык, которого нет в списке, или в словаре языка нет ключа, **Then** текст берётся из
   русского словаря, ошибки нет.

---

### Edge Cases

- Тексты с разметкой (жирный, ссылки в сообщениях бота): разметка — часть текста словаря; подставляемые значения
  (названия, имена) экранируются, как раньше.
- Данные людей — название события и комнаты, имена, письма, переписка, объявления, адреса, названия семей — в словарь
  не попадают и не переводятся.
- Формы числа: «1 участник / 2 участника / 5 участников» — по правилам языка (у русского три формы), итог побайтно
  прежний на всех числах сценариев и на 0–200.
- Даты и названия месяцев («25 ноября», календарь автожеребьёвки с днями недели) — из словаря или правил языка, итог
  прежний.
- Слова подтверждения («ОТКРЫТЬ», «ВЫЙТИ», «УДАЛИТЬ», «ОТМЕНА») — тексты словаря; сервер проверяет слово на языке
  того, кто подтверждает, — сейчас русское.
- Один текст в нескольких местах (например, «только для чтения» в API, боте и приложении — 034) — один ключ, совпадение
  обеспечено словарём.
- Тексты по коду (подписи журнала по коду действия, причины отказа жеребьёвки, правила обмена, названия открыток и масок
  по `id`) — семейства ключей; проверка требует ключ для каждого кода.
- Записи журнала, уже сохранённые в базе с подробностью («участников: 5»), и новые записи — подробность пишется по-русски,
  как сейчас; перевод подробностей — шаг 2.
- Сообщения в очереди, поставленные прежней версией, — уходят как есть. После отката на прежнюю версию сообщения,
  поставленные новой и ещё не отправленные, прежняя версия отправить не сможет (окно — минуты; выкат — `quickstart.md`).
- До ответа сервера приложение показывает только экран загрузки; тексты, нужные до ответа или без него («Загрузка…»,
  «Открой через Telegram», ошибка сети при запуске), — короткий встроенный набор.
- Страница `/setup` и команды, описание и кнопка меню бота, которые она ставит, — тексты словаря, русские.
- Название «Основная» компании № 1 (миграция 0015) и прочие данные в базе — не тексты кода, не меняются.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-6001**: Все тексты для людей — сообщения бота и их кнопки, ответы и отказы API, подписи и подсказки
  мини-приложения (включая разметку страницы, всплывающие сообщения, окна Telegram, подписи кнопок и полей, записи
  журнала, календарь, формы числа, месяцы), страница `/setup`, команды, описание и кнопка меню бота, названия открыток и
  масок, слова подтверждения, тексты подробностей журнала — берутся из словаря языка по ключу.
- **FR-6002**: Русский словарь содержит все тексты; для людей всё остаётся побайтно прежним (US1): эталоны и ожидаемые
  тексты тестов не меняются.
- **FR-6003**: Текст словаря поддерживает подстановки по имени, формы числа по правилам языка и вложенные тексты
  (подстановка, которая сама — текст словаря); подставляемые данные людей экранируются там же, где сейчас.
- **FR-6004**: Ответ на вызов (API, ответ бота в чате, страница `/setup`) собирается на языке вызывающего; сообщение
  в очереди хранит ключи и подстановки и собирается на языке получателя в момент отправки; сообщения прежнего вида
  (готовый текст) отправляются как есть.
- **FR-6005**: Язык человека хранится в его записи; пустое значение — язык по умолчанию (русский). В шаге 1 язык
  никто не ставит, кроме тестов; ставить его по Telegram и выбором человека — шаг 2.
- **FR-6006**: Приложение получает словарь только своего языка в ответе сервера при запуске; повторные запросы того же
  сеанса словарь не передают, пока язык не сменился. До ответа — встроенный набор нескольких текстов. Политика
  безопасности страницы (032) и число запросов к Worker при запуске не меняются.
- **FR-6007**: Если у языка нет ключа или язык неизвестен — текст из русского словаря; ошибки и пустого текста нет.
- **FR-6008**: Список языков — одно место; язык из списка без словаря не бывает (проверка). В шаге 1 в списке только
  русский; псевдоязык подключают только тесты.
- **FR-6009**: Проверка `npm test` падает с местом, если: вне словарей в коде сервера или в склейке приложения есть
  кириллица (кроме комментариев, сообщений исключений и журнала Worker для разработчика и явно перечисленных данных);
  код зовёт ключ, которого нет; ключ словаря не используется; подстановки вызова и текста не совпадают; у кода из
  семейства (журнал, причины, правила, открытки, маски) нет ключа. У каждого правила — проверка «от противного».
- **FR-6010**: Правила слов (013 «событие», 059 «комната», `ownerWord` 051) проверяются по текстам словаря; текст,
  который должен совпадать в API, боте и приложении (034), — один ключ.
- **FR-6011**: Число запросов к базе и к Telegram в сценариях — не больше прежнего; словарь готовится один раз на
  экземпляр Worker, вызов укладывается в лимит CPU бесплатного тарифа.
- **FR-6012**: Документы: `docs/api.md` (поля ответа `me` со словарём, язык ответов), `CLAUDE.md` (жёсткое правило
  «тексты для людей — только в словаре», структура), README — если меняются шаги выката (миграция).

### Key Entities

- **Словарь языка**: все тексты одного языка — тексты сервера и тексты приложения; ключ → текст или набор форм числа.
- **Ключ текста**: имя текста, одно на смысл; семейства ключей — тексты по коду (журнал, причины, открытки, маски).
- **Язык человека**: значение в записи человека; пусто — русский. Источник языка вызова и получателя сообщения.
- **Отложенный текст**: ключ и подстановки в сообщении очереди; собирается в текст при отправке.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-6001**: 0 текстов для людей вне словаря — проверка находит 0 нарушений в модулях сервера и в склейке приложения.
- **SC-6002**: Эталон отказов API — все ответы побайтно прежние, файл эталона не изменён; ожидаемые тексты остальных
  тестов не переписаны (меняются только проверки, которые искали текст в исходном коде, — теперь ищут в словаре).
- **SC-6003**: Человек с псевдоязыком в сценариях быстрых тестов и в Chrome видит 0 русских текстов, кроме данных людей;
  люди без языка в тех же сценариях — 0 изменений.
- **SC-6004**: Число запросов к базе и Telegram в сценариях `queries` — не больше базовых; ни одного `budget exceeded`.
- **SC-6005**: Добавить язык в шаге 2 — файлы словаря и строка списка; ни одной правки мест, где тексты используются
  (проверено псевдоязыком).

## Assumptions

- Шаг 1 не меняет то, что видят люди; Конституция (принцип «интерфейс на русском») меняется в шаге 2 вместе с выбором
  языка.
- Язык человека хранится уже в шаге 1 (новая колонка, миграция до выката, прежний код с ней работает): без него не
  проверить, что сообщения собираются на языке получателя. Пустое значение — русский; шаг 2 добавит язык Telegram и
  выбор человека.
- Подробности записей журнала пишутся в базу текстом по-русски, как сейчас (из словаря); хранить их без языка и
  переводить при показе — шаг 2.
- Страница `/setup` до шага 2 — по-русски (язык вызывающего неизвестен, по умолчанию русский).
- Сообщения исключений для разработчика (`new Error`), журнал Worker (`console`), комментарии, спецификации, тесты и
  данные базы — не тексты для людей.
- Витрина дизайн-системы (`preview.html`) — для разработчика, не текст для людей; скрипт поля с крестиком, который
  встраивается в страницу, — текст для людей.
- Откат на прежнюю версию после выката теряет только сообщения, поставленные новой версией и ещё не отправленные
  (минуты); это допустимо, порядок выката — в `quickstart.md`.
