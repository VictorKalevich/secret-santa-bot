## Контекст

При разрезе мини-приложения на части (021) нашлись семь недочётов; они записаны в `docs/todo.md` («Ждёт проверки на
iPhone» → «Недочёты интерфейса»). Каждый меняет поведение приложения, поэтому — отдельная фича. Сервер, API, тексты бота
и журнал не меняются.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Панель организатора показывает актуальные данные (Priority: P1)

Организатор меняет название события в «Параметрах» и сохраняет. Панель сразу строится по сохранённым данным: в
подтверждении «Удалить из события» и в списке «Удалить событие» — новое название; экран остаётся на том же месте (у
«Параметров»), загрузчик не мигает. Если, пока панель открыта, событие завершили (другой организатор или
автозавершение), то при следующей перерисовке панели «Опасная зона» предлагает только удалить событие (сбросить
завершённое нельзя), а вверху панели — плашка «Событие завершено». Журнал из панели — всегда журнал того события, чья
это панель.

**Why this priority**: подтверждение с устаревшим названием вводит в заблуждение перед необратимым действием; кнопка,
которую сервер отклонит, — ошибка интерфейса.

**Independent Test**: в браузере открыть панель, сменить название, сохранить, открыть «⋯» участника → «Удалить из
события» — текст окна с новым названием; завершить событие запросом со стороны, переключить вкладки — в «Опасной зоне»
нет «Полный сброс», есть плашка «завершено».

**Acceptance Scenarios**:

1. **Given** панель идущего события «Старое», **When** организатор вводит название «Новое» и нажимает «Сохранить»,
   **Then** — «Сохранено», заголовок «Новое», подтверждение удаления участника — «…из события «Новое»?», список
   удаляемого в «Удалить событие» — «событие «Новое» целиком…», кнопка «Сохранить» остаётся видна на экране (страница
   не прокручена к началу).
2. **Given** несохранённый черновик объявления, **When** сохраняются параметры, **Then** черновик объявления остаётся
   (как при других действиях панели).
3. **Given** владелец открыл панель идущего события, **When** событие завершают со стороны и панель перерисовывается
   (переход на другую вкладку и обратно), **Then** в «Опасной зоне» — только «Удалить событие» с текстом для
   завершённого события, вверху — плашка «🏁 Событие завершено …».
4. **Given** панель события X, **When** нажата кнопка «📜 Журнал действий» панели, **Then** открывается журнал
   события X.

### User Story 2 — Шторки не мешают друг другу (Priority: P1)

Организатор открывает обращение участника; пока оно загружается, закрывает его и открывает журнал. Журнал остаётся
«Журналом события» — заголовок «Обращение: …» на него не попадает. Опрос новых сообщений (раз в 6 секунд) идёт только
у открытой шторки, которой он принадлежит: закрыта или заменена — опрос останавливается.

**Why this priority**: чужой заголовок на шторке — видимая ошибка; лишний опрос — лишние запросы к бесплатному тарифу.

**Independent Test**: в браузере задержать ответ обращения, за это время открыть журнал, отпустить ответ — заголовок
журнала прежний.

**Acceptance Scenarios**:

1. **Given** ответ «обращение» задержан, **When** шторку обращения закрыли и открыли журнал, а затем ответ пришёл,
   **Then** заголовок открытой шторки — «Журнал события».
2. **Given** открыта шторка обращения, **When** ответ пришёл, **Then** её заголовок — «Обращение: <имя>» (как сейчас).
3. **Given** опрос шторки (переписка, обращения участника, обращение), **When** открыта другая шторка или ни одной,
   **Then** запросы этой шторки больше не уходят.

### User Story 3 — Нет вечного загрузчика (Priority: P1)

Если при построении вкладки «Подопечный» или «Админ» что-то сломалось уже после показа загрузчика (например, сервер
вернул неполный ответ), участник видит экран «Не получилось загрузить» с кнопкой «Попробовать снова» (и «К списку
событий»), а не загрузку без конца. То же — когда экран обновляется после закрытия шторки. Ошибка обновления после
закрытия шторки не теряется молча: если экран уже показан, она видна сообщением внизу экрана.

**Why this priority**: вечная загрузка — тупик: на iPhone пользователю остаётся только закрыть приложение.

**Independent Test**: в браузере подменить ответ панели неполным — на экране ошибка с «Попробовать снова»; вернуть
нормальный ответ и нажать — панель строится.

**Acceptance Scenarios**:

1. **Given** ответ панели неполный, **When** открыта вкладка «Админ», **Then** — «Не получилось загрузить» с кнопкой
   «Попробовать снова», загрузчика нет; после исправного ответа повтор строит панель.
2. **Given** открыта шторка обращения из панели и ответ панели неполный, **When** шторку закрывают (панель
   перерисовывается), **Then** — экран ошибки, а не загрузчик.
3. **Given** ошибка относится к экрану, который пользователь уже покинул, **When** она случилась, **Then** новый экран
   не заменяется ошибкой.

### User Story 4 — Подтверждения не обрезаются (Priority: P2)

Перед необратимыми действиями приложение спрашивает подтверждение окном Telegram; в окне помещается не больше 250
символов. Все тексты подтверждений приложения помещаются в этот предел даже при самых длинных именах (40 символов),
названиях семей (40) и названиях событий (80); новый текст, который при каких-то данных не поместился бы, не проходит
тест. Если текст всё же длиннее (данные вне известных пределов), конец заменяется «…» — видно, что текст обрезан.

**Why this priority**: сейчас длинных текстов нет (худший случай — ровно 250), это защита от будущих правок.

**Independent Test**: тест считает худший случай каждого подтверждения; добавить в пример слишком длинный текст — тест
его находит.

**Acceptance Scenarios**:

1. **Given** все подтверждения приложения, **When** подставлены самые длинные имена, названия и числа, **Then** каждый
   текст — не длиннее 250 символов.
2. **Given** текст длиннее 250 символов, **When** он показывается окном Telegram, **Then** окно получает 250 символов,
   последний — «…».
3. **Given** подставляемое значение без известного предела (новое поле), **When** запущен тест, **Then** он падает и
   называет это место.

### User Story 5 — Код без копий и с полным начальным состоянием (Priority: P3)

Поле ответа (текст, «Отправить», счётчик символов) строится одним помощником — и в переписке Санты и подопечного, и в
обращениях. Блоки «Исключения» и «Закреплённые пары» в панели строятся одним помощником: список «кто — кому» (взаимные —
одной строкой, ✕ — убрать), форма «Кто дарит… / кому… / и наоборот / добавить». Для людей ничего не меняется: та же
разметка, те же тексты, те же запросы. Начальное состояние приложения содержит все поля, которые приложение читает.

**Why this priority**: внутренний порядок — исправления одного места больше не нужно повторять во втором.

**Independent Test**: скриншоты панели до и после (исключения, закреплённые пары, переписка, обращения) совпадают,
кроме времени в подписях; тест находит вторую копию поля ответа и второй разбор пар правил.

**Acceptance Scenarios**:

1. **Given** скриншоты до правок, **When** сняты скриншоты после, **Then** экраны совпадают, кроме текстов времени
   («сегодня в …»).
2. **Given** переписка Санты, **When** набран текст длиннее 3500 символов, **Then** счётчик «N / 4000» виден, при
   превышении — красный и «Отправить» недоступна (как раньше).
3. **Given** исключения и закреплённые пары, **When** добавить и убрать пару, **Then** запросы, сообщения
   («Исключение добавлено», «Пара закреплена», «Закреплённая пара убрана»), флажок «и наоборот» (у исключений включён,
   у закреплённых выключен и пропадает при кольцевой) — как раньше.

---

### Edge Cases

- Сохранение параметров не прошло (сервер отказал) — панель не перестраивается, черновик параметров остаётся, сообщение
  об ошибке (как сейчас).
- Сохранили параметры, а повторное чтение панели не удалось — экран ошибки с «Попробовать снова» (как после других
  действий панели).
- Событие завершили со стороны, а панель не перерисовывалась — прежняя кнопка «Полный сброс» на экране остаётся до
  перерисовки; сервер её отклонит (как сейчас). Исправление — для перерисованной панели.
- Шторку обращения открыли и сразу закрыли, ответ не пришёл совсем — опрос не идёт, заголовков не трогает.
- Ошибка обращения (нет доступа) — опрос этой шторки останавливается (как сейчас).
- Ошибка построения экрана повторяется на каждом «Попробовать снова» — каждый раз экран ошибки, без загрузчика.
- Имя длиннее 40 символов из старых данных (до проверки длины) — подтверждение, если не помещается, обрезается с «…».
- Старые клиенты Telegram без окна подтверждения (до 6.2) и браузер — обычное окно браузера с полным текстом (как
  сейчас).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: После успешного «Сохранить» в «Параметрах» панель события MUST строиться заново по свежим данным
  сервера: название и параметры во всех текстах панели (подтверждения, список удаляемого, текст «Отправить в чат»,
  служебный просмотр) — новые; заголовок и список событий на главном экране — новые.
- **FR-002**: Перестройка после сохранения параметров MUST проходить без загрузчика и без прокрутки к началу: экран
  остаётся на том же месте.
- **FR-003**: Все данные события в панели MUST браться из её собственного ответа и её события: кнопка журнала открывает
  журнал события этой панели; «Опасная зона» выбирает «только удалить» или «сброс и удаление» по статусу из ответа
  панели; плашка «завершено» в панели — по статусу из ответа панели.
- **FR-004**: Заголовок «Обращение: <имя>» MUST ставиться только шторке этого обращения; на другие шторки он не попадает,
  даже если ответ пришёл после того, как открыли другую.
- **FR-005**: Опрос раз в 6 секунд (переписка Санты и подопечного, обращения участника, обращение в панели) MUST идти,
  только пока открыта шторка, которой он принадлежит; закрыта или заменена — опрос останавливается.
- **FR-006**: Сбой построения вкладок «Подопечный» и «Админ» (и любой вкладки события) MUST показывать экран «Не
  получилось загрузить» с «Попробовать снова», а не оставлять загрузчик; для покинутого экрана ошибка не рисуется.
- **FR-007**: Отказ обновления экрана после закрытия шторки MUST не теряться молча: экран ошибки (если перерисовка
  вкладки не удалась) или сообщение внизу экрана (если не удалось остальное).
- **FR-008**: Начальное состояние приложения MUST содержать все поля состояния, которые приложение читает или пишет
  (в т.ч. список объявлений — пустой).
- **FR-009**: Каждый текст подтверждения приложения MUST помещаться в предел окна подтверждения (250 символов) при
  самых длинных подставляемых данных: имя человека — 40, название семьи — 40, название события — 80, число участников —
  3 цифры; тест считает худший случай и называет место нарушения; подставляемое значение без известного предела — тоже
  нарушение.
- **FR-010**: Текст длиннее предела MUST показываться обрезанным с «…» в конце (250 символов вместе с «…»), не молча; в
  обычное окно браузера (без окна Telegram) текст уходит целиком, как сейчас.
- **FR-011**: Поле ответа (текст, «Отправить», счётчик) MUST строиться одним помощником в переписке Санты и подопечного
  и в обращениях; разметка, счётчик, доступность «Отправить», очистка после отправки — прежние.
- **FR-012**: Блоки «Исключения» и «Закреплённые пары» MUST строиться одним помощником (разбор взаимных пар, список с
  ✕, форма выбора двух людей); тексты, порядок элементов, значения флажка «и наоборот», сообщения, запросы и правила
  «только чтение» (исключения — после жеребьёвки для админа; закреплённые — после жеребьёвки для всех) — прежние.
- **FR-013**: Вид приложения MUST не меняться, кроме исправляемых мест: скриншоты до и после совпадают, кроме текстов
  времени.
- **FR-014**: Каждое исправленное поведение MUST иметь свою автоматическую проверку, которая падает до правки и
  проходит после (по образцу проверки кнопок 024), и проверку «от противного» (нарушение в примере находится).
- **FR-015**: Сервер, API, тексты бота, журнал, схема базы и число запросов к базе MUST не меняться.

### Key Entities

- **Панель события** — экран организатора одного события, строится по одному ответу сервера (параметры, участники,
  правила пар, заявки, обращения).
- **Шторка** — окно поверх экрана (обращение, переписка, журнал, меню участника…); открыта не больше одной; у
  шторки с перепиской — свой опрос.
- **Подтверждение** — окно «ОК / Отмена» перед действием; текст — до 250 символов.
- **Правило пары** — исключение («А не дарит Б») или закреплённая пара («А дарит Б»); взаимные показываются одной строкой.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: После сохранения параметров 100 % текстов панели с названием события показывают новое название без
  повторного открытия экрана; экран не прокручивается к началу.
- **SC-002**: В панели завершённого события (в т.ч. завершённого, пока панель была открыта) 0 кнопок «Полный сброс».
- **SC-003**: Заголовок «Обращение: …» ни разу не появляется на шторке другого вида (проверка с задержанным ответом).
- **SC-004**: 0 случаев вечного загрузчика при сбое построения вкладки: в проверке с неполным ответом экран ошибки
  появляется не позже чем через 3 секунды.
- **SC-005**: Худший случай каждого подтверждения — ≤ 250 символов; тест находит текст длиннее.
- **SC-006**: Поле ответа и блоки правил пар — по одной копии в коде приложения; скриншоты до и после совпадают, кроме
  времени.
- **SC-007**: Все прежние проверки (`npm test`, `npm run test:e2e`, `npm run screenshots`) зелёные; новые проверки
  падают на коде до правок.

## Assumptions

- Исправляется только мини-приложение (`src/app/`); сервер, `docs/api.md`, README (установка, команды, роли, работа с
  ботом не меняются) — без изменений. Тексты для людей прежние — новых нет.
- Проверки по образцу 024 — проверки кода склейки в `npm test` (быстро, без браузера); поведение, которое видно только в
  браузере (перестройка панели, заголовок шторки при задержанном ответе, экран ошибки вместо загрузчика, «Опасная зона»
  завершённого события), дополнительно проверяется в Chrome в `npm run screenshots` — там же, где проверки шторки и
  полей даты (011).
- Перестройка после сохранения параметров — та же, что после других действий панели (свежие событие, список событий,
  заголовок, вкладки), но без загрузчика и с сохранением места на экране: иначе после «Сохранить» внизу панели экран
  прыгал бы к началу — этого раньше не было.
- Плашка «завершено» в панели берётся из ответа панели (в нём есть статус, время завершения и срок переписки); строка
  «Переписка открыта до …» по-прежнему зависит от того, участвует ли организатор (данные экрана события).
- Заголовок шторки события (вверху приложения) после завершения события со стороны обновится при следующем открытии
  события — исправляется только панель.
- Предел 250 (у Telegram 256) — прежний; пределы данных берутся из проверок сервера и бота: имя и название семьи — до 40,
  название события — до 80. Для числа участников — до трёх цифр (жеребьёвка рассчитана на сотни человек).
- Обычное окно браузера (без Telegram или Telegram до 6.2) — полный текст, как сейчас; переход длинных текстов в
  обычное окно в Telegram не делается: на iOS такое окно может не показаться, и подтвердить было бы нельзя.
- Проверка на iPhone: правки меняют поведение приложения в Telegram для iOS (WebKit), а локально проверяется только
  Chrome; после выката владелец проверяет по инструкции (`quickstart.md`), откат — прежняя версия Worker.
