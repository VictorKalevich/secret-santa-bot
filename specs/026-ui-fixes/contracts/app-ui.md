# Контракт: помощники мини-приложения и правила проверки `app-ui` (026)

Внутреннее устройство частей `src/app/` после фичи 026. API сервера не меняется (`docs/api.md` — прежний).

## Помощники

| Помощник | Часть | Что делает |
|---|---|---|
| `CONFIRM_MAX = 250` | `02-core.js.txt` | предел текста окна подтверждения Telegram (у Telegram — 256 после обрезки пробелов) |
| `confirmBox(text)` | `02-core.js.txt` | Telegram 6.2+: `showConfirm` с текстом не длиннее `CONFIRM_MAX`; длиннее — первые `CONFIRM_MAX − 1` символов + «…»; иначе `window.confirm(text)` целиком |
| `screen(build)` | `03-home.js.txt` | асинхронный экран: `async (...args)`; отказ `build` → `showError(e)`, если `state.nav` не изменился; возвращает результат `build` |
| `render()` | `03-home.js.txt` | исключение вкладки или главного экрана → `showError(e)` |
| `renderWard`, `renderAdmin` | `04-event.js.txt`, `05-admin.js.txt` | объявлены через `screen(...)`; `renderAdmin({ quiet })` — `quiet: true`: без загрузчика, после замены панели прокрутка прежняя |
| `finishedNotice(e = state.ev)` | `04-event.js.txt` | плашка «завершено» по событию `e`; панель передаёт своё `s` |
| `openSheet(title, content, opts)` | `07-sheet-chat.js.txt` | возвращает свою шторку (`ds-sheet-backdrop`); `title` — строка или узел |
| `closeSheet()` | `07-sheet-chat.js.txt` | вызывает `onClose` с перехватом: исключение или отказ обещания → `toast('⚠️ ' + e.message)` |
| `poll(own, load)` | `07-sheet-chat.js.txt` | единственный `setInterval`: раз в 6 с `load()` (ошибки молча), пока `sheetEl === own`; иначе снимает себя; возвращает таймер |

## Правила проверки `tests/app-ui.test.mjs`

Проверяется склейка `APP` (`tests/support/app-source.mjs`); место нарушения — `where(n)` (часть и строка). Каждое
правило — функция, возвращающая список нарушений; тест — «нарушений нет» и «от противного» (пример с нарушениями
находится, исправленный — нет).

| № | Правило | Нарушение |
|---|---|---|
| 1 | Обработчик, который сохраняет параметры (`xapi('admin.game', values())`), перестраивает панель | в блоке нет `refresh(` или `again(` |
| 2 | Тело `renderAdmin` берёт событие только из своего ответа | `state.ev`, `state.can`, `state.evId` (кроме `evId = state.evId`), `finished()`, `eapi(`, `finishedNotice()` без аргумента |
| 3 | `sheetEl` знают только `openSheet`, `requestCloseSheet`, `closeSheet`, `poll`, `syncBack`, объявление `let sheetEl` и обработчик `BackButton.onClick`; `setInterval` — только в `poll` | `sheetEl` или `setInterval(` в другом месте |
| 4 | Асинхронный экран — через `screen(...)`; `render` перехватывает ошибку вкладки; `closeSheet` перехватывает отказ `onClose` | `async function render…`; в `render` нет `catch` с `showError`; в `closeSheet` нет `.catch(` |
| 5 | Каждое поле `state.X` объявлено в начальном литерале `const state = {…}` | поле, которого нет в литерале |
| 6 | Худший случай текста каждого `confirmBox(...)` ≤ `CONFIRM_MAX` | длиннее; подстановка без известного предела |
| 7 | Одна сборка поля ответа и одна — правил пар | `ds-composer__input` больше одного раза; разбор взаимных пар (`x.giver === … && x.receiver === …`), `'и наоборот (в обе стороны)'`, `'Выбери двух людей'`, `'Нужны два разных человека'` — больше одного раза |

Тело блока — по отступам: от строки начала до первой следующей строки с тем же отступом, которая начинается с `}` или
`)`.

### Худший случай подтверждения (правило 6)

| Подстановка | Предел | Откуда |
|---|---|---|
| имя человека (`u.name`, `t.name`, `u.name \|\| 'без имени'`) | 40 | бот и `admin.rename`: «от 1 до 40 символов» |
| название семьи (`f.name`) | 40 | `admin.family.save` |
| название события (`s.title`) | 80 | создание и параметры события |
| число (`c.count`, `k`) | 3 | сотни участников |
| `a \|\| b`, `x ? a : b` | длиннейшая ветвь | |
| `plural(n, a, b, c)` | длиннейшая форма | |
| `const`/`let` в той же функции (и `x += …` до вызова) | худший случай определения | |
| `title` у `typed(...)` | длиннейший заголовок вызовов `typed('…'` | |

Остальное — нарушение «подстановка без известного предела: `…`» — новый текст требует строки в таблице теста.

## Проверки в браузере (`tests/screenshots.mjs`, `checkUiFixes`)

Запускаются после всех снимков на отдельном событии «Проверка» (и на событии A для обращений), снимки не меняются.
Нарушения добавляются в общий список, скрипт завершается с кодом 1.

| Проверка | Сценарий | Ожидание |
|---|---|---|
| сохранение параметров | новое название → «Сохранить» → «⋯» участника → «Удалить из события» | текст окна — с новым названием; кнопка «Сохранить» параметров в видимой области |
| завершено со стороны | панель открыта → `admin.event.finish` запросом → «Инфо» → «Админ» | нет «Полный сброс», есть «Удалить событие» и плашка «Событие завершено» |
| заголовок своей шторки | ответ `admin.support.get` задержан → ✕ → «Журнал действий» → ответ отпущен | заголовок шторки — «Журнал события» |
| без вечного загрузчика | ответ `admin.state` — `{"ok":true}`: вкладка «Админ»; закрытие шторки обращения | экран «Не получилось загрузить», загрузчика нет; «Попробовать снова» с исправным ответом строит панель |
