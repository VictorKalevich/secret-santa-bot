# Research: недочёты интерфейса мини-приложения (026)

Места в коде — по именам функций (номера строк `docs/todo.md` — для коммита `5d8cc0e`). Все правки — в частях
`src/app/`; сервер не меняется.

## R1. Панель после «Сохранить» в «Параметрах»

**Сейчас.** `saveGame` (`renderAdmin`, `src/app/05-admin.js.txt`): `admin.game` → `reloadEvent` → `reloadMe` →
`renderHero()`. Панель не перестраивается: тексты, собранные из `s` (ответ `admin.state` до сохранения), остаются
старыми — подтверждение удаления участника (`«…» из события «${s.title}»`), список удаляемого у «Удалить событие»,
текст «Отправить в чат», служебный просмотр (`openVaultGate(evId, s, …)`).

**Decision.** После успешного сохранения — `refresh({ quiet: true })`: те же шаги, что у других действий панели
(`reloadMe`, `reloadEvent`, заголовок, вкладки, `again`), но перестройка «тихая»: без загрузчика, старая панель на
экране до прихода ответа, после замены — прежняя прокрутка (`window.scrollTo(0, y)`). `renderAdmin` получает параметр
`{ quiet }`, `again(opts)` и `refresh(opts)` его передают. Черновик параметров удаляется до перестройки (как сейчас),
черновик объявления остаётся (`state.drafts`).

**Rationale.** Все тексты панели строятся в одном месте — перестройка исправляет их разом, без списка «что обновить».
Без «тихого» режима панель после «Сохранить» (внизу страницы) показала бы загрузчик и прыгнула к началу — раньше этого не
было, а спецификация требует не менять вид, кроме исправляемого места.

**Alternatives considered.** Подменить поля `s` сохранёнными значениями — сервер нормализует ввод (обрезка, пустые
даты), а прочие тексты (заголовок, список событий) всё равно нужно перечитать. Обычный `again()` — прыжок к началу и
мигание загрузчика.

## R2. Панель — только из своего ответа

**Сейчас.** В `renderAdmin`: кнопка журнала — `openAudit(state.evId)` (событие экрана, а не панели); «Опасная зона» —
`finished()` (статус `state.ev` от прошлого `event.get`), хотя рядом `done` из свежего `admin.state`; плашка вверху —
`finishedNotice()` тоже по `state.ev`. Если событие завершили со стороны, а панель перерисовалась (переход между
вкладками — `render()` без `reloadEvent`), панель — в виде «завершено» (`done`), но без плашки и со «сбросом» в «Опасной
зоне»; сервер сброс отклонит.

**Decision.** `openAudit(evId)`; «Опасная зона» — по `done`; плашка — `finishedNotice(s)`: функция получает событие
параметром (по умолчанию `state.ev`), в ответе панели есть всё нужное (`status`, `finished_at`, `chat_until` —
`publicEvent`). Строка «Переписка открыта до …/только для чтения» по-прежнему — по `state.can.chat_write` (участвует ли
организатор; для события, завершённого не больше 7 суток назад, значение то же, что у свежего ответа). Правило теста: в
теле `renderAdmin` нет `state.ev`, `state.evId` (кроме захвата `evId = state.evId`), `state.can`, `finished()`,
`eapi(`, `finishedNotice()` без аргумента.

**Rationale.** Захваченные `evId` и `d` — уже принятое правило панели (009: «экран строится для эвента evId»); три места
его нарушали.

**Alternatives considered.** Перечитывать событие (`reloadEvent`), когда статус в ответе панели другой, — лишний
запрос и ещё одна ветка ради шапки, которая обновится при следующем открытии события (допущение спецификации).

## R3. Заголовок и опрос — только своей шторки

**Сейчас.** `openSupportThread.load` ставит заголовок `sheetEl.querySelector('.ds-sheet__title')` — шторке, открытой в
момент ответа. Опрос (`openChat`, `openSupport`, `openSupportThread`) — `setInterval(() => { if (sheetEl) load() }, 6000)`
— «открыта какая-то шторка». Интервал снимает `onClose`, так что лишний опрос — только при сбое порядка закрытия; а
заголовок на чужой шторке воспроизводится: ответ обращения пришёл после того, как шторку закрыли и открыли журнал.

**Decision.**
- `openSheet(...)` возвращает свою шторку (элемент `ds-sheet-backdrop`); заголовок может быть узлом — `h()` вставляет
  его как есть.
- `openSupportThread` передаёт заголовком свой текстовый узел и меняет только его (`titleText.data = 'Обращение: …'`) —
  шторку не ищет.
- `poll(own, load)` — единственный `setInterval` приложения: раз в 6 секунд `load()`, пока `sheetEl === own`; иначе
  интервал снимает себя сам. `onClose` по-прежнему снимает его сразу при закрытии.
- Правило теста: `sheetEl` знают только функции ядра шторки — `openSheet`, `requestCloseSheet`, `closeSheet`, `poll`,
  `syncBack` и обработчик системной кнопки «Назад»; `setInterval` — только в `poll`.

**Rationale.** Шторка — «владелец» своего заголовка и опроса; общий указатель «открытая шторка» нужен только ядру.

**Alternatives considered.** Сверять в `load` «открыта ли моя шторка» перед установкой заголовка — та же проверка,
размноженная по функциям; опрос внутри `openSheet` (параметр) — у обращения своя остановка опроса при ошибке, параметр
пришлось бы усложнять.

## R4. Без вечного загрузчика

**Сейчас.** `render()` вызывает `renderWard()` / `renderAdmin()` (асинхронные) и не ловит отказ; обе показывают
загрузчик, ошибки запроса ловят, но исключение при построении экрана (неполный ответ, ошибка в коде) оставляет загрузчик
навсегда. Те же функции вызываются мимо `render()`: `onClose` переписки (`renderWard({ cached: true })`), `again()`
панели (в т.ч. как `after` у шторки обращения). `closeSheet` вызывает асинхронный `onClose` без перехвата.

**Decision.**
- `screen(build)` (`src/app/03-home.js.txt`, рядом с `showError`) — обёртка асинхронного экрана: отказ `build` →
  `showError(e)` (кнопки «Попробовать снова» и «К списку событий»), если пользователь не ушёл с экрана (`state.nav`
  прежний). `renderWard` и `renderAdmin` объявляются через неё — защищены все пути вызова.
- `render()` ловит исключение синхронных вкладок («Письмо», «Инфо», главный экран) → `showError(e)` (из `openEvent`
  исключение `render()` тоже оставляло загрузчик).
- `closeSheet`: результат `onClose` (обещание или исключение) — с перехватом: отказ → сообщение `⚠️ …` внизу экрана.
- Правила теста: нет `async function render…` (асинхронный экран — только через `screen`); в `render` — перехват с
  `showError`; в `closeSheet` вызов `onClose` — с `.catch`.

**Rationale.** Перехват в месте объявления защищает все пути вызова; перехват в `render` один не закрыл бы `onClose` и
`again()`.

**Alternatives considered.** Перехват у каждого вызова (`render`, `onClose` ×2, `again`, `after`) — пять мест, легко
забыть шестое. Обернуть тело `renderAdmin` в `try` — перестановка отступов 660 строк.

## R5. Начальное состояние

**Decision.** `announcements: []` в `const state = {…}`. Правило теста: каждое поле `state.X`, которое встречается в
склейке, объявлено в начальном литерале `state` (сейчас не хватает только `announcements`).

**Rationale.** Общее правило ловит и будущие поля, а не только это.

## R6. Окно подтверждения

**Факты.** `Telegram.WebApp.showPopup` обрезает пробелы по краям и бросает `WebAppPopupParamInvalid`, если сообщение
длиннее 256 символов; `showConfirm` — обёртка над ним. `confirmBox` режет текст до 250 (`text.slice(0, 250)`, запас 009),
чтобы окно не бросало исключение. Худший случай сейчас (имя 40, название события 80, семья 40, числа — 3 цифры):
удаление участника после жеребьёвки — ровно 250; перенос участия — 218; вписывание — 201; жеребьёвка — 167 (в
`docs/todo.md` она названа самой длинной по ошибке).

**Decision.**
- Константа `CONFIRM_MAX = 250` (`src/app/02-core.js.txt`); текст длиннее показывается окном Telegram как первые
  249 символов + «…» — обрезка видна. Окно браузера (без Telegram или Telegram до 6.2) — полный текст, как сейчас.
- Тест считает худший случай каждого вызова `confirmBox(...)` в склейке: строки и шаблоны; подстановки — по таблице
  пределов (имя — 40, семья — 40, название события — 80, число — 3), `a || b` и `x ? a : b` — длиннейшая ветвь,
  `plural(n, …)` — длиннейшая форма, локальные `const`/`let` (и `x += …`) — по своему определению, параметр `title` у
  `typed(...)` — длиннейший из переданных заголовков. Подстановка без известного предела — нарушение с указанием места
  (части и строки). Предел берётся из склейки (`CONFIRM_MAX`).

**Rationale.** Защита — до выката: новый длинный текст не пройдёт `npm test`; «…» — страховка для данных вне пределов
(например, имя, сохранённое до проверки длины).

**Alternatives considered.** Длинный текст — в окно браузера `window.confirm`: в Telegram для iOS (WKWebView) окно
может не показаться, тогда подтвердить нельзя вовсе — проверить локально нельзя. Своё окно подтверждения в
дизайн-системе — новый элемент поверх шторки (подтверждения вызываются и из шторок), вне задачи. Заголовок + сообщение
(`showPopup`) — тоже с пределом.

## R7. Повторы кода

**Decision.**
- Поле ответа: `composerParts(placeholder)` переносится в начало раздела переписки (`src/app/07-sheet-chat.js.txt`) и
  используется в `openChat`: `setWritable(w)` — `c.show(w)`, `closedNote.hidden = w`, при `!w` счётчик скрыт; отправка —
  `c.clear(text)`; `beforeClose` — по `c.ta`. Разметка та же (`ds-composer`, `ds-composer__input`, `ds-composer__send`,
  `ds-counter ds-composer__counter`); при показе скрытого поля высота пересчитывается (как в обращениях).
- Правила пар: внутри `renderAdmin` — `rulePairs(rows)` (взаимные — одной строкой), `ruleList(pairs, { empty, both,
  one, del })` (список с ✕ или только чтение), `ruleForm({ to, label, mutual, add })` (два списка «Кто дарит…» /
  `to`, флажок «и наоборот (в обе стороны)», кнопка; проверки «Выбери двух людей», «Нужны два разных человека»; после
  `add` — `again()`). Исключения: флажок включён, «…кому НЕ может дарить», «Добавить исключение», ✕ без сообщения;
  закреплённые: флажок выключен и пропадает при кольцевой (`syncFixed`), «…кому дарит», «Закрепить пару», ✕ с «Закреплённая
  пара убрана». Порядок узлов на экране — прежний.
- Правила теста: в склейке одна сборка поля ответа (`ds-composer__input`), один разбор взаимных пар, одна форма
  (`'и наоборот (в обе стороны)'`, `'Выбери двух людей'`, `'Нужны два разных человека'` — по одному разу).

**Rationale.** Помощники — замыкания внутри `renderAdmin` (им нужны `players`, `byId`, `xapi`, `again`); вынос наружу
потребовал бы передавать всё параметрами.

## R8. Проверки

**Decision.**
- `tests/app-ui.test.mjs` (в `npm test`): правила R1–R7 по склейке (`tests/support/app-source.mjs`, место — `where`), по
  образцу `tests/app-buttons.test.mjs`: функция находит нарушения, тест — «нарушений нет», и «от противного» на примере с
  нарушениями. Тело функции/обработчика — по отступам: от строки объявления до первой строки с тем же отступом,
  начинающейся с `}` или `)` (стиль частей это гарантирует).
- `tests/screenshots.mjs` → `checkUiFixes()` в Chrome (как `checkSheetScroll`, `checkDateFields`), в конце, после всех
  снимков (отдельное событие «Проверка», чтобы снимки не менялись): (1) «Сохранить» с новым названием → текст окна
  «Удалить из события» с новым названием, кнопка «Сохранить» на экране; (2) событие завершено со стороны → после смены
  вкладки нет «Полный сброс», есть плашка; (3) ответ обращения задержан, открыт журнал → заголовок «Журнал события»;
  (4) неполный ответ панели (вкладка и закрытие шторки обращения) → экран ошибки, повтор строит панель.
- Сначала тесты (падают на коде до правки), затем правки. Скриншоты «до» — на коде до правок; «после» сравниваются
  попиксельно (отличия — только тексты времени).

**Rationale.** Проверки кода — быстрые и в каждом `npm test`; поведение, которое видно только в браузере, проверяется
в настоящем Chrome на настоящем Worker.

**Alternatives considered.** Своя имитация DOM для запуска приложения в Node — большая обвязка со своим поведением,
расходящимся с браузером; проверки в e2e — там нет браузера.
