# План единых названий ролей

**Ветка** `044-unify-role-labels`  
**Дата** 2026-11-19  
**Спецификация** [spec.md](spec.md)

## Изменения

1. Согласовать подписи ролей, общие списки и название вкладки в `src/app/` и демонстрационном экране дизайн-системы. Для списка «О событии» использовать уже передаваемый признак `owner`. Для кнопки и заголовка обращений использовать одинаковые названия в разных состояниях.
2. Обновить тексты приглашений, подсказок, ошибок и уведомлений. При ответе и закрытии обращения определять роль отправителя через кэш определения владельца текущего вызова. Если роль не нужна для понимания действия, использовать имя автора или описать результат.
3. Обновить README, API-справку и существующие проверки, которые сравнивают тексты. Проверить названия, доступ для обеих ролей, доставку уведомлений и узкий экран.

## Technical Context

JavaScript и HTML для Telegram Mini App, Cloudflare Workers и D1. Проверки на Node.js, локальный Worker для сквозных тестов и Playwright для браузерных сценариев. Схема D1, структура API, ключи вкладок и доступа сохраняются. Новые зависимости не нужны.

## Constitution Check

| Принцип | Проверка |
|---|---|
| I. Тайна | Тексты отражают существующий доступ. Пары, письма и адреса выдаются по прежним правилам. |
| II. Простота | Подписи ролей одинаковы, «Управление» подходит обеим ролям. Число шагов не меняется. |
| III. Спецификация | Требования, план и задачи описаны в ветке 044 до кода. |
| IV. Дизайн-система | Используются существующие компоненты и токены. Проверяется вёрстка вкладок. |
| V. Бесплатный тариф | Используются данные текущего вызова. Не добавляются зависимости, рассылки и запросы к внешним сервисам. |
| VI. Проверка | Быстрые, сквозные и браузерные проверки покрывают роли и актуальные тексты. |
| VII. Владелец | Существующие флаги и проверки доступа определяют, где называть владельца. |

## Структура

- `src/app/` — названия ролей, вкладки, экраны события и обращения.
- `src/{api,bot,db,events,format,membership,pairs,roles,setup,support}.js` — пользовательские тексты и подписи.
- `design-system/preview.html`, `README.md`, `docs/api.md` — действующие примеры и справка.
