# Feature Specification: Один текст «только для чтения» и журнал семьи только при изменении

**Feature Branch**: `034-small-consistency`

**Created**: 2026-11-17

**Status**: Реализовано (2026-11-17; задачи — `tasks.md`, все выполнены)

**Input**: User description: "сделай правки через спек кит и сразу пуш в гит как все проверишь" — две мелочи, оставленные
за рамками 029 и 024: (1) разная пунктуация одного и того же отказа «Событие завершено больше недели назад…» у сервера
API и у бота/приложения; (2) повторное сохранение семьи без изменений снова пишет «👪 Семья сохранена» в журнал.

## Контекст

| № | Сейчас | Нужно |
|---|---|---|
| 1 | Обращение в событии, завершённом больше недели назад: API отвечает «Событие завершено больше недели назад**:** обращения только для чтения.», бот и приложение пишут «… **—** обращения только для чтения.». Переписка: API — «…назад**:** переписка **доступна** только для чтения.», бот и приложение — «…назад **—** переписка только для чтения.» | один текст везде: «Событие завершено больше недели назад — обращения только для чтения.» и «Событие завершено больше недели назад — переписка только для чтения.» (как уже видят люди в боте и приложении) |
| 2 | «Сохранить» у семьи без изменений (то же название, тот же состав) — каждый раз запись «👪 Семья сохранена» в журнале | запись — только при настоящем изменении (название или состав), как у переименования (025) и закреплённых пар (023); новая семья — запись, как раньше |

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Один текст отказа (Priority: P1)

Участник пишет в обращение или переписку события, завершённого больше недели назад, — из приложения или из бота. В обоих
случаях он видит одну и ту же фразу.

**Independent Test**: отказ API на закрытие обращения и отправку в переписку завершённого больше недели назад события —
текст с тире, тот же, что у бота и в приложении.

**Acceptance Scenarios**:

1. **Given** событие завершено больше недели назад, **When** участник закрывает или пишет обращение через приложение,
   **Then** отказ — «Событие завершено больше недели назад — обращения только для чтения.»
2. **Given** то же событие, **When** участник пишет в переписку через приложение, **Then** отказ — «Событие завершено
   больше недели назад — переписка только для чтения.»
3. **Given** то же событие, **When** то же через бота, **Then** текст тот же.

### User Story 2 — Журнал семьи без лишних записей (Priority: P1)

Организатор открывает семью и нажимает «Сохранить», ничего не меняя, — в журнале новой записи нет. Меняет название или
состав — одна запись. Нажимает «Сохранить» с изменением дважды подряд (или два организатора сохраняют одно и то же
одновременно) — одна запись.

**Independent Test**: семья сохранена без изменений — записей `family.save` столько же; с новым названием — на одну
больше; два одинаковых сохранения с изменением в одну миллисекунду — одна запись.

**Acceptance Scenarios**:

1. **Given** семья «Ивановы» (Аня, Боря), **When** «Сохранить» с тем же названием и составом (в любом порядке), **Then**
   ответ «успех», семья прежняя, новой записи журнала нет.
2. **Given** та же семья, **When** название «Ивановы-Петровы», **Then** одна запись «««Ивановы-Петровы»: …»».
3. **Given** та же семья, **When** добавлена Вера, **Then** одна запись.
4. **Given** та же семья, **When** два одинаковых сохранения с изменением в одну миллисекунду, **Then** оба — успех, семья
   такая, как просили, запись одна.
5. **Given** семьи нет, **When** создать новую, **Then** запись, как раньше; два одновременных создания — как в 024 (одна
   семья, одна запись, второму — «уже в семье»).

### Edge Cases

- Название с лишними пробелами («  Ивановы ») — то же название после схлопывания пробелов: без записи.
- Повторы и пустые id в составе отбрасываются, как раньше: тот же набор людей — без записи.
- Заморозка состава идущим событием с жеребьёвкой — прежняя; сохранение без изменений не меняет состав и не
  отказывает.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Отказ «только для чтения» по обращениям MUST быть одним текстом в API, боте и приложении: «Событие
  завершено больше недели назад — обращения только для чтения.»
- **FR-002**: Отказ «только для чтения» по переписке MUST быть одним текстом в API, боте и приложении: «Событие завершено
  больше недели назад — переписка только для чтения.»
- **FR-003**: Сохранение существующей семьи MUST писать `family.save` только если меняется название или состав; без
  изменений — успех без записи.
- **FR-004**: Из одинаковых одновременных сохранений с изменением (в т.ч. в одну миллисекунду) запись MUST быть одна.
- **FR-005**: Создание семьи, отказы, заморозка, ответы и число запросов к базе MUST NOT меняться (кроме текстов FR-001,
  FR-002).

## Success Criteria *(mandatory)*

- **SC-001**: Тексты «только для чтения» по обращениям и по переписке — по одному на всё приложение (0 различий).
- **SC-002**: Сохранение без изменений — 0 новых записей журнала; с изменением — ровно 1 (в т.ч. при двух одновременных).
- **SC-003**: Эталон отказов меняется ровно в одном ответе (закрытие обращения в событии, завершённом больше недели
  назад), остальные автотесты зелёные.

## Assumptions

- Выбран вариант с тире: его уже видят люди в боте и приложении; меняется только ответ API (в приложении он показывается
  всплывающим сообщением).
- Другие расхождения пунктуации (например, «Участник не найден» с точкой и без) — не входят: владелец просил две
  названные правки.
- Сохранение без изменений — успех без записи в базу (как переименование тем же именем, 025).
