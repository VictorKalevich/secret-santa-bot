# Feature Specification: Подсказка о выходе для организаторов-участников

**Feature Branch**: `036-organizer-leave-hint`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "Подсказка о выходе для организаторов-участников (036). После жеребьёвки во вкладке «Инфо»
раздел «Выход из события» у участника-организатора показывает свою подсказку вместо общей «напиши организатору, он уберёт
тебя из события» (которая для них неверна): владельцу бота — удалить его из события не может никто, выйти можно только
отменив жеребьёвку («Админ» → «Опасная зона» → «↩️ Отменить жеребьёвку», пары удалятся у всех), затем выключить «Я
участвую» и провести жеребьёвку заново; после раскрытия Сант — выйти нельзя (жеребьёвку не отменить); кнопки «Написать
организатору» у владельца нет. Админу (не владельцу) — удалить администратора из события может только владелец бота:
напиши ему (кнопка «Написать организатору», если есть кому). Обычному участнику — прежняя подсказка и кнопка. До
жеребьёвки и в завершённом событии — без изменений. Только приложение (часть 04-event), сервер, API и тексты отказов не
меняются."

Решение владельца (2026-11-17): «да» на предложение сделать для организаторов свою подсказку после разбора «что будет,
если организатор с „Я участвую“ нажмёт „Выйти из события“».

## Контекст

С 035 после жеребьёвки на «Инфо» вместо кнопки выхода — подсказка «Жеребьёвка уже прошла — выйти можно только через
организатора: напиши ему, он уберёт тебя из события» и «💬 Написать организатору». Для организатора, который сам
участвует, это неверно:

| Кто | Может ли его кто-то удалить после жеребьёвки | Как на самом деле выйти |
|---|---|---|
| участник | любой организатор («⋯» → «Удалить из события») | написать организатору — как сейчас |
| админ (не владелец) | только владелец бота (админ админа удалить не может; себя — тоже) | написать — увидит и владелец |
| владелец бота | никто (владельца удалить нельзя, себя — тоже) | только отменив жеребьёвку (до раскрытия Сант), затем выключить «Я участвую» и провести жеребьёвку заново |

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Владелец-участник узнаёт, как выйти после жеребьёвки (Priority: P1)

Владелец бота сам участвует в событии, жеребьёвка уже прошла. Он открывает «Инфо», внизу — «Выход из события». Вместо
«напиши организатору» он видит: удалить его из события некому; выйти можно, только отменив жеребьёвку в «Админ» →
«Опасная зона» → «↩️ Отменить жеребьёвку» (пары удалятся у всех, участники получат уведомление), потом выключить «Я
участвую» и провести жеребьёвку заново. Кнопки «Написать организатору» в этом разделе нет — писать некому, кто бы мог
помочь.

**Why this priority**: прежняя подсказка владельцу прямо неверна — она отправляет к организатору, который ничего не может
сделать.

**Independent Test**: владелец участвует в событии с проведённой жеребьёвкой → «Инфо» → раздел «Выход из события»: текст
про отмену жеребьёвки, кнопок в разделе нет.

**Acceptance Scenarios**:

1. **Given** владелец — участник идущего события, жеребьёвка проведена, Санты не раскрыты, **When** он открывает «Инфо»,
   **Then** в разделе «Выход из события» — подсказка: «Ты владелец бота — удалить тебя из события некому. Выйти можно,
   только отменив жеребьёвку: «Админ» → «Опасная зона» → «↩️ Отменить жеребьёвку» (пары удалятся у всех, участники
   получат уведомление). Потом выключи «Я участвую» и проведи жеребьёвку заново.»; кнопок в разделе нет.
2. **Given** то же, но Санты уже раскрыты, **When** он открывает «Инфо», **Then** подсказка: «Тайна уже раскрыта —
   жеребьёвку не отменить, поэтому выйти из события нельзя: удалить владельца бота некому.»; кнопок в разделе нет.

---

### User Story 2 — Админ-участник узнаёт, кто может его удалить (Priority: P1)

Админ (не владелец) участвует в событии, жеребьёвка прошла. На «Инфо» в разделе «Выход из события» он видит, что удалить
из события администратора может только владелец бота, и кнопку «💬 Написать организатору» — обращение увидят все
организаторы, в том числе владелец.

**Why this priority**: прежняя подсказка обещает, что «организатор уберёт», хотя другой админ этого сделать не может.

**Independent Test**: админ участвует в событии с проведённой жеребьёвкой → «Инфо»: подсказка про владельца; кнопка
«Написать организатору» — если есть кому написать.

**Acceptance Scenarios**:

1. **Given** админ (не владелец) — участник идущего события с проведённой жеребьёвкой, в боте есть другие организаторы,
   **When** он открывает «Инфо», **Then** в разделе «Выход из события» — подсказка «Жеребьёвка уже прошла — удалить из
   события администратора может только владелец бота. Напиши организатору: обращение увидит и владелец.» и кнопка
   «💬 Написать организатору», открывающая его обращение.
2. **Given** то же, Санты раскрыты, **When** он открывает «Инфо», **Then** та же подсказка и кнопка (владелец может
   удалить участника и после раскрытия, пока событие не завершено).
3. **Given** у админа нет открытого обращения и писать некому, **When** он открывает «Инфо», **Then** подсказка та же,
   кнопки нет (как у участника в 035).

---

### User Story 3 — У остальных ничего не меняется (Priority: P2)

Участник без прав организатора после жеребьёвки видит прежнюю подсказку и кнопку «Написать организатору». До
жеребьёвки у всех (и у организаторов) — прежняя кнопка «🚪 Выйти из события». В завершённом событии и у не участника
раздела нет.

**Why this priority**: защищает уже принятое поведение 035.

**Independent Test**: участник после жеребьёвки, организатор до жеребьёвки, завершённое событие — как в 035.

**Acceptance Scenarios**:

1. **Given** участник (не организатор) после жеребьёвки, **When** он открывает «Инфо», **Then** подсказка «Жеребьёвка уже
   прошла — выйти можно только через организатора: напиши ему, он уберёт тебя из события.» и кнопка «💬 Написать
   организатору» (если есть кому).
2. **Given** владелец или админ — участник до жеребьёвки, **When** он открывает «Инфо», **Then** кнопка «🚪 Выйти из
   события» и прежняя подсказка, как у всех.

---

### Edge Cases

- Права меняются, пока экран открыт (админа назначили или сняли, владение передали): подсказка — по ролям на момент
  последней загрузки экрана; при следующем открытии события — по новым.
- Владелец — единственный организатор: подсказка про отмену жеребьёвки та же (обращения ему всё равно писать некому).
- Админ при этом ведёт или видит чужие обращения — на подсказку не влияет; кнопка открывает его собственное обращение как
  участника, как в 035.
- Сервер не меняется: если жеребьёвка прошла, пока была открыта шторка выхода, отказ прежний («Жеребьёвка уже прошла —
  выйти можно только через организатора: напиши ему.») — при следующем открытии «Инфо» организатор увидит свою подсказку.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: В идущем событии с проведённой жеребьёвкой раздел «Выход из события» на «Инфо» у участника-владельца бота
  MUST показывать подсказку про отмену жеребьёвки (US1, сценарий 1), а после раскрытия Сант — подсказку «выйти нельзя»
  (US1, сценарий 2); кнопок в разделе у владельца нет.
- **FR-002**: Там же у участника-админа, который не владелец, MUST быть подсказка «удалить из события администратора
  может только владелец бота…» (US2) и кнопка «💬 Написать организатору» по тому же правилу, что у участника (есть кому
  написать или обращение уже открыто).
- **FR-003**: У участника без прав организатора после жеребьёвки, у всех до жеребьёвки, в завершённом событии и у не
  участника раздел MUST остаться как в 035.
- **FR-004**: Сервер, действия, тексты отказов и сообщения бота MUST NOT меняться; изменение — только в мини-приложении.
- **FR-005**: README MUST описывать, как выйти после жеребьёвки организатору-участнику (владельцу — через отмену
  жеребьёвки; админу — его удаляет владелец).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В трёх ролях (владелец, админ, участник) × двух состояниях (жеребьёвка проведена, Санты раскрыты) подсказка
  на «Инфо» описывает способ выхода, который для этой роли действительно работает, — 6 из 6 случаев проверены в браузере.
- **SC-002**: Ни один ответ сервера и ни одно сообщение бота не изменились (эталон отказов и все прежние тесты — без правок).

## Assumptions

- Роль берётся из уже загруженных данных приложения (владелец, админ); новых запросов к серверу не нужно.
- Путь «Опасная зона» → «↩️ Отменить жеребьёвку» у владельца есть всегда, пока жеребьёвка проведена и Санты не раскрыты
  (принудительная отмена, 012); обычная отмена в разделе «Жеребьёвка» — частный случай, отдельно не упоминается.
- После отмены жеребьёвки владелец может выйти и кнопкой «🚪 Выйти из события» (жеребьёвки уже нет); подсказка называет
  привычный организатору путь — «Я участвую».
- Перенести участие или передать владение ради выхода — не предлагаем (сложнее и меняет роли).
