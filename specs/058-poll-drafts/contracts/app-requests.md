# Контракт 058: запросы приложения — опрос шторок и черновик письма

Касается только мини-приложения (`src/app/`). Сервер, API (`docs/api.md`), база и тексты не меняются.

## Видимость (`02-core`)

- `appVisible()` → `!document.hidden && !(tg && tg.isActive === false)`.
- `onVisibility(fn)` → отписка; `fn(onScreen)` вызывается только при смене `appVisible()`. Источники: `document`
  `visibilitychange`, `tg.onEvent('activated' | 'deactivated')`. Подписка на документ и SDK — одна, в ядре.

## Опрос шторки (`08-sheet-chat`)

```text
POLL_STEPS = [6, 10, 20, 30, 60]   // секунды
POLL_IDLE  = 300                   // секунд подряд без нового — сон (только открытый бот)
pollDelay(empty, quiet, open) → секунды | null
  open = false → 6
  quiet ≥ POLL_IDLE → null
  иначе POLL_STEPS[min(empty, 4)]
poll(own, load) → { now(), stop() }
```

- `load()` шторки — запрос и отрисовка; результат истинный — пришло новое (переписка: добавлены сообщения; обращения:
  сменился отпечаток). Отказ `load` при опросе проглатывается (как раньше), из `now()` — достаётся вызывающему.
- После запроса: новое → `empty = quiet = 0`; иначе `empty += 1`, `quiet += промежуток`. Следующий таймер — `pollDelay`,
  если шторка открыта (`sheetEl === own`), опрос не остановлен и приложение на экране; `null` — сон.
- Скрыто → таймер снят; снова на экране → `now()`.
- `now()` — `empty = quiet = 0`, таймер снят, `load()` сразу, затем таймер по расписанию. Вызывают: шторка при открытии
  (первая загрузка), после своей отправки и действий в обращении, возвращение на экран, касание (`pointerdown`) спящей
  шторки.
- `stop()` — опрос окончен: таймер снят, отписка от видимости. Вызывают `onClose` шторки и отказ обращения; шторка
  закрыта или заменена — опрос останавливается сам на ближайшем шаге.
- Таймеры опроса шторки — только в `poll`; `load` шторки вызывается только через `poll` (`now()` и таймер).

## Черновик письма (`05-event`)

```text
DRAFT_PAUSE = 450    // мс: первое сохранение после правки
DRAFT_GAP   = 5000   // мс: между началами сохранений
draftDelay(now, last) = max(DRAFT_PAUSE, last + DRAFT_GAP − now)
```

- Правка: копия в `localStorage` (041), `pending`; если сохранение не запланировано и не идёт — таймер `draftDelay`.
  Новая правка запланированное не откладывает. После сохранения, если набрано ещё, — снова по `draftDelay` (или сразу,
  если просили `saveNow`).
- `saveNow()` — ждущий черновик без ошибки сохраняется сразу; идёт сохранение — сразу после него. `saveLetterNow` —
  `saveNow` последнего открытого редактора.
- Вызывают `saveLetterNow`: смена `appVisible()` на «скрыто» (одна подписка части) и `mayLeave()`.
- Сохранение (`wishlist.draft`, `wishlist.publish`) — по одному во всём приложении (`letterQueue`); текст и версия берутся,
  когда подошла очередь; версия — максимум из черновика и `letterRevisions[ключ копии]`, ответ записывает обе.
- Публикация — по кнопке, сразу (снимает запланированное), как в 041; ошибка — «Черновик не сохранён. …» /
  «Публикация не удалась. …» и «Повторить сохранение»; новая правка снимает ошибку и планирует сохранение.

## Уход (`03-home`, `05-event`)

- `state.dirty`: `false` — ничего; `'draft'` — только несохранённый черновик письма; `true` — адрес доставки или письмо без
  черновиков. Вопрос Telegram при закрытии (`enableClosingConfirmation`) и точка на вкладке «Письмо» — при истинном.
- `mayLeave()` → истина, если можно уйти: `saveLetterNow()`; при `state.dirty === true` — вопрос `UNSAVED`; затем
  `setDirty(false)`. Им пользуются `leaveEvent` («‹», «Назад» Telegram) и переключение вкладок. `confirmBox(UNSAVED)` — только
  в `mayLeave`.
