# Data Model: 051. Компании, шаг 2

Схема не меняется (17, `migrations/0015_companies.sql` из 050). Здесь — как используются поля, созданные впрок, состояния
и правила видимости. Таблицы и инварианты I1–I6 — `specs/050-company-scope/data-model.md`.

## Поля, которые начинают работать

| Поле | Кто пишет | Правило |
|---|---|---|
| `companies.name` | `bot.company.create`, `company.label.set` владельца бота | 1–40 символов после `oneLine`; отдаётся только владельцу бота |
| `companies.owner_id` | `admin.owner.transfer`, переход по ссылке владельца | человек компании с `is_admin = 1` (I3) или 0; владелец бота как цель → 0 |
| `companies.owner_code` | `bot.company.link`, переход по ссылке | `''` или 16 символов `randomCode`; уникален среди непустых (индекс `companies_owner_code` из 0015); никому не отдаётся, кроме владельца бота в составе ссылки |
| `companies.created_by` | `bot.company.create` | владелец бота |
| `company_members.label` | `company.label.set` | 0–40 символов после `oneLine`; отдаётся только самому человеку |

## Состояния компании

```text
                 bot.company.create
                        │
                        ▼
        ┌──── ведёт владелец бота (owner_id = 0) ◄───────────────┐
        │               │                                        │
        │   admin.owner.transfer { id: человек }                 │ admin.owner.transfer { id: владелец бота }
        │   или переход по ссылке own_<код>                      │ («Вести самому» или передача ему)
        │               ▼                                        │
        │       назначенный владелец (owner_id = человек) ───────┘
        │               │  admin.owner.transfer { id: другой человек } / переход по новой ссылке
        │               ▼
        │       другой назначенный владелец (прежний — администратор)
        │
        └── bot.company.delete (только без событий) ──► нет компании
```

## Состояния ссылки владельца

| Состояние | `owner_code` | Переход |
|---|---|---|
| нет ссылки | `''` | `bot.company.link { on: true }` → действует |
| действует | код | переход по ссылке → нет ссылки, владелец назначен; `link { on: true }` → новый код (прежний недействителен); `link { on: false }` → нет ссылки |

Ожидание имени нового человека: `users.pending = 'name_own:<компания>:<код>'`. После имени права выдаются, только если
`owner_code` компании всё ещё равен коду из ожидания.

## Видимость компании для человека

Компания видна человеку, если выполнено хотя бы одно:

- он владелец бота;
- `companies.owner_id` = он;
- его строка `company_members.is_admin = 1`;
- он участник (`members`) хотя бы одного события этой компании.

Роль в ответе `me`: `owner` (он `ownerId()` компании), иначе `admin`, иначе `member`; владелец бота без строки человека
компании — `guest`. Признаки: `organizer` — может действия организатора (владелец, администратор, владелец бота);
`owner` — может действия владельца (владелец компании, владелец бота); `bot_run` — `owner_id = 0`.

Название: владельцу бота — `companies.name`; остальным — `label`, а если пусто — «Компания N» (N — номер компании среди
всех строк `company_members` человека по `joined_at`, затем `company_id`).

## `REGISTRY`: удаление компании

Новое обязательное решение у таблиц с ключом `company`: `onCompanyDelete`.

| Таблица | `onCompanyDelete` | Что происходит |
|---|---|---|
| `events` | `block` | компания с событиями не удаляется (условие пакета) |
| `family_members` | `delete` | раньше родителя `families` |
| `families` | `delete` | |
| `company_members` | `delete` | перед этим — пересчёт `users.is_admin` её администраторам |
| `audit` | `delete` | строки `company_id` этой компании (общий журнал и остатки журналов удалённых событий) |
| `companies` | якорь | удаляется последней — захват |

`companyDataDeleteStmts(db, companyId, guard, ...args)` — как остальные построители: условие у каждого оператора, якорь
последним. Тест `data-registry`: у каждой таблицы с `company` решение задано; после удаления компании не остаётся строк с
её `company_id`.

## Журнал

| Код | Где | Подробности |
|---|---|---|
| `company.create` | журнал бота | «<название>» |
| `company.owner` | журнал компании и журнал бота | «→ <имя>» / «→ владелец бота»; по ссылке — «по ссылке: <имя>» |
| `company.link` | журнал бота | «создана» / «отозвана» — без кода |
| `company.delete` | журнал бота | «<название>, людей: N» |

Журнал бота — строки `audit` с `company_id = 0` и `event_id = 0`. Названия компаний встречаются только в журнале бота
(его читает только владелец бота); в журнале компании запись `company.owner` названия не содержит.
