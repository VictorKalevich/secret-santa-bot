# Implementation Plan: 051. Компании, шаг 2 — компании, их владельцы и список компаний

**Branch**: `051-companies` | **Date**: 2026-11-23 | **Spec**: [spec.md](spec.md)

**Предусловие**: 050 влит в `main`, выкачен и проверен; перед началом в ветку вливается `main`.

## Summary

Основа (050) уже считает всё в пределах компании и умеет «владелец компании = `companies.owner_id` или владелец бота».
Этот шаг даёт людям сами компании:

- **Сервер.** Новый модуль `src/companies.js`: создать компанию, название (владельца бота — у компании, своё — у
  человека), владелец компании (назначение, передача, «Вести самому» — одно действие `admin.owner.transfer`), одноразовая
  ссылка владельца (`own_<код>`), удаление пустой компании, журнал бота. Шесть новых действий API (68 → 74): одно для
  всех (`company.label.set`) и пять только для владельца бота (`bot.*`, новая роль `BOT`). `me` отдаёт список видимых
  компаний, события — с компанией. Строки `ACTIONS` с ролью `OWNER` начинают работать для владельца компании сами — это
  свойство `ctx.isOwner()` из 050; исключение — перенос участия (только владелец бота).
- **Тексты.** «Владелец бота» → «владелец» в компании с назначенным владельцем (`ownerWord`), в остальных — побайтно
  прежние.
- **Бот.** `/start own_<код>`, регистрация нового человека сразу владельцем компании, компания рядом с событием в меню
  человека с несколькими компаниями.
- **Приложение.** Новая часть `04-companies` — экран «Компании», настройки компании владельца бота, своё название;
  главный экран работает в выбранной компании (`enterCompany`, `capi`), роли в интерфейсе берутся из роли в этой компании.

Миграций нет: `companies.owner_code`, `company_members.label` созданы в 0015.

## Точечные изменения прежнего поведения

Всё остальное для бота с одной компанией — прежнее. Меняется намеренно (и только это):

1. `admin.owner.transfer` — теперь «сделать владельцем компании» (`companies.owner_id`), а не передача прав владельца
   бота. Тексты отказов прежние. Прежний смысл — новое действие `bot.owner.transfer`. Тесты, которые передавали права
   владельца бота через `admin.owner.transfer` (`atomic`, `behavior`, `e2e`, `queries-scenario`), переводятся на
   `bot.owner.transfer`; число запросов — не больше прежнего.
2. `admin.transfer` — только владелец бота (раньше — «владелец»; при одной компании, которую ведёт владелец бота, это
   одно и то же).
3. `admin.rename` — отказ для человека из нескольких компаний (при одной компании недостижим).
4. `me` — новые поля `companies`, `events[].company`; `event.get` — `event.company`. Прежние поля — прежние.
5. Приложение: у владельца бота — раздел «Компании» на главном экране; кнопка 👑 в «Владелец и администраторы» — другой
   текст подтверждения. У остальных людей с одной компанией экраны прежние.
6. Эталон отказов: новые ключи «051 …» для шести действий; прежние ключи не меняются. Если какой-то прежний ключ
   изменился — это ошибка, кроме случаев, которые реализующий явно выпишет в заголовке теста и в этом разделе.

## Complexity Tracking

| Поправка | Зачем | Почему не проще |
|---|---|---|
| Принцип I: служебный просмотр и остальное «про пары» — владельцу компании в его компании | Запрос владельца: нынешние права владельца переходят к владельцу компании; иначе владелец компании по каждому вписыванию, обмену и спорной ситуации зависел бы от владельца бота, которого его люди не знают | Оставить «про пары» только владельцу бота — компания не была бы самостоятельной; вариант был вынесен владельцу на просмотр; утверждён первый (`research.md`, «Решения владельца») |
| Принцип VII: «владелец бота один» дополняется владельцем компании | Та же причина | — |
