# Контракт: компании — API, журнал, бот, приложение (051)

Опирается на контракт основы `specs/050-company-scope/contracts/company-scope.md` (контекст в компании, конвейер).
Состояния и видимость — [data-model.md](../data-model.md). После реализации описание действий переносится в
`docs/api.md` — он остаётся единственным актуальным описанием API.

## 1. Роль `BOT` и конвейер

`ROLES.BOT` — владелец бота. Проверка — сразу после «не зарегистрирован»: вызывающий не владелец бота — 403
**«Только для владельца бота.»**. Действия `bot.*` — без события и без проверки компании конвейером (компанию из тела
проверяет обработчик: нет такой — 404 **«Компания не найдена.»**). Слово подтверждения — общим шагом конвейера.

У строки `admin.transfer` — признак `bot: true`: после проверки владельца, если вызывающий не владелец бота, — 403
«Переносить участие на новый аккаунт может только владелец бота.».

Текст отказа владельца (`row.owner`) строится от компании вызова: `onlyOwner(what)` → «<what> может только
<ownerWord(botRun).nom>.» (раздел 6).

## 2. Действия

### `me` — дополнение ответа

```jsonc
{
  "me": { "id": 1, "name": "…", "is_admin": true, "is_owner": false, "notify_mode": "sound" },  // прежние поля и смысл
  "companies": [{
    "id": 2,
    "title": "Работа",          // data-model «Название»
    "named": true,              // у человека есть своё название (владельцу бота — всегда true)
    "role": "member",           // owner | admin | member | guest
    "organizer": false, "owner": false, "bot_run": false,
    "owner_name": "Петя",       // имя владельца компании
    "events": 2, "active": 1,   // события компании, видимые человеку, и идущие среди них
    "unread": 3,                // сумма unread его событий компании
    // только владельцу бота:
    "people": 14, "owner_id": 777, "link": false
  }],
  "events": [{ "id": 5, "company": 2, "…": "прежние поля" }]
}
```

Порядок компаний: по `joined_at` строки человека, затем `id`; владельцу бота — по `id`. Только видимые компании.
Чтения — в том же пакете `homeView` (всего у `me` 2 обращения к базе).

`event.get` → `event.company` (id компании события).

### `company.label.set` — зарегистрированный

Запрос `{ company, label }`. Компания не видна вызывающему (или её нет) — 404 «Компания не найдена.».

- Владелец бота: `oneLine(label)` 1–40 символов → `companies.name`; иначе 400 «Название компании — от 1 до 40 символов.».
- Остальные: `oneLine(label)` до 40 символов → `company_members.label`; длиннее — 400 «Название — до 40 символов.»; пустое
  — сброс.

Ответ `{ title }` — название, как его теперь покажет `me`. Журнал — нет. Сообщений — нет.

### `bot.company.create` — владелец бота

Запрос `{ name }`. Правило названия — как выше. Одним пакетом `atomic`: компания, строка владельца бота в ней
(`is_admin = 1`, инвариант I2), журнал бота `company.create`. Повтор того же названия от того же человека в течение минуты
(`REPEAT_MS`) — 400 «Компания с таким названием только что создана.» (защита от двойного нажатия; опора — запись
журнала). Ответ `{ company: id }`.

### `bot.company.link` — владелец бота

Запрос `{ company, on }`. `on: true` — новый код (прежний перестаёт действовать), ответ `{ link }`; `on: false` — код
стирается, ответ `{ link: '' }`. Без имени бота в настройках — 400 «Сначала открой страницу настройки /setup (см.
README).» (тот же текст, что у приглашений). Журнал бота `company.link` («создана» / «отозвана») — только при изменении.

Действующая ссылка повторно не отдаётся ни одним действием, кроме этого: `me` отдаёт только признак `link`.

### `admin.owner.transfer` — владелец (переопределено)

Запрос `{ company?, id }`. Владельцем компании вызова становится `id`.

| Проверка (по порядку) | Отказ |
|---|---|
| `id` — не владелец бота и не зарегистрированный человек компании (гость не подходит) | 400 «Передать права владельца можно только зарегистрированному человеку.» |
| `id` уже владелец компании (`ownerId()`) | 400 «Ты и так владелец.», если это вызывающий; иначе «Он(а) уже владелец.» |
| одновременно сменили | 400 «Права владельца уже переданы.» |

Запись: `owner_id` := `id`, а если `id` — владелец бота, то 0. Пакет `atomic` по прежнему значению `owner_id`: новому
владельцу — строка `is_admin = 1` и `adminFlagStmt`; сообщения — новому владельцу (со звуком, кнопка в приложение),
прежнему назначенному владельцу («ты остаёшься администратором»), администраторам компании (без звука), владельцу бота
(если вызывал не он и он не среди получателей); журнал компании `company.owner` и журнал бота; захват последним.

Сообщение новому владельцу, если до этого он не был организатором: «👑 Ты — владелец своей компании в «Тайном Санте»:
создаёшь события, приглашаешь людей, назначаешь администраторов.» Владельцу бота при «Вести самому» сообщение не шлётся.

### `bot.owner.transfer` — владелец бота

Запрос `{ id }`. Прежняя передача прав владельца бота (`setOwner(via: 'transfer')`), прежние тексты и отказы. Получатель —
зарегистрированный человек компании с `owner_id = 0`; иначе 400 «Передать права владельца можно только
зарегистрированному человеку.». Дополнительно в том же пакете: компании, где новый владелец бота был назначенным
владельцем, получают `owner_id = 0` (I8). Журнал: `owner.transfer` в журнале бота и в журналах компаний, которые ведёт
владелец бота.

### `bot.company.delete` — владелец бота

Запрос `{ company, confirm: 'УДАЛИТЬ' }`; без слова — 400 «Для удаления введи слово УДАЛИТЬ.». Есть события — 400
«В компании есть события — сначала удали их.». Пакет `atomic` «компания есть и событий нет»: сообщения владельцу и
администраторам компании («Владелец бота удалил компанию, которую ты вёл: событий в ней не было.» — владельцу; «…в
которой ты был администратором…» — администраторам; самому вызывающему — нет), журнал бота `company.delete`, пересчёт
`users.is_admin`, `companyDataDeleteStmts`, якорь — строка компании. Проигравшему одновременный вызов — 404 «Компания не
найдена.» или отказ «есть события» по свежему состоянию.

`admin.events.create` вставляет событие с условием «компания существует»; нет — 404 «Компания не найдена.».

### `bot.audit` — владелец бота

Ответ `{ entries }` — последние 100 записей журнала бота, формат как у `admin.audit`.

### Изменения прежних действий

- `admin.rename`: цель состоит более чем в одной компании, а вызывающий не владелец бота — 400 «Имя этого человека
  меняет он сам: «Профиль» → «✏️ Изменить имя».».
- `admin.transfer`: только владелец бота (раздел 1).
- Все действия с ролью `OWNER` доступны владельцу компании в его компании (свойство `ctx.isOwner()` из 050).

## 4. Бот

### `/start own_<код>`

| Кто перешёл | Ответ | Что меняется |
|---|---|---|
| кода нет (использован, отозван, заменён) | «Эта ссылка владельца уже использована или отозвана. Попроси новую.» + меню, если зарегистрирован | ничего |
| владелец бота | «Ты владелец бота — эту компанию и так ведёшь ты.» + меню | ничего |
| уже владелец этой компании | «Ты уже владелец.» + меню | ничего |
| зарегистрированный человек | «👑 Ты — владелец своей компании в «Тайном Санте»: создаёшь события, приглашаешь людей, назначаешь администраторов. Всё — в приложении.» + меню | права (пакет раздела 2, «по ссылке») |
| новый человек | вопрос об имени (`nameOffer`, кнопка «Продолжить как …») с тем же вступлением; `pending = name_own:<компания>:<код>` | пользователь создан; права — после имени |

После имени (`signUp`): код компании тот же — права и ответ «Приятно познакомиться, …!» + «Создай первое событие в
приложении — там появится пригласительная ссылка.»; код уже другой — «Приятно познакомиться, …!» + «Ссылка владельца уже
использована или отозвана. Попроси новую.» (человек зарегистрирован, прав нет).

Владельцу бота после перехода: «👑 <имя> (@username) — теперь владелец компании «<название>».» (название — только ему).

Два одновременных перехода: права и сообщения — у одного; второму — первая строка таблицы.

### Меню

- Человек с двумя и более видимыми компаниями: строка события — «• «Событие» (<название компании>) — …»; название —
  по data-model (экранируется). Остальным — прежнее меню.
- Строка роли: владелец бота — прежняя; назначенный владелец какой-либо компании — «👑 Ты владелец — события и
  администраторы в приложении.»; администратор — прежняя.

### Режим ожидания

`users.pending`: новое значение `name_own:<компания>:<код>` (начинается с `name` — ввод имени обрабатывается тем же
обработчиком). Разбор — в одном месте с остальными (`parsePending` / разбор `name…` в `signUp`).

## 5. Приложение

### Состояние и вход

`state.companies` (из `me`), `state.companyId`, `state.view`: `'companies' | 'home' | 'event'`.

- `start`: есть параметр `event` — событие (как раньше); иначе `companies.length >= 2` — экран «Компании»; одна —
  `enterCompany(её id)` и главный экран; ни одной — главный экран без компании (пустой список, «Профиль»,
  «Уведомления»; у владельца бота — раздел «Компании»).
- `enterCompany(id)`: `state.companyId`, `state.company`; `state.me.is_admin = company.organizer`,
  `state.me.is_owner = company.owner` — остальные части читают права как раньше. Открытие события выставляет компанию
  события (`event.company`).
- `capi(action, body)` — `api` с полем `company: state.companyId`. Одиннадцать общих действий организатора (050,
  раздел 2) вызываются только через `capi`.
- «‹» в шапке события — в главный экран его компании; «‹» в шапке главного экрана — к «Компаниям», если их две и больше
  (иначе кнопки нет). Системная кнопка «Назад» Telegram — так же.

### Экран «Компании» (часть `04-companies`)

- Шапка «Тайный Санта», «Привет, <имя>!».
- Раздел «Компании»: строки `ds-list-item--link` — название; метки: «👑 владелец» / «🛠 администратор» / «участник» /
  «👁 владелец бота» (гость); подсказка «Владелец — <owner_name> · событий: <events>» (идущих нет — «· идущих нет»);
  значок непрочитанного; «✏️» — шторка «Название для себя» (поле до 40 символов, подсказка «Это название видишь только
  ты.», «Сохранить»; у владельца бота подсказка «Название компании видишь только ты — владелец бота.»).
- Владельцу бота: в строке «⚙️» — шторка «Компания» (ниже); под списком — «Создать компанию» (шторка: название,
  подсказка «У компании свои люди, события, семьи и администраторы. Её можно вести самому или отдать владельцу по
  ссылке.»), «📜 Журнал бота», «👑 Передать права владельца бота».
- «Профиль» и «Уведомления» — здесь (корневой экран); на главном экране компании у человека с несколькими компаниями
  их нет.

### Шторка «Компания» (владелец бота)

- «Кто ведёт»: «ты» или имя назначенного владельца; при назначенном — кнопка «Вести самому» (подтверждение `confirmBox`).
- «🔗 Ссылка владельца компании»: «Создать ссылку» → показ ссылки, «Скопировать», «📤 Отправить в чат» (`shareInvite`
  тем же способом, что приглашение), «Отозвать»; подсказка «Ссылка одноразовая: кто первым перейдёт по ней, станет
  владельцем компании и сможет открывать пары её событий. Отправляй её лично.» Уже созданную ссылку приложение не
  показывает повторно — только «Ссылка действует» с кнопками «Создать новую» и «Отозвать».
- «🗑 Удалить компанию» — `typedSheet` со словом «УДАЛИТЬ»; при событиях — вместо кнопки подсказка «В компании есть
  события — сначала удали их.».

### Главный экран в компании

- Шапка: у человека с несколькими компаниями — название компании; иначе «Тайный Санта».
- Гостю — плашка `ds-notice`: «Ты здесь как владелец бота: в списках компании тебя нет, уведомления её
  администраторам тебе не приходят. Твои изменения записываются в журнал компании.»
- События — только этой компании. Разделы организатора — при `organizer`.
- «Владелец и администраторы»: кнопка 👑 у человека — владельцу компании и владельцу бота. Подтверждение: у назначенного
  владельца — прежний текст передачи; у владельца бота в компании, которую он ведёт, — «Сделать «<имя>» владельцем этой
  компании? Он(а) сможет всё, что владелец: администраторы, сброс и удаление событий, служебный просмотр пар. Ты
  останешься владельцем бота и сможешь вернуть компанию себе.» Кандидаты — люди компании (а не только администраторы):
  список администраторов + выбор «Кого сделать владельцем…» из остальных.
- У владельца бота с единственной компанией внизу главного экрана — раздел «Компании» с теми же кнопками, что под
  списком на экране «Компании», и «⚙️» единственной компании.

### Тексты

`ownerWord()` в `02-core` (по `state.company.bot_run`) — раздел 6. Во всех частях слово «компания» — только на экране
«Компании», в шторках компании и в подтверждении 👑 владельца бота.

## 6. «Владелец» и «владелец бота»

```js
ownerWord(botRun) → { nom, gen, dat, ins }
// botRun: 'владелец бота', 'владельца бота', 'владельцу бота', 'владельцем бота'
// иначе:  'владелец',      'владельца',      'владельцу',      'владельцем'
```

Сервер: `ctx.ownerWord()` привязанного контекста. Через помощника строятся все тексты для людей (отказы API, сообщения
бота, подсказки приложения), где сказано, кто может действие владельца в событии или компании: «… может только …»,
«Попроси … вписать тебя», «… начал событие заново», «удалено …», «Служебный просмотр доступен только …» и т. п.

Всегда «владелец бота»: тексты `bot.*`, `admin.transfer`, страница `/setup`, ссылка владельца бота, сообщения о смене
владельца бота, плашка гостя, сообщение об удалении компании.

Тест (`tests/wording.test.mjs` или `tests/app-companies.test.mjs`): каждая строка `src/*.js` и `src/app/*` с «владел… бота»
находится либо в помощнике, либо в списке разрешённых мест теста; «от противного».
