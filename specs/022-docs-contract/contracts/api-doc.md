# Контракт: сводный документ API и его тест

Внутренний контракт фичи 022 — формат `docs/api.md` и правила `tests/api-doc.test.mjs`. Само API описывает
`docs/api.md`.

## Где что лежит

| Что | Где |
|---|---|
| Актуальное описание API, бота, журнала, ссылки `/app` | `docs/api.md` |
| Источник имён, ролей, события, «в завершённом», отказов владельца, слов подтверждения | `ACTIONS` в `src/api.js` |
| Тест соответствия | `tests/api-doc.test.mjs` (в скрипте `test` `package.json`) |
| История фич (не править, кроме указателя) | `specs/001…014/*/contracts/*.md` |

## Формат документа (то, что читает тест)

1. **Сводная таблица** — под заголовком `## Сводная таблица действий`; строки вида
   `| \`имя\` | кто | событие | в завершённом | условия |`. Значения колонок 2–4 — только из словаря:
   - кто: `любой` | `зарегистрированный` | `участник или админ` | `участник` | `админ` | `владелец`;
   - событие: `да` | `если передано` | `—`;
   - в завершённом: `нет` | `да` | `7 суток` | `проверяет обработчик` | `—`.
2. **Разделы действий** — заголовок `### \`имя\``; раздел кончается перед следующим `##`/`###`. Заголовок третьего
   уровня, состоящий из одного имени в обратных кавычках, — только у действий (иначе тест примет его за раздел
   несуществующего действия); у прочих разделов — слова, например «### Режим ожидания (`users.pending`)».
   Пробелы и переводы строк при поиске текстов считаются одним пробелом.
3. **Коды журнала** — под заголовком `## Коды журнала`; строки вида `| \`код\` | … |`.

Остальной текст — свободный: тест его не читает.

## Правила теста

| Проверка | Отказ (сообщение называет) |
|---|---|
| Имена сводной таблицы = имена разделов = `Object.keys(ACTIONS)` | действие без строки, без раздела, лишняя строка или раздел, повтор |
| Кто ↔ `role` | действие, ожидаемое и найденное значение |
| Событие ↔ `event` | то же |
| В завершённом ↔ `finished` (`нет` — строка; `да`/`7 суток`/`проверяет обработчик` — `true`; `—` — нет поля) | то же |
| В разделе — `finished` (строка), `owner`, `confirm[0]` и `confirm[1]` | действие и недостающий текст |
| Коды таблицы журнала = коды, которые пишет `src/*.js` | код без строки, лишний код, повтор |

Каждая проверка — чистая функция; у каждой есть проверка «от противного» на искусственном документе (нет раздела,
лишний раздел, неверная роль, неверное «в завершённом», убран текст отказа не владельцу, лишний код журнала).

## Как добавить действие API

1. Строка в `ACTIONS` (`src/api.js`) — как раньше (019).
2. Строка в сводной таблице `docs/api.md` и раздел `### \`имя\`` в группе своей роли: запрос, ответ, отказы (код и
   текст — как в коде), журнал.
3. `npm test` — тест документа падает, пока нет строки или раздела, или если роль/событие/«в завершённом» не совпали.

## Как добавить код журнала

Новый код в вызове `auditStmt` / `auditIfStmt` / `.audit(…)` (или в `INSERT INTO audit`, или параметром `action:`) →
строка в таблице «Коды журнала» `docs/api.md` и подпись в `AUDIT_LABELS` (`src/app/06-vault-audit.js.txt`). Код,
собранный из переменной не этими способами, тест не увидит — такие коды не заводить.
