# Research: Сводный контракт API и правки документов

Основа — `docs/refactoring/step-7-docs-contract.md`. Номера строк файла шага верны для `24b85d3`; шаги 3–6 их сдвинули,
поэтому всё ниже сверено с кодом `main` на `046bc74` (после шага 6) — по именам функций и текстам.

## R1. Где лежит сводный документ

**Decision**: `docs/api.md`. `CLAUDE.md` указывает на него как на актуальное описание API вместо цепочки контрактов
005–014.

**Rationale**: папки `specs/NNN-…` — история фич: следующая фича, меняющая API, правила бы папку 022, а `CLAUDE.md` пришлось
бы перенаправлять на новый номер с каждой фичей. `docs/` уже хранит живые документы проекта (план рефакторинга, замеры).
Контракт самой фичи (`contracts/api-doc.md`) описывает не API, а формат документа и правила теста.

**Alternatives considered**: `specs/022-docs-contract/contracts/api.md` с указателем — отвергнуто (см. выше); README —
для владельца бота, а не для разработчика, и уже длинный; разбить документ на несколько файлов — вернуло бы
«собери из многих мест».

## R2. Состав и формат документа

**Decision**: один файл, разделы по порядку:

1. Как читать документ (обозначения ролей, «в завершённом», источник истины).
2. Запрос и ответ: `POST /api/<действие>`, заголовок `x-init-data`, тело JSON (нечитаемое тело = `{}`), ответ
   `{ ok: true, … }` / `{ ok: false, error }`, заголовки ответа.
3. Порядок проверок конвейера (`handleApi`) и общие отказы — таблица «код, текст, когда» (401, 403 ×3+, 404 ×2, 405, 400
   «завершено», 400 слово подтверждения, 500 ×2).
4. Сводная таблица 59 действий (машиночитаемая, R4).
5. Разделы действий — участника (13), админа без события (11), действий события (35); порядок — как в `ACTIONS`.
   Раздел: заголовок `### \`имя\``, строка «Кто / Событие / В завершённом», запрос (поля), ответ (поля), отказы
   (код и текст), журнал (код или «не пишет»), примечания (сообщения людям — без текстов, только кому и когда).
6. Коды журнала — таблица «код, где событие (событие / общий), кто пишет, подробности» (машиночитаемая, R3).
7. Бот: команды (`/start`, `/start adm_…`, `/start inv_…`, `/cancel`, прочий текст), `users.pending` (5 форматов,
   включая старый `msg_<сторона>:<событие>`), кнопки `callback_data` (6 видов), кнопки-ссылки.
8. Ссылка на мини-приложение: `/app?event=&chat=&support=` и кто её строит.
9. Остальные маршруты: `/tg`, `/app`, `/setup`, прочие пути, cron — коротко, со ссылками на код.

Тексты отказов — побайтно как в коде (в «ёлочках»); шаблоны с подстановкой — с `<…>` на месте подстановки. Тексты
сообщений людям не переписываются (их много, они меняются чаще API) — указывается, кому и когда уходит сообщение.

**Rationale**: файл шага требует для каждого действия поля запроса, поля ответа, отказы, роль и «в завершённом», и
отдельные разделы о порядке проверок, журнале, `pending`, `callback_data`, ссылке `/app`. Порядок разделов действий как
в `ACTIONS` — тот же, что в коде, искать легко.

**Alternatives considered**: JSON-схема ответов — избыточно для проекта без сборщика и без внешних клиентов, тест
по ней пришлось бы писать отдельно; переписать тексты сообщений бота — дублирование `src/` без проверки.

## R3. Что проверяет тест

**Decision**: `tests/api-doc.test.mjs`, чистые функции и проверки «от противного» на искусственных данных (как в
`tests/app-parts.test.mjs`):

- **Действия**: множество строк сводной таблицы = множество разделов `### \`…\`` = `Object.keys(ACTIONS)`; без повторов;
  у каждой строки роль, событие и «в завершённом» соответствуют полям строки `ACTIONS` (R4); раздел действия содержит
  текст `finished` (если строка), текст `owner` (если есть), слово и текст `confirm` (если есть).
- **Коды журнала**: множество кодов таблицы журнала = множество кодов, которые пишет `src/*.js`. Коды собираются из
  исходников тремя образцами: строковые литералы в той же строке, что вызов `auditStmt(` / `auditIfStmt(` / `.audit(`
  (ловит и тернарные `add ? 'exclusion.add' : 'exclusion.del'`); `INSERT INTO audit … 'код'` (событие создаётся одним
  пакетом — `event.create`); параметр `action: 'код'` / `action = 'код'` перед `,` или `}` (коды жеребьёвки и отмен —
  `draw`, `draw.auto`, `draw.cancel`, `draw.cancel.force`). Прототип на `main` дал 42 кода — ровно столько подписей в
  журнале приложения (`AUDIT_LABELS`, `src/app/06-vault-audit.js.txt`).
- Поля запроса и ответа тест **не** разбирает: ответы уже сверяют эталон отказов (1125 ответов) и тесты прав, тайны и
  «мира»; описание полей сверяется вручную (`quickstart.md`).

**Rationale**: имена, роли, «в завершённом», отказы владельца и слова подтверждения — ровно то, что лежит в `ACTIONS`
как данные: сверка дешёвая и точная. Коды журнала — второе место, где документ легко отстаёт (контракты 007 и 012
расходились). Поля ответа — вычисляются обработчиками; проверка потребовала бы запускать каждое действие в «мире» —
это уже делают тесты прав и тайны.

**Alternatives considered**: проверять только имена (минимум файла шага) — роль или «в завершённом» в документе
могли бы разойтись с кодом незаметно; сверять коды журнала с `AUDIT_LABELS` — проверяло бы приложение, а не сервер
(сервер может писать код, которого нет в приложении); запускать действия в «мире» и сверять ключи ответа — дорого и
дублирует существующие тесты.

## R4. Значения колонок сводной таблицы

**Decision**: колонки `| Действие | Кто | Событие | В завершённом | Условия |`; первые четыре сверяет тест:

| Колонка | Значение в документе | Поле `ACTIONS` |
|---|---|---|
| Кто | `любой` / `зарегистрированный` / `участник или админ` / `участник` / `админ` / `владелец` | `role`: `any` / `user` / `viewer` / `member` / `admin` / `owner` |
| Событие | `да` / `если передано` / `—` | `event`: `true` / `'given'` / нет |
| В завершённом | `нет` | `finished` — строка (отказ 400 конвейера) |
| | `да`, `7 суток`, `проверяет обработчик` | `finished: true` (конвейер пропускает; `7 суток` — запись после завершения ограничена `CHAT_GRACE_MS`; `проверяет обработчик` — свой порядок отказов) |
| | `—` | действие без события (`finished` нет) |

«Условия» — свободный текст: условия, зависящие от данных (переименовать админа, удалить админа, исключения после
жеребьёвки, взятое обращение, поле `fixed`, заморозка семей), тест их не читает.

**Rationale**: одно слово на значение — разбор без эвристик; три значения для `finished: true` сохраняют смысл таблицы
файла шага («да / нет / 7 суток»).

## R5. Указатель в старых контрактах

**Decision**: в начало каждого из 16 файлов `specs/001…014/*/contracts/*.md` — строка цитаты и пустая строка:
`> История фичи NNN. Актуальное описание API, бота и журнала — [docs/api.md](../../../docs/api.md) (с фичи 022).`
Остальной текст не меняется. Контракты 016–021 (опоры тестов, правила жеребьёвки, список данных, таблица действий,
захваты, части приложения) описывают внутреннее устройство и действуют — без указателя.

**Rationale**: файл шага: «в начало каждого — строка "актуальное описание — в сводном контракте"»; «не переписывать
старые спецификации». У 011 (`ui.md`) и 013 (`texts.md`) контракты не про API, но указатель с формулировкой
«история фичи» безвреден и единообразен.

## R7. Конституция: PATCH 2.3.0 → 2.3.1

**Decision**: через `/speckit-constitution`, уточнения без смены смысла принципов:

- **II**: «Длинные тексты (письмо до 1000 слов)» → «(письмо — до 4000 символов: столько помещается в одно сообщение
  Telegram)» — `MAX_CHARS`, `src/chat.js`.
- **I**: «Администратор видит только статусы (зарегистрирован, письмо заполнено/пусто, подарок готов)» → добавить
  «открыл ли подопечного, получен ли подарок, указан ли адрес» — так отдаёт `admin.state` (`ward_seen`,
  `gift_received`, `has_delivery`). Смысл «только статусы» тот же.
- **VII**: «ссылка владельца … снова выдаётся только после смены `ADMIN_SECRET`» → «… после смены `ADMIN_SECRET` (или
  токена бота `BOT_TOKEN`: от обоих считается код ссылки)».
- **Безопасность и данные**: в список хранимых данных — журнал действий организаторов и бота (без пар, писем и
  текстов); он хранится, а в списке его нет.
- **Процесс разработки**: «`npm test` (юнит-тесты + проверка дизайн-системы)» → быстрые тесты всего Worker (тайна,
  права, одновременные вызовы, запросы, дизайн-система, слова, документ API); перед слиянием и выкатом —
  `npm run test:e2e` (или `npm run test:all`).

**Rationale**: файл шага требует согласовать принцип II с кодом через `/speckit-constitution` со сменой версии; прочие
пункты — те же расхождения «документ ↔ код», найденные при сверке. Ни один принцип не снят и не добавлен — PATCH.
