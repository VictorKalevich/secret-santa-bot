# Implementation Plan: Сводный контракт API и правки документов

**Branch**: `022-docs-contract` | **Date**: 2026-11-14 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/022-docs-contract/spec.md`; шаг 7 плана рефакторинга
(`docs/refactoring/step-7-docs-contract.md`), замеры `docs/refactoring/baseline.md` (раздел 1).

## Summary

Новый документ `docs/api.md` — единственное актуальное описание API мини-приложения и того, что с ним связано: формат
запроса и ответа, порядок проверок конвейера и общие отказы, сводная таблица 59 действий (машиночитаемая), раздел на
каждое действие (кто, событие, в завершённом, поля запроса и ответа, отказы с кодом и текстом, запись журнала), коды
журнала (машиночитаемая таблица), бот (команды, `/start`, `users.pending`, `callback_data`), ссылка `/app` и прочие
маршруты (research R1, R2). Составляется по коду `main` после шага 6, не по старым контрактам. Новый
`tests/api-doc.test.mjs` сверяет документ с таблицей `ACTIONS` (имена в обе стороны; роль, событие, «в завершённом»;
тексты отказа «завершено», отказа не владельцу и слова подтверждения — в разделе действия) и коды журнала — с кодами,
которые пишет серверный код (в обе стороны); проверки — чистые функции с проверками «от противного» (R3, R4). Старые
контракты 001–014 получают строку-указатель в начале (R5). `CLAUDE.md`, README, Конституция (через
`/speckit-constitution`, PATCH 2.3.0 → 2.3.1) и заголовок `tests/e2e.test.mjs` правятся по списку R6–R9; найденные
расхождения, похожие на ошибку кода, — в «Решения владельца» плана рефакторинга (R10).

## Technical Context

**Language/Version**: Markdown (документ); тест — JavaScript ES2022, Node 24.21 (минимум 22.15), `node:test`

**Primary Dependencies**: нет новых

**Storage**: D1 — не затрагивается; версия схемы 11, файлов миграций 7, миграций нет

**Testing**: `npm test` — новый `tests/api-doc.test.mjs` (включается в скрипт `test`); остальные тесты без правок;
`npm run test:e2e` — без правок (только комментарий-заголовок файла)

**Target Platform**: Cloudflare Workers (бесплатный тариф) — код не меняется

**Project Type**: веб-сервис (Worker) + мини-приложение; фича — документация и тест для разработчика

**Performance Goals**: тест документа — миллисекунды (чтение двух текстов и таблицы); `npm test` — в пределах прежнего
времени (около 1,2 с с запуском npm)

**Constraints**: `src/`, `migrations/`, `design-system/` не меняются (`git diff main -- src/ migrations/ design-system/`
пуст); старые спецификации — только указатель в начале контрактов; документ описывает код как есть

**Scale/Scope**: `docs/api.md` (59 разделов действий, ~42 кода журнала, 6 видов `callback_data`, 5 форматов `pending`);
1 новый тест; 16 файлов контрактов 001–014 (+1 строка в каждом); `CLAUDE.md`, `README.md`,
`.specify/memory/constitution.md`, `tests/e2e.test.mjs` (строка 1), `package.json` (скрипт `test`), план рефакторинга,
`baseline.md`, память

| III. Спецификация до кода | spec → plan → tasks в ветке `022-docs-contract`; сводный документ становится источником истины по API, а спецификации фич — историей с указателем; `CLAUDE.md` и README — отдельной задачей. | ✅ |
| IV. Только дизайн-система | Интерфейс не меняется; `tests/design-system.test.mjs` без правок. | ✅ |
