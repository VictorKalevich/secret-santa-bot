# Research: Маска Санты в переписке (040)

## R1. Где хранить маску

- **Decision**: колонка `pairs.mask` (идентификатор из набора или `''`).
- **Rationale**: маска — свойство пары «Санта → подопечный» в событии (спецификация, FR-002). Все места, где пары
  пересоздаются (жеребьёвка — `DELETE` + `INSERT`; `applyPairsChange` при вписывании и удалении — `DELETE` +
  `INSERT` только изменившихся пар; обе отмены жеребьёвки; сброс и удаление события — `DELETE`), дают новой паре
  умолчание `''` без нового кода. Перенос участия (`REGISTRY.pairs.onTransfer: 'update'`) меняет `santa`/`ward` в той же
  строке — маска остаётся (FR-010).
- **Alternatives**: `members.mask` (у участника в событии) — маска пережила бы смену подопечного при вписывании;
  `users.mask` — одна маска во всех событиях выдала бы Санту подопечному, у которого он Санта дважды (запрещено
  `docs/todo.md`).

## R2. Идентификатор, а не эмодзи

- **Decision**: в базе — `id` маски (`dragon`), наружу — `{ id, emoji, title }` в наборе; тексты бота строит
  `maskLabel(id)` → «🐉 Дракон».
- **Rationale**: как у открыток (038): название и эмодзи можно поправить без миграции; маска, убранная из набора,
  показывается как «без маски» (`maskLabel` → `''`).

## R3. Набор и пересечение со значками

- **Decision**: 20 масок (`elf` 🧝 Эльф, `wizard` 🧙 Волшебник, `fairy` 🧚 Фея, `genie` 🧞 Джинн, `dragon` 🐉 Дракон,
  `ghost` 👻 Привидение, `matryoshka` 🪆 Матрёшка, `agent` 🕵️ Тайный агент, `ninja` 🥷 Ниндзя, `stranger` 🎭 Незнакомец,
  `superhero` 🦸 Супергерой, `robot` 🤖 Робот, `alien` 👽 Пришелец, `dinosaur` 🦖 Динозавр, `lion` 🦁 Лев, `frog` 🐸
  Лягушка, `turtle` 🐢 Черепаха, `octopus` 🐙 Осьминог, `whale` 🐳 Кит, `seal` 🦭 Тюлень).
- **Проверка (тест)**: (1) эмодзи масок без селекторов начертания (`U+FE0E`/`U+FE0F`) не равны эмодзи значков без них и
  не содержат кодовых точек значков (так «🐻‍❄️» был бы пойман по «🐻»); (2) названия масок не содержат слов из списка
  смыслов значков (`BADGE_MEANINGS` в тесте: санта, ёлка, снеговик, олень, медведь, лиса, сова, волк, тигр, единорог,
  пингвин, звезда, снежинка, подарок…); список сверяется с числом значков (у каждого значка — хотя бы одно слово), чтобы
  новый значок без смысла не прошёл молча.
- **Alternatives**: свой текст маски — отклонено владельцем (имя другого участника, эмодзи своего значка).

## R4. Когда маску можно менять

- **Decision**: пока событие идёт (конвейер: `finished: 'Событие завершено: маску больше не сменить.'`) и тайна не
  раскрыта; есть пара, где человек — Санта. Порядок отказов: маска не из набора → тайна раскрыта (по событию вызова) →
  нет подопечного. `UPDATE pairs SET mask = ? WHERE event_id = ? AND santa = ? AND EXISTS (событие с revealed = 0)`;
  0 строк → повторное чтение события: раскрыта — «Тайна уже раскрыта — маску больше не сменить.», иначе «У тебя пока
  нет подопечного.»
- **Rationale**: раскрытие называет маску в сообщении — смена после него разошлась бы с тем, что подопечный уже
  прочитал; условие в `UPDATE` закрывает гонку «смена ↔ раскрытие» (маска в сообщении раскрытия — последняя записанная
  до раскрытия, хотя пакет раскрытия читает пары до записи: маска, сменённая между чтением и захватом раскрытия, в
  сообщении — прежняя; это допустимо — заголовок переписки после раскрытия тоже показывает маску, а смена после захвата
  уже невозможна).
- **Alternatives**: `atomic` — не нужен: один оператор, сообщений и журнала нет; двойное нажатие — тот же результат.

## R5. Где маска видна и откуда берётся

- **Decision**:
  - Санта: `ward.get` → `mask` (кнопка, подсказки «Подопечного»); `chat.get` с `with: 'ward'` → `mask` (подсказка шторки);
    бот — просьба «Напиши подопечному…» (`onReplyButton`, пара уже прочитана).
  - Подопечный: `event.get` → `member.santa_mask` (подсказка «Письма», заголовок шторки сразу при открытии — без
    мигания); `chat.get` с `with: 'santa'` → `mask` (заголовок обновляется опросом); бот — уведомление о сообщении Санты
    (`sendChatMessage`, пара уже прочитана), просьба «Напиши своему Санте…», раскрытие (`revealAll` читает
    `pairLinksQuery` — к выборке добавляется `mask`).
- **Rationale**: все выборки уже есть (`SELECT *` пары или узкая выборка того же запроса) — число запросов прежнее.
- **Не видна**: `admin.state` (`panelPairsQuery` — явный список колонок), журнал, `roster`, `admin.wishlist`,
  `admin.users`, `admin.vault.*` (явные поля). `pairsQuery` (`SELECT *`) читают `remindSantas` и изменения пар — наружу
  не отдаются.

## R6. Тексты

- Уведомление подопечному: `💬 <b>Твой Тайный Санта «🐉 Дракон» (${t}) пишет:</b>`; без маски — прежнее.
- Просьба подопечному: `✍️ Напиши сообщение своему Санте «🐉 Дракон» (${q(ev)}) — я передам его. …`.
- Просьба Санте: `… <b>анонимно</b>, от имени «Тайного Санты · 🐉 Дракон».`
- Раскрытие: `В событии ${q(ev)} твой Тайный Санта «🐉 Дракон» — <b>Боря</b>.`
- Приложение: заголовок шторки «Твой Тайный Санта · 🐉 Дракон»; подсказки «для подопечного ты — «Тайный Санта ·
  🐉 Дракон», имя не раскрывается»; «Письмо» — «Твой Санта — в маске «🐉 Дракон».»
- Все без глаголов прошедшего времени (FR-011). Слово «событие» — по правилам 013 (тест `wording`).
- Длина: самый длинный заголовок уведомления — «💬 Твой Тайный Санта «🕵️ Тайный агент» («<40>») пишет:» + `\n\n` —
  93 единицы UTF-16 ≤ 96 (запас `MAX_CHARS`); проверяет тест по всему набору.

## R7. Эталон отказов

- **Decision**: `mask.set` — третий поздний проход (`NEW_ACTIONS_040`, ключи «040 <ситуация> mask.set») и «040 extra»:
  маска не из набора, в завершённом, без подопечного, после раскрытия. Прежние ключи не меняются.

## R8. Приложение

- Плитка маски — `ds-choice` с эмодзи и `ds-choice__label` в сетке `ds-choices--labeled` (новый модификатор; размеры —
  существующие токены `--ds-size-choice-card`, шрифт `--ds-text-xs`).
- `maskLabel(id)` в приложении — по `state.looks.masks` (набор из `me`), свой копии набора нет.
- Шторка переписки: заголовок — узел, текст ставит `maskTitle(mask)`; первый показ — из `state.member.santa_mask`
  (подопечный) или `state.wardCache` (Санта), затем каждый ответ `chat.get`.
