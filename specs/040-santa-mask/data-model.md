# Data Model: Маска Санты в переписке (040)

## Пара (`pairs`) — новая колонка

| Колонка | Тип | Умолчание | Значение |
|---|---|---|---|
| `mask` | `TEXT NOT NULL` | `''` | `id` маски из `MASKS` или `''` — без маски |

- Пишет только `mask.set` (Санта своей пары, пока событие идёт и тайна не раскрыта).
- Новая строка пары (жеребьёвка, изменения пар после неё) — без маски (умолчание; `INSERT` колонку не называет).
- Перенос участия меняет `santa`/`ward` в той же строке — маска остаётся.
- Удаление пары (отмены жеребьёвки, удаление участника, сброс, удаление события) — маска уходит со строкой.
- `REGISTRY` (`src/db.js`) не меняется: колонка не содержит человека.

Миграция `migrations/0011_santa_mask.sql`: `ALTER TABLE pairs ADD COLUMN mask TEXT NOT NULL DEFAULT ''`; версия схемы
`14` (`REQUIRED_SCHEMA = 14`). Прежний код работает со схемой 14 (требует не ниже 13) — порядок выката «миграция → код».

- `validMask(x)` — `x`, если `''` или `id` из набора; иначе `null`.
- `maskLabel(id)` — «<emoji> <title>» или `''` (нет маски или её больше нет в наборе).
- Правила набора (тест): `id` уникальны, `emoji` — одна графема, ни один `emoji` (без селекторов начертания) не равен
  значку и не содержит кодовой точки значка; `title` не содержит слов из списка смыслов значков.
