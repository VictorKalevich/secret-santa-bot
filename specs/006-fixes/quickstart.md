# Quickstart: проверка 006-fixes

## Подготовка

```powershell
npm install
npx wrangler d1 migrations apply DB --local   # локальная база для npm run dev
```

## Автотесты

```powershell
npm test            # draw: бюджет шагов, замер ≤ 10 мс для 50 участников; дизайн-система
npm run test:e2e    # сквозные сценарии ниже (миграции применяет сама обвязка)
```

| Сценарий (e2e) | Ожидание |
|---|---|
| админ переносит участника с подопечным на свой аккаунт | 400; `ward.get` админа — без подопечного участника |
| перенос на обычный новый аккаунт | успех; прежний аккаунт и другой админ получили уведомление |
| эвент с названием 80 символов, сообщение 4000 символов | получатель получил уведомление (имитация Telegram отклоняет > 4096) |
| два одновременных `admin.draw` | один успех, один «уже проведена»; по одному уведомлению о жеребьёвке на участника |
| сообщение заблокировавшему бота участнику | в `admin.state` `blocked: true`; после `/start` от него — `false` |
| повторный `admin.reveal` | 400, второй рассылки нет |
| `admin.remove` не-участника, исключение с не-участником, переименование админа обычным админом | отказы |
| база без миграции 0002 (только 0001 с данными) → применить миграции | данные на месте, бот отвечает |
| база без миграций | `/` и `/api/me` → 500 с текстом «База не подготовлена» |

## Ручная проверка (по желанию)

1. `npm run dev`. Откройте `http://127.0.0.1:8787/` до применения миграций: должен прийти текст «База не подготовлена».
2. Примените миграции — бот отвечает «работает».
3. В панели эвента у участника, которому Telegram не доставил сообщение, видна метка «🚫 не получает сообщения».
