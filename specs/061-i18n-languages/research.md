# Research 061: бот на языке человека

## R1. Хранение языка: выбор и язык Telegram — две колонки

**Decision**: `users.lang` (060) — язык, выбранный человеком (`''` — «как в Telegram»); новая `users.tg_lang` — последний
известный язык Telegram, уже приведённый к языку бота (`''` — неизвестен). Язык человека —
`langOf(user, telegram) = lang || telegram || tg_lang || 'ru'`, где `telegram` — язык Telegram текущего обращения
(приведённый). Запись `tg_lang` — только когда приведённый язык обращения есть и отличается от сохранённого.

**Rationale**: два факта, одна формула; «Как в Telegram» — просто `lang = ''`; язык Telegram нужен и без обращения
(сообщение очереди получателю), поэтому хранится; запись при изменении — ноль запросов в обычном обращении.

**Alternatives considered**: одна колонка «язык» + признак «выбран вручную» — та же информация, но при снятии выбора
неизвестно, какой язык Telegram был; вычислять язык Telegram при каждой отправке — у очереди его нет.

## R2. Где определяется язык Telegram

**Decision**: код языка берётся из `from.language_code` (сообщение, нажатие) и `user.language_code` в `initData`
(мини-приложение); `openContext(env, userId, { telegramLang })` приводит его (`telegramLanguage(code)`) и строит
`ctx.lang`; `syncLanguage(ctx)` (`src/language.js`) сразу после контекста во всех точках входа (API, сообщение, нажатие,
кнопки регистрации) пишет `tg_lang` при изменении и ставит кнопку меню чата (R6). Новая запись человека
(`createUserStmt`) получает `tg_lang` из контекста.

Правило приведения (`telegramLanguage`): нижний регистр, основной код до `-`/`_`; есть в боте → он; `be`, `uk`, `kk`,
`ky`, `tg`, `uz`, `hy`, `az`, `tk` → `ru`; пусто/нет поля → `''` (неизвестен); прочее → `en`. `pt-br` → `pt`,
`zh-hant`, `zh-tw` → `zh`.

**Rationale**: одна функция на сервере; та же — в приложении для текстов загрузки (R7), сверка тестом по склейке.

## R3. Выбор языка: действие `lang.set`, кнопки `/language`

**Decision**: API `lang.set { lang: '' | код }` (роль — как `notify.set`, зарегистрированный человек); в ответе — `lang`
(язык человека после выбора). Бот: `/language` (после проверки «есть запись», до регистрации тоже) — сообщение с
кнопками `lang:auto` и `lang:<код>` (по 2 в ряд, названия языков на самих языках, текущий отмечен ✓); нажатие — до
проверки «зарегистрирован» (как кнопки регистрации 047): сохраняет, отвечает на новом языке, зарегистрированному — меню
на нём, ждущему имени — просьба имени на нём. Общая функция `setLanguage(ctx, choice)` (`src/language.js`): проверка
кода (`api.lang.unknown`), запись, кнопка меню (R6), команды чата (R5).

Приложение: «🌐 Язык: <название>» в «Профиле» — шторка `openLangSheet` (строки `ds-list-item`
с ✓ у текущего выбора); после ответа — `reloadMe()` (новый словарь по версии) и тихая перестройка текущего экрана
(`render()` с прежней прокруткой).

## R4. Профиль бота: части в конце обычных обращений

**Decision**: `src/bot-profile.js`: цели — `''` (по умолчанию, английский), 10 языков бота кроме английского (`ru`, `es`,
`pt`, `fr`, `de`, `zh`, `it`, `tr`, `id`, `pl`) и 9 «русских» кодов (`be`…`tk`, тексты `ru`): 20 целей × 3 вызова
(`setMyCommands`, `setMyDescription`, `setMyShortDescription`) = 60 вызовов; версия — отпечаток JSON всех вызовов.
Настройка `settings.bot_profile = '<версия>:<следующий>'`. Обращение (API, бот) читает настройки в первом пакете —
если версия другая или не дошла до конца и бот настроен (`base_url`), после ответа (`afterRequest`, `waitUntil`) идёт
`sendProfile` — вызовы по порядку, пока остаток бюджета вызова больше запаса (4), затем запись прогресса одним
оператором. Ошибка Telegram части — журнал Worker и следующая часть (без повторов). `/setup` — те же вызовы с 0 в своём
бюджете (шаг «Команды» — результат первой цели), остальное — обращениями. Cron профиль не трогает (минута без
запросов, SC-006).

**Rationale**: `/setup` на боевых ботах заблокирован после ссылки владельца (423) — профиль должен доходить сам; 60
вызовов не помещаются в лимит 50 одного вызова; настройки уже читаются в первом пакете обращения — проверка бесплатна;
два одновременных обращения повторят одну часть — вызовы идемпотентны.

**Alternatives considered**: cron — +1 чтение настроек каждую минуту (057: обычная минута — 3 запроса); скрипт у
владельца с токеном — ручной шаг с секретом; меньше целей (без «русских» кодов) — нарушит правило языка в меню.

## R5. Команды в чате при ручном выборе

**Decision**: при `setLanguage` с выбором, отличным от `''`, — `setMyCommands` с `scope: { type: 'chat', chat_id }` на
выбранном языке; при `''` — `deleteMyCommands` с тем же scope. Только при явном выборе (не при смене языка Telegram).
Новые тексты команд в следующих выкатах в чатах с ручным выбором обновятся при следующем выборе (допущение).

## R6. Кнопка меню чата

**Decision**: новая `users.menu_lang` — язык, на котором поставлена кнопка меню чата (`''` — общая кнопка бота,
русская). `syncLanguage`: если запись есть, бот настроен и язык человека (кроме `ru`) ≠ `menu_lang` (или язык `ru`, а
`menu_lang` не пуст) — `setChatMenuButton` с `chat_id` (подпись `setup.menuButton` на его языке, адрес `/app`) или
`{ type: 'default' }` для русского; `menu_lang` пишется в любом случае (ошибка — в журнал Worker, без повторов в каждом
обращении). Общая кнопка бота (`/setup`) — русская, как прежде.

**Rationale**: подпись кнопки меню у Telegram не зависит от языка — только общая и для чата; колонка делает действие
идемпотентным и ловит нового человека со второго обращения.

## R7. Тексты загрузки приложения на всех языках

**Decision**: в страницу вместо `/*@boot-texts*/null` — `{ texts: { <язык>: { app.boot.* } }, rule: { languages,
russian, fallback } }`; приложение до `me` выбирает язык по `tg.initDataUnsafe.user.language_code` (вне Telegram —
`navigator.language`) тем же правилом (функция `telegramLanguage` в `02-core` по данным `rule`); после `me` — словарь
языка человека. Отпечаток CSP считается по отдаваемой странице, как прежде.

## R8. Подробности журнала на языке смотрящего

**Decision**: новая `audit.details_tx` — JSON отложенного текста подробностей (`''` — нет: строка, пусто или JSON длиннее
2000); `details` — прежний русский текст (читает прежний код при откате, тесты и выгрузки). `getAudit` выбирает обе и
собирает `details_tx` на языке смотрящего (переводчик вызова), иначе `details`; разбор с защитой (ошибка — `details`).

## R9. Слова подтверждения

**Decision**: сравнение «как набрано» → `foldWord(s, lang)`: `trim` → `toLocaleUpperCase(lang)` → NFD → без
диакритики (`\p{M}`); то же у ожидаемого слова. Сервер (`confirmed`) и приложение (`typedSheet`) — одно правило; русские
слова принимаются как прежде (дополнительно — без «й», безвредно). Переводчики выбирают одно слово без пробелов.

## R10. Переводы: 10 языков параллельно

**Decision**: словарь языка — `src/i18n/<язык>/` с тем же `index.js` (те же `AREAS`), что у русского; переводят
исполнители (по одному на язык) параллельно с инфраструктурой, каждый — только в своей папке, проверка —
`node tests/support/i18n-lang-check.mjs <язык>` (ключи, подстановки, формы числа, списки, кириллица, разметка, длины,
слова подтверждения). Регистрация языков в `src/i18n/index.js` — после переводов. Глоссарий языка — в
`contracts/glossary/<язык>.md` (термины и решения переводчика). Источник — русский; английский — не промежуточный.

Формы числа: у нового языка набор форм содержит все категории `Intl.PluralRules(<язык>)` для целых 0…1000 и `other`;
`app.core.locale` — код языка (`pt`, `zh`…), чтобы приложение и сервер выбирали одну форму.
