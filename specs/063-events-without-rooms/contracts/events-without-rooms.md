# Контракт 063: события без комнат

Сводный контракт после выката — `docs/api.md` (правится в этой ветке). Здесь — что меняется относительно 062.

## 1. Роли и конвейер (`src/api.js`)

- `ROLES` прежние. `ADMIN`/`OWNER` действия события — в контексте события `ctx.at(ev)`: админ — организатор этого
  события (строка `event_admins`) или владелец бота; владелец — `ev.owner_id` (0 — владелец бота) или владелец бота.
- Порядок проверок `admin.*` с событием: регистрация → общий признак `users.is_admin` (иначе 403 «Только для
  администратора.») → событие есть (иначе 404) → организатор этого события (иначе: участник события — 403 «Только для
  администратора.», не участник — 404 «Событие не найдено.») → «в завершённом» → владелец → слово → обработчик.
- Действие без события с ролью `OWNER` и `bot: true` (`admin.rename`, `admin.transfer`): после общего признака —
  `ctx.isBotOwner()`, иначе 403 текстом `owner`.
- Признака `company`, отказа «Выбери комнату.», `ctx.in`, `soleCompany`, `mine`, `companies` — нет.

### `event.create`

- **Запрос**: `title`; `from` — образец (событие, где вызывающий — организатор; владелец бота — любое); `invite` —
  пригласить участников образца; `participate` — «Я тоже участвую» (по умолчанию `true`, если поле не передано).
- **Ответ**: `event` (`publicEvent` + `role: 'owner'`), `invited`, `invite_error` (как прежде).
- **Отказы по порядку**: 403 «Создавать события может владелец бота и те, кому он разрешил.» (закрытый бот, нет
  разрешения); 400 «Название события — от 1 до 80 символов.»; 400 «Образец не найден.»; 400 «За последние 12 месяцев
  создано 10 твоих событий — это предел. Следующее можно будет создать {date}.» (по свежему счёту; также второй из
  одновременных у границы); 403 разрешения — если его сняли одновременно (условие пакета).
- **Пакет** (`createEvent`): вставка события с условиями (закрытый бот — `can_create = 1` или владелец бота; лимит —
  кроме владельца бота) и `company_id = 0`, `owner_id = создатель`; по коду приглашения — `event_admins`
  создателя, `event_creations`, участие (`participate`), исключения образца, журнал события `event.create`, журнал бота
  `event.create` («<название>»), `adminFlagStmt` создателя. Приглашение участников образца — после, как прежде.

### `admin.role.grant` / `admin.role.revoke`

- **Запрос**: `event`, `id`.
- **grant** — отказы: 400 «Назначить можно только участника события.» (не участник или не зарегистрирован); 400
  «Он(а) уже администратор.» (в т. ч. второй из одновременных). Сообщения: назначенному — «🛠 Тебя назначили
  администратором события {title}…» с кнопкой события; остальным организаторам события — без звука. Журнал события
  `role.grant` (имя).
- **revoke** — отказы: 400 «Он(а) не администратор.»; 400 «Нельзя снять права владельца. Сначала передай владение
  событием.» Обращения, которые он вёл в этом событии, — снова ничьи (`support.return`). Сообщения: снятому, остальным
  организаторам (без звука). Журнал события `role.revoke`.
- Не владельцу — 403 «Назначать и снимать администраторов может только {owner.nom}.»

### `admin.owner.transfer`

- **Запрос**: `event`, `id` — участник или организатор события, зарегистрированный.
- **Отказы**: 400 «Передать владение можно только участнику или администратору события.»; 400 «Он(а) уже владелец.» /
  «Ты и так владелец.»; 400 «Владение уже передано.» (второй из одновременных — владелец уже другой).
- **Пакет** по прежнему владельцу: строка `event_admins` нового → сообщения (новому — «👑 Ты теперь владелец события
  {title}…»; прежнему, если передал не он — «ℹ️ Владение событием {title} перешло к {who}. Ты остаёшься
  администратором.»; остальным организаторам — без звука) → журнал события `event.owner` («→ <имя>») → `owner_id`
  (захват) → `adminFlagStmt` обоих.
- Не владельцу — 403 «Передать владение событием может только {owner.nom}.»

### `admin.rename`

- Только владелец бота (403 «Переименовать человека может только владелец бота.»). Цель — любой зарегистрированный (400
  «Участник не найден»). Журнал бота `rename` («<старое> → <новое>») — только при изменении.

### `bot.events`

- **Запрос**: `offset` (по умолчанию 0). **Ответ**: `events: [{ id, title, status, event_date, owner_name, people }]`
  — новые первыми, до 50; `more` — есть ли следующая страница.

### `bot.people`

- **Ответ**: `people: [{ id, name, username, can_create }]` по имени; закрытый бот — все зарегистрированные; открытый —
  люди событий, где владелец бота организатор (кроме него самого).

### `bot.creator.set`

- **Запрос**: `id`, `on`. **Отказы**: 400 «В открытом боте создавать события может любой.» (открытый бот); 400
  «Назначить можно только зарегистрированного человека.»; 400 «Уже разрешено.» / «Уже не разрешено.» (в т. ч. второй
  из одновременных). **Пакет** по прежнему значению: сообщение человеку, журнал бота `creator.grant` / `creator.revoke`
  (имя) → `can_create` (захват).

### `bot.owner.transfer`

- Цель — любой зарегистрированный человек (не себя). Журнал — только журнал бота. Сообщения — новому владельцу бота.
  События и организаторство не меняются. Прежний владелец бота получает разрешение создавать события (`can_create = 1`,
  в том же пакете, до захвата): лимит у него появляется, а не пропадает возможность создавать (то же — при ссылке
  владельца `/setup`).

## 3. Ответы чтения

- `me`: `me` — `{ id, name, is_admin, is_owner, notify_mode }` (`is_admin` — организатор хотя бы одного события или
  владелец бота; `is_owner` — владелец бота); `events` — мои события (участник или организатор), каждое `{ id, title,
  status, finished_at, event_date, draw_done, member, role, unread }`, `role` — `owner` | `admin` | `member`;
  `create` — владельцу бота `{ bot: true }`, кто может — `{ left, limit: 10, next }` (`next` — мс, когда освободится
  место, только при `left = 0`), кто не может — поля нет; `open` — как прежде. Полей `companies`, `events[].company` нет.
- `event.get`: `event.role` — `owner` | `admin` | `member` | `guest` (гость — владелец бота без участия и организаторства);
  `event.company` нет; роли в `roster` — по событию.
- `admin.state`: `users[].is_admin` — организатор этого события; `organizers: [{ id, name, username, owner }]` —
  владелец первым, остальные по имени (зарегистрированные строки `event_admins`); `other_events` — события, где
  вызывающий — организатор (владелец бота — ещё события владельца этого события), кроме текущего; `settings.owner_id`.
- `admin.event.invite_from`: источник — событие, где вызывающий организатор (владелец бота — любое), не текущее;
  иначе «Выбери другое событие.»

## 5. Бот

- `/start own_<код>` → «Эта ссылка больше не действует. Попроси у организатора пригласительную ссылку на событие.» и
  меню (незнакомцу закрытого бота — прежний ответ «закрытый бот»; открытого — просьба имени). Ожидание `name_own:…`
  после имени — регистрация и тот же текст.
- Меню: события без названий комнат; строка роли — только у владельца бота («👑 Ты владелец бота.»); без идущих
  событий: может создавать — «Создай своё событие в приложении или попроси пригласительную ссылку на событие.», не может
  — прежний текст.
- После регистрации без события: может создавать — «Создай первое событие в приложении…» (прежний `bot.createFirstEvent`
  без слова «комната»), иначе — прежнее приветствие.

## 6. Приложение

- Корень — «Мои события» (`renderHome`): шапка «🎅 Тайный Санта», подзаголовок «Привет, <имя>!», кнопка ⚙️ справа
  (`heroAction`); «Идут» — по дате вручения (без даты — в конце, новые первыми), «Завершённые · N» — `ds-details`,
  свёрнуто; строка — `eventRow` с чипами роли (`app.core.role.owner`/`admin`), даты, «не участвуешь»; пусто —
  подсказка по `state.create`. Внизу — `ds-bottom-bar` с «🎄 Создать событие» (только при `state.create`), у страницы
  `ds-page--bar`.
- Шторка создания: название, образец (события с ролью `owner`/`admin`), «Пригласить участников образца», «Я тоже
  участвую» (вкл.), подсказка «Можно создать ещё N» / «предел… следующее — <дата>» (кнопка недоступна при `left = 0`).
- «Настройки» (`view: 'settings'`, часть `04-settings`): «Профиль», «🌐 Язык», «Уведомления» + пояснение, «О боте»
  (три пункта «Как это работает» и «Поддержать проект» в открытом боте — `donateSection`), «Владелец бота» (только
  `state.botOwner`): «📜 Журнал бота», «👑 Передать права владельца бота», «🗂 Все события», закрытый бот — «✍️ Кто может
  создавать события». «‹» — к списку.
- «Все события» и «Кто может создавать события» — шторки (`openSheet`), список — `bot.events` (страницы, «Показать
  ещё»), `bot.people` (переключатели `ds-switch`).
- Событие: «‹» — к списку; права — `enterEvent(role)`; гость — плашка «Ты здесь как владелец бота: в списках события
  тебя нет, сообщения администраторам тебе не приходят. Твои изменения записываются в журнал события.»
- «Управление»: секция `adminOrganizers(p)` «Владелец и администраторы» (перенесена с главного экрана): список
  `organizers` с ✕ и 👑 владельцу; «Назначить администратором» из участников-неорганизаторов; «Передать владение» —
  из участников и организаторов; не владельцу — «Назначает администраторов владелец события — <имя>.» Переименование
  участника — только `state.botOwner`.
- Журнал: только журнал события и журнал бота (`openAudit(null)` убран).
