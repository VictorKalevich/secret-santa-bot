# Feature Specification: Терминология «событие» и подписи

**Feature Branch**: `013-event-wording`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "Во всём боте и мини-приложении слово «эвент» заменяется на «событие». Перед названием события
в сообщениях бота слово убирается, где название стоит отдельно; где от слова зависит падеж — «событие» в нужном падеже.
«Мои эвенты» → «Мои события», «＋ Новый эвент» → «🎄 Создать», «Новый эвент» в шапке → «Новое событие», плюсы с
кнопок убрать, «Завершить эвент» → «Завершить», «Параметры эвента» → «Параметры», «Завершить эвент через 3 дня…» →
«Завершить через 3 дня…», «Полный сброс эвента» → «Полный сброс», «Удалить эвент» → «Удалить событие», «Как это
работает» — «событие». Поведение не меняется."

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Сообщения бота без слова «эвент» (Priority: P1)

Участник и организатор получают от бота уведомления (вступление, жеребьёвка, переписка, обращения, напоминания,
завершение и т. д.). Слово «эвент» в них больше не встречается: где название события стоит отдельно (в скобках, после
запятой), слово просто убрано; где от него зависит падеж или согласование, стоит «событие» в нужной форме — так
предложение остаётся грамотным при любом названии.

**Why this priority**: уведомления видят все участники, и именно о них просил владелец.

**Independent Test**: пройти сквозной сценарий (вступление, жеребьёвка, переписка, обращение, завершение) и
просмотреть все пришедшие сообщения — ни одного «эвент»; уведомление о вступлении — в точной форме из FR-1304.

**Acceptance Scenarios**:

1. **Given** Артём вступает в событие «Тест 1», **When** организатор получает уведомление, **Then** текст —
   «👋 **Артём** присоединяется к событию «Тест 1»».
2. **Given** проведена жеребьёвка в «Тест 1», **When** участник получает уведомление, **Then** в тексте «событии «Тест 1»»
   (а не «эвенте»).
3. **Given** подопечный написал Санте, **When** Санта получает сообщение, **Then** заголовок — «💬 Тебе пишет твой
   подопечный («Тест 1»):» (слова «эвент» нет, как и раньше).
4. **Given** админ получает уведомление об обращении, **When** в нём указано событие, **Then** вместо «(эвент «X»)» —
   «(«X»)».
5. **Given** событие завершено, **When** участник получает итоговое сообщение, **Then** «🏁 Событие «X» завершено.»

### User Story 2 — Подписи мини-приложения (Priority: P1)

Владелец, админы и участники видят в приложении «события» вместо «эвентов», а отдельные подписи — в короткой форме,
которую выбрал владелец проекта.

**Why this priority**: главный экран и панель организатора — то, что видят каждый день.

**Independent Test**: открыть главный экран, создание события, вкладки «Инфо» и «Админ» (в том числе «Опасная зона» и
параметры) — подписи совпадают с FR-1305, слова «эвент» нигде нет.

**Acceptance Scenarios**:

1. **Given** главный экран, **Then** разделы «Мои события» / «Другие события», кнопка «🎄 Создать» (без плюса).
2. **Given** нажата «🎄 Создать», **Then** открывается прежний диалог с заголовком «Новое событие».
3. **Given** панель организатора, **Then** кнопки «Завершить», «Полный сброс», «Удалить событие», «Новая семья»,
   «Добавить исключение» (без плюсов и без лишнего пробела в начале), раздел «Параметры», галочка «Завершить через 3 дня
   после вручения».
4. **Given** вкладка «Инфо», **Then** в «Как это работает» — «события» / «Событие сохранится в истории».

### User Story 3 — README в тех же словах (Priority: P2)

Владелец проекта читает README и находит в нём те же слова и подписи, что в боте.

**Why this priority**: README ведёт от нуля до работы (Конституция, правило README) — подписи должны совпадать.

**Independent Test**: в пользовательских разделах README нет «эвент», все цитаты подписей совпадают с приложением.

**Acceptance Scenarios**:

1. **Given** README, **When** ищу «Новый эвент», «Параметры эвента», «Удалить эвент», «Полный сброс эвента»,
   **Then** находятся новые подписи («🎄 Создать», «Параметры», «Удалить событие», «Полный сброс»).

### Edge Cases

- Название события, которое ввёл организатор (например «Эвент отдела»), не меняется — это пользовательские данные.
- Записи журнала и сообщения в очереди, созданные до обновления, остаются в прежних словах; новые — в новых.
- Название — в родительном/дательном/предложном положении («из», «к», «в», «для»): всегда со словом «событие» в
  нужном падеже, потому что название не склоняется («к событию «Новый год 2026»», а не «к «Новый год 2026»»).
- Согласование рода: «событие» среднего рода — «Событие не найдено», «Событие завершено», «это событие», «новое
  событие».

## Requirements *(mandatory)*

### Functional Requirements

- **FR-1301**: Ни один текст, который видит человек (сообщения и кнопки бота, мини-приложение, подтверждения, ошибки,
  страница `/setup`, журнал действий), не содержит слова «эвент» ни в какой форме; автотест это проверяет.
- **FR-1302**: Если название события стоит отдельно — в скобках («(эвент «X»)» → «(«X»)») или через запятую
  («…, эвент «X»» → «…, «X»») — слово убирается.
- **FR-1303**: Если от слова зависит падеж или согласование (после предлогов, подлежащее), используется «событие» в
  нужной форме и роде: «в событии «X»», «к событию «X»», «из события «X»», «Событие «X» завершено».
- **FR-1304**: Уведомление организаторам о вступлении: «👋 **Имя** присоединяется к событию «X»» (форма
  «присоединяется» — без рода).
- **FR-1305**: Подписи приложения: «Мои эвенты» → «Мои события»; «＋ Новый эвент» → «🎄 Создать»; заголовок диалога
  «Новый эвент» → «Новое событие»; «＋ Новая семья» → «Новая семья»; «＋ Добавить исключение» → «Добавить исключение»;
  «Завершить эвент» → «Завершить»; «Параметры эвента» → «Параметры»; «Завершить эвент через 3 дня после вручения» →
  «Завершить через 3 дня после вручения»; «Полный сброс эвента» → «Полный сброс»; «Удалить эвент» → «Удалить событие»;
  «Как это работает» — «событие».
- **FR-1306**: Ни одна кнопка не начинается со знака «＋»; текст кнопки начинается без пробела.
- **FR-1307**: Поведение не меняется: те же действия, кнопки, ссылки, проверки, права и данные; меняются только тексты.
- **FR-1308**: README (пользовательские разделы) использует «событие» и новые подписи.

### Key Entities

- **Событие** (бывший «эвент») — одна игра со своей ссылкой, участниками и жеребьёвкой. Меняется только название
  в текстах; данные и их смысл те же.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 0 вхождений «эвент» в текстах, которые видит человек (проверка автотестом по коду бота и приложения).
- **SC-002**: Все 11 подписей из FR-1305 видны на скриншотах в новой форме.
- **SC-003**: Сквозной сценарий проходит без изменений поведения: те же шаги, те же результаты, обновлены только
  ожидаемые тексты.
- **SC-004**: Каждое сообщение бота с названием события грамотно читается при названии «Новый год 2026» (нет конструкций
  «предлог + «название»» без слова «событие»).

## Assumptions

- Внутренние имена (код, база, API: `event`, `events`) и прошлые спецификации (`specs/001`–`012`) не меняются —
  это не тексты для людей; в коде и комментариях допустимо «эвент».
- Картинка для «Создать» — 🎄 (тема игры), выбор владельца проекта «подходящая картинка».
- Витрина дизайн-системы (`preview.html`) — для разработчика; примеры текста в ней не трогаем.
- Регистр заголовков разделов задаёт дизайн-система (заглавные буквы на экране), в тексте — «Мои события».
