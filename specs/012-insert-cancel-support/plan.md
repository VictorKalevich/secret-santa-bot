# Implementation Plan: Вписывание по приоритету, принудительная отмена жеребьёвки, обращения к организатору

**Branch**: `012-insert-cancel-support` | **Date**: 2026-11-13 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/012-insert-cancel-support/spec.md`

## Summary

Три изменения:

1. **Вписывание после жеребьёвки** — только владелец; Санта, у которого сменится подопечный, выбирается по группам
   (не открыл подопечного и без переписки → подарок не готов и не получен → отказ одной общей фразой). Выбор — чистая
   функция в `src/draw.js` (ранг связки), условие группы повторено в захвате версии пар, чтобы Санта, открывший
   подопечного или отметивший подарок в ту же секунду, не потерял его.
2. **Принудительная отмена жеребьёвки** — новое действие владельца `admin.draw.cancel.force` (слово «ОТМЕНА»): один batch
   с захватом по `draw_token` и `revealed = 0`; удаляет пары и переписку Сант эвента, открывает регистрацию, рассылка и
   журнал — по условию. Кнопка — в опасной зоне.
3. **Обращения к организатору** — новый модуль `src/support.js`, миграция `0006_support.sql` (таблицы `support_threads`,
   `support_messages`, схема 10), действия API `support.*` (участник) и `admin.support.*` (админы), кнопки бота
   `sup:take:<id>`, `sup:u:<эвент>`, `sup:a:<id>` и режим ответа `sup_u:`/`sup_a:` в `bot.js`. В приложении — раздел
   «Нужна помощь?» во вкладке «Инфо», раздел «Обращения» в панели «Админ», новый элемент дизайн-системы `ds-chat__note`.

## Technical Context

**Language/Version**: JavaScript ES2022, ES-модули (Cloudflare Workers, workerd)

**Primary Dependencies**: нет рантайм-зависимостей; Wrangler 4 (dev/deploy/миграции)

**Storage**: Cloudflare D1 (SQLite); новая миграция `migrations/0006_support.sql`, `REQUIRED_SCHEMA = 10`

**Testing**: `node:test` (юнит: ранжированное вписывание, правила дизайн-системы), e2e — `wrangler dev` +
`tests/mock-telegram.mjs` (блок 012), скриншоты — `playwright-core`

**Target Platform**: Cloudflare Workers (бесплатный тариф) + Telegram Bot API + Telegram Mini App (iOS WebKit, Android, ПК)

**Project Type**: веб-сервис (Worker) + одностраничное мини-приложение (`src/app.html`)

**Performance Goals**: ≤ 10 мс CPU и ≤ 50 внешних запросов на вызов; сообщение обращения — ≤ 10 запросов (рассылка
админам — один batch)

**Constraints**: тайна пар (I), владелец ⊇ админ (VII), только дизайн-система, рассылки только через `outbox`,
«одно действие — один результат» (захват + операторы по условию в одном batch), несвязанные элементы UI не меняются

**Scale/Scope**: одна группа (десятки человек, единицы админов и эвентов)

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Принцип | Проверка | Итог |
|---|---|---|
| I. Тайна по умолчанию | Вписывание — только владелец (админ по отметкам «не открыл»/«готов» вычислил бы, кто дарит новичку). Отказ вписывания — одна общая фраза (без «какая группа пуста»). Обращения не содержат пар: тексты пишут люди, подсказка просит не писать подопечного; админ видит переписку только ничьих и своих обращений. Уведомления без имени подопечного и без писем. Принудительная отмена — только владелец (участвующий админ мог бы переигрывать жеребьёвку). | ✅ |
| II. Проще некуда для участника | «Написать организатору» — вкладка «Инфо», одна кнопка; ответ приходит в чат бота с кнопкой «Ответить». | ✅ |
| III. Спецификация до кода | spec → plan → tasks; контракт — `contracts/api.md`; поправка Конституции (хранимые данные) — в этой ветке. | ✅ |
| IV. Только дизайн-система | Экраны из существующих компонентов (`ds-card`, `ds-list-item`, `ds-chips`, `ds-chat`, `ds-composer`, `ds-badge`, `ds-sheet`); новый элемент `ds-chat__note` — токены → `components.css` → `preview.html` → README. | ✅ |
| V. Бесплатно и без своего сервера | Новые действия — единицы запросов; рассылки — `outbox` в одном batch; без новых сервисов. | ✅ |
| VI. Проверено до выката | Юнит: группы вписывания (100 прогонов). e2e: только владелец вписывает/отменяет принудительно, отмена чистит пары и переписку, обращения (взять, гонка, видимость, передача, закрытие, ответ из бота, снятие прав, удаление участника, перенос), бюджет запросов. | ✅ |
| VII. Владелец — максимальные права | Владелец проходит все `admin.*` (автотест), видит все обращения, передаёт любое, закрывает любое; owner-only: `admin.insert`, `admin.draw.cancel.force`. | ✅ |

Поправка Конституции 2.1.0 → 2.2.0 (MINOR): раздел «Безопасность и данные» — хранятся обращения к организатору; их
переписку видят участник, взявший админ и владелец (до взятия — все админы).

**Post-design re-check**: research R1–R9 и контракты не вводят новых мест, где наружу отдаются пары; единственное
место, где админ влияет на пары после жеребьёвки без владельца, — удаление участника (не меняется). ✅
