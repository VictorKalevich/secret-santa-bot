# Контракт: компания в контексте вызова, конвейере API и модулях (050)

Внутренний контракт Worker. Внешнее поведение в боте с одной компанией не меняется; отличия видны только при двух и
более компаниях (в 050 — в тестах). Схема и инварианты — [data-model.md](../data-model.md), причины —
[research.md](../research.md).

## 1. Контекст вызова (`src/context.js`)

### Непривязанный (общий) контекст

```js
openContext(env, userId)      // API, сообщение боту, нажатие кнопки: один пакет чтений
makeContext(env, { me })      // cron: всё лениво
```

Первый пакет `openContext` (один запрос к базе): пользователь, настройки, строки компаний пользователя
(`company_members` по `user_id`), компании (`id, owner_id`), строка владельца бота. С 055 (`specs/055-api-indexed-reads/`)
компании — только его (по его строкам компаний); все — только владельцу бота по настройке `owner_id` (условие
`companiesQuery` проверяется до чтения строк).

| Поле | Смысл |
|---|---|
| `env`, `db`, `settings()` | как раньше |
| `me` | строка `users`; `me.is_admin` — «администратор хотя бы в одной компании или владелец бота» |
| `companies()` | `Map id → { id, owner_id }`, не больше одного чтения на вызов. С 055 — компании вызывающего: свои; владельцу бота — все (найденный запасным поиском дочитывает их одним запросом); без вызывающего (cron) — пусто, без запроса |
| `company(id)` | (055) одна компания по номеру или `null`: из прочитанных — без запроса, иначе одна строка; не больше раза на компанию за вызов |
| `read({ inCompany: id, ...named })` | (055) строка компании для `in(id)` тем же пакетом — вступление по ссылке (новичок ещё не человек компании); прежний `companies: true` упразднён |
| `mine()` | `Map company_id → { is_admin, label }` — компании вызывающего |
| `botOwnerId()` | владелец бота (`resolveOwner`: недействителен — самый ранний админ компаний с `owner_id = 0`) |
| `isBotOwner()` | вызывающий — владелец бота |
| `soleCompany()` | id единственной компании вызывающего или 0: у человека — единственная строка `mine()`; у владельца бота — единственная компания бота |
| `in(companyId)` | привязанный контекст; компании нет — `null`. Один объект на компанию за вызов. Компанию берёт `company(id)` |
| `users()`, `ownerId()`, `isOwner()`, `read({ users: true })` | **ошибка** «контекст без компании» |

### Привязанный контекст — `ctx.in(companyId)`

Передаётся в обработчики `ACTIONS` и во все функции модулей вместо общего.

| Поле | Смысл |
|---|---|
| `company` | `{ id, owner_id }` |
| `me` | копия `me` с `is_admin` = «организатор этой компании»: администратор компании, владелец компании или владелец бота |
| `users()` | люди компании: строки `users` с `is_admin` из `company_members` этой компании, порядок — `users.created_at`; плюс гость (ниже). Один запрос, не больше раза на вызов; с 055 — от строк компании, а не проходом по всем людям |
| `ownerId()` | `company.owner_id` или, если 0, `botOwnerId()` |
| `isOwner()` | вызывающий — `ownerId()` или владелец бота |
| `read({ users, settings, ...named })` | как раньше; `users: true` — люди компании тем же пакетом |
| `forgetUsers()` | как раньше |
| остальное | наследуется от общего (`settings()`, `botOwnerId()`, `mine()`, `in()`) |

**Гость.** Если у владельца бота нет строки в компании, `users()` добавляет его запись с `guest: true, is_admin: 0` —
чтобы его действия подписывались именем. Гость не человек компании: `adminRecipients` его не берёт (у него
`is_admin = 0`), `admin.users`, `admin.families`, состав семьи, назначение админом и «кому передать обращение» его
пропускают (`!u.guest`). Права гостя даёт `ctx.me.is_admin` и `ctx.isOwner()`, а не его запись в списке.

**Правило чтения прав.** В модулях: `ctx.me.is_admin`, `u.is_admin` из `ctx.users()`, `ctx.isOwner()` — права в компании
вызова. Общий признак `users.is_admin` читают только: первая проверка конвейера `admin.*`, меню бота, приветствие после
регистрации, запрет цели переноса.

## 2. Конвейер `handleApi` (`src/api.js`)

Шаги 1–4 прежние (метод, подпись, пакет `openContext`, «не зарегистрирован»).

5. `admin.*`, а `me.is_admin` ложно и вызывающий не владелец бота — 403 «Только для администратора.» (текст и место
   прежние). Затем определяется владелец бота (`botOwnerId()`).
6. Действие без события:
   - **общее действие организатора** (признак `company: true`): компания — `Number(body.company)` или `soleCompany()`;
     нет — 400 «Выбери компанию.»; компании нет или вызывающий в ней не организатор — 403 «Только для администратора.»;
     затем проверка владельца (403, текст строки) и обработчик с привязанным контекстом;
   - остальные (`me`, `notify.set`, `name.set`) — обработчик с общим контекстом.
7. Событие не найдено (или у события нет компании) — 404 «Событие не найдено.». Контекст привязывается к `ev.company_id`.
8. `admin.*`: вызывающий не организатор компании события — 404 «Событие не найдено.». Не `admin.*`: не участник — 403
   «Ты не участвуешь в этом событии.» (у `event.get` организатор компании события проходит без участия).
9–12. Как раньше («завершено», владелец, слово подтверждения, обработчик) — с привязанным контекстом.

### Действия с признаком `company: true`

`admin.events.create`, `admin.families`, `admin.family.save`, `admin.family.delete`, `admin.audit` (без `event`),
`admin.users`, `admin.rename`, `admin.transfer`, `admin.role.grant`, `admin.role.revoke`, `admin.owner.transfer`.

Тест `api-table`: у строки `admin.*` без `event: true` есть `company: true`; у `event: 'given'` — тоже (ветка без события).

## 3. Что считается в пределах компании

| Место | Правило |
|---|---|
| `me` (`homeView`) | события: где человек участник, плюс все события компаний, где он администратор; владельцу бота — все. `me.is_admin`, `me.is_owner` — как сейчас («админ где-нибудь», владелец бота). Непрочитанные обращения «ничьи» — только события компаний, где он администратор |
| `event.get` | организаторы и роли — компании события; гость среди организаторов не показан |
| `admin.state` | `users[].is_admin`, `is_owner`, `settings.owner_id` — компании события; `other_events`, семьи — компании события |
| `admin.events.create` | событие создаётся в компании вызова; образец `from` из другой компании — «Образец не найден.» |
| `admin.event.invite_from` | `from` из другой компании — «Выбери другое событие.» |
| `admin.users` | люди компании (зарегистрированные, без гостя); `owner_id`, `owner_name` — владелец компании |
| `admin.families`, `admin.family.save`, `admin.family.delete` | семьи компании; члены — люди компании («Участник не найден.»); «один человек — одна семья» и «уже в семье» — в компании; заморозка — по событиям компании; чужая семья — «Семья не найдена.» |
| `admin.audit` без события | общий журнал компании |
| `admin.rename` | цель — человек компании, иначе «Участник не найден»; запись `rename` — в журнал компании вызова |
| `name.set` | запись `rename` — по одной в журнал каждой компании человека (один пакет, условие общее) |
| `admin.role.grant`, `admin.role.revoke` | цель — человек компании (не гость); меняется `company_members.is_admin`, затем `adminFlagStmt`; «снова ничьи» — только обращения событий компании; сообщения остальным админам — компании |
| `admin.owner.transfer` | в 050 — прежний смысл (передача прав владельца бота); цель — зарегистрированный человек компании вызова |
| `admin.transfer` | переносит человека целиком; цель не владелец бота, не `users.is_admin`, не `companies.owner_id`; сообщения организаторам и запись `transfer` — по каждой компании старой записи |
| заявки, вступление, выход, обращения, роли | получатели — `adminRecipients(await ctx.users(), …)` привязанного контекста |
| вступление в событие с одобрением | без заявки вступает организатор компании события |
| жеребьёвка, проверка, вписывание, удаление, обмен | `familyRowsQuery(db, ev.company_id)`; прошлые пары — события той же компании; `SNAPSHOTS.families` — строки семей компании события (обе половины, паритет — `tests/snapshots.test.mjs`) |
| автодействия cron | контекст привязан к компании события; о неудаче автожеребьёвки — организаторам компании |

## 4. Человек компании

`joinCompanyStmt(db, companyId, userId, guard = '1', ...args)` — `INSERT … ON CONFLICT DO NOTHING` в `company_members`.
Ставится в тот же пакет (или вместо одиночного оператора — пакетом из двух), где бот принимает человека:

- `/start inv_…` незарегистрированного — вместе с созданием пользователя или записью ожидания имени;
- `joinByInvite` (вступление), заявка (`requestJoin`), одобрение заявки, «Я участвую», регистрация после ссылки.

Строка не удаляется при выходе, удалении участника, удалении и сбросе события.

## 5. Права администратора и владелец бота (`src/roles.js`)

- `grantAdmin`/`revokeAdmin` — по прежнему состоянию строки `company_members` (условие и захват — на ней); после захвата
  безусловный `adminFlagStmt(db, userId)` — пересчёт `users.is_admin` (инвариант I4).
- `setOwner` (ссылка владельца, передача): новому владельцу — `users.is_admin = 1` и строка `is_admin = 1` в каждой
  компании с `owner_id = 0` (I2); сообщения «теперь владелец бота» — администраторам этих компаний; записи `owner.link`,
  `owner.transfer` — в журнал каждой такой компании.
- `resolveOwner`: действителен, если запись владельца есть и `users.is_admin = 1`; иначе — самый ранний (по
  `users.created_at`) администратор среди компаний с `owner_id = 0`.

## 6. Журнал (`src/db.js`, `src/claim.js`)

Сфера записи — первым параметром вместо `eventId`: число > 0 — событие (компания записи — компания события, подзапросом в
операторе); `{ company: id }` — общая запись компании (`event_id = 0`). Ноль и пустое значение — ошибка. То же у
`auditStmt`, `auditIfStmt`, `atomic(...).audit` и чтения `getAudit(db, сфера)`. Коды и тексты записей прежние.

## 7. Бот (`src/bot.js`) и cron

- Обработчик, который нашёл событие, дальше работает с `c.ctx.in(ev.company_id)`.
- Нажатие кнопки открывает контекст одним пакетом (`openContext`) вместо `getUser`.
- `req:…`, `sup:take|a:…`, ответ админа в обращение: сначала общий признак («Только для администратора.» /
  «Отвечать на обращения могут владелец и администраторы.»), затем права в компании события — тот же отказ.
- Меню и тексты — прежние.
