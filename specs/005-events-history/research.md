# Research: эвенты и кольцевая жеребьёвка

## 1. «Кольцевая» = без взаимных пар

- **Decision**: при `ring = 1` запрещены циклы длины 2. Сначала ищется единый круг (как раньше), иначе — случайное
  распределение без взаимных пар (до 60 попыток), иначе — понятный отказ. При `ring = 0` — случайное распределение без
  предпочтения круга (взаимные пары возможны).
- **Rationale**: определение пользователя — «если А дарит Б, Б не дарит А»; единый круг удовлетворяет ему и остаётся
  предпочтительным. Для n = 2 кольцевая невозможна.
- **Замены**: удаление «S→X→W ⇒ S→W» запрещено, если W→S; обмен подопечными проверяет обе новые связки.

## 2. Модель данных

- **Decision**: `events` + `members(event_id, user_id, wishlist, …)`; `event_id` в `exclusions`, `pairs`, `messages`.
  Таблица `history` упразднена: пары прошлых эвентов и так хранятся.
- **Rationale**: эвенты живут вечно как история; параллельные эвенты изолированы ключом.
- **Alternatives considered**: отдельная БД на эвент — сложно и против лимитов бесплатного тарифа.

## 3. Права

- **Decision**: роли общие для бота (002). Админ видит и ведёт все эвенты. Участие = строка в `members`.
- **Rationale**: «админ и владелец могут видеть всю историю, даже если не участвуют».

## 4. Завершение и окно переписки

- **Decision**: `status = 'finished'`, `finished_at`; писать в переписку можно, пока `now < finished_at + 7 суток`.
- **Rationale**: прямое требование; проверяется на сервере (`chat_write` в `event.get` — подсказка интерфейсу).

## 5. «Не повторять пары»

- **Decision**: брать пары того прошлого эвента, где больше всего пар среди текущих участников (при равенстве — последнего
  по созданию); правило мягкое.
- **Rationale**: эвенты идут параллельно для разных групп; «последний» эвент может оказаться рабочим на 2 человек,
  а семейный — годом раньше. Выбор по наибольшему пересечению берёт «свой» прошлый эвент.

## 6. Старые данные

- **Decision**: если в базе есть таблица `history` (признак схемы 001–004), старые таблицы удаляются и создаются новые;
  настройки бота (`bot_username`, `base_url`) сохраняются. Бот ещё не разворачивался — потерь нет.
