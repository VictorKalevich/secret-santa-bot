# Implementation Plan: Эвенты, история и кольцевая жеребьёвка

**Branch**: `005-events-history` | **Date**: 2026-11-12 | **Spec**: [spec.md](./spec.md)

## Summary

Схема данных становится многособытийной: таблица `events` (параметры, статус, приглашение, `ring`), таблица `members`
(участие и письмо), а `exclusions`, `pairs`, `messages` получают `event_id`. Пользователь (`users`) хранит только имя, роли
и настройки. Все игровые API-действия принимают `event`. Алгоритм жеребьёвки получает флаг `ring` (запрет взаимных пар,
в том числе при заменах). Завершение эвента делает письмо и «подарок готов» только для чтения, переписка пишется 7 суток.
Мини-приложение: главный экран со списком эвентов (мои / все для админа), создание эвента и раздел «Администраторы»;
экран эвента — прежние вкладки. Решения — [research.md](./research.md).

## Technical Context

**Language/Version**: JavaScript ES2022, Cloudflare Workers · **Dependencies**: без новых

**Storage**: D1, новая схема ([data-model.md](./data-model.md)); при обнаружении таблиц старой схемы (`history`) — пересоздание

**Testing**: юнит-тесты `ring`; e2e переписан под эвенты (параллельные эвенты, кольцевая, завершение и окно переписки,
история, права админа без участия, приглашение из прошлого, сброс/удаление/перенос); скриншоты списка эвентов

**Constraints**: ≤ 50 внешних запросов на вызов; cron обходит только идущие эвенты
