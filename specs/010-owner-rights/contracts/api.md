# Contract changes: 010 — права владельца

Базовый контракт — `specs/005-events-history/contracts/events.md` с изменениями 006–009. Ниже — только отличия 010.

## Страница настройки `/setup`

| Запрос | Ответ |
|---|---|
| `GET /setup` (с `?key=` или без) | `200`, форма ввода ключа; ключ из адреса не читается |
| `POST /setup`, `key` неверный | `403`, «Неверный ключ» + форма |
| `POST /setup`, `key` верный, ссылка владельца для этого секрета ещё не использована | `200`, настройка бота (как раньше) + ссылка владельца |
| `POST /setup`, `key` верный, ссылка уже использована | `423`, «Страница заблокирована» + как разблокировать: `npx wrangler secret put ADMIN_SECRET`, затем открыть страницу снова; настройка не выполняется |

Заголовки всех ответов: `cache-control: no-store`, `referrer-policy: no-referrer`, `content-security-policy:
frame-ancestors 'none'`, `x-robots-tag: noindex`. В HTML — `<meta name="referrer" content="no-referrer">`.

## Бот

- `/start adm_<код>`:
  - первый переход для текущего секрета — как раньше (владелец + предупреждение прежнему владельцу);
  - повторный (кем угодно) — владелец не меняется, ответ: «Ссылка владельца уже использована. Чтобы получить новую —
    смени ADMIN_SECRET и снова открой страницу настройки.»
- `/start inv_<код>` и ввод имени после него: при `rejoin = 0` и отметке «удалён» — «Организатор удалил тебя из эвента
  «…» — вернуться по ссылке нельзя. Если это ошибка — напиши ему.»; участие и заявка не создаются, админам ничего.
- Кнопка `req:<id>:a` при закрытой регистрации — всплывающий ответ «Регистрация в эвент «…» закрыта — открой её, чтобы
  принять заявку.»; заявка остаётся ожидающей.

## API мини-приложения

### Изменённые

| Действие | Изменение |
|---|---|
| `admin.transfer` | только владелец; админу `403` «Переносить участие на новый аккаунт может только владелец бота.» Переносит отметки «удалён». |
| `admin.exclusion.add/del` | владельцу разрешено и после жеребьёвки (админу — как в 009) |
| `admin.family.save/delete` | владельцу разрешено при идущей жеребьёвке (админу — как в 009) |
| `admin.insert` | владелец может вписать себя (админу — как в 009) |
| `admin.remove` | дополнительно пишет отметку «удалён организатором» |
| `admin.request.decide` | `approve: true` при закрытой регистрации → `400` «Регистрация в эвент «…» закрыта — открой её, чтобы принять заявку.» |
| `admin.event.invite_from` | при закрытой регистрации → `400` «Регистрация закрыта — открой её, чтобы приглашать.»; при `rejoin = 0` отмеченные «удалён» пропускаются |
| `admin.draw` | при смене семей во время расчёта → `400` «Участники, исключения или семьи изменились во время жеребьёвки — попробуй ещё раз.» |
| `admin.event.delete` | второй одновременный запрос → `400` «Эвент уже удалён.» (без рассылки и журнала) |
| `admin.game` | новое поле `rejoin` (bool) |
| `admin.state` | `settings.rejoin` (bool); `removed: [{ id, name, removed_at }]` |
| `event.get` | `event.rejoin` (bool) — в `publicEvent` |
| `admin.events.create` с `from` | копирует `rejoin` образца |

### Новые

| Действие | Кто | Тело | Ответ |
|---|---|---|---|
| `admin.removed.allow` | админ, владелец | `{ event, id }` | `{}`; снимает отметку, журнал `member.allow`; нет отметки → `400` «Этого человека нет среди удалённых.» |
| `admin.vault.person` | только владелец (`403` «Служебный просмотр доступен только владельцу бота.») | `{ event, id }` | `{ person: { id, name }, in_draw, ward: { id, name } \| null, santa: { id, name } \| null, wishlist, wishlist_updated_at, delivery?, chat_with_santa: [msg], chat_with_ward: [msg] }`, `msg = { from: 'santa' \| 'ward', text, created_at }`; журнал `vault.person` |
| `admin.vault.pairs` | только владелец | `{ event }` | `{ pairs: [{ santa: { id, name }, ward: { id, name } }] }` (по имени Санты); журнал `vault.pairs` |

`admin.vault.*` разрешены и в завершённых эвентах; не меняют `seen_text`, `read_at`, `notified_at`, `gift_*`.
Человек не участник эвента → `400` «Участник не найден». До жеребьёвки: `ward`/`santa` = `null`, `pairs: []`.

### Инварианты

- Ни один ответ, кроме `ward.get` Санте и `admin.vault.*` владельцу, не содержит пар (FR-1014).
- Владелец получает не-`403` на каждое `admin.*` (FR-1007, автотест).
