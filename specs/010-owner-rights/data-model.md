## removed_members (новая)

| Поле | Тип | Смысл |
|---|---|---|
| `event_id` | INTEGER NOT NULL | эвент |
| `user_id` | INTEGER NOT NULL | удалённый человек |
| `removed_by` | INTEGER NOT NULL DEFAULT 0 | кто удалил (для журнала/отладки) |
| `removed_at` | INTEGER NOT NULL | когда |

Ключ: `PRIMARY KEY (event_id, user_id)`.

**Жизненный цикл**:
- создаётся/обновляется: `admin.remove` (в том же batch, по условию версии пар);
- удаляется: вступление этого человека в эвент (ссылка, имя, заявка, «Я участвую»), `admin.removed.allow`, полный сброс
  эвента, удаление эвента;
- переносится: `admin.transfer` (на новый аккаунт; если у нового уже есть отметка в эвенте — остаётся одна).

**Правила**:
- при `events.rejoin = 0` человек с отметкой не вступает и не подаёт заявку по ссылке; приглашения из прошлого эвента ему
  не отправляются;
- при `rejoin = 1` отметка ни на что не влияет, но хранится (переключатель можно выключить позже).
