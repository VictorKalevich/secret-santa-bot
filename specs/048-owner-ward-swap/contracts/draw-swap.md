# Контракт: обмен подопечных (048)

Сводное описание API — `docs/api.md` (разделы `admin.draw.swap.check`, `admin.draw.swap`, код журнала `draw.swap`); здесь
— то же плюс сообщения, интерфейс и компонент дизайн-системы. **049** (`specs/049-swap-unopened-mark/contracts/swap-marks.md`):
сообщения — только Сантам, открывшим прежнего подопечного; метка «не открыл подопечного» в шторке; новые тексты окна и плашки.

## API

Оба действия: **Кто** владелец (`role: OWNER`; админу — 403 «Менять подопечных после жеребьёвки может только владелец
бота.», участнику — 403 «Только для администратора.»). **Событие** да. **В завершённом** нет — 400 «Событие завершено —
менять его уже нельзя (доступны просмотр, раскрытие и удаление).»

Общие отказы обработчика (в этом порядке):

1. 400 «Жеребьёвка ещё не проведена.» (`NO_DRAW`)
2. 400 «Тайна уже раскрыта — менять подопечных нельзя.»
3. 400 «Выбери двух разных участников.» — `a`, `b` не числа, равны или нет одного из них
4. 400 «Участник не в жеребьёвке.» — у `a` или `b` нет подопечного

### `admin.draw.swap.check`

- **Запрос**: `event`, `a`, `b` — id двух участников жеребьёвки (порядок не важен).
- **Ответ**: `possible` — `false`, если кто-то дарил бы сам себе; `rules` — `[{ rule, text }]`: при `possible: false` —
  одна строка `self`, иначе нарушенные правила в порядке `exclusion`, `family`, `ring`, `fixed`, `history` (пусто —
  нарушений нет); `version` — версия пар (строка), её передать в `admin.draw.swap`.
- **Журнал**: нет. **Сообщения**: нет. Ни пар, ни имён в ответе.

| `rule` | `text` |
|---|---|
| `self` | «Один из двоих дарит другому: после обмена кто-то дарил бы сам себе.» |
| `exclusion` | «Исключения: кто-то из двоих будет дарить тому, кому по исключениям дарить не должен.» |
| `family` | «Семьи: кто-то из двоих будет дарить члену своей семьи.» |
| `ring` | «Кольцевая жеребьёвка: появится взаимная пара — двое будут дарить друг другу.» |
| `fixed` | «Закреплённые пары: обмен разорвёт пару, которую ты закрепил.» |
| `history` | «Прошлые пары: кто-то из двоих будет дарить тому же, кому дарил в прошлом событии.» |

Правила (только две новые связки `a → w(b)`, `b → w(a)`): `self` — `w(a) = b` или `w(b) = a`; `exclusion` — связка есть в
исключениях события; `family` — при «учитывать семьи», связка внутри семьи; `ring` — при кольцевой, `w(w(b)) = a` или
`w(w(a)) = b`; `fixed` — закреплённая пара с обеими сторонами в жеребьёвке действовала до обмена и не действует после;
`history` — при «не повторять пары», связка есть среди пар прошлого события (то же правило выбора события, что у
жеребьёвки).

### `admin.draw.swap`

- **Запрос**: `event`, `a`, `b`, `version` — из `admin.draw.swap.check`; `agree` — массив кодов правил, на нарушение
  которых владелец согласен (без нарушений — можно не передавать).
- **Ответ**: пустой.
- **Отказы** (после общих): 400 «Пары уже изменились — открой обмен заново.» — `version` не равна текущей; 400 «Этих двоих
  поменять нельзя — выбери другую пару.» — `self`; 400 «Правила жеребьёвки для этого обмена изменились — проверь ещё
  раз.» — нарушено правило не из `agree`; проигравшему одновременное изменение — 400 «Тайна уже раскрыта — менять
  подопечных нельзя.», если тайну раскрыли, иначе `PAIRS_RACE` «Пары изменились одновременно с этим действием — попробуй
  ещё раз.» (в том числе при одновременном завершении события).
- **Данные**: пары `a → w(a)` и `b → w(b)` удаляются вместе с перепиской этих пар; создаются `a → w(b)` и `b → w(a)` с
  отметками по умолчанию (не открыл, подарок не готов, не отправлен, без маски, не получен). Остальные пары, письма,
  адреса, черновики — без изменений. Версия пар меняется.
- **Журнал**: `draw.swap` — «пар изменено: 2».
- **Сообщения** (со звуком; 049 — только тем из `a` и `b`, у кого прежняя пара открыта, `seen_text IS NOT NULL` в момент
  записи): «🔄 Владелец изменил жеребьёвку события «<название>»: у тебя теперь <b>новый
  подопечный</b>. Прежняя пара больше не действует, переписка в ней удалена. Загляни во вкладку «Подопечный».» с кнопкой
  «🎁 Посмотреть». Подопечным и организаторам — нет.
- **Одно действие — один результат**: захват — оператор версии пар (`pairsVersion`) с условием `revealed = 0 AND status =
  'active'` и снимком правил (`snapshotGuard`); удаление, вставки, сообщения и журнал — при своём захвате.

## Интерфейс

- Секция «Управление жеребьёвкой» (`adminSwap(p)`, `05-admin`): владельцу, `s.draw_done && !s.revealed && !done`, перед
  «Служебным просмотром». Подсказка «Только для владельца бота: поменять подопечных у двух участников. Кто кому дарит, не
  видно и здесь.» и кнопка «🔀 Открыть управление жеребьёвкой» (`secondary`, `block`).
- Шторка «🔀 Управление жеребьёвкой» (`openSwapSheet(p)`, `06-vault-audit`):
  - если владелец в жеребьёвке — `ds-notice ds-notice--error`: «Ты участник этого события. Если выберешь себя,
    предупреждение о правилах или отказ могут подсказать, кто твой Санта.»;
  - подсказка «Выбери двух участников — они обменяются подопечными. Кто кому дарит, здесь не видно.»;
  - список участников с подопечным (`in_draw`) по алфавиту: `label.ds-list-item.ds-check` с флажком, имя, у себя —
    «(ты)», под именем — метка «👀 не открыл подопечного» при `ward_seen === false` (049); при двух отметках остальные
    флажки недоступны;
  - кнопка «🔀 Поменять подопечных» (недоступна, пока не отмечены двое), место результата под ней;
  - нажатие: `admin.draw.swap.check` → `possible: false` — плашка «Этих двоих поменять нельзя — выбери другую пару.» +
    «Подробнее»; нарушений нет — `confirmBox` «Поменять подопечных у «А» и «Б»? Тем, кто уже открыл подопечного, бот
    напишет, что он сменился. Отметки подарка, маски и переписка этих двух пар начнутся заново.» (049) → `admin.draw.swap`; нарушения есть — плашка
    «⚠️ Обмен нарушает один из принципов жеребьёвки.» («…несколько принципов…» при двух и больше), «Подробнее» со списком
    текстов, строка «Если поменять, тем, кто уже открыл подопечного, бот напишет, что он сменился. Отметки подарка,
    маски и переписка этих двух пар начнутся заново.» (049), галочка «Согласен — всё равно поменять», кнопка «🔀 Поменять подопечных» (`danger`,
    доступна с галочкой) → `admin.draw.swap` с `agree` — кодами правил;
  - смена отметок очищает место результата;
  - успех — toast «🔀 Подопечные поменялись», отметки сняты, место результата пусто, панель — тихая перестройка.
- Журнал (`AUDIT_LABELS`): `'draw.swap': '🔀 Подопечные поменялись'`.

## Компонент дизайн-системы `ds-details`

`<details class="ds-details"><summary class="ds-details__summary">Подробнее</summary> … </details>` — свёрнутый блок с
подробностями внутри плашки или карточки: заголовок цветом родителя, полужирный, значок «▸» поворачивается при раскрытии,
системный маркер скрыт, строка не ниже `--ds-size-control-sm`, содержимое — с отступом `--ds-space-1-5` сверху.
