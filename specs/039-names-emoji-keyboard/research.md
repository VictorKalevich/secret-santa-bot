# Research: 039 — значок после имени, обращения, главный экран, клавиатура

## R1. Где ставить значок относительно имени

- **Decision**: одна функция `withEmoji(name, emoji)` → `name + ' ' + emoji` (без значка — `name`); `emojiName(u, name =
  u.name)` вызывает её. Все места 038 (`personTitle`, «Профиль», «Администраторы», «Организаторы», имя подопечного)
  уже идут через `emojiName` — порядок меняется в одном месте.
- **Rationale**: одно правило — один тест; вызывающие не знают о порядке.
- **Alternatives**: отдавать с сервера готовую строку «Аня 🦊» — нет: бот и журнал пишут те же имена без значков, а
  сервер стал бы знать о виде строк приложения.

## R2. Значки в обращениях: форма ответа

- **Decision**: рядом с каждым именем — поле значка: у обращения `emoji` (автор), `assignee_emoji`, `closed_by_emoji`;
  у сообщения `author_emoji`; в счётчиках `event.get` — `support.assignee_emoji`. Пусто — `''`. Списки «кому передать»
  (`admins`) — без значка (решение владельца: выпадающие списки без значков).
- **Rationale**: имена остаются строками — прежние поля и проверки (`api-doc`, эталон отказов) не ломаются; значки берутся
  из тех же `users` контекста (запросов не больше); счётчики — второй скалярный подзапрос в том же операторе.
- **Alternatives**: объекты `{ name, emoji }` вместо строк — меняет форму полей, которые читают приложение и тесты, без
  пользы.

## R3. Обновление главного экрана после смены имени или значка

- **Decision**: `renderHome` собирает «Профиль» и разделы с именами; после сохранения имени или значка — обновить
  «Профиль» и приветствие из `state.me` и перечитать «Администраторы» и «Семьи» (`load` каждого раздела: содержимое
  заменяется, когда пришёл ответ, — без загрузчика, высота прежняя, прокрутка не прыгает). Только если человек ещё на том
  же главном экране (`state.nav` не изменился).
- **Rationale**: данные разделов — с сервера (имена всех людей, роли, семьи); перечитать — проще и вернее, чем латать
  копии; два чтения только у организатора и только после действия.
- **Alternatives**: перерисовать весь главный экран (`render`) — загрузчики в разделах и прокрутка вверх; латать
  строки «меня» в DOM — дублирует правила раздела.

## R4. Тап мимо поля прячет клавиатуру

- **Decision**: в ядре (`02-core`) — обработчики `pointerdown`/`pointerup`/`pointercancel` на документе (фаза захвата):
  тап — основной указатель, `pointerup` того же указателя, сдвиг ≤ 10 px, без `pointercancel` (прокрутка на iOS его
  присылает). На тап по элементу вне `input, textarea, select, button, a, label, [role="button"], [contenteditable]`,
  если фокус в `input`/`textarea`, — `blur()`.
- **Rationale**: WebKit (iOS) снимает фокус только переходом в другое поле; клик по пустому месту не всегда доходит до
  документа на iOS, события указателя — доходят. Кнопки и ссылки исключены: спрятанная клавиатура меняет высоту окна, и
  нажатие попало бы не туда; поле, список, флажок управляют фокусом сами. Desktop/Chrome снимают фокус сами при нажатии —
  обработчик там ничего не меняет.
- **Alternatives**: `click` на документе — на iOS не приходит с «некликабельных» элементов; `touchstart` — срабатывал бы
  и на начале прокрутки; `Telegram.WebApp.hideKeyboard()` — только в новых клиентах, `blur` работает везде.
- **Проверка**: в Chrome — синтетические события указателя (сами они фокус не снимают, значит снимает только
  обработчик): тап по заголовку — фокус снят; сдвиг 30 px, `pointercancel`, тап по кнопке — фокус остаётся; на iPhone —
  по `quickstart.md`.
