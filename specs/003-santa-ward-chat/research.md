# Research: переписка и лимит

## 1. Лимит текста

- **Decision**: 4000 символов для письма и сообщения; длина — `String.length` (UTF-16 code units).
- **Rationale**: лимит текста сообщения Telegram Bot API — 4096 символов после разбора разметки; Telegram считает длину
  в UTF-16, как JavaScript. 96 символов — запас под заголовок уведомления («💬 Твой Тайный Санта пишет:»). Экранирование
  HTML (`&lt;` и т.п.) на длину не влияет: Telegram считает текст после разбора.
- **Alternatives considered**: 4096 ровно — уведомление с заголовком могло бы не поместиться; лимит в словах — не связан
  с лимитом Telegram (1000 слов ≈ 6–7 тыс. символов).

## 2. Где хранится переписка

- **Decision**: таблица `messages(santa, ward, sender, text, created_at, read_at)`; переписка определяется парой.
- **Rationale**: новая пара автоматически получает новую пустую переписку; удалить историю пары — один запрос.
- **Alternatives considered**: пересылка только через Telegram (как в 001) — нет общей истории в приложении.

## 3. Доставка новых сообщений в открытую переписку

- **Decision**: опрос `chat.get {after: lastId}` каждые 6 с, только пока экран переписки открыт.
- **Rationale**: без WebSocket/Durable Objects (платно/сложно); 10 человек × 1 открытая переписка × 10 запросов/мин —
  ничтожно против 100 000 запросов/сутки.

## 4. Уведомление

- **Decision**: сообщение бота с текстом + кнопки `↩️ Ответить` (callback → ввод в чате) и `💬 Вся переписка`
  (web_app `/app?chat=santa|ward`, мини-приложение сразу открывает переписку).
- **Rationale**: привычно как мессенджер; ответить можно, не открывая приложение. Имена бот не добавляет (принцип I).

## 5. Прочтение

- **Decision**: `read_at` у сообщений от собеседника ставится при `chat.get`; `me` возвращает `unread.from_santa`,
  `unread.from_ward`. Ответ через бота тоже помечает прочитанными сообщения собеседника (человек их видел в Telegram).
