# Data Model: Жеребьёвка быстрее при том же результате

Хранимых данных фича не добавляет и не меняет: схема D1 (версия 11), миграции и таблицы — прежние. Ниже —
структуры в памяти, на которые опираются требования.

## Матрица допустимости

- `adj` — `Uint8Array` длиной `n²`, `n` — число людей в жеребьёвке; `adj[i * n + j] = 1`, если `ids[i]` может дарить
  `ids[j]`, иначе `0`.
- Строится в `findAssignment` один раз на попытку поиска (каждая попытка `planDraw` — свои правила, та же `ids`).
- Инвариант (FR-1704): для любого `ids` с различными id и любых правил `pairRules(bans, fixed)`
  `adj[i * n + j] === (ids[i] !== ids[j] && rule(ids[i], ids[j]) ? 1 : 0)` — независимо от того, построена матрица
  через `fillMatrix` или перебором.
- Диагональ — всегда `0`.

## Правило «кто кому может дарить» (`pairRules`, 014)

- Вход: `bans` — `{ giver, receiver }[]` (исключения события, семьи, прошлые пары); `fixed` — `{ giver, receiver }[]`
  (закреплённые пары владельца). Любой из них может называть людей не из списка жеребьёвки.
- Внутри: `banned: Map<giver, Set<receiver>>`, `wardOf: Map<giver, receiver>`, `santaOf: Map<receiver, giver>`.
- Порядок проверки `rule(a, b)`:
  1. `a` — закреплённый Санта → `b` его закреплённый подопечный;
  2. `b` — закреплённый подопечный (его Санта — не `a`) → нельзя;
  3. иначе → нет запрета `a → b`.
- С 017 у функции есть свойство `fillMatrix(ids, adj)` — та же матрица без вызовов `rule` (`contracts/draw-rules.md`).
