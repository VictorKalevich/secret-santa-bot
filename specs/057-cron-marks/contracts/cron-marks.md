# Контракт 057: отметки минутной проверки

Кому: тому, кто меняет `src/cron.js`, запись письма и адреса, параметры события, жеребьёвку или сброс. Модель —
`../data-model.md`, решения — `../research.md`.

## Отметка правки `members.notify_at`

1. Время письма или адреса (`wishlist_updated_at`, `delivery_updated_at`) меняют только `saveWishlist`, `writeLetterDraft`
   (публикация), `saveDelivery` — и каждая из них в том же `UPDATE` ставит отметку выражением `NOTIFY_MARK`
   (`src/participant.js`: время правки, если у участника есть Санта, иначе прежнее значение). Новое место, которое меняет
   эти времена, обязано ставить отметку так же (тест `cron-marks` перебирает литералы `src/*.js`: каждый, где есть
   `wishlist_updated_at = ?` или `delivery_updated_at = ?`, содержит `${NOTIFY_MARK}`). Публикация неизменённого
   черновика времени не меняет и отметки не ставит: она только снимает черновик.
2. Минутная проверка читает только отметки старше `NOTIFY_DELAY_MINUTES` — запрос начинается с `members` по индексу
   `members_notify` (тест `cron-reads` — план запроса). Решение «уведомлять» — прежнее: событие `active`, пара есть, `upd >
   notified_at`.
3. Отметка снимается только условно: `UPDATE members SET notify_at = 0 WHERE event_id = ? AND user_id = ? AND notify_at =
   <прочитанное>` — в одном пакете с `UPDATE pairs SET notified_at` и сообщением.
4. Сброс обнуляет, слияние ставит, перенос переносит — через `REGISTRY.members.notify`, своих `UPDATE … notify_at` в
   построителях нет.

## Отметка дня `events.checked_on`

1. Ежедневный шаг читает события `status = 'active' AND checked_on < <сегодня>` (индекс `events_unchecked`).
2. Ставится вместе с `last_daily` в тех же записях: тихие события и события со снятой отметкой «проверено» (один `UPDATE`
   на ≤ 90 событий), снятие отметки 056, пакет напоминания, захват `warnStale`. Не ставится, пока событию нужно автодействие.
3. Снимается (`''`): `saveEventSettings` (любое сохранение), захват `runDraw`, полный сброс (`EVENT_STATE_RESET`). Новое
   действие, которое меняет вход `dueAutoAction` так, что автодействие может наступить в тот же день, обязано снимать
   отметку (перечень входов — `research.md` R7; тест `cron-marks` — «от противного» на каждый вход).
4. `last_daily` при снятии `checked_on` не трогается — напоминание не повторяется.

## Число запросов и чтения

- Обычная минута (нет отметок старше задержки, все события проверены) — 3 запроса к базе (уведомления, ежедневный шаг,
  очередь; тест `queries`, `cron-reads`), ни одной прочитанной строки событий, пар, участников и людей.
- Полный просмотр в операторах cron — только `settings` и `outbox` (тест `cron-reads`); частичные индексы — только
  поиском по диапазону.

## Миграция и сверка

- `0020_cron_marks.sql`: `ALTER TABLE` ×2, `CREATE INDEX IF NOT EXISTS` ×2, отметки ждущих правок (`UPDATE members … WHERE
  EXISTS (пара идущего события с upd > notified_at)`), версия схемы 20.
- `tools/notify-reconcile.sql` — тот же `UPDATE` побайтно (тест `migrations`), без версии схемы; повтор ничего не меняет.
