# Research: значок у имени и открытка для письма (038)

## R1. Где хранить

- **Decision**: значок — `users.emoji` (один на человека, как имя); открытка — `members.card` (у письма в событии).
  Миграция `0010_looks.sql`, версия схемы 13 (`REQUIRED_SCHEMA`).
- **Rationale**: письмо своё в каждом событии — и открытка своя; значок — «я», общий для всех событий.
- **Alternatives considered**: открытка у человека (одна на все письма) — смена в одном событии неожиданно меняла бы
  письмо в другом.

## R2. Набор — один список на сервере

- **Decision**: `src/looks.js` (без импортов): `EMOJIS` — 40 эмодзи (новогодние, звери, прочее), `POSTCARDS` — 15
  `{ id, title }`; `validEmoji`, `validCard` (пустая строка — «без»). Приложение получает набор в ответе `me`
  (`looks: { emojis, postcards }`), своих копий не держит. Узор, «бумага», цвет текста и наклейка открытки — в
  дизайн-системе (класс `ds-postcard--<id>`); тест сверяет набор с классами, токенами и витриной в обе стороны.
- **Rationale**: проверка на сервере против того же списка, что видит человек; новая открытка — строка набора + тема в
  дизайн-системе (тест не даст забыть одно из двух).

## R3. Тайна

- **Decision**: значок отдаётся там, где отдаётся имя человека в списках: `roster` (`people`, `organizers`),
  `admin.state` (`users`, `requests`, `removed`), `admin.users`, `ward.get` (`ward.emoji` — Санте о подопечном). Не
  отдаётся: `chat.get`, сообщения бота, журнал, `event.get.member`. В приложении у Санты значок подопечного — внутри
  скрытого имени (`ds-ward-card__name--hidden`), открывается вместе с ним.
- **Rationale**: значок не связан с парой; опасно лишь показать значок Санты подопечному рядом с перепиской — в
  переписке значков нет ни с одной стороны. Скрытое имя на «Подопечный» защищает от взгляда через плечо — значок не
  должен его выдавать.
- **Открытка**: видна тем, кто видит письмо (сам участник, его Санта, организатор при открытии письма с записью в
  журнал). Служебный просмотр и уведомления бота — без открытки (прежние тексты).

## R4. Открытка — часть письма в REGISTRY

- **Decision**: `REGISTRY.members.personal` — группы полей `[значение, время, ...спутники]`: `['wishlist',
  'wishlist_updated_at', 'card']`, `['delivery', 'delivery_updated_at']`. Сброс у оставшегося владельца: значение и
  спутники — `''`, время — 0; перенос (слияние участий): вся группа берётся у нового аккаунта, если его письмо не пустое,
  иначе у старого. `eventDataDeleteStmts`, `mergeMembership`, `personTransferStmts` — по группам.
- **Rationale**: открытка без письма бессмысленна; одно правило слияния — открытка не «разъезжается» с письмом.

## R5. Смена открытки — не изменение письма

- **Decision**: `card.set` — один `UPDATE members SET card` без `wishlist_updated_at`; уведомлений и журнала нет. Тот же
  отказ в завершённом событии, что у `wishlist.save` (`LETTER_CLOSED`). `emoji.set` — `UPDATE users SET emoji`, без
  журнала (как оформление; имя — с журналом, его видят в списках как опознавательное).
- **Rationale**: уведомление «подопечный изменил письмо» о смене фона — шум; время изменения письма — про текст.

## R6. Как рисуется открытка

- **Decision**: `ds-postcard` — рамка с узором (`--ds-postcard-frame`: только градиенты CSS — точки, ёлочки через
  `conic-gradient`, полосы, клетка), внутри `ds-postcard__paper` — «бумага» (`--ds-postcard-paper`) с текстом
  (`--ds-postcard-ink`), в правом верхнем углу — наклейка-эмодзи (`--ds-postcard-mark`, `::after`, наклон). Цвета
  открытки фиксированы (как у праздничного градиента): одинаковы в светлой и тёмной теме Telegram; контраст чернил и
  бумаги ≥ 4.5 : 1 проверяет тест (по `tokens.css`). Редактор письма — прозрачное поле на бумаге (`.ds-postcard__paper
  .ds-input`). Мини-вид (`ds-postcard--mini`) — плитка выбора с названием.
- **Rationale**: без картинок — нет новых адресов в политике страницы и проверки на iPhone ради них; градиенты
  масштабируются и весят ничего.
- **Alternatives considered**: SVG-узоры `data:` — запрещены политикой `img-src` (по умолчанию `'self'`); картинки с
  сервера — лишние запросы и правка CSP.

## R7. Эталон отказов

- **Decision**: `NEW_ACTIONS_038 = ['emoji.set', 'card.set']` — отдельный проход после прохода 035 (ключи «038
  <ситуация> <действие>» и «038 extra …»: значок не из набора, открытка не из набора, открытка в завершённом). Прежние
  ключи эталона — побайтно те же; новые дописаны в `tests/fixtures/api-refusals.json`.
