# 052. Исследование и решения

Решения владельца собраны в чате 2026-11-24 (итог — в «Запросе» `spec.md`). Ниже — как они ложатся на код 050/051 и
что выбрано там, где владелец сказал «если я не так понял — сделай как понял ты».

## R1. Признак открытости — настройка окружения

**Решение.** Переменная `OPEN_BOT = "1"` в `[env.second.vars]` `wrangler.toml`; у первого бота её нет. Проверка —
одна функция `openBot(env)` в `src/companies.js` (`env.OPEN_BOT === '1'`). В тестах — `startWorld({ open: true })`
(быстрые) и `startWorld({ vars: { OPEN_BOT: '1' } })` (Chrome, `wrangler dev --var`).

**Почему.** Владелец сказал «первый закрытый, второй открытый» — это свойство бота, а не настройка, которую меняют с
телефона. Без переменной поведение прежнее, поэтому первый бот после выката не меняется.

**Отвергнуто.** Строка в `settings` с переключателем у владельца бота — можно случайно открыть семейный бот; отдельная
сборка кода — два кода вместо одного.

## R2. Создание компании человеком — отдельное действие `company.create`

**Решение.** Новое действие `company.create { name }`, роль `USER`. Обработчик: владелец бота → прежний `createCompany`
(компанию ведёт он, название личное); иначе в закрытом боте — отказ `Только для владельца бота.` (403, тот же текст, что
у `bot.*`); в открытом — `createOwnCompany`: компания с назначенным владельцем-создателем и общим названием.

**Почему.** Роль `BOT` проверяет конвейер до обработчика (`api.js`) — `bot.company.create` нельзя открыть людям, не
сломав смысл роли и эталон отказов 051. Отдельное действие держит `bot.*` прежними.

## R3. Лимит «не больше двух» в одном пакете

**Решение.** Пакет `atomic` с условием «за минуту не было такой же записи журнала бота от него» (как у 051,
`RECENT_CREATE`):

1. `INSERT INTO companies (name, owner_id, shared, created_by, created_at) SELECT … WHERE <условие> AND (SELECT COUNT(*)
   FROM companies WHERE owner_id = ?) < 2` — счёт проверяет только сама вставка;
2. дальше — подпакет `and('EXISTS (компания с created_by = я, created_at = now, name = название, owner_id = я)')`:
   строка человека компании (`is_admin = 1` — инвариант I3), общий признак `adminFlagStmt`, запись журнала бота —
   захват (последней).

Исход: захват прошёл — компания создана; нет — отказ по свежему состоянию: «владеет двумя» → текст лимита, иначе «только
что создана» (повтор).

**Почему счёт не в общем условии.** Вставка сама увеличивает счёт: у владельца одной компании следующие операторы того
же пакета увидели бы «уже две» и не записали бы строку человека. Поэтому лимит — условие только вставки, а остальное
опирается на «эта вставка состоялась».

**Одновременные вызовы** (D1 выполняет пакеты по одному):
- то же название, та же миллисекунда — второй пакет: вставку и зависимые операторы отсекает журнал первого (`RECENT_CREATE`);
- разные названия при одной компании во владении — второй пакет: счёт уже 2, вставки нет, зависимые не находят «свою»
  компанию (у неё другое название) — ничего не записано, отказ «лимит»;
- разные названия без компаний — обе проходят (лимит 2), как и должно.

## R4. Общее название — колонка `companies.shared`

**Решение.** Миграция `0016_open_bot.sql`: `ALTER TABLE companies ADD COLUMN shared INTEGER NOT NULL DEFAULT 0`, схема
18. `shared = 1` ставит только `createOwnCompany`. Название по-прежнему одно — `companies.name`.

**Почему не без миграции.** «Название видно людям, если у компании есть назначенный владелец» раскрыло бы названия,
которые владелец бота дал компаниям 051 и отдал по ссылке (по 051 их видит только он). Нужен свой признак.

**Почему одно поле.** Владелец бота видит то же название, что люди компании, — меньше путаницы; оба могут его менять
(FR-5241).

**Миграция ↔ выкат.** Прежний код колонку не читает — порядок «миграция, потом код» и откат кода безопасны.

## R5. Какое название видит человек

**Решение** (`visibleCompanies`):

| Кто | Название | `named` (поле «своё» в шторке заполнено) |
|---|---|---|
| владелец бота | `companies.name` | да |
| остальные | своё название, иначе общее (`shared`), иначе «Компания N» | только если есть своё |

Владелец компании с общим названием (и владелец бота) меняет общее название тем же `company.label.set`: для него это
«Название компании» (1–40, не пусто), и его своё название в том же пакете стирается — иначе он не увидел бы того, что
сам задал. Люди компании меняют только своё.

## R6. Удаление владельцем компании — `company.delete`

**Решение.** Действие `company.delete { company, confirm }`, роль `USER`, слово `УДАЛИТЬ`. Владелец бота — прежнее
удаление; в открытом боте — назначенный владелец этой компании; иначе отказ: в закрытом боте «Удалить компанию может
только владелец бота.», в открытом — «Удалить компанию может только её владелец.». `deleteCompany` получает
«удаляет владелец компании»: в условии пакета ещё `owner_id = я`, тексты сообщений — «Владелец удалил компанию…».

## R7. Экраны приложения

Правило «список доступен» — `withList()` (`02-core`): компаний две и больше, или это владелец бота, или бот открытый.

| | Без компаний | Одна компания | Две и больше |
|---|---|---|---|
| Закрытый, человек | пустой главный экран (как в 051) | главный экран, без «‹» | «Компании» |
| Закрытый, владелец бота | «Компании» | главный экран **со «‹»** | «Компании» |
| Открытый, любой | «Компании» | главный экран **со «‹»** | «Компании» |

- Раздел «Компании» с главного экрана компании убран (`companiesTools` — только на экране «Компании»).
- В шапке экрана компании со «‹» — название компании (`companyTitle`).
- «Профиль» и «Уведомления» — на экране «Компании» и, как раньше, на главном экране при одной компании.
- После создания (и владельцем бота) — экран новой компании.
- «Создать компанию»: владельцу бота — как в 051; человеку открытого бота — своя кнопка; при двух своих — кнопка
  недоступна, под ней — текст лимита.
- ⚙️ у строки: владельцу бота — прежняя шторка «Компания»; владельцу компании в открытом боте — шторка только с
  удалением (`typedSheet`).

## R8. Бот

- Незнакомый человек в открытом боте (`/start` без ссылки или любое сообщение): запись без имени с ожиданием `name`,
  просьба имени с приветствием `🎄 Привет! Это бот для игры в Тайного Санту.` и кнопками 047 («Продолжить как …»).
  После имени — прежнее «Приятно познакомиться» и меню (там кнопка приложения).
- Меню открытого бота у человека без событий: «Сейчас ты не участвуешь ни в одном идущем событии. Создай свою компанию
  в приложении или попроси пригласительную ссылку на событие.» В закрытом боте — прежний текст.
- Закрытый бот — прежний `CLOSED_BOT`.

## R9. Поля ответа `me`

Только там, где они нужны, — у людей закрытого бота (кроме владельца бота) ответ побайтно прежний:

- `open: true` — открытый бот (и у незарегистрированного: `{ registered: false, open: true }` — другой текст «сначала
  регистрация»);
- `create` — владельцу бота `{ bot: true }`, человеку открытого бота `{ left: 0..2 }`;
- в строке компании: `shared: true` (общее название), `rename: true` (может менять общее название — владелец компании с
  общим названием), `deletable: true` (владелец компании в открытом боте).

Число запросов `me` прежнее: `shared` читается тем же запросом компаний, счёт своих компаний — из него же.

## R10. Конституция 3.1.0 (MINOR)

Принципы не снимаются и не переопределяются — у трёх правил появляется исключение «в открытом боте»:

- II: регистрация — по пригласительной ссылке; в открытом боте — и без неё.
- I: названия компаний личные, кроме общего названия компании, созданной человеком в открытом боте: его видят её люди и
  владелец бота.
- VII: в открытом боте компанию создаёт любой (не больше двух во владении), владелец компании удаляет свою пустую.

## R12. Выкат

Миграция `0016` — в обе базы до кода (второй бот, затем первый); затем выкат второго, проверка на iPhone (новичок без
ссылки, создание, лимит), выкат первого (у владельца бота — «‹»). Откат кода безопасен: прежний код колонку не читает;
созданные людьми компании остаются с владельцами, их люди видят «Компания N» (правила 051).
