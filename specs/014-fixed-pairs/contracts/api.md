# Contract: API закреплённых пар (014)

Все запросы — `POST /api/<action>` с подписью `initData`, как раньше (`specs/005-events-history/contracts/events.md`).

## `admin.state` (изменение)

Владельцу бота в ответе добавляется поле:

```json
{ "fixed": [{ "giver": 101, "receiver": 102 }] }
```

- Только пары, оба человека которых — участники события.
- **Админу (не владельцу) поля `fixed` нет вовсе.**

## `admin.fixed.add` (новое)

Тело: `{ "event": 7, "giver": 101, "receiver": 102, "mutual": false }` → `{ "ok": true }`.

| Условие | Ответ |
|---|---|
| не владелец | 403 «Закреплять пары может только владелец бота.» |
| событие завершено | 400 «Событие завершено — менять его уже нельзя (…)» (общее правило) |
| жеребьёвка проведена | 400 «После жеребьёвки закреплённые пары не меняются. Чтобы поменять их, отмени жеребьёвку.» |
| нет двух разных людей | 400 «Выбери двух разных людей» |
| кто-то не зарегистрированный участник события | 400 «Закрепить пару можно только между участниками события.» |
| кольцевая и `mutual` | 400 «При кольцевой жеребьёвке пару можно закрепить только в одну сторону.» |
| кольцевая и есть обратная пара | 400 «При кольцевой жеребьёвке пару можно закрепить только в одну сторону: «<receiver>» уже дарит «<giver>».» |
| у дарящего другой закреплённый подопечный | 400 «У «<имя>» уже есть закреплённый подопечный — сначала убери ту пару.» |
| у получающего другой закреплённый Санта | 400 «Санта для «<имя>» уже закреплён — сначала убери ту пару.» |
| та же пара уже есть | `{ "ok": true }`, без изменений |

`mutual: true` (только без кольцевой) закрепляет обе стороны; проверки — для обеих. Журнал: `fixed.add`, без подробностей.

## `admin.fixed.del` (новое)

Тело: `{ "event": 7, "giver": 101, "receiver": 102, "mutual": false }` → `{ "ok": true }`.
Права и «после жеребьёвки» — как у `admin.fixed.add`. `mutual: true` убирает обе стороны. Журнал: `fixed.del`.

## `admin.draw.check`, `admin.draw`, автожеребьёвка (изменение)

- Закреплённые пары участников соблюдаются; они важнее исключений, семей и истории.
- Новая причина невозможности (одна, без имён): «Мешают закреплённые пары: с ними распределить всех по правилам не
  получается. Владелец бота может убрать часть закреплённых пар.» — если без закреплённых пар распределение есть или
  при кольцевой есть взаимная закреплённая пара. Иначе — обычные причины, посчитанные без закреплённых пар.
- Если закреплённые пары изменились между расчётом и записью — прежняя ошибка «Участники, исключения или семьи
  изменились во время жеребьёвки — попробуй ещё раз.»

## `admin.remove`, `admin.insert` (изменение)

Замены после жеребьёвки не ломают закреплённые пары оставшихся; удаление человека удаляет его закреплённые пары.
Тексты отказов прежние.
