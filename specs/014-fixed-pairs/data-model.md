# Data Model: Закреплённые пары владельца (014)

## Таблица `fixed_pairs` (миграция `0007_fixed_pairs.sql`, схема 11)

| Поле | Тип | Смысл |
|---|---|---|
| `event_id` | INTEGER NOT NULL | событие |
| `giver` | INTEGER NOT NULL | кто дарит (Telegram ID) |
| `receiver` | INTEGER NOT NULL | кому дарит (Telegram ID) |

- `PRIMARY KEY (event_id, giver)` — у Санты не больше одного закреплённого подопечного.
- `UNIQUE INDEX fixed_pairs_receiver (event_id, receiver)` — у подопечного не больше одного закреплённого Санты.
- `giver != receiver` проверяет код.

## Правила

- Создаёт и удаляет строки только владелец бота, только пока `events.draw_done = 0` (условие на каждом операторе).
- При `events.ring = 1` новая строка, обратная существующей (взаимная пара), не создаётся.
- Взаимная пара (обе строки) показывается одной строкой списка и удаляется одним действием (`mutual`).

## Жизненный цикл строк

| Событие | Что происходит |
|---|---|
| Удаление участника (`removeMember`), «Я участвую» выкл. | строки с этим человеком удаляются |
| Перенос участия (`transferAccount`) | `giver`/`receiver` переходят на новый аккаунт; конфликтующие и `giver = receiver` — удаляются |
| Отмена жеребьёвки (обычная и принудительная) | без изменений |
| Полный сброс, удаление события | все строки события удаляются |
| Событие по образцу | не копируются |

С 018 удаление, сброс и перенос строятся из списка `REGISTRY` (`src/db.js`), правила те же.

## Снимок для записи жеребьёвки

`COUNT(*) : SUM(giver) : SUM(receiver) : SUM((giver % 1000003) * (receiver % 1000003))` по строкам события —
одинаково в JS (`checkDraw`) и SQL (условие захвата `runDraw`).
