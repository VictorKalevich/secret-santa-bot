# Research: 007-admin-tools

## R1. Журнал в той же транзакции

- **Decision**: `auditStmt(db, eventId, actorId, action, details)` возвращает подготовленный `INSERT`. Он добавляется
  в batch самого действия, поэтому запись появляется ровно тогда, когда действие выполнено (SC-705). Действия из одного
  `UPDATE` (регистрация, ссылка, кольцевая и т.п.) делаются через `db.batch([update, audit])`.
- Бот — `actor = 0`. Имена авторов подставляются при чтении: `LEFT JOIN users`; удалённый пользователь показывается как «кто-то».
- `details` — короткий текст, собранный на сервере: имена людей, название эвента, число. Не пишутся пары, тексты писем
  и тексты объявлений: объявление и так хранится отдельно.
- **Alternatives**: писать журнал после действия отдельным запросом. Отклонено: при сбое теряются записи и расходится
  счёт.

## R2. Автодействия в cron

- **Decision**:
  - Проход (`dailyReminders`, с `REMINDER_HOUR`) берёт все идущие эвенты: наступившее автодействие выполняется сразу
    (даже если напоминания по эвенту сегодня уже прошли — например, дату автожеребьёвки поставили днём), напоминания —
    по-прежнему раз в день (`last_daily`).
  - Чтобы уложиться в лимит запросов, автодействие (жеребьёвка, раскрытие или завершение) выполняется не больше чем
    для одного эвента за вызов. Остальные эвенты остаются с прежним `last_daily` до следующей минуты. Напоминания без
    автодействий обрабатываются как раньше.
  - Порядок: жеребьёвка (`draw_auto_date <= сегодня`, не проведена) → раскрытие (`reveal_auto`, проведена, не раскрыта,
    `event_date + 1 <= сегодня`) → завершение (`finish_auto`, `event_date + 3 <= сегодня`).
  - Неудачная автожеребьёвка: сообщение всем админам с причиной, `draw_auto_date = ''`, запись в журнал.
- **Rationale**: прежний час напоминаний понятен организатору и уже описан в README. Жеребьёвка — до 10 запросов,
  раскрытие — до 3, плюс отправка очереди.

## R3. Отмена жеребьёвки атомарно

- **Decision**:
  - Первый оператор batch: `UPDATE events SET draw_done=0, draw_at=0, draw_token='' WHERE id=? AND draw_token=?
    AND revealed=0 AND status='active' AND NOT EXISTS (pairs с seen_text IS NOT NULL) AND NOT EXISTS (messages эвента)`.
  - Удаление пар, уведомления и запись журнала выполняются только при `draw_token=''` для этого эвента.
  - Если первый оператор ничего не изменил, это отказ.
- **Rationale**: `ward.get` записывает `seen_text` при первом открытии. Если кто-то открыл подопечного между проверкой
  и batch, условие не выполнится, и пары останутся. Тот, кто уже видел подопечного, никогда не увидит другого.
- `admin.state` отдаёт `draw_cancelable`. Это общий факт «кто-то уже открыл», он не раскрывает пар.

## R4. Исключения образца

- **Decision**: при создании по образцу исключения копируются как есть. `admin.state` отдаёт только исключения, где оба
  человека — участники. `checkDraw` уже фильтрует по участникам. `admin.exclusion.add` по-прежнему требует участников
  (006): копирование — внутреннее действие, не API добавления.
- **Rationale**: супруги вступают по ссылке в разное время, и исключение должно заработать само.

## R5. «Подарок получен»

- **Decision**:
  - `pairs.gift_received` и `gift_received_at`.
  - `ward.received {event, received}` меняет пару, где `ward = я`.
  - Санта получает уведомление, только если отметка ставится впервые (`gift_received_at = 0` до запроса).
  - Снятие отметки не обнуляет `gift_received_at`, поэтому повторная отметка уведомления не шлёт.
- **Rationale**: защита от спама переключателем.

## R6. Объявления в «Инфо»

- **Decision**: `event.get` отдаёт `announcements` (до 20 последних) с именем автора. Админ без участия видит их тоже,
  так как `event.get` для админа уже разрешён. Текст выводится через `textContent` в `ds-card ds-letter`.
