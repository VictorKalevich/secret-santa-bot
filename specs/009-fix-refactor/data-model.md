# Data Model: 009 — без изменения схемы

Схема остаётся 8 (`migrations/0001…0004`), новых таблиц и полей нет. Меняется только смысл и формат значений в
существующих полях.

## users.pending (режим ввода в чате бота)

| Значение | Когда | Изменение в 009 |
|---|---|---|
| `''` | обычный режим | — |
| `name` | владелец по ссылке /setup вводит имя | — |
| `name:<eid>:<invite_code>` | регистрация по приглашению эвента | + код приглашения (было `name:<eid>`); старый формат читается как «без кода» и проверяется только по членству |
| `msg_ward:<eid>:<ward_id>:<ms>` | ответ подопечному после «↩️ Ответить» | + собеседник и момент нажатия (было `msg_ward:<eid>`) |
| `msg_santa:<eid>:<santa_id>:<ms>` | ответ Санте | то же; id Санты хранится только на сервере и никуда не отдаётся |

Правила: любая команда сбрасывает `msg_*`; режим `msg_*` действует 60 минут; при отказе нажатия «Ответить» — сброс.
Значения старого формата `msg_*:<eid>` считаются истёкшими.

## events.revealed

- Было: `0` / `1`. Стало: `0` / момент раскрытия в мс. Везде читается как логическое (`!!revealed`), API отдаёт
  `revealed: boolean`, как раньше. Ставится только условным `UPDATE … WHERE revealed = 0` (атомарность, R7).

## events.draw_token

- Было: токен жеребьёвки (защита от двойной жеребьёвки) и проверка в отмене.
- Стало: ещё и версия пар — меняется при каждом удалении/вписывании после жеребьёвки; любое изменение пар применяется,
  только если версия не менялась с момента чтения (R8).

## events.finished_at

- Ставится только условным `UPDATE … WHERE status = 'active'`; служит меткой «чьё» завершение (R7).

## members.delivery при вступлении

- Предзаполняется последним непустым адресом человека, только если эвент спрашивает адрес (`delivery_on = 1`).
- При переносе участия в эвент, где новый аккаунт уже участвует: письмо и адрес — нового аккаунта, если не пустые,
  иначе старого (каждое поле отдельно, вместе со своим `*_updated_at`).

## join_requests

- Отклонённая заявка (`status='rejected'`, `decided_at`) в течение 24 часов не даёт создать новую того же человека в тот
  же эвент.

## Ограничения после жеребьёвки (правила, не данные)

- `exclusions` эвента с `draw_done = 1` не меняются (до отмены жеребьёвки).
- Состав семьи не меняется для людей, участвующих в эвентах `status='active' AND draw_done=1 AND families_on=1`.
