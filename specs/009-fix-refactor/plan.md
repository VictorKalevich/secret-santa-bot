# Implementation Plan: Исправление багов и рефакторинг перед первым выкатом

**Branch**: `009-fix-refactor` | **Date**: 2026-11-12 | **Spec**: [spec.md](./spec.md)

## Summary

Без новых функций и без смены схемы базы:

- **Рефакторинг**: `src/game.js` (≈1000 строк) разбивается на модули по зонам ответственности (`format`, `outbox`,
  `pairs`, `events`, `chat`, `roles`, `membership`; меню — в `bot.js`); повторы (имя человека, адресаты-админы,
  нормализация текста, даты, добавление участника) сводятся в одно место; `api.js` перестаёт зависеть от `bot.js`.
  Первый шаг — перенос без изменений поведения, проверяемый всеми тестами.
- **Лимиты**: счётчик внешних запросов на вызов (`src/budget.js`); отправка очереди — одна точка в конце вызова и
  ограничена остатком бюджета; cron — изолированные шаги и одно тяжёлое действие за запуск; таймаут запросов к Telegram;
  меню одним запросом; общий бюджет попыток жеребьёвки (`planDraw`).
- **Тайна**: после жеребьёвки исключения заморожены, семьи участников идущих эвентов с жеребьёвкой заблокированы, себя не
  вписать, ответы жеребьёвки без признаков прошлых пар, адрес копируется только в эвенты с адресом.
- **Целостность**: атомарные раскрытие и завершение; версия пар (`draw_token`) для удаления/вписывания; снимок состава
  при жеребьёвке.
- **Бот**: режим ответа привязан к собеседнику и истекает через час, сбрасывается командами и отказом; единая логика
  входа по ссылке и после ввода имени; пауза после отклонённой заявки; обрезка без разрыва эмодзи.
- **Мини-приложение**: счётчик навигации против «чужого экрана», повтор неудавшейся загрузки, переписка без пропусков,
  прокрутка журнала, переключатели с откатом, защита несохранённого ввода, вкладка админа по умолчанию, «Назад» Telegram,
  честные тексты.

Решения — [research.md](./research.md), данные — [data-model.md](./data-model.md), изменения API —
[contracts/api-changes.md](./contracts/api-changes.md), проверка — [quickstart.md](./quickstart.md).

## Technical Context

**Language/Version**: JavaScript ES2022, ES-модули, Cloudflare Workers · **Primary Dependencies**: без новых

**Storage**: D1, схема 8 без изменений (миграций нет)

**Testing**:
- юнит (`node:test`): `planDraw` — общий бюджет ≤ 10 мс на 50 участниках с историей и семьями; счётчик запросов и
  отправка очереди в пределах остатка бюджета; изоляция шагов cron (фейковая база); `shortTitle`/кнопки меню без
  одиночных суррогатов;
- e2e: блок «009» (см. quickstart), обновлённые ожидания прежних блоков (`history_used` убран); имитация Telegram
  отвергает одиночные суррогаты; журнал Worker проверяется на отсутствие `budget exceeded`;
- скриншоты: прежний набор, журнал с прокруткой.

**Target Platform**: Cloudflare Workers (бесплатный тариф) + Telegram Mini App · **Project Type**: web-service

**Performance Goals / Constraints**: ≤ 10 мс CPU, ≤ 50 внешних запросов на вызов (D1 входит, `batch` = 1), ≤ 100
параметров в SQL-запросе. Плановый запуск: основа ≤ 6 запросов + одно тяжёлое действие ≤ ~10 + отправка остатка.

**Scale/Scope**: до 50 участников в эвенте, единицы параллельных эвентов, десятки людей.
