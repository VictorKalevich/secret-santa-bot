# Quickstart: проверка 009

## Автоматически

```powershell
npm test             # юнит: жеребьёвка (общий бюджет planDraw ≤ 10 мс), правила дизайн-системы, счётчик запросов,
                     # изоляция шагов cron, сокращение строк без разрыва эмодзи
npm run test:e2e     # сквозные сценарии 001–008 (ожидания обновлены по 009) + блок «009»
npm run screenshots  # визуальная проверка экранов → test-results/
```

Блок «009» в `tests/e2e.test.mjs` проверяет:

1. **Тайна** — после жеребьёвки исключения не меняются; семья участника идущего эвента с жеребьёвкой не меняется
   (после завершения — меняется); админ не вписывает себя; в ответе проверки нет `history_*`; адрес не копируется в
   эвент без `delivery_on`.
2. **Рассылка** — три эвента с напоминаниями в один день: после нескольких запусков cron у каждого ровно одно
   напоминание; в журнале Worker нет `budget exceeded` (в т.ч. для /setup-ссылки и приглашения при 5 эвентах).
3. **Режим ответа** — «Ответить» → /start → текст не доставлен; «Ответить» с временем назад на 2 часа → не доставлен;
   смена пары → не доставлен; отказ нажатия сбрасывает режим.
4. **Вход** — участник после жеребьёвки по ссылке → «уже участвуешь»; удалённый до имени при закрытой регистрации →
   «закрыта», админам «присоединяется» не приходит; отклонённый повторно → новой заявки нет; меню с эмодзи в названии
   доставлено (имитация Telegram отвергает одиночные суррогаты).
5. **Атомарность** — два параллельных раскрытия/завершения → одно сообщение каждому; два параллельных удаления после
   жеребьёвки → корректная перестановка.

## Вручную (в Telegram, перед выкатом)

- Открыть эвент A, сразу «‹» и эвент B, пока не загрузилась панель → видна только панель B.
- Выключить сеть, открыть эвент, включить сеть → «Попробовать снова» открывает эвент.
- Открыть журнал с 40+ записями → прокручивается до конца.
- В открытой переписке получить сообщение собеседника во время своей отправки → видны оба.
- Android: системная «Назад» в эвенте → список эвентов; в шторке → закрывает шторку.
