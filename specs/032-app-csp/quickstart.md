# Quickstart: 032 — проверка, выкат, проверка на iPhone и откат

## 1. Локально (разработчик, до слияния)

```powershell
npm test                              # в т.ч. tests/app-csp.test.mjs: заголовок /app, отпечаток, правила кода
node --test tests/app-csp.test.mjs    # только политика
npm run test:e2e                      # wrangler dev: у /app политика, отпечаток = встроенный скрипт страницы
npm run screenshots                   # все экраны без нарушений политики + checkCsp (нужен Google Chrome)
```

Ожидается: всё зелёное; в выводе `screenshots` — строка `✔ CSP (032): …`, код выхода 0. Строка `⚠ … настоящий скрипт
Telegram не скачан` означает, что проверка с настоящим `telegram-web-app.js` пропущена (нет сети) — перед выкатом её
стоит повторить с сетью.

Правила политики и кода — `contracts/app-csp.md`.

## 2. Выкат (владелец)

База этой фичей не меняется. Но в `main` уже есть фича 031 с миграцией `0008` (только индексы); если 031 ещё не
выкачена (в бою — версия 030), шаги с базой ниже её применят, в любом порядке это безопасно (README, «Обновление бота»).

```powershell
git checkout main
git pull
npm install
npx wrangler deployments list                                 # ЗАПИШИТЕ Version ID текущей версии — к ней откат
npx wrangler d1 migrations list secret-santa-db --remote      # есть ли 0008_unread_index.sql
# если 0008 в списке — копия базы и миграция (как в specs/031-pins-audit-index/quickstart.md):
npx wrangler d1 export secret-santa-db --remote --output "backup-$(Get-Date -Format yyyy-MM-dd-HHmm).sql"
npx wrangler d1 migrations apply secret-santa-db --remote
npm run deploy
```

Копию базы храните у себя, не в папке проекта (в ней все пары и письма).

## 3. Проверка на iPhone (Telegram для iOS)

Страница не кэшируется (`cache-control: no-store`) — новая версия открывается сразу; если нет — закройте мини-приложение
(✕ вверху) и откройте снова.

Главный признак сбоя политики — **пустой экран, вечная «Загрузка…» или страница без оформления** (чёрный текст на белом,
кнопки как ссылки). Тогда — сразу откат (раздел 4).

1. **Открытие.** Чат с ботом → «🎁 Санта». Ожидается: шапка «Тайный Санта» с 🎅, список событий, оформление и цвета как
   раньше; в тёмной теме Telegram — тёмное.
2. **Событие.** Откройте событие → вкладки «Письмо», «Подопечный» (если жеребьёвка была), «Инфо», «Админ» — каждая
   открывается, данные на месте.
3. **Сохранение.** «Письмо» → допишите в конце точку → «Сохранить» — под полем «Сохранено …»; уберите точку и сохраните
   снова.
4. **Шторка и календарь.** «Админ» → «📜 Журнал действий» — шторка открывается и закрывается ✕. В событии до жеребьёвки:
   «Автожеребьёвка» → календарь (свой, в шторке) → «Закрыть».
5. **Окно подтверждения.** «Админ» → любое действие с подтверждением (например, «🏁 Завершить») → окно Telegram с
   текстом → «Отмена».
6. **Переписка.** Если есть подопечный: «Подопечный» → «💬 Написать подопечному» — поле ввода, «Отправить» (можно не
   отправлять) → ✕.
7. **Ссылка.** «Админ» → у пригласительной ссылки «📋 Копировать» — «Ссылка скопирована»; «📤 Отправить в чат» —
   открывается выбор чата Telegram; отмените.

При возможности — то же на компьютере (Telegram Desktop) и в веб-версии `https://web.telegram.org` (приложение внутри
окна веб-клиента, цвета веб-клиента).

Что-то выглядит или работает иначе, чем до выката, — откат.

## 4. Откат

Откатывается только код Worker; база не меняется (миграция `0008`, если применялась, прежнему коду не мешает — она
только добавляет индексы).

```powershell
npx wrangler rollback <Version ID из шага 2> -m "откат 032"
```

Проверка: откройте мини-приложение заново — прежний вид. Сообщите, что именно не работало (экран, клиент, версия
iOS) — политику поправим и выкатим снова (`npm run deploy` с `main`).
