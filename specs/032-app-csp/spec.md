# Feature Specification: Заголовок Content-Security-Policy для мини-приложения

**Feature Branch**: `032-app-csp`

**Created**: 2026-11-16

**Status**: Draft

**Input**: User description: "032-app-csp: заголовок Content-Security-Policy для страницы мини-приложения /app. Скрипт —
только встроенный скрипт страницы (по хешу sha256) и https://telegram.org (telegram-web-app.js); стили — свои встроенные
и 'unsafe-inline' (telegram-web-app.js в веб-клиенте создаёт <style> с темой); запросы — только свой сервер; встраивание
во фрейм — только веб-клиент Telegram (web.telegram.org); object-src 'none', base-uri 'none', form-action 'none'.
Страница и поведение приложения прежние. Проверки: быстрый тест (хеш в заголовке = хеш встроенного скрипта), Chrome
(скриншоты — нет нарушений CSP на всех экранах, «от противного» — внедрённый скрипт и запрос на чужой адрес
заблокированы), e2e (заголовок у /app). Выкат с проверкой на iPhone и откатом — quickstart. README и docs/todo.md — в
той же ветке."

## Контекст

Пункт `docs/todo.md` «Заголовок Content-Security-Policy для `/app`» (раздел «Ждёт проверки на iPhone»); 2026-11-16
владелец решил его сделать (фича 032). Главное условие владельца — стабильность проекта.

Сейчас страница мини-приложения отдаётся без политики безопасности содержимого: браузер выполнит любой скрипт и
отправит запрос куда угодно, если в страницу когда-нибудь попадёт чужая разметка. Пользовательский текст и сейчас
вставляется только как текст (`textContent`), поэтому политика — второй рубеж защиты, а не исправление известной дыры.

Проверено на текущем коде (`main` `c90fd4b`) и на текущем скрипте Telegram (`telegram-web-app.js`, 2026-11-09):

| Что загружает или делает страница | Откуда | Что нужно разрешить |
|---|---|---|
| Свой скрипт приложения | встроен в страницу (один) | только он — по отпечатку содержимого |
| Скрипт Telegram для мини-приложений | `https://telegram.org/js/telegram-web-app.js` | только этот адрес |
| Свои стили (дизайн-система) | встроены в страницу (один блок) | встроенные стили |
| Тема веб-клиента Telegram | скрипт Telegram в веб-клиенте сам создаёт блок стилей и пишет в него тему | встроенные стили (иначе в веб-клиенте теряется тема) |
| Запросы к API | свой сервер (`/api/…`) | только свой адрес |
| Картинки, шрифты, плагины, формы | нет (значки — эмодзи, шрифты — системные) | ничего чужого |
| Встраивание страницы | веб-клиент Telegram открывает приложение во фрейме `web.telegram.org`; iOS, Android и Desktop — без фрейма | только сайты Telegram |
| Связь с Telegram | нативные клиенты — свой мост, веб-клиент — сообщения окну-родителю | политика их не ограничивает |

Ошибка в политике проявляется не сообщением, а пустым или «голым» экраном — и именно в Telegram на телефоне, где
локально не проверить. Поэтому у фичи есть инструкция выката, проверки на iPhone и отката.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Приложение работает как раньше во всех клиентах Telegram (Priority: P1)

Участник или организатор открывает мини-приложение в Telegram на iPhone, Android, компьютере или в веб-версии. Всё
выглядит и работает так же, как до фичи: главный экран, события, письмо, подопечный, переписка, обращения, панель
организатора, шторки, календарь, подтверждения, тема Telegram (светлая и тёмная).

**Why this priority**: стабильность — главное условие владельца; политика, которая ломает приложение, хуже её
отсутствия.

**Independent Test**: прогон всех экранов в Chrome с политикой — ни одного нарушения политики; проверка на iPhone по
инструкции выката.

**Acceptance Scenarios**:

1. **Given** новая версия выкачена, **When** владелец открывает приложение на iPhone, **Then** главный экран и все
   вкладки события открываются и работают как раньше, тема — как у Telegram.
2. **Given** приложение открыто в веб-версии Telegram (`web.telegram.org`), **When** экран загружается, **Then**
   приложение показано внутри веб-клиента (фрейм не заблокирован), тема веб-клиента применяется.
3. **Given** прогон всех снимков экранов в Chrome, **When** страницы открываются и проверяются, **Then** браузер не
   сообщает ни об одном нарушении политики.
4. **Given** страница открыта в обычном браузере (не в Telegram), **When** она загружается, **Then** — как раньше:
   «Открой через Telegram».

---

### User Story 2 — Чужой код в странице не выполняется и ничего не отправляет (Priority: P1)

Если в страницу каким-то образом попала чужая разметка (ошибка в будущей правке, подмена текста), браузер не выполнит
её скрипт — ни встроенный, ни из обработчика события, ни загруженный с чужого сайта — и не отправит данные на чужой
адрес. Чужой сайт не может встроить приложение в свою страницу.

**Why this priority**: это и есть смысл фичи — второй рубеж защиты тайны пар и данных участников.

**Independent Test**: «от противного» в Chrome — внедряются встроенный скрипт, обработчик события, скрипт с чужого
адреса, запрос на чужой адрес, встраивание с чужого сайта; всё заблокировано, браузер сообщает о нарушении.

**Acceptance Scenarios**:

1. **Given** приложение открыто, **When** в страницу вставлен встроенный скрипт, которого не было в ответе сервера,
   **Then** он не выполняется.
2. **Given** приложение открыто, **When** в страницу вставлен элемент с обработчиком события в разметке (например,
   картинка с `onerror`), **Then** обработчик не выполняется.
3. **Given** приложение открыто, **When** в страницу вставлен скрипт с чужого адреса (в том числе с другого адреса
   `telegram.org`), **Then** он не загружается.
4. **Given** приложение открыто, **When** код страницы пытается отправить запрос на чужой адрес, **Then** запрос
   заблокирован браузером.
5. **Given** чужой сайт, **When** он встраивает приложение во фрейм, **Then** браузер не показывает приложение.

---

### User Story 3 — Правка приложения не ломает политику (Priority: P2)

Разработчик меняет код мини-приложения (любую часть `src/app/`). Политика сама соответствует новой странице — ручного
шага («пересчитать отпечаток») нет. Если правка добавляет то, что политика заблокирует (второй встроенный скрипт,
обработчик события в разметке, выполнение строки как кода, скрипт с нового адреса), быстрые тесты падают до коммита и
называют место.

**Why this priority**: без этого любая будущая правка приложения рискует пустым экраном на телефоне, который заметят
только после выката.

**Independent Test**: быстрые тесты на текущей странице и на искусственных примерах с нарушениями («от противного»).

**Acceptance Scenarios**:

1. **Given** любая правка кода приложения, **When** сервер отдаёт страницу, **Then** отпечаток в политике совпадает
   с отпечатком встроенного скрипта этой страницы.
2. **Given** в страницу добавлен второй встроенный скрипт или скрипт с адреса, которого нет в политике, **When**
   запускаются быстрые тесты, **Then** тест падает с указанием причины.
3. **Given** в код приложения добавлено выполнение строки как кода или обработчик события в разметке, **When**
   запускаются быстрые тесты, **Then** тест падает и называет часть и строку.

---

### User Story 4 — Выкат с проверкой на iPhone и откатом (Priority: P2)

Владелец выкатывает новую версию по инструкции, проверяет приложение на iPhone по списку шагов и, если что-то не так,
возвращает прежнюю версию одной командой. База при этом не меняется.

**Why this priority**: iOS локально не проверить; безопасный путь — выкат, проверка, откат при сбое.

**Independent Test**: инструкция `quickstart.md` описывает выкат, шаги проверки (iPhone, при возможности — компьютер и
веб-версия) и откат.

**Acceptance Scenarios**:

1. **Given** инструкция выката, **When** владелец выполняет её, **Then** перед выкатом записан номер текущей версии,
   после выката — проверка по шагам.
2. **Given** после выката на iPhone пустой экран или нет оформления, **When** владелец выполняет откат, **Then**
   возвращается прежняя версия; данные бота не затронуты.

---

### Edge Cases

- **Веб-клиент Telegram.** Скрипт Telegram во фрейме создаёт блок стилей и пишет в него тему, присланную веб-клиентом;
  встроенные стили разрешены — тема применяется.
- **Скрипт Telegram не загрузился** (сеть, блокировка) — как раньше: приложение берёт данные входа из адреса страницы.
- **Нативные клиенты** (iOS, Android, Desktop) передают события в страницу через свой мост, а не через скрипты страницы;
  политика их не ограничивает. Подтверждается проверкой на iPhone.
- **Клиент без поддержки политики** (очень старый) — заголовок игнорируется, всё как раньше.
- **Переводы строк.** Браузер считает отпечаток по тексту скрипта после разбора страницы (перевод строки CRLF → LF);
  отпечаток в политике считается так же, даже если в частях окажутся CRLF.
- **Ссылки и переходы** (`openTelegramLink`, ссылки `t.me`) — переходы политика не ограничивает; приложение открывает
  ссылки, как раньше.
- **Окна подтверждения** (`confirm` браузера вне Telegram, окна Telegram внутри) — не затрагиваются.
- **«База не подготовлена»** — ответ `/app` при неприменённых миграциях остаётся текстом без политики (страницы
  приложения в нём нет).
- **Другие адреса Worker** (`/setup`, `/api/…`, `/tg`, `/`) — без изменений; у `/setup` остаётся своя политика
  `frame-ancestors 'none'`.
- **Telegram изменит свой скрипт** так, что он станет загружать что-то с других адресов или создавать скрипты, —
  политика это заблокирует. Признак — сбой при проверке после выката или жалоба участника; действие — откат и правка
  политики. Проверка в Chrome с настоящим скриптом Telegram (при доступной сети) замечает это и до выката.
- **Первый запрос после запуска Worker** считает отпечаток скрипта (страница ~140 КБ) — доли миллисекунды процессора,
  дальше — готовое значение.

## Requirements *(mandatory)*

### Functional Requirements

**Политика**

- **FR-3201**: Ответ страницы мини-приложения `/app` содержит действующую (не «только отчёт») политику безопасности
  содержимого.
- **FR-3202**: Скрипты: разрешены только встроенный скрипт этой страницы (по отпечатку SHA-256 его содержимого) и
  скрипт Telegram ровно по адресу `https://telegram.org/js/telegram-web-app.js`. Встроенные скрипты без совпадающего
  отпечатка, обработчики событий в разметке, выполнение строк как кода и скрипты с любых других адресов (в том числе
  других адресов `telegram.org`) запрещены.
- **FR-3203**: Стили: разрешены встроенные стили (свой блок дизайн-системы и блок темы, который создаёт скрипт Telegram
  в веб-клиенте); стили с чужих адресов запрещены.
- **FR-3204**: Запросы из страницы (API и любые другие) — только к своему адресу.
- **FR-3205**: Всё остальное (картинки, шрифты, медиа, фреймы внутри страницы, фоновые обработчики) — только со своего
  адреса; плагины (`object`/`embed`) запрещены; базовый адрес страницы (`<base>`) менять нельзя; отправка форм
  запрещена.
- **FR-3206**: Встраивать страницу во фрейм могут только сайты Telegram (`https://web.telegram.org` и другие адреса
  `*.telegram.org`); остальные сайты — нет. Нативные клиенты открывают страницу без фрейма, на них это не влияет.

**Отпечаток**

- **FR-3207**: Отпечаток встроенного скрипта считается сервером по той странице, которую он отдаёт, — без ручного шага
  при правке приложения; один раз на экземпляр Worker, в пределах лимита процессора бесплатного тарифа.
- **FR-3208**: Отпечаток считается по тексту скрипта так, как его видит браузер после разбора страницы (переводы строк
  CRLF и CR — как LF).

**Без изменений**

- **FR-3209**: Содержимое страницы побайтно прежнее; остальные заголовки `/app` (`content-type`, `cache-control:
  no-store`) прежние; ответы и заголовки других адресов Worker, API, бота и число запросов к базе и Telegram не меняются.
- **FR-3210**: Поведение и вид приложения не меняются ни в одном клиенте Telegram.

**Проверки**

- **FR-3211**: Быстрые тесты: у `/app` есть политика с перечисленными ограничениями; в странице ровно один встроенный
  скрипт, и отпечаток в политике равен его отпечатку; каждый внешний скрипт страницы разрешён политикой; «от
  противного» — изменённый скрипт даёт другой отпечаток, CRLF и LF — один, страница с двумя встроенными скриптами или
  скриптом с чужого адреса замечается.
- **FR-3212**: Быстрые тесты по коду приложения: нет того, что политика заблокирует, — выполнения строк как кода
  (`eval`, `new Function`, строка в таймере), обработчиков событий и адресов `javascript:` в разметке; нарушение
  называет часть и строку; у каждого правила — «от противного».
- **FR-3213**: Проверка в Chrome (`npm run screenshots`): на всех открываемых страницах — ни одного нарушения политики;
  «от противного» — внедрённый встроенный скрипт, обработчик события в разметке, скрипт с чужого адреса и запрос на
  чужой адрес заблокированы (браузер сообщает о нарушении, код не выполнен); фрейм на странице `web.telegram.org`
  показывает приложение и применяет блок стилей, созданный в странице, а фрейм на чужом сайте заблокирован; при
  доступной сети — то же с настоящим скриптом Telegram (без сети эта часть пропускается с предупреждением).
- **FR-3214**: Сквозной тест (`wrangler dev`): у `/app` есть политика, отпечаток в ней равен отпечатку встроенного
  скрипта отданной страницы.

**Документы и выкат**

- **FR-3215**: Инструкция `quickstart.md`: локальные проверки, выкат (с записью текущей версии; если фича 031 ещё не
  выкачена — с её миграцией по порядку README), проверка на iPhone по шагам (и, при возможности, на компьютере и в
  веб-версии), откат одной командой; база не меняется.
- **FR-3216**: README — что страница приложения защищена политикой и что делать, если после обновления приложение
  открывается пустым (откат); `docs/api.md` — заголовок у `/app`; `CLAUDE.md` — строка фичи, модуль и тесты; пункт
  убран из `docs/todo.md`.

### Key Entities

- **Политика страницы** — набор правил «что странице можно загружать, выполнять и куда отправлять»; один на страницу
  приложения, меняется вместе с кодом.
- **Отпечаток встроенного скрипта** — SHA-256 текста встроенного скрипта страницы; разрешает браузеру выполнить ровно
  этот скрипт.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-3201**: Прогон всех снимков и проверок в Chrome — 0 нарушений политики на всех страницах.
- **SC-3202**: Все 5 видов внедрения из User Story 2 (встроенный скрипт, обработчик в разметке, чужой скрипт, запрос
  на чужой адрес, встраивание чужим сайтом) заблокированы в Chrome — 5 из 5.
- **SC-3203**: После выката владелец проходит на iPhone все шаги проверки из инструкции — приложение работает как раньше
  (без пустого экрана и потери оформления); при сбое прежняя версия возвращается одной командой, данные не теряются.
- **SC-3204**: Содержимое страницы побайтно совпадает с прежним; `npm run test:all` зелёный; число запросов всех
  действий — прежнее.
- **SC-3205**: Правка кода приложения не требует ручного обновления политики: быстрые тесты зелёные после любой правки
  скрипта, если она не добавляет запрещённого политикой.

## Assumptions

- Политика сразу действующая, а не «только отчёт»: отчётам некуда приходить без новой точки входа (без проверки подписи
  её мог бы засыпать кто угодно, и каждый отчёт — вызов Worker в дневной лимит), а на iPhone отчёт в консоли владелец
  не увидит. Защита от сбоя — проверка на iPhone сразу после выката и откат одной командой.
- Встроенные стили разрешены целиком (`'unsafe-inline'` для стилей): без этого в веб-клиенте теряется тема Telegram;
  стили не выполняют код, а пользовательский текст и так вставляется только как текст.
- Нативные клиенты Telegram (iOS, Android, Desktop) подключают свой мост к странице средствами самого клиента, а не
  скриптами страницы, поэтому политика их не ограничивает; это подтверждает проверка на iPhone (Android и Desktop — по
  возможности владельца).
- Встраивание разрешено всем адресам `*.telegram.org`, а не только `web.telegram.org`: прежние адреса веб-клиентов
  (`webk`, `weba`) тоже принадлежат Telegram; риск для приложения — нулевой, а пустой экран у участника со старым адресом
  был бы сбоем.
- Скрипт Telegram разрешён по точному адресу файла, а не всему `telegram.org`: так с этого сайта нельзя подключить
  другие скрипты.
- Другие заголовки безопасности (`x-content-type-options`, `referrer-policy` и т. п.) и политика для `/setup` — вне
  объёма фичи.
- Конституция не меняется: политика — дополнительная защита к правилу «пользовательский текст — только как текст».
- Фича 031 влита в `main`, но может быть ещё не выкачена (в бою — 030): выкат 032 выкатывает и её; её миграция `0008`
  безопасна в любом порядке (README, «Обновление бота»).
