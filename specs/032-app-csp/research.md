# Research: 032 — Content-Security-Policy для `/app`

Исходные данные — `main` `c90fd4b` и скрипт Telegram `https://telegram.org/js/telegram-web-app.js` (скачан 2026-11-16:
127 770 байт, `Last-Modified: Mon, 09 Nov 2026`; ответ 200 без перенаправлений, `cache-control: max-age=345600`).

## R1. Где и как считать отпечаток встроенного скрипта

**Decision**: новый модуль `src/csp.js` (без импортов): `inlineScripts(page)` — тексты встроенных скриптов страницы,
`appPolicy(page)` — строка политики с отпечатками `'sha256-…'` этих скриптов. `src/index.js` считает политику по
`APP_PAGE` при первом запросе `/app` и хранит обещание в переменной модуля (`appCsp ??= appPolicy(APP_PAGE)`): один раз
на экземпляр Worker, дальше — готовая строка.

**Rationale**: отпечаток всегда соответствует отдаваемой странице — правка любой части `src/app/` не требует ручного
шага (SC-3205); страница побайтно прежняя (FR-3209). Замер на Node 24 (страница 172 198 байт, скрипт 140 942 байта):
`crypto.subtle.digest` с кодированием — 2,9 мс на первом вызове (прогрев), затем 0,35–0,45 мс; в Worker это один раз
на экземпляр, в пределах 10 мс CPU.

**Alternatives considered**:
- *Отпечаток константой в коде* (тест сверяет): каждая правка приложения — ручной шаг и падающий тест; отклонено.
- *Вынести скрипт в файл `/app.js` и разрешить `'self'`*: страница меняется, на каждое открытие — второй вызов Worker
  (дневной лимит, задержка на телефоне), а при выкате возможна смесь старой страницы и нового скрипта; отклонено.
- *Одноразовый `nonce`*: нужно менять страницу на каждый ответ (вставка значения) — страница уже не побайтно прежняя,
  а пользы перед отпечатком нет (страница статична); отклонено.
- *`'unsafe-inline'` для скриптов*: снимает главную защиту — внедрённый встроенный скрипт выполнился бы; отклонено.
- *Посчитать при загрузке модуля (`await` верхнего уровня)*: в Workers асинхронная работа в глобальной области
  ограничена; ленивый расчёт проще и надёжнее.

## R2. Текст, по которому браузер считает отпечаток

**Decision**: отпечаток — SHA-256 от UTF-8 текста между `<script>` и `</script>` после замены CRLF и CR на LF;
кодировка — base64.

**Rationale**: по CSP отпечаток считается от текста элемента `<script>` после разбора страницы, а разбор HTML заменяет
CRLF и одиночный CR на LF ещё до токенизации; текст кодируется в UTF-8 (страница отдаётся `charset=utf-8`, в скрипте
кириллица). Сейчас в частях только LF (`.gitattributes`: `* text=auto eol=lf`, правило частей 021), замена —
страховка на случай рабочей копии с CRLF. Встроенный скрипт — ровно `<script>` без атрибутов (`01-shell.html`, строка
24); `</script>` внутри скрипта невозможен (разбор HTML закончил бы скрипт раньше), поэтому граница находится
однозначно.

**Alternatives considered**: считать по байтам файла без замены переводов строк — отпечаток разошёлся бы с браузером в
рабочей копии с CRLF; отклонено.

## R3. Что делает скрипт Telegram и что ему нужно

Разбор `telegram-web-app.js` (2026-11-09):

| Поведение | Где | Что требует |
|---|---|---|
| Во фрейме: создаёт `<style>` и пишет в него `innerHTML` из события `set_custom_style` (только от `https://web.telegram.org`) | строки 21–53 | встроенные стили |
| Отладочная панель (`tgWebAppDebug` в адресе): `<style>` с анимацией | 1037–1066 | встроенные стили |
| Тема, высота окна, безопасные зоны: `document.documentElement.style.setProperty(…)` | `setCssProperty` | ничего (изменение стилей из скрипта политика не ограничивает) |
| Связь с клиентом: `TelegramWebviewProxy.postEvent` (iOS, Android), `window.external.notify` (Desktop), `parent.postMessage` (веб) | `postEvent`, 128–159 | ничего |
| `fetch('/api/' + name)` — «serverless endpoints» | ~2784 | приложение их не вызывает; был бы свой адрес — `connect-src 'self'` |
| `openProtoUrl` — `<iframe>` для `tg://` на iOS | 202–232 | функция не вызывается нигде в скрипте |
| `openLink`/`openTelegramLink` без поддержки клиента — `window.open`/`location.href` | 3259–3305 | переходы политика не ограничивает |
| `eval`, `new Function`, загрузка скриптов, картинок, шрифтов | — | нет |

Нативные клиенты подключают мост средствами клиента: iOS и macOS — `WKUserScript` и `evaluateJavaScript`, Android —
`addJavascriptInterface` и `evaluateJavascript`, Desktop — скрипты WebView; такой код страничная политика не
ограничивает. Локально это не проверить — проверка на iPhone (quickstart).

**Decision**: `style-src 'unsafe-inline'`; скрипт Telegram — по точному адресу файла.

**Rationale**: без встроенных стилей веб-клиент теряет тему (стиль не применится), а отпечаток для стилей отключил бы
`'unsafe-inline'` (по CSP при отпечатке или `nonce` `'unsafe-inline'` игнорируется), тогда блок, созданный скриптом
Telegram, был бы заблокирован. Точный адрес вместо всего `https://telegram.org` не даёт подключить с этого сайта другие
скрипты.

## R4. Состав политики

**Decision** (контракт — `contracts/app-csp.md`):

```text
default-src 'self'; script-src 'sha256-<встроенный скрипт>' https://telegram.org/js/telegram-web-app.js;
style-src 'unsafe-inline'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none';
frame-ancestors https://*.telegram.org
```

**Rationale**:
- `default-src 'self'` — картинки, шрифты, медиа, фреймы, обработчики — только свой адрес; чужого странице не нужно
  (значки — эмодзи, шрифты — системные, в CSS нет `url(` и `@font-face`). `'self'`, а не `'none'`: своё всё равно
  отдаёт этот же Worker, а неожиданная загрузка своего адреса (например, клиентом) не станет пустым экраном.
- `script-src` — только встроенный скрипт и файл Telegram; обработчики в разметке, `eval`, строки в таймерах и
  `javascript:` запрещены (нет `'unsafe-inline'`, `'unsafe-eval'`, `'unsafe-hashes'`). В приложении их нет: обработчики —
  `addEventListener` (в `h()` ключи `on…`), строк как кода нет (проверяет тест, FR-3212).
- `connect-src 'self'` — запросы только к `/api/…` своего адреса (`api()` в `02-core`).
- `object-src 'none'`, `base-uri 'none'`, `form-action 'none'` — плагинов, `<base>` и форм в приложении нет
  (`base-uri` и `form-action` не наследуются от `default-src`, поэтому заданы явно).
- `frame-ancestors https://*.telegram.org` — веб-клиент (`web.telegram.org`, прежние `webk`/`weba`); `*.telegram.org`
  охватывает `web.telegram.org`. Нативные клиенты открывают страницу без фрейма.

**Не включено**: `upgrade-insecure-requests` (все загрузки — свой адрес или `https`), `require-trusted-types-for`
(поддержка в WebKit неполная, приложение и так без `innerHTML`), `'strict-dynamic'` (скрипты не подгружают скрипты),
`report-uri`/`report-to` (R5).

## R5. Действующая политика или «только отчёт»

**Decision**: действующая политика (`Content-Security-Policy`) с первого выката, без отчётов о нарушениях.

**Rationale**: режим «только отчёт» полезен, когда отчёты где-то собираются. Для этого нужна новая точка входа без
проверки подписи (её мог бы засыпать кто угодно; каждый отчёт — вызов Worker в дневной лимит бесплатного тарифа), а
консоль браузера на iPhone владелец не увидит. Риск действующей политики закрывают проверки до выката (быстрые тесты,
Chrome со всеми экранами, при сети — с настоящим скриптом Telegram), проверка на iPhone сразу после выката и откат
одной командой (база не меняется).

**Alternatives considered**: `Content-Security-Policy-Report-Only` на неделю с `report-uri` в Worker — отклонено по
причинам выше; можно вернуться, если появятся жалобы, которые не воспроизводятся.

## R6. Проверка в Chrome

**Decision** — в `tests/screenshots.mjs`:
- Все страницы открываются одним помощником `openPage`: он ставит сборщик нарушений — обработчик
  `securitypolicyviolation`, добавленный через `addInitScript`, передаёт нарушение в Node (`exposeFunction`); код,
  добавленный средствами отладки браузера, политика страницы не ограничивает, поэтому сам сборщик нарушений не создаёт.
  Любое нарушение на обычной странице — ошибка прогона.
- `checkCsp()` «от противного» на открытом приложении: встроенный `<script>`, `onclick` в разметке, `eval`,
  `<script src>` с чужого адреса и с другого пути `telegram.org`, `fetch` на чужой адрес — каждое даёт нарушение
  нужного вида, код не выполнен.
- Фреймы: адреса `https://web.telegram.org/…` (страница-родитель с фреймом) и `https://santa.test/…` (приложение:
  запросы пересылаются в Worker теста через `route.fetch`, ответ — с его заголовками) обслуживает перехват Playwright.
  Так родитель и приложение — `https`, без смешанного содержимого и запретов доступа к локальной сети. На родителе
  `https://web.telegram.org` приложение загружается и применяет блок `<style>`, созданный в странице (как это делает
  скрипт Telegram); на родителе `https://csp-check.example` фрейм заблокирован.
- При доступной сети Node скачивает настоящий `telegram-web-app.js` (таймаут), и проверка фрейма повторяется с ним:
  скрипт Telegram во фрейме создаёт свой `<style>`, родитель присылает `set_custom_style` — стиль применён, нарушений
  нет. Без сети — предупреждение `⚠`, остальные проверки идут.

**Rationale**: нарушения политики видны только в браузере; обычные снимки уже проходят все экраны, поэтому сборщик на
них проверяет «нет нарушений» на всех страницах без отдельного обхода. Настоящий скрипт Telegram ловит его будущие
изменения до выката, но не делает прогон зависимым от сети.

## R7. Быстрые тесты и e2e

**Decision**: новый `tests/app-csp.test.mjs` (в `npm test`):
- заголовок `/app` «мира» = контракт (набор директив, отпечаток = SHA-256 единственного встроенного скрипта,
  посчитанный в тесте через `node:crypto`), остальные заголовки и тело — прежние; у `/setup` политика прежняя;
- страница: каждый `<script>` — либо встроенный без атрибутов (ровно один), либо файл Telegram по точному адресу;
- `inlineScripts`/`appPolicy`: CRLF, CR и LF дают один отпечаток, изменённый скрипт — другой, два скрипта — два
  отпечатка;
- код приложения (склейка, место — `where`): нет `eval(`, `new Function`, строк в `setTimeout`/`setInterval`,
  `javascript:`, обработчиков `on…=` в HTML-частях и `setAttribute('on…'`; «от противного» на каждом правиле.

`tests/e2e.test.mjs` — отдельный тест: `/app` из `wrangler dev` с политикой, отпечаток = SHA-256 встроенного скрипта
отданной страницы.

**Rationale**: быстрые тесты ловят расхождение до коммита (US3), e2e — что заголовок отдаёт настоящий workerd.
