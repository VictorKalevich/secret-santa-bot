# Research: Быстрые тесты всего Worker

## R1 — Минимальная версия Node

- **Факты (документация Node, nodejs.org/api)**: `node:sqlite` — «Added in: v22.5.0»; история модуля: «v23.4.0,
  v22.13.0 — SQLite is no longer behind `--experimental-sqlite` but still experimental». `module.registerHooks` —
  «Added in: v23.5.0, v22.15.0». С v26.11.0 `DatabaseSync` — устаревший по документации (DEP0210,
  «Documentation-only») псевдоним нового имени `Database`; предупреждения во время работы нет.
- **Решение**: `engines.node` = `^22.15.0 || >=23.5.0` (точнее, чем `>=22.15`: в 23.0–23.4 нет `registerHooks`).
  В подмене D1 класс берётся как `sqlite.Database ?? sqlite.DatabaseSync` — работает и в 22.15, и после
  переименования. README: «нужна 22.15 или новее (LTS 24 подходит)».
- **Отклонено**: оставить `>=20` (в 20 нет ни `node:sqlite`, ни `registerHooks` — `npm test` упадёт на импорте);
  `--experimental-sqlite` в скрипте (лишний флаг, в 22.13+ не нужен).

## R2 — Подмена D1

- **Решение**: прототип `d1-shim.mjs` → `tests/support/d1-sqlite.mjs` без изменения поведения. Свойства, на которые
  опирается `src/` (каждое закрепляется в `tests/d1-sqlite.test.mjs`):
  - `first()` — строка или `null`; `first('колонка')` — значение или `null` (`src/db.js:22`);
  - `meta.changes` — изменённые этим оператором строки, у `SELECT` — 0 (разница `total_changes()`: SQLite
    `changes()` после `SELECT` вернул бы число от предыдущего оператора);
  - `batch()` — одна транзакция `BEGIN IMMEDIATE`/`COMMIT`, ошибка любого оператора — `ROLLBACK` всех; результат —
    по одному на оператор, у `RETURNING` заполнен `results` (`src/events.js:43`, `src/chat.js:67`, `src/support.js:128`);
  - нумерованные параметры `?1`, `?2` с повтором (`src/outbox.js:35`, `src/chat.js:72`);
  - числа привязываются как REAL (`typeof(?)` = `real`), колонки `INTEGER` приводят целые обратно — как в D1;
  - `boolean` → 0/1 (в новых Node `node:sqlite` принимает и сам, но в 22.15 — нет), `undefined` — ошибка
    `D1_TYPE_ERROR` (в Node 26.10+ `node:sqlite` привязал бы `NULL` — подмена держит поведение D1).
- Счётчики: `stats.queries` — запросы так же, как их считает `metered` (`batch` и `exec` — один запрос),
  `stats.log` — текст каждого запроса (для печати SQL в `tests/bench/queries.mjs`).
- `gate` — барьер перед первой записью вызова (для `together`): записью считается оператор, начинающийся с
  `INSERT|UPDATE|DELETE`, и любой `batch`. В `src/` нет записей через `WITH …`/`REPLACE` (проверено поиском).
- **Отклонено**: Miniflare/workerd в процессе (зависимость, секунды на старт); `better-sqlite3` (зависимость).

## R3 — Импорт `.html` и `.css`

- **Решение**: `tests/support/text-hooks.mjs` — синхронный `load`-перехватчик `registerHooks`: для `.html|.css|.txt`
  возвращает `{ format: 'module', shortCircuit: true, source: 'export default <JSON-строка>' }` — так же, как правило
  `Text` в `wrangler.toml`. Подключается первым импортом `world.mjs` (до импорта `src/index.js`).
- **Отклонено**: `--import`/`--loader` в командной строке (меняет скрипт `npm test` и e2e); асинхронный `register`
  (отдельный поток, медленнее, сложнее отлаживать).

## R4 — Подмена Telegram и сети

- **Решение**: один перехватчик `globalThis.fetch` на процесс, который направляет запрос «миру» по хосту `TG_API`
  (`http://tg<N>.test` — у каждого мира свой). Неизвестный хост — ошибка «сеть в быстрых тестах недоступна»: тест не
  может случайно уйти в настоящий Telegram. `restoreFetch()` возвращает исходный `fetch` (`after` в каждом файле).
- **Почему по хосту**: в одном файле живёт несколько миров (атомарность — по миру на группу проверок); последний
  созданный мир не должен перехватывать сообщения предыдущего.
- Ответы — общая чистая функция `telegramReply` (R5); все вызовы записываются (`calls`), включая отвергнутые — как
  `mock.calls` в e2e (`texts()` их тоже видит).

## R5 — Общие правила поддельного Telegram

- **Решение**: `tests/support/telegram-rules.mjs`: `BLOCKED_CHAT`, `visibleLength`, `brokenUtf16`,
  `telegramReply(method, params, nextMessageId)` → `{ status, body }` — 403 заблокировавшему, 400 при видимой длине
  больше 4096, 400 при разорванном эмодзи в тексте или кнопках, `getMe` — бот `test_santa_bot`, `sendMessage` —
  `message_id` (номер выдаётся только при успехе, как сейчас). `tests/mock-telegram.mjs` вызывает её и
  реэкспортирует `BLOCKED_CHAT` (e2e импортирует его оттуда), заголовок `connection: close` (015) остаётся.

## R6 — Одновременные вызовы

- **Решение**: `together(thunks, { writeOrder, sameMoment })` и `beforeWrite(marker, inject)` из прототипа без
  изменений. Вызовы запускаются по одному: каждый идёт до первой записи и встаёт на барьер; затем пишут по очереди в
  порядке `writeOrder`. `sameMoment` подменяет `Date.now` на время вызовов — это не поддельные таймеры (FR-1603: таймеры
  и перемотка не вводятся), а «одна миллисекунда» одновременных запросов в Workers; без неё захват по метке времени
  (`ward.received`) дубля не показывает.
- `beforeWrite` узнаёт оператор по подстроке SQL — допустимо: это выбор точки вставки чужого вызова в тесте, а не
  проверка ответа (в атомарности используется в одной проверке).
- **Отклонено**: `Promise.all` (вызовы фактически идут по очереди — гонку не проверяет); случайные задержки
  (недетерминированно).

## R7 — Тайна по значениям

- **Перестановка**: администратор `adm` не участвует в событии (его собственная пара по замыслу видна ему в
  `ward.get`). После жеребьёвки и статусов (открыл подопечного, подарок готов, подарок получен, переписка, обращение)
  снимаются ответы: админу и владельцу-неучастнику — `admin.state`, `admin.audit` (событие и общий), `admin.users`,
  `admin.families`, `event.get`, `me`; `admin.draw.check` — на втором событии тех же людей, созданном позже, с
  «не повторять прошлые пары» (только там пары первого события влияют на ответ — R7 спецификации, допущения).
  Сначала контроль: два снимка подряд без изменений обязаны совпасть (иначе ответы зависят не от данных).
- В одной транзакции SQLite строки `pairs` события удаляются и вставляются заново по другой допустимой расстановке
  (никто не дарит себе, у каждого Санты подопечный сменился): колонки Санты (`seen_text`, `gift_ready`, `notified_at`)
  остаются у Санты, колонки подопечного (`gift_received`, `gift_received_at`) переезжают с подопечным. Первичный ключ
  `(event_id, santa)` и уникальность `(event_id, ward)` не нарушаются (удаление и вставка, а не `UPDATE` по одной).
- Сравнение — текст тела ответа (`world.api(…, true).text`): «побайтно».
- **Замена писем и адресов**: `UPDATE members SET wishlist = …, delivery = …` другими непустыми строками другой длины,
  без правки `*_updated_at`; снимок — тот же набор без `admin.wishlist` (оно отдаёт письмо по замыслу и пишет журнал).
- **Сообщения**: отдельный мир со всеми рассылками после жеребьёвки (письмо обновлено — cron, переписка в обе стороны,
  «подарок готов/получен», напоминания, объявление, удаление и вписывание после жеребьёвки, раскрытие, завершение).
  Имена участников — разные, ни одно не входит в другое и в слова текстов бота; письма и адреса — с уникальными
  метками. Для каждого сообщения участнику-неадмину: текст без «Тайна раскрыта» не содержит имени ни одного его
  подопечного (за всё время, с учётом замен) и ни одного текста письма или адреса. Админы-участники исключены:
  уведомления организаторам об обращениях и вступлениях называют автора по замыслу (допущение спецификации).
- **Отклонено**: проверка по именам ключей JSON (как в e2e: ничего не говорит о значениях); сравнение после
  `JSON.parse` (теряется порядок ключей и формат).

## R8 — Права

- **Решение**: список — `case '(admin\.[a-z._]+)'` по тексту `src/api.js`, уникальные, `assert.equal(n, 46)`. Для каждой
  пары (действие, роль) — новое событие владельца и минимальное тело `{ event, id: 0, from: 0, to: 0, giver: 0,
  receiver: 0 }` (как в e2e). Участник — 403 и ровно «Только для администратора.»; админ — множество действий с 403
  равно списку 12 действий владельца, текст отказа — «… может только владелец бота.» или «Служебный просмотр доступен
  только владельцу бота.»; владелец — ни одного 403. Отдельно: незарегистрированный — 403 «Сначала зарегистрируйся…»,
  неверная подпись — 401, `GET /api/me` — 405.
- Свежее событие на каждый вызов — иначе `admin.event.finish` завершает событие раньше `admin.reset.full` и право
  владельца на сброс не проверяется (дыра e2e). 46 × 3 ролей ≈ 140 вызовов + 140 созданий — доли секунды.
- **Отклонено**: одно событие на роль в порядке исходника (повторяет дыру e2e).

## R9 — Известные дефекты как `todo`

- **Решение**: `test(name, { todo: 'шаг N' }, fn)` в `node:test`: тест выполняется, его падение не роняет прогон, в
  выводе помечен `# шаг N`. Утверждения в `todo` — правильное поведение (один результат), поэтому сейчас они падают;
  шаг, который чинит дефект, снимает пометку. В имени — «(будет исправлено в шаге N)».
- 5 дефектов: шаг 3 — двойной перенос участия, «Я участвую» выкл ↔ жеребьёвка (жеребьёвка пишет первой), двойное
  удаление до жеребьёвки; шаг 5 — двойное исключение, двойная отметка «получил» в одну миллисекунду. 6 строк «захвата
  нет» (объявление, напоминание, сброс, назначение админа, передача владения, двойное сохранение новой семьи) — не
  тесты (решения владельца, `baseline.md`, раздел 4).
- **Отклонено**: `skip` (тело не выполняется — починку никто не заметит); утверждать текущее неверное поведение
  (тест падал бы от починки).

## R10 — Число запросов

- **Решение**: сценарий прототипа `queries.mjs` → `tests/support/queries-scenario.mjs` (возвращает строки «действие,
  запросов к базе, запросов к Telegram, SQL»). `tests/queries.test.mjs`: для каждой строки `db ≤ базовое` и
  `tg = базовое` (сообщения — поведение, R10 спецификации, допущения), полный список имён совпадает с базовым (новое или
  пропавшее действие — падение). Базовые числа — таблица в тесте (= `baseline.md`, раздел 3). Журнал Worker без
  `budget exceeded`. Жеребьёвка на 40 человек: `db + tg ≤ 50`, остаток очереди уходит следующим cron.
- `tests/bench/queries.mjs` печатает таблицу (с `sql` — текст запросов) — инструмент шага 4.

## R11 — Эталон жеребьёвки

- **Решение**: генератор случаев из `draw-equivalence.mjs` → `tests/support/draw-cases.mjs`: 400 случаев (зерна
  1–400): размеры 2–15 и до 61 у каждого пятого, исключения разной плотности (в том числе с людьми не из списка),
  семьи, история, закреплённые пары, кольцевая и нет, малый бюджет поиска. На случай: `planDraw`; `findAssignment` с
  `pairRules` и с обёрткой-функцией (путь без быстрых веток); `removeFromAssignment`; `insertIntoAssignment` без ранга и
  с рангом. Сериализация — весь результат (`Map`/`Set` → массивы), по строке на случай.
- `tests/fixtures/make-draw-golden.mjs` пишет `tests/fixtures/draw-golden.json` от текущего `src/draw.js`;
  `tests/draw-golden.test.mjs` пересчитывает и сравнивает строки; при расхождении называет первые случаи. Эталон не
  пересоздаётся в шагах плана рефакторинга (комментарий в скрипте).
- **Отклонено**: хэши вместо результатов (меньше файл, но не видно, что разошлось); 6000 случаев (файл в мегабайты,
  прогон дольше; для разовой сверки шага 2 остаётся `draw-equivalence.mjs`).

## R12 — `tests/unit.test.mjs`

- **Решение**: `fakeD1` с узнаванием SQL по подстроке заменяется подменой `createD1` с миграциями:
  - «бесконечная очередь» — 100 настоящих строк `outbox`;
  - «падающий шаг cron» — таблица `events` переименована: шаги `notify` и `daily` падают (оба пишут
    `cron step failed`), очередь всё равно уходит;
  - «в batch уходят исходные операторы, а не обёртки» — перехват `batch` подмены: у каждого оператора есть `sql`, нет
    `raw_stmt`.
- `familySnapshot` и прочие чистые проверки — без изменений.

## R13 — Журнал Worker в «мире»

- **Решение**: на время мира `console.log` собирается в `world.log()` и не печатается (ожидаемые записи вроде
  «telegram 403» не засоряют вывод); `WORLD_LOG=1` — печатать тоже. По журналу проверяется `budget exceeded`.

## R14 — Параллельные файлы и проверки времени

- `node --test` запускает файлы в отдельных процессах параллельно. Проверки `< 10 мс` в `tests/draw.test.mjs` меряют
  настенное время. **Решение**: сначала параллельно; если пороги станут нестабильными (5 прогонов подряд) —
  `--test-concurrency=1`, пороги не трогаются (файл шага, «Подводные камни»).

## R15 — Что остаётся только в e2e

- «База не подготовлена» (`tests/e2e.test.mjs:476`): `src/db.js:16` запоминает готовность схемы на весь процесс.
