# Data Model: мини-приложение по частям

Данных в базе фича не добавляет: схема, миграции и `REGISTRY` не меняются. Ниже — «данные» сборки страницы.

## Часть приложения

Файл в `src/app/`. Имя — `NN-слово.html` или `NN-слово.js.txt` (`NN` — порядок, с `01`, подряд; слово — латиница,
цифры, дефис). Текст — непрерывный кусок прежнего `src/app.html` от шва до шва (research R2).

| Файл | Строки `src/app.html` | Строк | Байт | Область |
|---|---|---|---|---|
| `01-shell.html` | 1–25 | 25 | 1 076 | `<head>`, плейсхолдер стилей, разметка (`heroBack`, `heroTitle`, `heroSub`, `tabs`, `main`, `toast`), `<script>`, `(() => {` |
| `02-core.js.txt` | 26–216 | 191 | 9 185 | `'use strict'`, Telegram и подпись, утилиты (`h`, `ui`, `api`, тост, подтверждение, `busy`, `bindToggle`, форматы), сравнение версий письма |
| `03-home.js.txt` | 217–512 | 296 | 19 602 | состояние, загрузчики, `render`, навигация (`goHome`, `openEvent`, `syncBack`), главный экран, семьи, администраторы |
| `04-event.js.txt` | 513–778 | 266 | 17 621 | шапка события, вкладки, плашка завершения, `chatButton`, `finishedNotice`, вкладки «Письмо», «Подопечный», «Инфо» |
| `05-admin.js.txt` | 779–1433 | 655 | 50 901 | `renderAdmin` целиком (вкладка «Админ») |
| `06-vault-audit.js.txt` | 1434–1544 | 111 | 9 863 | служебный просмотр владельца, журнал действий |
| `07-sheet-chat.js.txt` | 1545–1838 | 294 | 17 254 | шторка (`openSheet`, `closeSheet`), переписка Санты и подопечного, обращения к организатору |
| `08-start.html` | 1839–1872 | 34 | 1 560 | `start`, запуск, `})();`, `</script>`, `</body>`, `</html>` |

Итого 1872 строки, 127 062 байта.

**Правила** (проверяет `tests/app-parts.test.mjs`):

- LF, без BOM, не пустая; кончается непустой строкой и ровно одним `\n`. Пустая строка перед заголовком раздела —
  первая строка части (части 3–8).
- Часть `.js.txt` — целые объявления и операторы верхнего уровня обёртки: разбирается как тело функции.
- Расширение `.js` запрещено (wrangler собрал бы файл как модуль).
- Код внутри — без изменений относительно `src/app.html` на момент разреза; дальше части правятся как обычные исходники.

**Связи**: части 3, 4, 5, 7 ссылаются друг на друга (функции поднимаются в общей области видимости обёртки):
3↔4, 3↔5, 3↔7, 4↔7. Объявления `const`/`let` исполняются по порядку частей; `start()` вызывается последним (часть 8).

## Модуль сборки страницы — `src/app-page.js`

| Экспорт | Что | Кто пользуется |
|---|---|---|
| `default` | склейка: тексты `APP_PARTS` по порядку без разделителей | `src/index.js` (вставка стилей вместо `/*@design-system*/`) |
| `APP_PARTS` | `[[имя файла, текст], …]` в порядке сборки | тесты (`tests/support/app-source.mjs`) |

Порядок частей задан только здесь.

## Склейка в тестах — `tests/support/app-source.mjs`

| Экспорт | Что |
|---|---|
| `APP` | склейка (тот же `default` из `src/app-page.js`) |
| `PARTS` | `[{ name, text, start }]` — `start`: номер первой строки части в склейке (с 1) |
| `where(line)` | номер строки склейки → `src/app/<имя>:<строка в части>` |

## Состояния

Нет: части и склейка — статический текст, собирается один раз при загрузке модуля.
