# Внутренний контракт: части мини-приложения (021)

Внешний интерфейс не меняется: `GET /app` отдаёт ту же страницу (заголовки `content-type: text/html; charset=utf-8`,
`cache-control: no-store`), API и бот не затронуты. Здесь — правила для разработчика, который правит интерфейс.

## 1. Где что лежит

- `src/app/NN-слово.(html|js.txt)` — части страницы по областям (таблица — `data-model.md`). Правится часть своей
  области; новая функция кладётся в часть, где её область, — между объявлениями верхнего уровня.
- `src/app-page.js` — **единственное** место, где перечислены части по порядку; отдаёт склейку (`default`) и
  `APP_PARTS`.
- `src/index.js` — `import APP_HTML from './app-page.js'`; стили дизайн-системы вставляются вместо `/*@design-system*/`
  заменой через функцию.

## 2. Правила частей

1. Склейка — конкатенация частей по порядку, без разделителей. Скрипт — один встроенный `<script>` с одной обёрткой
   `(() => { 'use strict'; … start(); })();`, без модулей и без второго тега: код держится на общей области видимости и
   подъёме функций.
2. Части скрипта — `.js.txt`, оболочка и запуск — `.html`. **Не `.js`**: wrangler соберёт такой файл как модуль, а не
   как текст.
3. Формат: LF, без BOM, последняя строка непустая и кончается одним `\n`; пустая строка перед заголовком раздела
   (`  // ---------- … ----------`) — первая строка следующей части.
4. Часть скрипта — целые объявления и операторы верхнего уровня обёртки: функция или блок не переходят через шов.
5. Объявления `const`/`let` исполняются по порядку частей; вызов `start()` — последний оператор обёртки (часть `08`).
6. Дизайн-система и слова — как прежде для `src/app.html`: только классы `ds-*`, без `style`, сырых цветов и px; в
   текстах для людей «событие», кнопки без «＋». Проверки идут по склейке.

## 3. Как добавить часть

1. Файл `src/app/NN-слово.js.txt` с номером на своём месте (части после него — перенумеровать, номера подряд).
2. Строка импорта и элемент `APP_PARTS` в `src/app-page.js` — на том же месте.
3. `npm test`: `tests/app-parts.test.mjs` проверит, что каждый файл папки в сборке ровно один раз и по порядку, формат
   и разбор частей, один скрипт и `start()` последним.

Правило `Text` в `wrangler.toml` и перехватчик тестов (`tests/support/text-hooks.mjs`) трогать не нужно: `.html` и
`.txt` уже подключаются как текст.

## 4. Тесты

- Склейку тесты берут только из `tests/support/app-source.mjs` (`APP`, `PARTS`, `where(line)`), он импортирует
  `src/app-page.js` через перехватчик — без своего списка файлов.
- `tests/design-system.test.mjs`, `tests/wording.test.mjs` — по склейке; нарушение слов называет
  `src/app/<часть>:<строка>`.
- `tests/world.test.mjs` — `GET /app` = склейка со вставленными стилями.
- `tests/app-parts.test.mjs` — правила раздела 2 (кроме 6) и раздела 3.
