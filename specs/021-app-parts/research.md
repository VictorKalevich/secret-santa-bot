# Research: мини-приложение по частям

Основа — `docs/refactoring/step-6-app-split.md` (карта частей, проверенные расширения, подводные камни). Исходное
состояние: `src/app.html` не менялся с `24b85d3` — SHA-256 `440b0db84c32e7dab6a4407854796ed2685aa5e83b43d6f614975b716b5f32ff`,
1872 строки, 127 062 байта, только LF, без BOM; заголовки разделов — в строках из файла шага (сверено `grep`).

Замеры «до» (2026-11-14, `main` на `35bc60d`): `npm test` — 164 теста, все прошли, 0,72–0,80 с (с запуском npm —
1,18 с); страница `/app` с `wrangler dev` (через `tests/harness.mjs`) — 200, `text/html; charset=utf-8`, 153 719 байт,
SHA-256 `b4ab9c8f819c7f05886eedaac1e857e99dedcfb474bfc47cbae0a7d3fdb01a58`; скриншоты — два прогона по 38 снимков (R8).

## R1. Расширения частей

**Decision**: оболочка (`01-…`) и запуск (`08-…`) — `.html`, шесть частей скрипта — `.js.txt`. `wrangler.toml` не
меняется.

**Rationale**:
- `.html` подключается как текст правилом проекта (`wrangler.toml`, `[[rules]] type = "Text"`), `.txt` — правилом
  wrangler по умолчанию (`**/*.txt`): у правила проекта `fallthrough = true`, правила по умолчанию продолжают действовать.
  Оба варианта проверены сборкой в файле шага; в этом шаге — повторно `wrangler deploy --dry-run --outdir` (quickstart).
- Перехватчик быстрых тестов (`tests/support/text-hooks.mjs`) уже понимает `.html`, `.css`, `.txt` — правка не нужна.
- `.js.txt` говорит, что внутри, и при этом не попадает под форматтеры и линтеры, которые редактор запускает для `.js`
  и `.html` (например, форматирование при сохранении): единственный, кто меняет текст части, — разработчик.
- Нет подсветки синтаксиса по умолчанию — цена выбора; её закрывает проверка разбора каждой части в быстрых тестах (R5).
  Связать `*.js.txt` с JavaScript в редакторе — выбор разработчика (с оглядкой на форматирование при сохранении).

**Alternatives considered**:
- `.js` под правилом `Text` — wrangler собирает такой файл как модуль (проверено в файле шага), склейка невозможна.
- Все части `.html` — без правки `wrangler.toml`, но HTML-форматтер редактора переформатирует «HTML» из одного скрипта,
  а подсветка показывает код текстом.
- Своё расширение (`.jspart`) с добавлением в правило `Text` — правка `wrangler.toml` и перехватчика без выигрыша.

## R2. Швы: где пустая строка

**Decision**: разрез — между объявлениями верхнего уровня, по заголовкам разделов из файла шага; пустая строка перед
заголовком раздела — **первая строка следующей части**. Каждая часть кончается непустой строкой и ровно одним `\n`.

| № | Строки | Строк | Байт |
|---|---|---|---|
| 1 | 1–25 | 25 | 1 076 |
| 2 | 26–216 | 191 | 9 185 |
| 3 | 217–512 | 296 | 19 602 |
| 4 | 513–778 | 266 | 17 621 |
| 5 | 779–1433 | 655 | 50 901 |
| 6 | 1434–1544 | 111 | 9 863 |
| 7 | 1545–1838 | 294 | 17 254 |
| 8 | 1839–1872 | 34 | 1 560 |

Сумма — 1872 строки, 127 062 байта.

**Rationale**: пустая последняя строка файла — «лишний перевод строки в конце»: `git diff --check` отмечает её
(`blank-at-eof` входит в `core.whitespace` по умолчанию), редакторы с обрезкой лишних переводов строк в конце удалят её
при сохранении — и склейка тихо потеряет строку. Пустую первую строку не трогают ни git, ни редакторы. Границы областей
те же, что в файле шага: сдвигается только пустая строка.

**Alternatives considered**:
- Пустая строка в конце части (как в таблице файла шага) — отвергнуто по причинам выше.
- Части без пустой строки, склейка через `join('\n')` — склейка перестаёт быть простой конкатенацией, правило «между
  частями одна пустая строка» надо помнить и проверять.

## R3. Модуль сборки страницы

**Decision**: `src/app-page.js` — восемь статических импортов по порядку, `export const APP_PARTS` — массив `[имя файла,
текст]` в том же порядке, `export default` — `APP_PARTS.map(…).join('')`. `src/index.js:3` импортирует склейку оттуда
(`import APP_HTML from './app-page.js'`); вставка стилей (`src/index.js:16`) — та же замена через функцию.

**Rationale**: порядок задан в одном месте, и его же берут тесты (FR-2109); склейка — один раз при загрузке модуля, как
и вставка стилей, на CPU вызова не влияет (восемь строк общей длиной 127 КБ). `APP_PARTS` с именами файлов нужен тестам
(список и сообщения с номером строки в части); Worker им не пользуется.

**Alternatives considered**:
- Импорт частей прямо в `src/index.js` — точка входа разрастается, тестам пришлось бы повторять список.
- Шаблон с плейсхолдерами частей — лишняя замена; в скрипте 54 строки с `${`, замену пришлось бы задавать функцией.
- Импорт по маске (`import.meta.glob`) — без сборщика его нет.

## R4. Тесты получают склейку

**Decision**: `tests/support/app-source.mjs` — регистрирует перехватчик (`text-hooks.mjs`), динамически импортирует
`src/app-page.js` и отдаёт `APP` (склейка), `PARTS` (имя, текст, первая строка в склейке) и `where(line)` →
`src/app/<часть>:<строка в части>`. Тесты импортируют его статически: сам он файлов `.html` статически не импортирует.

- `tests/design-system.test.mjs`: `const app = APP` вместо чтения `src/app.html`; проверки те же, в текстах сообщений
  «app.html» → «приложение».
- `tests/wording.test.mjs`: файлы `src/*.js` (теперь и `src/app-page.js`) + склейка как один текст; проверка «эвент» и
  «＋» идёт по склейке, номер строки переводится в часть через `where`.
- `tests/world.test.mjs` («`/app`: страница приложения со встроенной дизайн-системой»): эталон — `APP` со вставленными
  стилями.

**Rationale**: если оставить чтение `src/app.html`, тесты упадут (файла нет), а чтение каждой части отдельно молча
ослабит проверки: регулярки `openSheet`/`closeSheet`, `closeOnReset`, «ровно два `ds-root--locked`», «один `type:
'date'`», «только плейсхолдер в `<style>`» написаны для всего текста. Динамический импорт — тот же приём, что в
`tests/support/world.mjs`: статический загрузил бы части раньше, чем зарегистрирован перехватчик.

**Alternatives considered**: список файлов частей в каждом тесте — порядок в двух местах (запрещено файлом шага);
чтение папки `src/app/` по алфавиту — тест не заметил бы расхождения со сборкой Worker.

## R5. Тест частей

**Decision**: новый `tests/app-parts.test.mjs` (в скрипт `test` в `package.json`). Проверки — чистые функции, у каждой
есть проверка «от противного» на искусственных данных (как статическая проверка SQL в `tests/claims.test.mjs`):

1. **Список**: имена в `APP_PARTS` = файлы папки `src/app/` по возрастанию, каждый ровно один раз; имя — `NN-слово.html`
   или `NN-слово.js.txt`, номера подряд с `01`; текст из сборки = файл на диске.
2. **Формат части**: без `\r`, без BOM, не пустая, кончается `\n`, но не `\n\n`.
3. **Разбор**: каждая часть `.js.txt` разбирается как тело функции (`new vm.Script('(function () {\n' + text + '\n})')`
   — только компиляция, без исполнения): разрез прошёл между объявлениями верхнего уровня. Встроенный скрипт склейки
   разбирается целиком.
4. **Один скрипт**: в склейке один внешний `<script src=…>` (SDK Telegram) и один встроенный `<script>`, один
   `'use strict'`; склейка начинается с `<!doctype html>` и кончается `  start();\n})();\n</script>\n</body>\n</html>\n` —
   `start()` последний оператор обёртки.

**Rationale**: части `.js.txt` редактор не проверяет как код, а ошибку порядка в одном месте молча проглотил бы
`try/catch` в `syncBack` — значит, проверять должны быстрые тесты. Компиляция без исполнения не требует DOM и стоит
миллисекунды.

**Alternatives considered**: исполнение скрипта в поддельном DOM — зависимость или сотни строк заглушек, а
исполнение и так проверяют скриншоты; проверка SHA-256 склейки в постоянном тесте — запретила бы любую правку
интерфейса (сумма — однократная приёмка, quickstart).

## R6. Проверка «от противного» для дизайн-системы и слов

**Decision**: вручную при реализации: временно `style=` в части 5 → падает тест дизайн-системы; «эвент» в строке текста
части 5 → падает тест слов с `src/app/05-…:<строка>`; «＋» в `ui.btn` части 4 → падает тест «＋». Правки откатываются;
шаги — в quickstart.

**Rationale**: сами проверки не меняются (меняется источник текста); постоянные искусственные примеры для них не
добавляют уверенности сверх ручной проверки один раз.

## R7. Страница настоящего Worker и сборка для выката

**Decision**: страница снимается через `tests/harness.mjs` (`startWorld` — `wrangler dev` с миграциями и секретами во
временной папке) скриптом из quickstart, до разреза (снято: 153 719 байт, `b4ab9c8f…`) и после. Сборка для выката —
`npx wrangler deploy --dry-run --outdir <временная папка>`: в ней восемь текстовых модулей частей, каждый побайтно равен
файлу части.

**Rationale**: `npm run dev` без `.dev.vars` отвечает 500 («Не задан секрет BOT_TOKEN»), а без применённых миграций —
500 о схеме; харнесс e2e делает и то и другое во временной папке и не трогает локальную базу разработчика. Это тот же
`wrangler dev` и тот же Worker, что в файле шага. Перехватчик тестов и правило `Text` wrangler — разные механизмы, поэтому
сборка проверяется отдельно.

## R8. Скриншоты

**Decision**: сравнение попиксельное (сравнитель PNG на `node:zlib`, без зависимостей — quickstart). Критерий: 8
снимков, попиксельно одинаковых в двух прогонах на `main` (`00-home`, `00-home-dark`, `01-my-letter-empty`,
`12-danger-zone`, `13-new-event`, `16-home-participant`, `19-vault-gate`, `28-force-cancel`), после разреза попиксельно
равны снимкам «до»; у остальных 30 отличия того же рода, что между двумя прогонами «до» (время в тексте, случайная
жеребьёвка — другой подопечный, другая высота экрана); проверки цветов и прокрутки шторки в самом скрипте — зелёные.

**Rationale**: два прогона на одном коде дали 30 из 38 разных PNG — побайтное сравнение ничего не говорит; при
побайтно равной странице отличия могут идти только от данных и времени, а стабильные снимки это подтверждают.

## R9. Документы

**Decision**: `CLAUDE.md` — строка фичи 021, структура (`src/app/` — части по областям, `src/app-page.js` — порядок и
склейка, правила частей), жёсткое правило 2 («в частях приложения (`src/app/`)»), тесты (`app-parts`, `app-source`);
`design-system/README.md` — где назван файл приложения; `README.md` — структура папок и строка о проверке частей в
списке `npm test`; комментарии `tests/support/text-hooks.mjs` и `tests/support/world.mjs`; план рефакторинга — статус
шага 6; `baseline.md` — строка `npm test` после шага 6 и строка e2e; память проекта. Спецификации прошлых фич не
правятся (история). Конституция не меняется: принцип IV называет тест, а не файл.

## R10. Что не входит

- Недочёты интерфейса из файла шага (`busy(null, …)`, перерисовка после параметров, `state.evId`, заголовок шторки,
  опрос, `closeSheet`/`render`, `state.announcements`, `confirmBox`, копии блоков) — отдельная фича.
- `Content-Security-Policy` для `/app` — решение владельца (план, «Решения владельца»).
- `.editorconfig`, форматтер, настройки редактора — не добавляются (файл шага).
