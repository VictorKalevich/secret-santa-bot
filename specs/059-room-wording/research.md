# Research: «Комната» вместо «компании» (059)

## R1. Падежи и согласование

**Decision**: «компания» → «комната» в той же форме: им. «комната» / «комнаты», род. «комнаты» / «комнат», дат.
«комнате» / «комнатам», вин. «комнату» / «комнаты», твор. «комнатой» / «комнатами», предл. «в комнате» / «в комнатах».
Совпадающая форма «компании» (род., дат., предл. ед.; им., вин. мн.) разбирается по месту: «владелец компании» →
«владелец комнаты», «в компании есть события» → «в комнате есть события», «удалять компании» → «удалять комнаты».
Оба слова женского рода — «её», «свою», «новая», «основная», «создана», «удалена» не меняются.

**Rationale**: смысл и грамматика каждого предложения прежние, меняется одно слово; список целиком — `contracts/texts.md`.

**Alternatives considered**: механическая замена «компани» → «комнат» — неверна («в компании» → «в комнати»,
«компанию» → «комнатю»).

## R2. Значок кнопки

**Decision**: 🏢 → 🚪 в трёх местах: кнопка «🚪 Создать комнату», всплывающее «🚪 Комната создана», запись журнала бота
«🚪 Создана комната».

**Rationale**: 🏢 — «офисное здание», значок делового слова «компания»; при «комнате» он противоречит смыслу. 🚪 — дверь в
комнату, на всех платформах Telegram отображается. Владелец просил «Создать комнату» — значок не обсуждался, поэтому
решение записано в Assumptions спецификации и в отчёте.

**Alternatives considered**: оставить 🏢 (меньше правок, но деловой оттенок остаётся); 🏠 «дом» (это скорее «семья»,
а слово «семья» в боте занято — 008).

## R3. «Компания» в значении «круг людей»

**Decision**: два текста переписываются без слова:
- подсказка «Из какого события пригласить» (`06-admin`): «…например, ту же компанию на следующий год.» →
  «…например, тех же людей на следующий год.»;
- краткое описание бота (`/setup`, `setMyShortDescription`): «🎄 Тайный Санта для своей компании» → «🎄 Тайный Санта
  для друзей, семьи и коллег».

В README то же: «в своей компании» → «с друзьями, семьёй или коллегами», «для компании до ~40 человек» → «для группы до
~40 человек», «Пригласить ту же компанию» → «Пригласить тех же людей».

**Rationale**: «ту же комнату на следующий год» и «для своей комнаты» — бессмыслица или другой смысл; оставить
«компанию» — слово, от которого владелец уходит, осталось бы на виду рядом с «комнатой».

**Alternatives considered**: оставить прежние тексты (тест слов пришлось бы учить исключениям, людям — два слова для
разного).

## R4. Проверка слов

**Decision**: в `tests/wording.test.mjs` — тест «в текстах для людей — «комната», а не «компания» (059)»: те же
источники (`src/*.js` и склейка приложения), те же `stripComments`; строка с «компани» (без учёта регистра) — нарушение,
кроме строк с `new Error(` (сообщения исключений идут в журнал Worker, людям API отвечает «Ошибка сервера…», бот —
молчит). «От противного»: строка `ui.hint('Название компании')` в части приложения и `return no('Компания …')` в модуле
дают по нарушению с местом; `throw new Error('… компании')` — нет.

Места «владелец бота» (`BOT_OWNER_ALWAYS`, 051) — по новым текстам («эту комнату и так ведёшь ты», «Комнату снова ведёт
владелец бота», «Владелец бота удалил комнату»).

**Rationale**: тот же подход, что у «эвента» (013): правило на весь код текстов, место — файл или часть и строка.

**Alternatives considered**: искать только в строковых литералах (разбор JS ради одного правила — сложнее, а
комментарии и так вырезаются); переименовать и три сообщения исключений (это текст для разработчика, внутренний термин
— «компания»).

## R5. Правило 051 «слово видят только …»

**Decision**: в `tests/app-companies.test.mjs` правило «слово «компания» — только в части 04-companies и в разрешённых
местах» (FR-5127) проверяет слово «комнат…»; разрешённые места — те же по смыслу: плашка гостя (два куска), 👑 владельца
бота, записи журнала бота. Подсказка «ту же компанию на следующий год» из списка уходит (R3). Добавочно: «компани» в
склейке вне комментариев — 0 (сверх R4, чтобы правило 051 не прошло на старом слове).

**Rationale**: смысл правила 051 — человек с одной компанией не видит понятия «компания»; теперь понятие называется
«комната».

## R6. Эталон отказов

**Decision**: в `tests/fixtures/api-refusals.json` точечно меняются тексты восьми отказов (коды и ключи прежние), список —
в заголовке `tests/api-refusals.test.mjs` (как 025, 034):
«Компания не найдена.» → «Комната не найдена.»; «Выбери компанию.» → «Выбери комнату.»; «Название компании — от 1 до 40
символов.» → «Название комнаты — от 1 до 40 символов.»; «Компания с таким названием только что создана.» → «Комната с
таким названием только что создана.»; «В компании есть события — сначала удали их.» → «В комнате есть события — сначала
удали их.»; «Вести можно не больше двух своих компаний — передай или удали одну из них.» → «… своих комнат …»;
«Удалить компанию может только владелец бота.» → «Удалить комнату может только владелец бота.»; «Удалить компанию может
только её владелец.» → «Удалить комнату может только её владелец.» Остальные ответы — побайтно прежние.

**Rationale**: эталон не пересоздаётся (019); в файле меняются только эти восемь строк (53 ответа), остальное тест
по-прежнему сверяет побайтно.

## R7. Документы

**Decision**: README — тексты для владельца и людей: возможности, роли, раздел «Компании» → «Комнаты» (якорь
`#комнаты`, ссылки на него), открытый бот, частые вопросы, обновление бота — «комната»; имена файлов (`0015_companies.sql`,
`companies-reconcile.sql`), действий и полей — прежние. `docs/api.md` — контракт для разработки: прозой остаётся внутренний
термин «компания», цитаты текстов для людей («…») — новые, в начале раздела о компаниях — строка «в текстах для людей —
«комната» (059)». `CLAUDE.md` — строка 059 в таблице фич, правило 3 «Слова» и правило 10 (слово «комната»).
Конституция, спецификации 050–058, комментарии — без изменений (история и внутренний термин).

**Rationale**: README читают владелец и люди, ему нужны те же слова, что на экране; `docs/api.md` сверяется с кодом
(тест `api-doc` — имена действий и кодов), его проза — для разработки.
