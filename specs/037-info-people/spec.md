# Feature Specification: Список участников на «Инфо»

**Feature Branch**: `037-info-people`

**Created**: 2026-11-17

**Status**: Реализовано (2026-11-17; задачи — `tasks.md`, все выполнены)

**Input**: User description: "Список участников на «Инфо» (037). Под «О событии» — раздел «Участники · N»: строки в одну
линию в оформлении списка панели (имя, «(ты)», метка 👑 владелец / 🛠 организатор), только зарегистрированные, по
алфавиту, больше 8 — свёрнуто с «Показать всех (N)». Над списком — общий прогресс без имён: до жеребьёвки «Письма
написали X из N», после — «Подарки готовы: X из N · получено: Y из N». Параметр события «Участники могут писать друг
другу» (флажок в «Параметрах», по умолчанию выключен, копируется из образца): включён — в списке @username, нажатие на
имя с @username (не своё) спрашивает «Открыть чат с <имя> в Telegram?» и открывает чат; выключен — без @username (сервер
их не отдаёт), имена не нажимаются. В «О событии» — строка «Организаторы» (имена всех организаторов бота) и до
жеребьёвки «Автожеребьёвка» (дата или «не установлена»); строка «Участников» уходит (число — в заголовке списка).
«Пригласить друга» — у участника, пока регистрация открыта и событие идёт: кнопка пересылки ссылки-приглашения в чат
Telegram (при вступлении по одобрению — подсказка, что организатор подтвердит заявку). Нельзя показывать отметки по людям
(письмо, подарок готов, открыл, получил), адреса, семьи, исключения, пары."

Решения владельца (2026-11-17, после предложения): @username и чат — по переключателю организатора в настройках события,
с вопросом перед открытием чата; общий прогресс — нужен; строки «Организаторы» и «Автожеребьёвка» («не установлена», если
не назначена) — да; «Пригласить друга» — да; длинный список — сворачивать.

## Контекст

Сейчас участник на «Инфо» видит только число участников. Кто ещё играет, знают лишь организаторы (панель «Админ»: имя,
@username, отметки по каждому, действия «⋯»). Владельцу нравится вид списка панели, но участнику из него нужно только
«кто»: отметки по людям и действия — организаторские, а часть отметок (подарок готов, открыл подопечного) по времени
изменения выдала бы пары.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Участник видит, кто играет (Priority: P1)

Вера открывает событие → «Инфо». Под «О событии» — «Участники · 7»: Аня, Боря 🛠 организатор, Вера (ты), Гена, Дима
👑 владелец… — по строке на человека, как в списке организатора, но без отметок и без кнопок. Над списком — «Письма
написали 5 из 7». После жеребьёвки там же — «🎁 Подарки готовы: 4 из 7 · 📦 получено: 1 из 7». В «О событии» — строка
«Организаторы: Дима, Боря» и, пока жеребьёвки нет, «Автожеребьёвка: 15 декабря» (или «не установлена»).

**Why this priority**: основная просьба — участникам видно, кто в событии, в привычном оформлении.

**Independent Test**: участник события с несколькими людьми открывает «Инфо» — список по алфавиту, своя строка с «(ты)»,
метки организаторов, общий прогресс; ни одной отметки по людям.

**Acceptance Scenarios**:

1. **Given** событие с 7 зарегистрированными участниками и одним, кто ещё вводит имя, **When** участник открывает «Инфо»,
   **Then** раздел «Участники · 7» под «О событии», 7 строк по алфавиту (кто вводит имя — не показан), у своей — «(ты)», у
   владельца бота — «👑 владелец», у остальных организаторов — «🛠 организатор»; строки «Участников» в «О событии» нет.
2. **Given** жеребьёвки нет и 5 из 7 написали письмо, **When** участник открывает «Инфо», **Then** над списком «Письма
   написали 5 из 7».
3. **Given** жеребьёвка проведена: 6 человек в парах, 4 Санты отметили «подарок готов», 1 подопечный — «получил»,
   **When** участник открывает «Инфо», **Then** над списком «🎁 Подарки готовы: 4 из 6 · 📦 получено: 1 из 6».
4. **Given** в боте организаторы Дима (владелец) и Боря, **When** участник открывает «Инфо», **Then** в «О событии»
   строка «Организаторы: Дима, Боря» (владелец первым, остальные по алфавиту).
5. **Given** жеребьёвки нет, автожеребьёвка назначена на 15 декабря, **When** участник открывает «Инфо», **Then** строка
   «Автожеребьёвка: 15 декабря»; не назначена — «Автожеребьёвка: не установлена»; после жеребьёвки строки нет.
6. **Given** 12 участников, **When** участник открывает «Инфо», **Then** видны первые 8 строк и «Показать всех (12)»;
   нажатие показывает все 12.
7. **Given** любое событие, **When** участник получает данные «Инфо», **Then** в них нет отметок по людям (письмо,
   подарок готов, открыл, получил, адрес), семей, исключений и пар — только имена, роли и общие числа.

### User Story 2 — Организатор разрешает участникам писать друг другу (Priority: P1)

Организатор в «Параметрах» включает «Участники могут писать друг другу» и сохраняет. Теперь у участников в списке рядом с
именем — @username, а нажатие на имя (с @username, не своё) спрашивает «Открыть чат с Аня в Telegram?»; «Да» — открывается
чат с ней в Telegram. Выключено (по умолчанию) — @username не видны и в данных не приходят, имена не нажимаются.

**Why this priority**: владелец хочет, чтобы прямые контакты участников зависели от решения организатора.

**Independent Test**: включить и выключить параметр — список у участника с @username и без; нажатие на имя — вопрос и
открытие чата.

**Acceptance Scenarios**:

1. **Given** параметр выключен, **When** участник открывает «Инфо», **Then** строки без @username, нажатие на имя ничего
   не делает, а в данных «Инфо» нет ни одного @username.
2. **Given** параметр включён, **When** участник открывает «Инфо», **Then** у людей с @username он показан серым после
   имени, а их строки (кроме своей) нажимаются.
3. **Given** параметр включён, **When** участник нажимает строку Ани (@anya), **Then** вопрос «Открыть чат с Аня в
   Telegram?»; «Да» — открывается чат с @anya; «Нет» — ничего.
4. **Given** человек без @username, **When** параметр включён, **Then** его строка не нажимается (написать ему через
   Telegram нельзя).
5. **Given** новое событие по образцу с включённым параметром, **When** оно создано, **Then** параметр включён и в нём;
   полный сброс события возвращает его к «выключено».

### User Story 3 — Участник зовёт друга (Priority: P2)

Пока регистрация открыта и событие идёт, под списком у участника — «📨 Пригласить друга»: кнопка открывает выбор чата
Telegram с готовым сообщением и ссылкой-приглашением события. Если вступление по одобрению — подсказка, что организатор
подтвердит заявку.

**Why this priority**: удобно, но не главное; владелец решил дать участникам звать людей самим.

**Independent Test**: регистрация открыта — кнопка есть и пересылает ссылку события; закрыта или событие завершено —
кнопки нет и ссылки в данных нет.

**Acceptance Scenarios**:

1. **Given** регистрация открыта, событие идёт, **When** участник открывает «Инфо», **Then** под списком подсказка «Позови
   друга — по ссылке он сразу вступит в событие.» и кнопка «📨 Пригласить друга»; нажатие — выбор чата Telegram с текстом
   «🎄 Играем в Тайного Санту — «<название>»! Заходи по ссылке:» и ссылкой события (то же, что «📤 Отправить в чат» у
   организатора).
2. **Given** вступление по одобрению, **When** участник открывает «Инфо», **Then** подсказка «Позови друга — он отправит
   заявку, организатор её подтвердит.»
3. **Given** регистрация закрыта или событие завершено, **When** участник открывает «Инфо», **Then** ни подсказки, ни
   кнопки, ссылки в данных нет.

---

### Edge Cases

- В событии нет ни одного зарегистрированного участника (организатор смотрит «Инфо» до вступлений): «Участники · 0» и
  строка «Пока никого нет».
- Ровно 8 участников — список целиком, без «Показать всех»; 9 и больше — свёрнут. Раскрытый список остаётся раскрытым,
  пока человек в этом событии (обновления экрана не сворачивают его).
- Организатор, который не участвует, в списке не показан — только в строке «Организаторы». Организатор-участник — в
  списке с меткой и в строке «Организаторы».
- Свою строку нажать нельзя, даже если @username есть.
- Параметр выключили, пока у участника открыт экран: при следующей загрузке «Инфо» @username пропадают.
- Организатор, который не участвует, видит «Инфо» как участник (список, прогресс, приглашение) — это и есть «как увидят
  участники».
- Завершённое событие: список и итог по подаркам остаются (история), приглашения и автожеребьёвки нет.
- Порядок строк не зависит от пар, времени вступления и отметок — только имя (при равных — по внутреннему номеру).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: «Инфо» MUST показывать под «О событии» раздел «Участники · N» со строкой на каждого зарегистрированного
  участника события по алфавиту: имя, «(ты)» у своей, метка «👑 владелец» у владельца бота и «🛠 организатор» у остальных
  организаторов; строка в одну линию, оформление — как у списка участников в панели организатора.
- **FR-002**: Больше 8 строк — MUST показываться первые 8 и «Показать всех (N)»; раскрытие держится до ухода из события.
- **FR-003**: Над списком MUST быть общий прогресс: до жеребьёвки «Письма написали X из N» (N — зарегистрированные
  участники), после — «🎁 Подарки готовы: X из N · 📦 получено: Y из N» (N — участники жеребьёвки).
- **FR-004**: Данные «Инфо» MUST NOT содержать отметок по людям (письмо, подарок готов, открыл подопечного, получил),
  адресов, семей, исключений, закреплённых пар и пар; общие числа — только суммы.
- **FR-005**: У события MUST быть параметр «Участники могут писать друг другу»: по умолчанию выключен, меняет организатор
  в «Параметрах» (сохранение — как у остальных параметров, с записью «параметры» в журнал), копируется из образца, полный
  сброс возвращает умолчание.
- **FR-006**: При выключенном параметре данные «Инфо» MUST NOT содержать @username участников и организаторов; при
  включённом — содержат у тех, у кого он есть.
- **FR-007**: При включённом параметре нажатие на строку участника с @username (кроме своей) MUST спрашивать «Открыть чат
  с <имя> в Telegram?» и по согласию открывать чат с ним в Telegram; без @username или при выключенном параметре строка не
  нажимается.
- **FR-008**: «О событии» MUST содержать строку «Организаторы» (имена всех организаторов бота: владелец первым, остальные
  по алфавиту) и, пока жеребьёвка не проведена и событие идёт, «Автожеребьёвка» — дату или «не установлена»; строка
  «Участников» убирается.
- **FR-009**: Пока регистрация открыта и событие идёт, под списком MUST быть подсказка и «📨 Пригласить друга» —
  пересылка ссылки-приглашения в чат Telegram с тем же текстом, что у организатора; при вступлении по одобрению —
  подсказка про заявку. Иначе ссылки в данных «Инфо» нет.
- **FR-010**: Вступление по ссылке от участника MUST идти по прежним правилам (закрытая регистрация, одобрение, запрет
  возврата удалённых — без изменений).
- **FR-011**: README MUST описывать список, прогресс, приглашение друга и параметр; описание API — новые поля ответа
  события и параметр.

### Key Entities

- **Строка списка**: имя, роль (владелец / организатор / участник), @username — только при включённом параметре.
- **Прогресс события**: до жеребьёвки — сколько написали письмо из скольких; после — сколько подарков готово и получено из
  числа участников жеребьёвки.
- **Параметр события «Участники могут писать друг другу»**: да/нет, по умолчанию нет.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Участник видит состав события на «Инфо» за одно открытие вкладки, без обращения к организатору.
- **SC-002**: Список из 30 человек занимает на экране не больше 8 строк, пока его не раскроют.
- **SC-003**: При выключенном параметре ни один ответ, который видит участник, не содержит @username других людей; при
  перестановке пар данные «Инфо» не меняются ни в одном байте.
- **SC-004**: Включение параметра организатором меняет вид списка у участника при следующем открытии «Инфо» — без других
  действий.

## Assumptions

- «Организаторы» — все администраторы бота и владелец (права в боте общие, не по событию), а не только те, кто открывал
  это событие.
- Чат открывается средствами Telegram по @username; у человека без @username такой ссылки нет.
- Ссылка-приглашение у участника — та же ссылка события, что у организатора; «🔄 Новая ссылка» организатора делает
  прежнюю недействительной и у участников.
- Число «получено» и «готово» считается по парам текущей жеребьёвки; вписанный после неё (012) входит в N.
- Тайна (Конституция I): общие суммы пар не раскрывают — перестановка пар их не меняет; отметки по людям не отдаются.
