# Research: 049. «Не открыл подопечного» при обмене — отметка в шторке и без сообщения

## R1. Откуда брать признак в шторке

- **Decision**: поле `ward_seen` пользователя из ответа `admin.state` (`src/panel.js`): `false` — Санта не открыл
  подопечного, `true` — открыл, `null` — не в жеребьёвке (в шторке таких нет: список — только `in_draw`).
- **Rationale**: тот же признак, что у метки «👀 не открыл подопечного» в «Участниках» (`adminMembers`) — FR-03; шторка
  получает пользователей из объекта панели `p.players`, новых запросов нет.
- **Alternatives considered**: новое поле в ответе `admin.draw.swap.check` — лишний запрос и правка API ради уже
  имеющихся данных; отвергнуто.

## R2. Вид метки

- **Decision**: `ui.chip('👀 не открыл подопечного', 'warning')` в `ds-chips` под именем (как строка «Участников»:
  имя, ниже метки); строка списка остаётся `label.ds-list-item.ds-check` с флажком — нажатие по метке тоже отмечает
  флажок.
- **Rationale**: тот же вид и текст, что в «Участниках» (FR-01); существующие компоненты дизайн-системы (принцип IV).
- **Alternatives considered**: значок 👀 без текста — короче, но не совпадает с «Участниками»; отвергнуто.

## R3. Метка после обмена

- **Decision**: после успешного `admin.draw.swap` у двоих выбранных `ward_seen = false`, их строки перерисовываются в
  открытой шторке; при отказе ничего не меняется. Панель под шторкой обновляется тихо (`p.again({ quiet: true })`, 048).
- **Rationale**: новые пары создаются с пустым `seen_text` (048), значит оба Санты точно не открыли новых подопечных;
  правило известно без запроса (FR-04).
- **Alternatives considered**: перечитать `admin.state` и перестроить шторку — лишний запрос; отвергнуто.

## R4. Сообщение о смене — только открывшему (строгое правило владельца)

- **Decision**: `swapWards` сам ставит сообщение каждому из двух Сант в пакет `atomic` сразу после оператора версии
  пар и до удаления прежних пар — через `change.and('EXISTS (SELECT 1 FROM pairs WHERE event_id = ? AND santa = ? AND
  ward = ? AND seen_text IS NOT NULL)', …).enqueue(…)`. `applyPairsChange` вызывается с пустым списком `changed` (своих
  сообщений не ставит); параметр `text`, добавленный в 048 только для обмена, убирается.
- **Rationale**: условие проверяется в момент записи в том же неделимом пакете (FR-06): Санта, открывший подопечного
  между проверкой и записью, получит сообщение, не открывший к записи — нет; при проигрыше спора (версия пар) условие
  захвата ложно — сообщений нет. Признак тот же, что у отметки (`seen_text IS NOT NULL` ↔ `ward_seen`). Операторов в
  пакете столько же — лимиты прежние.
- **Alternatives considered**: решать по `d.rows`, прочитанным до записи, — не строго (между чтением и записью Санта
  мог открыть подопечного); отвергнуто. Флаг «писать только открывшим» в `applyPairsChange` — сообщения ставятся там
  после удаления прежних пар, условие по ним уже не проверить; отвергнуто.

## R5. Тексты шторки

- **Decision**: окно подтверждения — «Поменять подопечных у «А» и «Б»? Тем, кто уже открыл подопечного, бот напишет,
  что он сменился. Отметки подарка, маски и переписка этих двух пар начнутся заново.»; строка плашки нарушений — «Если
  поменять, тем, кто уже открыл подопечного, бот напишет, что он сменился. Отметки подарка, маски и переписка этих двух
  пар начнутся заново.»
- **Rationale**: текст верен при любом состоянии (шторка могла устареть); кто именно не открыл, видно по меткам рядом
  с именами (US1). Длина окна с двумя именами предельной длины проверяется тестом `app-ui` (`CONFIRM_MAX`).
- **Alternatives considered**: текст под конкретную пару («бот напишет только А») — по данным шторки, которые могли
  устареть; отвергнуто.
