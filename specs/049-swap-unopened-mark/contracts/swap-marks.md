# Контракт: «не открыл подопечного» при обмене (049)

Дополняет обмен подопечных (`specs/048-owner-ward-swap/contracts/draw-swap.md`). Действия API, их ответы, отказы и
журнал — без изменений.

## Сервер: сообщения при обмене

- Сообщение «🔄 Владелец изменил жеребьёвку события «<название>»: у тебя теперь новый подопечный…» с кнопкой «🎁
  Посмотреть» получает каждый из двух Сант (`a`, `b`) **только если его прежняя пара открыта** — `seen_text IS NOT NULL`
  у строки `pairs (event_id, santa = он, ward = прежний подопечный)` в момент записи обмена.
- Санта, не открывший прежнего подопечного, не получает никакого сообщения об обмене (строгое правило владельца).
- Устройство (`swapWards`, `src/pairs.js`): в пакете `atomic` — оператор версии пар (захват), затем для каждого из
  двоих `change.and('EXISTS (SELECT 1 FROM pairs WHERE event_id = ? AND santa = ? AND ward = ? AND seen_text IS NOT
  NULL)', …).enqueue(…)`, затем удаления и вставки пар (`applyPairsChange` с пустым `changed`), журнал. Проигравший
  спор пакет не ставит ничего.
- Вписывание и удаление участника (012) не меняются: они пишут каждому Санте со сменившимся подопечным.

## Приложение: шторка «🔀 Управление жеребьёвкой»

- Строка — `label.ds-list-item.ds-check`: флажок, затем блок `ds-grow` — имя (и « (ты)» у себя), под ним `ds-chips` с
  меткой `ui.chip('👀 не открыл подопечного', 'warning')`, если `u.ward_seen === false`. У `ward_seen === true` блока
  меток нет; других меток в шторке нет. Источник — `p.players` (`admin.state`); порядок — по имени.
- Успешный `admin.draw.swap`: у двоих `ward_seen = false`, их метки перерисовываются в той же шторке; отказ — без
  изменений; повторное открытие — данные свежей панели.
- Окно подтверждения: «Поменять подопечных у «А» и «Б»? Тем, кто уже открыл подопечного, бот напишет, что он сменился.
  Отметки подарка, маски и переписка этих двух пар начнутся заново.» (≤ 250 символов — тест `app-ui`).
- Плашка нарушений, строка последствий: «Если поменять, тем, кто уже открыл подопечного, бот напишет, что он сменился.
  Отметки подарка, маски и переписка этих двух пар начнутся заново.»

## Проверки

- `tests/swap.test.mjs`: оба открыли — по сообщению; один — только ему; никто — ни одного (обмен и журнал есть);
  Санта открыл подопечного прямо перед записью (`beforeWrite`) — сообщение есть; по склейке — метка по
  `ward_seen === false` тем же текстом, что в `adminMembers`, после успеха `ward_seen` двоих — `false`, тексты без
  «обоим».
- `tests/atomic.test.mjs`: обмен ×2 в одну миллисекунду, оба открыли — по одному сообщению.
- Chrome (`checkSwap`): метки совпадают с сервером при открытии; после обмена открывшего и не открывшего — метка у обоих;
  сообщение — только открывшему.
