# Research: 011 — правки мини-приложения

## R1. Почему раскрытый список белый с белым текстом

- **Причина**: у `<select class="ds-input">` цвет текста наследуется из темы Telegram (в тёмной — светлый), фон поля —
  полупрозрачный `--ds-color-fill`. Раскрытый список рисует сам браузер/WebView по `color-scheme` страницы; страница
  схему не объявляла (`normal` = светлая), поэтому список белый, а пункты наследуют светлый цвет текста. Видна только
  подсвеченная строка под курсором. Та же схема у календаря `type=date`, флажков и полос прокрутки.
- **Decision**: объявить схему страницы по теме Telegram и задать цвета пунктов явно.
  - Токен `--ds-color-scheme: var(--tg-color-scheme, light dark)`. `telegram-web-app.js` выставляет
    `--tg-color-scheme` (`light`/`dark`) на `<html>` при старте и при смене темы (проверено в исходнике SDK:
    `setCssProperty('color-scheme', colorScheme)`). Без Telegram — `light dark`: браузер следует системной теме.
  - `:where(:root, .ds-theme) { color-scheme: var(--ds-color-scheme); }` — корень (полосы прокрутки страницы, все
    элементы наследуют) и области `.ds-theme` (тёмная колонка витрины).
  - `:where(.ds-root) :where(option, optgroup) { background-color: var(--ds-color-surface); color: var(--ds-color-text); }`
    — Chromium (Telegram Desktop на Windows, Android) применяет эти цвета к пунктам; WebView без поддержки
    (iOS — системное колесо выбора) берёт схему из `color-scheme`.
- **Rationale**: одно правило в дизайн-системе покрывает все существующие и будущие списки (FR-1106), тема Telegram
  главнее системной (крайний случай «тёмный Telegram на светлой Windows»).
- **Alternatives considered**: JS-класс темы на `<html>` по `tg.colorScheme` — лишний код и подписка на
  `themeChanged`, SDK уже даёт переменную; свой выпадающий список вместо `<select>` — много кода, хуже доступность и
  нативный выбор на телефоне; задать только цвета `option` — не чинит календарь и полосы прокрутки.

## R2. Почему колесо мыши прокручивает страницу под шторкой

- **Причина**: шторка — `position: fixed` поверх документа. Если под курсором затемнённый фон или содержимое шторки
  короче экрана/уже прокручено до края, браузер передаёт прокрутку (scroll chaining) документу.
- **Decision**:
  - Пока шторка открыта — модификатор `ds-root--locked` на `<body>`: `overflow: hidden`. Для `<body>` значение
    переносится на окно просмотра (у `<html>` `overflow: visible`), поэтому страницу нельзя прокрутить ни колесом, ни
    жестом, ни клавишами; текущая позиция прокрутки сохраняется.
  - `overscroll-behavior: contain` у `.ds-sheet` и `.ds-chat` — прокрутка, дошедшая до края шторки/ленты, не уходит
    дальше (и на телефоне не тянет страницу).
  - Ставит и снимает класс только `openSheet`/`closeSheet` — одно место для всех шторок, включая переписку и закрытие
    кодом (FR-1110). `openSheet` сначала вызывает `closeSheet`, затем сразу ставит класс — между шторками прокрутка
    не «размораживается» видимо для пользователя.
- **Rationale**: минимум кода, работает на Chromium, WebView Android и iOS 16+ (Telegram требует актуальный iOS).
- **Alternatives considered**: `preventDefault` на `wheel`/`touchmove` у фона — ломает прокрутку внутри шторки и
  требует пассивных/непассивных слушателей; `position: fixed` на `<body>` с запоминанием `scrollY` — нужен inline
  `style` (запрещён принципом IV) и восстановление позиции вручную; нативный `<dialog>` — переписать все шторки.

## R3. Сдвиг страницы при исчезновении полосы прокрутки

- **Decision**: не трогать. На Windows при `overflow: hidden` полоса прокрутки страницы скрыта, страница под
  затемнением может сдвинуться на её ширину — под затемнением это незаметно, а `scrollbar-gutter: stable` оставлял бы
  пустую полосу на коротких экранах всегда.
