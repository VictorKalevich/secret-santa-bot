# Feature Specification: Правки мини-приложения — «Как это работает», тёмная тема списков, прокрутка шторок

**Feature Branch**: `011-ui-polish`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "Блок «Как это работает» — оставить только три пункта (письмо Санте, вкладка «Подопечный»,
после завершения). Убрать пункты про то, что организатор может открыть письмо и что владелец может открыть пары;
честное раскрытие — в README (поправка конституции 2.1.0). Выпадающие списки в тёмной теме: раскрытый список белый и
текст белый, виден только при наведении («Кто дарит…» / «…кому НЕ может дарить») — исправить для светлой и тёмной темы
через дизайн-систему, проверить все такие места. Открытые шторки (например «Открыть служебный просмотр»): колесо мыши
на ПК прокручивает контент под шторкой, а не шторку — пока шторка открыта, прокручивается только она; проверить во всём
приложении."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Читаемые выпадающие списки в любой теме (Priority: P1)

Организатор в Telegram с тёмной темой открывает вкладку «Админ» и раскрывает список «Кто дарит…». Пункты списка видны
сразу: фон и текст контрастны, как и в остальном приложении. То же — в светлой теме и во всех остальных выпадающих
списках и системных элементах (выбор даты, флажки) приложения.

**Why this priority**: сейчас в тёмной теме нельзя выбрать исключение, назначить админа, перенести участие, выбрать
эвент-образец или участника в служебном просмотре, не наводя курсор на каждую строку. Это блокирует работу
организатора.

**Independent Test**: открыть приложение в тёмной теме Telegram (и в браузере с тёмной системной темой), раскрыть
каждый выпадающий список — все пункты читаются без наведения; переключить тему на светлую — то же.

**Acceptance Scenarios**:

1. **Given** тёмная тема Telegram, **When** организатор раскрывает «Кто дарит…» или «…кому НЕ может дарить», **Then**
   раскрытый список тёмный, текст пунктов светлый и читается без наведения курсора.
2. **Given** светлая тема Telegram, **When** раскрывается любой выпадающий список, **Then** список светлый, текст тёмный.
3. **Given** любая тема, **When** открывается выбор даты в «Параметрах эвента», **Then** календарь и значок календаря
   в цветах той же темы (не белый календарь в тёмном приложении).
4. **Given** приложение открыто в обычном браузере без темы Telegram, **When** раскрывается список, **Then** цвета
   следуют системной теме браузера и текст читается.

### User Story 2 - Прокрутка внутри открытой шторки (Priority: P1)

Владелец открывает «🔐 Открыть служебный просмотр» на ПК и крутит колесо мыши. Прокручивается содержимое шторки; эвент
под шторкой остаётся на месте. Так ведут себя все шторки приложения: «Новый эвент», «Семья», участник, «Имя участника»,
перенос, письмо, подтверждения со словом, журнал, переписка.

**Why this priority**: длинное содержимое шторки (журнал, служебный просмотр, переписка) нельзя дочитать колесом мыши;
страница под шторкой уезжает, и после закрытия пользователь теряет место.

**Independent Test**: открыть любую шторку с длинным содержимым на ПК, крутить колесо над шторкой и над затемнённым
фоном — прокручивается только шторка (или ничего, если её содержимое короткое); после закрытия страница там же, где была.

**Acceptance Scenarios**:

1. **Given** открыта шторка, содержимое которой выше экрана, **When** пользователь крутит колесо над шторкой, **Then**
   прокручивается шторка, страница под ней не двигается.
2. **Given** шторка прокручена до конца, **When** пользователь продолжает крутить колесо, **Then** страница под шторкой
   не начинает прокручиваться.
3. **Given** открыта короткая шторка, **When** пользователь крутит колесо над шторкой или над затемнённым фоном,
   **Then** страница под шторкой не двигается.
4. **Given** открыта переписка, **When** пользователь крутит колесо над лентой сообщений, **Then** прокручивается лента,
   а не страница.
5. **Given** шторка закрыта (✕, фон, «Назад», после действия), **When** пользователь крутит колесо, **Then** страница
   снова прокручивается как обычно и стоит на том же месте, что до открытия шторки.
6. **Given** на телефоне открыта шторка, **When** пользователь ведёт пальцем по шторке, **Then** поведение то же:
   прокручивается шторка, не страница.

### User Story 3 - Короткий блок «Как это работает» (Priority: P2)

Участник открывает вкладку «Инфо» эвента и в блоке «Как это работает» видит ровно три пункта:

1. Напиши письмо Санте — его увидит тот, кто будет дарить тебе подарок.
2. После жеребьёвки во вкладке «Подопечный» появится, кому даришь ты.
3. После завершения эвента письмо остаётся для чтения, переписка открыта ещё 7 дней. Эвент сохранится в истории.

**Why this priority**: решение владельца проекта — блок должен объяснять игру, а не возможности организаторов.

**Independent Test**: открыть вкладку «Инфо» любого эвента — в блоке ровно три пункта с указанным текстом.

**Acceptance Scenarios**:

1. **Given** любой эвент, **When** участник открывает «Инфо», **Then** «Как это работает» содержит ровно три пункта
   выше, без упоминания того, что организатор может открыть письмо и что владелец может открыть пары.
2. **Given** владелец проекта читает README, **When** ищет, кто может видеть пары и письма, **Then** README честно
   описывает открытие письма организатором и служебный просмотр владельца (с журналом) и не ссылается на «Как это
   работает» как на место, где это сказано участникам.

---

### Edge Cases

- Шторка открывается поверх другой (новая сменяет старую) — блокировка прокрутки страницы не снимается между ними и
  снимается, только когда закрыта последняя.
- Шторку закрывает не пользователь, а код (после успешного действия, при переходе на другой эвент) — прокрутка
  страницы восстанавливается так же.
- Выпадающий список внутри шторки — раскрывается и читается в обеих темах; колесо над раскрытым списком прокручивает
  сам список.
- Тема Telegram меняется при открытом приложении — цвета списков меняются вместе с темой.
- Telegram сообщает тему, а системная тема ПК другая (тёмный Telegram на светлой Windows и наоборот) — побеждает тема
  Telegram.
- Отключённые (disabled) пункты и подсказки-заглушки («Кто дарит…») — тоже читаются, но выглядят приглушённо, как
  сейчас.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-1101**: Блок «Как это работает» на вкладке «Инфо» MUST содержать ровно три пункта с текстом из User Story 3,
  в указанном порядке.
- **FR-1102**: Конституция MUST быть поправлена (2.1.0): раскрытие возможностей «организатор открывает письмо» и
  «служебный просмотр владельца» участникам обязательно в README; в приложении — не обязательно. Остальные гарантии
  принципа I (журнал каждого открытия, только владелец, статусы не меняются) не меняются.
- **FR-1103**: README MUST по-прежнему честно описывать открытие письма и служебный просмотр и MUST NOT утверждать, что
  это сказано участникам во вкладке «Инфо».
- **FR-1104**: Все системные элементы управления приложения (выпадающие списки и их раскрытые пункты, выбор даты,
  флажки, полосы прокрутки) MUST отображаться в цветовой схеме текущей темы Telegram; без темы Telegram — в схеме
  системной темы.
- **FR-1105**: Пункты раскрытого выпадающего списка MUST иметь фон и цвет текста из дизайн-системы (поверхность и
  основной текст темы), чтобы текст читался без наведения в светлой и тёмной теме.
- **FR-1106**: Исправление MUST быть сделано в дизайн-системе (токены → компоненты/базовые стили → показ в
  `preview.html` → строка в `design-system/README.md`) и действовать на все существующие и будущие выпадающие списки,
  без правок отдельных мест.
- **FR-1107**: Пока открыта шторка, страница под ней MUST NOT прокручиваться — ни колесом мыши, ни жестом, ни
  клавишами; прокручивается только содержимое шторки (или её прокручиваемая часть, например лента переписки).
- **FR-1108**: Прокрутка, дошедшая до края шторки или её ленты, MUST NOT передаваться странице под шторкой.
- **FR-1109**: После закрытия шторки любым способом страница MUST снова прокручиваться и оставаться в том же
  положении, что до открытия.
- **FR-1110**: Поведение FR-1107–FR-1109 MUST быть общим для всех шторок приложения (одно место в коде шторки и
  дизайн-системе), включая полноэкранную шторку переписки.
- **FR-1111**: Поведение сервера, API, бота и данные MUST NOT меняться.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В тёмной и светлой теме 100 % выпадающих списков приложения (6 мест: эвент-образец, назначение админа,
  эвент для приглашения, перенос участия, исключения «кто/кому», участник служебного просмотра) читаются без наведения.
- **SC-002**: Ни в одной из шторок приложения прокрутка колесом мыши не сдвигает страницу под шторкой.
- **SC-003**: После закрытия шторки положение страницы совпадает с положением до открытия.
- **SC-004**: Блок «Как это работает» содержит ровно 3 пункта.
- **SC-005**: Автотесты дизайн-системы проходят: новые стили — только из токенов, базовые стили элементов — через
  `:where()`, новое отражено в `preview.html` и README дизайн-системы.

## Assumptions

- Цвет раскрытого выпадающего списка задаёт браузер/WebView по цветовой схеме страницы; Telegram сообщает схему
  (светлая/тёмная) мини-приложению вместе с цветами темы. Если схема неизвестна (обычный браузер), берётся системная.
- «Другие места с той же проблемой» — системные элементы, которые рисует браузер: выпадающие списки, выбор даты,
  флажки, полосы прокрутки. Собственные компоненты дизайн-системы уже берут цвета темы и не меняются.
- «Диалоги» в приложении — это шторки (`openSheet`); системные окна Telegram (подтверждения `showConfirm`) рисует сам
  Telegram, их прокрутка не меняется.
- Решение убрать раскрытие из приложения принял владелец проекта (вопрос задан 2026-11-13, ответ: «убрать, поправить
  конституцию»).
- Спецификация 010 (FR-1015, сценарий 9) в части текста «Как это работает» заменяется этой спецификацией.
