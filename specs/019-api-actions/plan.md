## Summary

**Часть А — таблица и модули.** В `src/api.js` появляется экспортируемая таблица `ACTIONS` (59 строк: роль, текст отказа
владельца, нужно ли событие, что в завершённом событии, слово подтверждения, обработчик) и один конвейер проверок в
прежнем порядке (research R1–R2). Неизвестные действия проходят тот же путь через две строки-заглушки. Предметная логика
с SQL уходит в модули: правила пар (`src/constraints.js` — исключения, закреплённые пары, семьи как исключения, снимки),
участник (`src/participant.js` — письмо, адрес, подопечный, отметки подарка, экраны «мои события» и «событие»), панель
(`src/panel.js` — `admin.state`, письмо для админа, список пользователей), участие и семьи (`src/membership.js`),
параметры события (`src/events.js`), история переписки (`src/chat.js`). Простые проверки состояния события — в
`src/status.js` без импортов. Тесты прав и автотест e2e берут список из таблицы; новый эталон отказов
(`tests/fixtures/api-refusals.json`) снимается до изменений и сверяется тестом.

**Часть Б — контекст и чтения.** `src/context.js`: один контекст на вызов API, сообщения боту и запуск расписания —
`env`, `db`, `me`; `settings()`, `users()`, `ownerId()` — одно чтение на вызов, лениво; пользователь и настройки в
начале вызова — одним пакетом; `ctx.read({...})` — пакет именованных чтений (R4–R5). Функции модулей получают контекст
первым параметром. Узкие чтения: признак «пусто» считается в базе выражением, совпадающим с `trim()` JS (тест паритета;
R6). Подмена D1 в быстрых тестах считает пакет без записей чтением (барьер `together()` — перед первой записью).
Ожидаемые числа запросов — research R10: `admin.state` 15 → 4, `admin.draw` 14 → 8, `admin.remove` 16 → 8.

**Мелочи** (R9): общие тексты, помощник клавиатуры, рассылка «присоединяется», разбор `pending`, `/setup` в модуль,
недостижимая ветка, пустой набор полей, имена для журнала исключений.

## Technical Context

**Language/Version**: JavaScript ES2022, ES-модули (Workers/workerd); тесты — Node 24.21 (минимум 22.15)

**Primary Dependencies**: нет новых

**Storage**: D1 (SQLite), схема 11 без изменений; миграции не добавляются

**Testing**: `npm test` (`node:test`, «мир» `tests/support/world.mjs` на `node:sqlite`): новые `tests/api-table.test.mjs`
(таблица), `tests/api-refusals.test.mjs` (эталон отказов), паритет пустоты в `tests/unit.test.mjs`, пакет чтений в
`tests/d1-sqlite.test.mjs`; `tests/rights.test.mjs` — список из таблицы; `tests/queries.test.mjs` — пороги ниже;
`npm run test:e2e` (автотест — список из таблицы), `npm run bench:draw` до и после

**Target Platform**: Cloudflare Workers, бесплатный тариф (10 мс CPU, 50 внешних запросов на вызов)

**Project Type**: веб-сервис (Worker) + мини-приложение; фича — внутренняя перестройка API

**Performance Goals**: пороги запросов к базе из файла шага (`admin.state` ≤ 6, `admin.draw.check` ≤ 6, `admin.draw` ≤ 10,
`admin.remove` ≤ 12, `admin.insert` ≤ 11, обращения — на 2 меньше, остальные — не больше); к Telegram — то же; разбор писем
(до 1,9 мс на 200 человек, `baseline.md` раздел 6) уходит из проверки жеребьёвки и панели

**Constraints**: коды, тексты, поля ответов, порядок проверок — прежние (FR-1901–1902); условия захватов и состав пакетов
записи — прежние (FR-1903); `src/draw.js`, `src/outbox.js`, `src/budget.js` не трогаются; порядок участников жеребьёвки
(`ORDER BY m.joined_at`, план запроса тот же — R6); эталон жеребьёвки не пересоздаётся; порядок действий админа в
таблице — порядок прежних `case` (автотест e2e); тексты, отличающиеся хотя бы знаком, не объединяются; решения
владельца не входят

**Scale/Scope**: `src/api.js` (757 → ~330 строк: таблица и конвейер), новые `src/status.js`, `src/context.js`,
`src/constraints.js`, `src/participant.js`, `src/panel.js`, `src/setup.js`; сигнатуры функций `events`, `pairs`, `chat`,
`support`, `membership`, `roles`, `vault`; `bot.js`, `cron.js`, `index.js`; 3 новых тестовых файла + скрипт эталона
