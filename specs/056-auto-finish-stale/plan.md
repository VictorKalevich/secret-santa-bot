# План 056: автозавершение брошенных событий в открытом боте

**Branch**: `056-auto-finish-stale` | **Date**: 2026-11-24 | **Spec**: [spec.md](spec.md)

## Summary

В открытом боте ежедневный шаг cron раз в сутки на событие проверяет три правила владельца: А — дата вручения прошла 7
дней назад; Г — без даты, без жеребьёвки, кроме организаторов никого, 23 дня от создания; Б — без даты, 113 дней от
создания. Подходит и не предупреждено → организаторам предупреждение, отметка `events.finish_warned` (местная дата) и
запись журнала `finish.warn`. Предупреждено 7 и больше дней назад и всё ещё подходит → обычное `finishEvent` от бота. Не
подходит, а отметка стоит → отметка тихо снимается. Закрытый бот — без изменений (`openBot(env)`).

Технически:

1. Миграция `0019_finish_warned.sql`: `events.finish_warned TEXT NOT NULL DEFAULT ''`, схема 19 (`REQUIRED_SCHEMA`); в
   обе базы до выката кода — прежний код колонку не читает.
2. Новый модуль `src/stale.js`: пороги `STALE`, чистые `staleReason` / `staleStep` (по местным датам), запрос событий
   ежедневного шага `dailyEventsQuery` (тот же `SELECT` идущих событий по индексу `events_active` плюс колонка
   `outsiders` — сколько участников не организаторы; считается только у кандидатов правила Г и только в открытом боте),
   предупреждение `warnStale` (атомарно по прежнему состоянию: сообщения и журнал — перед захватом, захват —
   `UPDATE events SET finish_warned … WHERE finish_warned = ''`).
3. `src/cron.js` `dailyStep`: запрос — `dailyEventsQuery`; для события, ещё не проверенного сегодня: завершение по
   правилам → кандидат (важнее напоминания); иначе напоминание; иначе предупреждение → кандидат; иначе снятие отметки
   (пакетом вместе с `last_daily`); иначе «тихое» как раньше. Кандидаты — тот же список «одно тяжёлое действие за
   запуск».
4. `EVENT_STATE_RESET.finish_warned = ''` — полный сброс снимает отметку; образец не копирует (служебная колонка).
5. Журнал: код `finish.warn` (`docs/api.md`, подпись в `AUDIT_LABELS` приложения), `finish` — и от автозавершения.

Число запросов минутной проверки в обычную минуту — 3, как было (`queries`, `cron-reads`).
