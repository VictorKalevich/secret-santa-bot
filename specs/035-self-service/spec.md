# Feature Specification: Участник сам меняет имя и выходит из события

**Feature Branch**: `035-self-service`

**Created**: 2026-11-17

**Status**: Реализовано (2026-11-17; задачи — `tasks.md`, все выполнены)

**Input**: User description: "Самообслуживание участника (035): смена своего имени и выход из события. 1) Имя: раздел
«Профиль» на главном экране приложения (над «Уведомлениями»), только в приложении (без команды бота); правило имени как
при регистрации и admin.rename (одна строка, 1–40 символов); общий журнал `rename` только при настоящем изменении
(renameUser), админам сообщений нет. 2) Выход: кнопка внизу вкладки «Инфо» у участника идущего события; диалог с вводом
слова ВЫЙТИ (проверяет и сервер, `confirm` в ACTIONS); только до жеребьёвки — после неё вместо кнопки подсказка «выйти
можно через организатора» и кнопка «Написать организатору» (обращение); выход удаляет данные участия как выход админа
(memberDataDeleteStmts по REGISTRY), без отметки «удалён организатором» — вернуться можно по ссылке при открытой
регистрации; атомарно: одновременная жеребьёвка — отказ, двойное нажатие — одно уведомление и одна запись; уведомление
всем админам (кроме самого) со звуком и кнопкой «Открыть событие»; журнал события `member.leave`."

Решения владельца (2026-11-17, после разбора): после жеребьёвки — вариант A (сам не выходит, только через организатора);
уведомление о выходе — со звуком; имя — только в приложении; о смене имени админам не сообщаем.

## Контекст

| | Сейчас | Нужно |
|---|---|---|
| Имя | вводится один раз при регистрации в боте; дальше меняет только организатор (`admin.rename`) | человек меняет своё имя сам на главном экране приложения |
| Выход | участник выйти не может (только организатор удаляет его); админ выходит переключателем «Я участвую» до жеребьёвки | участник выходит сам до жеребьёвки — с вводом слова ВЫЙТИ; организаторы узнают сразу |

Имя одно на все события: его видят организаторы (панель, журнал), Санта — как имя подопечного, подопечный — как имя
Санты при раскрытии.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Выйти из события до жеребьёвки (Priority: P1)

Аня вступила в событие «Новый год — семья», но поняла, что не сможет прийти. Она открывает событие, вкладку «Инфо»,
внизу нажимает «Выйти из события». Открывается шторка: что удалится (письмо, адрес, переписка, обращения в этом событии)
и что вернуться можно по пригласительной ссылке, пока открыта регистрация. Аня вводит слово ВЫЙТИ — кнопка «Выйти»
становится доступной, нажимает её. Приложение возвращает её на главный экран с сообщением, что она вышла. Каждый
организатор (кроме неё самой, если она организатор) получает в боте сообщение со звуком: «🚪 Аня выходит из события
«Новый год — семья»» с кнопкой «🛠 Открыть событие». В журнале события — запись «вышел(а) из события».

**Why this priority**: сейчас человек, который передумал, должен просить организатора удалить его; организатор может
не заметить просьбу до жеребьёвки — и в парах окажется человек, который не будет дарить.

**Independent Test**: участник идущего события без жеребьёвки вызывает выход со словом ВЫЙТИ — он больше не участник,
его данных в событии нет, админам ушло по одному сообщению, в журнале одна запись `member.leave`.

**Acceptance Scenarios**:

1. **Given** Аня — участница события без жеребьёвки, **When** она вводит ВЫЙТИ и нажимает «Выйти», **Then** она больше
   не участница, её письмо, адрес, исключения, закреплённые пары, переписка и обращения в этом событии удалены, другие
   события не затронуты.
2. **Given** то же, **When** выход прошёл, **Then** каждый админ и владелец, кроме самой Ани, получает одно сообщение со
   звуком с её именем, названием события и кнопкой «🛠 Открыть событие»; в журнале события — одна запись `member.leave`
   с её именем.
3. **Given** в шторке выхода ничего не введено или введено другое слово, **When** Аня смотрит на кнопку «Выйти»,
   **Then** кнопка недоступна; запрос к серверу без слова ВЫЙТИ получает отказ «Чтобы выйти, введи слово ВЫЙТИ.», и
   ничего не меняется.
4. **Given** Аня вышла, регистрация открыта, **When** она снова открывает пригласительную ссылку, **Then** она вступает,
   как обычно (имя не спрашивается; при «одобрении» — подаёт заявку): отметки «удалён организатором» у неё нет.
5. **Given** Аня нажала «Выйти» дважды подряд (или два запроса пришли в одну миллисекунду), **When** оба обработаны,
   **Then** выход один: организаторы получили по одному сообщению, запись журнала одна, второй запрос получил отказ
   «Ты не участвуешь в этом событии.»

### User Story 2 — После жеребьёвки — только через организатора (Priority: P1)

Жеребьёвка в событии уже прошла. Боря открывает вкладку «Инфо» — внизу вместо кнопки «Выйти из события» подсказка:
«Жеребьёвка уже прошла — выйти можно только через организатора: напиши ему, он уберёт тебя из события.» и кнопка
«💬 Написать организатору», которая открывает обращение к организатору.

**Why this priority**: после жеребьёвки уход меняет подопечного у Санты ушедшего (подарок мог быть уже куплен) и может
быть невозможен без нарушения правил; это решает организатор (решение владельца — вариант A).

**Independent Test**: участник события с проведённой жеребьёвкой вызывает выход со словом ВЫЙТИ — отказ, он
по-прежнему участник, сообщений и записей журнала нет; в приложении на вкладке «Инфо» нет кнопки выхода, есть подсказка.

**Acceptance Scenarios**:

1. **Given** жеребьёвка проведена, **When** Боря открывает «Инфо», **Then** кнопки «Выйти из события» нет, есть
   подсказка и кнопка «💬 Написать организатору» (если организатору можно написать) — она открывает ту же шторку
   обращения, что и «Нужна помощь?».
2. **Given** жеребьёвка проведена, **When** запрос выхода со словом ВЫЙТИ приходит на сервер, **Then** отказ «Жеребьёвка
   уже прошла — выйти можно только через организатора: напиши ему.», ничего не меняется.
3. **Given** Аня нажимает «Выйти», а в это же время проходит жеребьёвка (вручную или автожеребьёвка), **When** жеребьёвка
   записана первой, **Then** Аня получает отказ «Жеребьёвка уже прошла…», остаётся участницей и есть в парах; **When**
   первым записан выход, **Then** жеребьёвка не записывается с ней (состав изменился — обычная проверка снимка).
4. **Given** событие завершено, **When** участник открывает «Инфо», **Then** ни кнопки выхода, ни подсказки о выходе нет;
   запрос выхода получает отказ «Событие завершено — выйти из него уже нельзя.»

### User Story 3 — Сменить своё имя (Priority: P2)

Вера при регистрации написала «верунчик». На главном экране приложения в разделе «Профиль» (над «Уведомлениями») она
видит своё имя и кнопку «✏️ Изменить имя». В шторке — поле с текущим именем, подсказка, кто видит имя, и «Сохранить».
Она пишет «Вера Петрова», сохраняет — приветствие «Привет, Вера Петрова!» и раздел «Профиль» показывают новое имя,
организаторы видят его в панели и в общем журнале («верунчик → Вера Петрова»). Сообщений организаторам нет.

**Why this priority**: сейчас опечатку или шуточное имя может исправить только организатор; это неудобно, но не мешает
игре — поэтому P2.

**Independent Test**: зарегистрированный человек сохраняет новое имя — имя изменилось, в общем журнале одна запись
`rename`, сообщений в очереди нет; то же имя ещё раз — успех без записи.

**Acceptance Scenarios**:

1. **Given** Вера зарегистрирована, **When** она сохраняет «Вера Петрова», **Then** её имя — «Вера Петрова» во всех
   событиях; в общем журнале одна запись `rename` «верунчик → Вера Петрова» от её имени; организаторам сообщений нет.
2. **Given** то же, **When** она сохраняет имя с лишними пробелами («  Вера   Петрова »), **Then** сохраняется «Вера
   Петрова» (пробелы схлопнуты, как при регистрации).
3. **Given** то же, **When** имя пустое или длиннее 40 символов, **Then** отказ «Имя должно быть от 1 до 40 символов»,
   имя прежнее; в приложении поле не даёт ввести больше 40 символов.
4. **Given** имя уже «Вера Петрова», **When** она сохраняет то же имя (в т.ч. дважды подряд или два запроса в одну
   миллисекунду с новым именем), **Then** успех; записей журнала — ноль для того же имени и одна для нового.

---

### Edge Cases

- **Организатор-участник** (админ или владелец) видит ту же кнопку выхода на «Инфо»; переключатель «Я участвую» в панели
  остаётся как был (без сообщения организаторам, запись `participate`). Выход через «Инфо» — сообщение остальным
  организаторам и запись `member.leave`. Если других организаторов нет — сообщений нет, запись журнала есть.
- **Организатор после выхода** остаётся организатором: приложение открывает главный экран, событие — в «Других
  событиях».
- **Организатору некому написать** (в боте нет других организаторов) — после жеребьёвки на «Инфо» только подсказка,
  без кнопки «Написать организатору».
- **Открытое обращение** уходящего удаляется вместе с ним (как при удалении организатором); организатор, который его
  вёл, видит, что обращения больше нет.
- **Режим ответа в боте** (`pending` переписки или обращения в этом событии) после выхода не отправляет сообщение: бот
  отвечает, как сейчас отвечает не участнику.
- **Одновременно с выходом** событие удаляют, завершают или сбрасывают — выход либо проходит до этого, либо получает
  отказ; лишних сообщений и записей нет.
- **Семья** не меняется: семьи общие для бота, выход из события их не трогает.
- **Заявка на вступление** (если была) не трогается: выход удаляет только данные участия.
- **Имя** меняет только зарегистрированный (кто ещё не написал имя боту, раздела «Профиль» не видит — он и приложение
  не открывает). Организатор по-прежнему может переименовать человека (`admin.rename`); правило одно — 1–40 символов,
  одна строка.
- **Смена имени после раскрытия** — допустима: старые сообщения бота остаются со старым именем, приложение показывает
  новое.

## Requirements *(mandatory)*

### Functional Requirements

**Выход из события**

- **FR-001**: Участник идущего события, в котором жеребьёвка ещё не проведена, MUST иметь возможность выйти из него сам,
  из вкладки «Инфо» (внизу экрана) мини-приложения.
- **FR-002**: Выход MUST требовать ввода слова ВЫЙТИ (без учёта регистра и пробелов по краям); кнопка подтверждения
  недоступна, пока слово не введено; сервер проверяет слово сам и без него отказывает «Чтобы выйти, введи слово ВЫЙТИ.»
- **FR-003**: Шторка выхода MUST перечислять, что удалится (письмо и адрес, переписка, обращения к организатору в этом
  событии), и сообщать, что вернуться можно по пригласительной ссылке, пока регистрация открыта.
- **FR-004**: Выход MUST удалять данные участия в событии так же, как уход участника по списку данных события и
  человека (письмо, адрес, исключения, закреплённые пары, переписка, обращения); другие события и общие данные (имя,
  семьи, заявки) не меняются.
- **FR-005**: Выход MUST NOT ставить отметку «удалён организатором»: человек может вернуться по ссылке по обычным
  правилам вступления.
- **FR-006**: Выход MUST проходить, только если в момент записи человек ещё участник и жеребьёвка не проведена; иначе —
  отказ без изменений, сообщений и записей журнала.
- **FR-007**: После выхода каждый организатор (админы и владелец), кроме самого вышедшего, MUST получить одно сообщение
  бота со звуком: «🚪 <имя> выходит из события «<название>»» с кнопкой «🛠 Открыть событие» (открывает событие в
  приложении).
- **FR-008**: Выход MUST записываться в журнал события кодом `member.leave` с именем вышедшего (без пар и текстов).
- **FR-009**: Из двух одновременных выходов одного человека (в т.ч. в одну миллисекунду) MUST пройти один: одно
  сообщение каждому организатору, одна запись журнала; второй получает отказ «Ты не участвуешь в этом событии.»
- **FR-010**: Если жеребьёвка проведена, на вкладке «Инфо» вместо кнопки выхода MUST быть подсказка «Жеребьёвка уже
  прошла — выйти можно только через организатора: напиши ему, он уберёт тебя из события.» и, если организатору можно
  написать, кнопка «💬 Написать организатору», открывающая обращение; запрос выхода — отказ «Жеребьёвка уже прошла —
  выйти можно только через организатора: напиши ему.»
- **FR-011**: В завершённом событии выход MUST быть недоступен: ни кнопки, ни подсказки о выходе; запрос — отказ
  «Событие завершено — выйти из него уже нельзя.»
- **FR-012**: Выйти MUST может только участник события (не участнику — общий отказ «не участник», как у других
  действий участника); любой участник — в том числе админ и владелец.
- **FR-013**: После выхода приложение MUST вернуть человека на главный экран и показать, что он вышел из события.

**Имя**

- **FR-014**: Зарегистрированный человек MUST иметь возможность сменить своё имя на главном экране мини-приложения в
  разделе «Профиль» (над «Уведомлениями»): текущее имя, кнопка «✏️ Изменить имя», шторка с полем, подсказкой «кто видит
  имя» и кнопкой «Сохранить».
- **FR-015**: Правило имени MUST совпадать с регистрацией и переименованием организатором: пробелы схлопываются в один,
  по краям обрезаются; от 1 до 40 символов; иначе отказ «Имя должно быть от 1 до 40 символов».
- **FR-016**: Смена имени MUST писать общий журнал `rename` («<старое> → <новое>», автор — сам человек) только при
  настоящем изменении; то же имя — успех без записи; из одинаковых одновременных смен — одна запись.
- **FR-017**: О смене имени организаторам MUST NOT приходить сообщения бота.
- **FR-018**: После сохранения приложение MUST сразу показывать новое имя (приветствие и «Профиль») без перезагрузки.
- **FR-019**: Смена имени — только в приложении: новых команд бота нет.

**Общее**

- **FR-020**: Новые действия MUST быть описаны в сводном описании API (кто, событие, «в завершённом», запрос, ответ,
  отказы, журнал), новый код журнала — в списке кодов и в подписях журнала приложения.
- **FR-021**: Все тексты для людей — со словом «событие» (не «эвент»), кнопки — без «＋»; интерфейс — только из
  дизайн-системы; кнопки недоступны на время запроса.
- **FR-022**: Прежние действия, ответы, тексты и число запросов к базе у прежних действий MUST NOT меняться.

### Key Entities

- **Человек** (`users`): имя — одно на все события; меняет сам человек или организатор.
- **Участие** (`members` и связанные данные события): письмо, адрес, исключения, закреплённые пары, переписка,
  обращения — удаляются при выходе.
- **Запись журнала**: `member.leave` (журнал события), `rename` (общий журнал) — без пар и текстов.
- **Сообщение организатору** (очередь бота): о выходе — со звуком, с кнопкой открытия события.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Участник выходит из события до жеребьёвки за 3 действия (кнопка «Выйти из события», ввод слова, «Выйти»)
  без участия организатора.
- **SC-002**: После выхода в событии не остаётся ни одной записи данных вышедшего (0 строк участия, письма, адреса,
  исключений, закреплённых пар, переписки, обращений).
- **SC-003**: На каждый выход — ровно 1 сообщение каждому организатору (кроме вышедшего) и ровно 1 запись журнала, в
  том числе при двух нажатиях в одну миллисекунду.
- **SC-004**: После жеребьёвки и в завершённом событии успешных выходов — 0, в том числе при выходе одновременно с
  жеребьёвкой (выход или жеребьёвка — что-то одно, участник в парах всегда участник события).
- **SC-005**: Человек меняет имя за 3 действия («Изменить имя», ввод, «Сохранить»); новое имя видно сразу.
- **SC-006**: Смена на то же имя — 0 записей журнала; на новое — ровно 1 (в т.ч. при двух одновременных); сообщений
  организаторам — 0.
- **SC-007**: Все прежние автотесты зелёные; ответы прежних действий и эталон отказов прежних действий не меняются.

## Assumptions

- Слово подтверждения — «ВЫЙТИ», по образцу «УДАЛИТЬ», «СБРОС», «ОТМЕНА», «ОТКРЫТЬ»: приложение не даёт нажать без
  слова, сервер проверяет сам. Второго окна «точно?» после ввода слова нет: слово — уже явное подтверждение, а выход до
  жеребьёвки обратим (можно вернуться по ссылке).
- Отдельного сообщения бота самому вышедшему нет: он действует в приложении и видит результат сразу.
- Текст сообщения организаторам — «выходит из события», по образцу «присоединяется к событию»; в отличие от него — со
  звуком (решение владельца: выход редок и требует внимания до жеребьёвки).
- Переключатель «Я участвую» у организатора не меняется (без сообщения, запись `participate`): это его управление
  своим участием из панели; кнопка на «Инфо» — путь участника.
- Владелец после жеребьёвки по-прежнему не может выйти сам (как и сейчас: «удалить себя» нельзя) — вне рамок фичи.
- Отказ «не участник» — общий отказ действий участника (как у письма и переписки).
- Тайна не затронута: выход до жеребьёвки не меняет пар (их нет), смена имени не раскрывает пар; организатор и так
  видит состав и имена.
- Добавление в событие знакомых боту людей — отдельная отложенная задача (`docs/todo.md`), в эту фичу не входит.
