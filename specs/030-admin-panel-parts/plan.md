# Implementation Plan: Панель организатора — переключатель регистрации, панель по секциям

**Branch**: `030-admin-panel-parts` | **Date**: 2026-11-16 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/030-admin-panel-parts/spec.md`.

## Summary

Только мини-приложение. (1) `renderAdmin` (`src/app/05-admin.js.txt`, 675 строк) остаётся точкой входа: читает
`admin.state`, собирает объект панели `p` и склеивает секции — функции верхнего уровня `adminXxx(p)` → список узлов, в
прежнем порядке. Связь секций — `p.watch(ключ, fn)` / `p.set(ключ, значение)`: кольцевая (секция «Жеребьёвка») → форма
закреплённых пар, регистрация («Приглашение») → кнопка приглашения из прошлого события и подсказка у заявок. (2)
Исправление переключателя регистрации — `p.set('registration_open', on)` после ответа сервера; зависимые секции
обновляются на месте. (3) Помощники `personTitle(u)` (05-admin) и `backToEvent(evId)` (07-sheet-chat). Новый тест
`tests/app-panel.test.mjs`; правило 2 `tests/app-ui.test.mjs` — на всю часть `05-admin`; проверка в Chrome
`checkRegistration` в `tests/screenshots.mjs`.

## Decisions (research)

- **R1. Объект панели.** `p = { d, s, users, byId, players, me, done, evId, drafts, xapi, again, refresh, live, watch,
  set }` — всё, что раньше было замыканием `renderAdmin`. Секции разбирают нужное (`const { s, d, xapi } = p;`): тексты
  подтверждений остаются выражениями `u.name`, `s.title` — правило 6 `app-ui` считает их худший случай по именам.
  Отвергнуто: глобальная «текущая панель» — две перестройки подряд (ответ для покинутого экрана) смешали бы данные.
- **R2. Связь секций.** `p.watch(key, fn)` — подписка; `p.set(key, value)` — записать в `s` и вызвать подписчиков. Так
  уже работала кольцевая (`syncFixed`, 014) — теперь общим способом. Переключатель, от значения которого зависит другая
  секция, вызывает `p.set` или перестраивает панель (`again`/`refresh`): правило `app-panel` ищет `checked: s.ключ` /
  `d.ключ` у переключателя и чтение того же ключа в другом месте панели. Отвергнуто: перестраивать всю панель (`again`)
  — сбросило бы выбор в «Из какого события…» (владелец просил обновлять только два места).
- **R3. Подсказка у заявок.** В идущем событии узел подсказки есть всегда, `hidden` при открытой регистрации (как
  `noDate` в «Параметрах»); у завершённого — прежняя постоянная подсказка. Кнопка «Пригласить участников» и её
  подсказка — функция `sync` секции; после рассылки (`busy`) — снова `sync`, чтобы кнопка не стала доступной при
  закрытой регистрации.
- **R4. Секции.** Порядок и состав — прежние: идущее событие — «Приглашение», «Заявки», «Удалённые», «Пригласить из
  прошлого», «Обращения», «Объявление»; завершённое — «Заявки», «Обращения»; далее у всех — «Участники»,
  «Исключения», «Закреплённые пары», «Жеребьёвка», «Параметры», «Журнал», «Служебный просмотр», «Опасная зона».
  Шторки участника — `adminMemberMenu(p, u, chips)`, `adminTransfer(p, u)`; правила пар — `nameOf(p, id)`,
  `rulePairs(rows)`, `ruleList(p, pairs, opts)`, `ruleForm(p, opts)`. Предел — 100 строк на функцию панели (самая
  длинная секция — «Жеребьёвка»).
- **R5. Правило 2 `app-ui` (026).** Раньше проверялся блок `renderAdmin`; теперь — вся часть `05-admin.js.txt` (её
  строки в склейке берутся из `PARTS`): иначе секции вне `renderAdmin` выпали бы из проверки.
- **R6. Помощники без копий.** `personTitle(u)` — заголовок строки списка «имя  @username» (заявки, удалённые,
  участники); `backToEvent(evId)` — после закрытия шторки переписки и «Организатору»: перечитать событие и обновить
  экран, если пользователь на нём. Правило `app-panel` «без копий» — по образцу правила 7 `app-ui`.
- **R7. Проверка в Chrome.** `checkRegistration` (событие B скриншотов: заявка Стёпы, прошлое событие A): выбрать A в
  «Из какого события…», набрать черновик объявления, прокрутить к переключателю; выключить — кнопка недоступна,
  подсказки по закрытой регистрации, выбор/черновик/прокрутка прежние, загрузчика не было; включить — обратно. Отказ
  сервера (подмена ответа) — переключатель вернулся, кнопка и подсказки прежние. В конце регистрация открыта —
  снимки после проверки не меняются.
