# Контракт: панель организатора по секциям (030)

Часть `src/app/05-admin.js.txt`. Проверки — `tests/app-panel.test.mjs`, правило 2 `tests/app-ui.test.mjs` (026), в
Chrome — `checkRegistration` (`tests/screenshots.mjs`).

## Точка входа

`renderAdmin({ quiet })` (через `screen`, 026) — единственная функция панели, которая читает `state`: захватывает
`state.nav` и `state.evId`, читает `admin.state` своего события, собирает объект панели `p` и склеивает узлы секций в
порядке:

| Событие | Секции |
|---|---|
| идёт | `adminInvite`, `adminRequests`, `adminRemoved`, `adminInviteFrom`, `adminSupport`, `adminAnnounce` |
| завершено | `adminRequests`, `adminSupport` |
| любое (далее) | `adminMembers`, `adminExclusions`, `adminFixed`, `adminDraw`, `adminParams`, `adminLog`, `adminVault`, `adminDanger` |

Перед секциями — `finishedNotice(s)`. После склейки — `main.replaceChildren(…)`; при `quiet` прокрутка прежняя.

## Объект панели `p`

| Поле | Что |
|---|---|
| `d`, `s` | ответ `admin.state` и его `settings` — всё о событии панели только отсюда (026) |
| `users`, `byId`, `players`, `me`, `done` | люди ответа, по id, зарегистрированные, кто смотрит (`state.me`), событие завершено |
| `evId`, `drafts` | событие панели (захвачено), черновики панели этого события (`state.drafts[evId]`) |
| `xapi(action, body)` | запрос с `event: evId` |
| `again(opts)` | перестроить панель (если экран не покинут) |
| `refresh(opts)` | перечитать пользователя и событие, заголовок, вкладки — и перестроить панель |
| `live()` | экран панели ещё на месте |
| `watch(key, fn)` | подписка секции на изменение параметра `s[key]` |
| `set(key, value)` | записать `s[key]` и вызвать подписчиков — после успешного запроса |

Секция — функция верхнего уровня `adminXxx(p)` → массив узлов (пустой, если секции нет; `null` отбрасываются).
Разбирает нужное из `p` (`const { s, d, xapi } = p;`): выражения в текстах подтверждений — `u.name`, `s.title` (правило
6 `app-ui` знает их пределы).

## Связи секций

| Параметр | Кто меняет | Кто обновляется на месте |
|---|---|---|
| `registration_open` | «Приглашение» (переключатель) | «Заявки» (подсказка «Регистрация закрыта…», `hidden`), «Пригласить из прошлого» (кнопка и подсказка) |
| `ring` | «Жеребьёвка» (переключатель) | «Закреплённые пары» (флажок «и наоборот», предупреждение о взаимных) |

Остальные переключатели, от значения которых зависит другая часть панели, перестраивают её (`again`/`refresh`):
«Удалённые могут вернуться», «Я участвую», «Учитывать семьи». Не зависят — «Вступление по одобрению», «Не повторять
пары».

## Правила (`tests/app-panel.test.mjs`)

1. **Переключатель и зависимые секции.** У каждого `bindToggle` в части `05-admin` значение берётся из
   `checked: s.ключ` или `d.ключ`; если тот же ключ читается где-то ещё в панели, обработчик вызывает `set('ключ'`,
   `again(` или `refresh(`.
2. **Длина.** Функции верхнего уровня части `05-admin` — не длиннее 100 строк.
3. **Без копий.** Заголовок «имя  @username» (`'  @' +`) — только в `personTitle`; возврат к событию после шторки
   (`renderWard({ cached: true })`) — только в `backToEvent`.

У каждого правила — пример «от противного».
